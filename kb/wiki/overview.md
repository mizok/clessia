# Clessia 系統總覽

本文件整理 PRD 第 1-5 章，說明專案背景、系統目標、核心名詞與角色邊界，作為各流程與功能規格的共同語意基準。

## 1. 專案背景與目標

### 1.1 專案背景

Clessia 要解決補習班營運常見痛點：

1. 出勤紀錄依賴人工或紙本，容易錯漏。
2. 例外處理（忘記打卡、臨時請假、補請）成本高。
3. 教學紀錄（聯絡簿、作業、成績）分散，追溯困難。
4. 課表常異動，但缺乏完整歷史紀錄。

### 1.2 系統目標

1. 以「開課班（Class）」與「課堂（Session）」為核心管理單位。
2. 出勤、請假、聯絡簿可追溯到具體課堂。
3. 成績可追溯到具體考試事件。
4. 降低管理員處理例外的負擔。
5. 讓老師快速完成每日教學紀錄。
6. 讓家長清楚查看孩子上課、成績、餐費與繳費資訊。
7. 重要操作都需可稽核（誰、何時、做了什麼）。

### 1.3 系統範圍

**MVP 主要包含**：課程與開課班、報名、到班掃碼、出勤、請假、聯絡簿、考試成績、餐費、課務異動、通知、報表匯出。  
**不包含**：線上金流串接、招生行銷、排名競賽、複雜多層審批。  
**簡化處理**：繳費採線下收款，系統做單據與確認流程管理。

## 2. 核心概念與名詞（PRD 4.x）

### 2.1 分校（Campus）

- 補習班實體據點，可多分校並存。
- 課堂發生在特定分校與教室。

### 2.1.1 教室（Classroom）

- 分校內實體教學空間。
- 上課時間（Schedule）需指定教室以避免衝突。

### 2.2 課程（Course）

- 定義「教什麼」，不定義「何時上」。
- 由管理者建立，例如國一數學、小五英文。

### 2.3 開課班（Class）

- 同課程下實際運作班級（學生群 + 固定上課時間）。
- 可設定推薦加選、適用年級範圍、名額上限。
- 一門課可有多個開課班。

### 2.4 上課時間（Schedule）

- 開課班的規則性上課時段（例：每週三 19:00-21:00）。
- 一個開課班可有多個時段，且時段可配置不同老師。

### 2.5 課堂（Session）

- 某天實際發生的一堂課，為核心資料單位。
- 由 Schedule 自動產生。
- 出勤、請假、聯絡簿依附於 Session。
- Session 不可刪除，只能停課標記。

### 2.6 學生報名（Enrollment）

- 學生加入開課班的正式學籍紀錄，含生效起訖。
- 只有生效期間內才出現在課堂名單。
- 支援 `monthly`、`semester` 繳費週期；同生可跨課程不同週期。
- 轉為非活躍狀態（如 `suspended`、`withdrawal`、`void`）需記錄原因。

### 2.7 日到班（Check-in）

- 學生某日到達分校的事件。
- 同分校同日最多一次（跨分校可各一次）。
- 到班是觸發訊號，不等於課堂出席結果。

### 2.8 課堂出席（Attendance）

- 學生在某堂課最終狀態：`present`、`late`、`leave`、`absent`。

### 2.9 請假（Leave）

- 針對課堂的請假紀錄，由管理員建立。
- 建立後該課堂出席狀態改為 `leave`。

### 2.10 聯絡簿（Teacher Log）

- 老師對單堂課紀錄：課程範圍、作業、備註。
- 可附檔最多 3 個，每檔 5MB 內（圖/影/文字）。

### 2.11 考試事件（Assessment Event）

- 屬於某課程，可分為：
  1. 隨堂考：關聯特定 Session。
  2. 聯合模擬考：獨立事件，可跨多開課班。
- 每次考試可設定滿分與及格線。

### 2.12 成績（Grade）

- 學生在某次考試的成績資料。
- 狀態：`normal`、`absent`、`makeup`。

### 2.13 餐費報帳（Meal Record）

- 學生某日餐費紀錄，可同日多筆。
- 僅記帳，不等同收款。

### 2.14 課務異動（Schedule Change）

- 調課、代課、停課的結構化紀錄。

### 2.15 通知（Notification）

- 主要通知家長/老師課務異動與流程事件。
- 通知保留 90 天；稽核紀錄保留 2 年。

### 2.16 出勤模式（Attendance Mode）

- 分校層級設定，僅管理員可改：
  - 日到班模式（預設）：到班後自動推算當日課堂出席/遲到。
  - 課堂模式：逐堂人工確認，不自動決定最終出席。

### 2.17 報名申請（Enrollment Request）

- 正式 Enrollment 前的流程資料。
- 來源：`public_form`、`parent_portal`、`add_course`、`renewal`。
- 狀態：`pending` → `awaiting_payment` → `completed`，或 `rejected` / `canceled` / `expired`。
- `public_form` 來源在繳費完成前不建立家長帳號與學生主資料。

### 2.18 繳費單（Invoice）

- 報名申請對應的應收單據。
- 狀態含 `pending`、`partial_paid`、`paid`、`overdue`、`void`、`canceled`、`refunded`。
- 含 `access_token`（UUIDv4）供免登入連結，但需輕量驗證後才顯示完整內容。

### 2.19 繳費紀錄（Payment Record）

- 記錄實際收款（MVP：現金/銀行轉帳）。
- 收款確認後觸發：更新 invoice、更新 request、啟用 Enrollment、必要時建立家長/學生與關聯。
- 支援部分付款與強制啟用、失效後重啟、退款後失效。

### 2.20 費用方案（Fee Template）

- 開課班收費規格模板，支援生效期間與按比例計算。

### 2.21 系統設定（System Settings）

- 管理報名、試聽、繳費、續課、學年升級、分校帳務資訊。
- 可用模板快速建立繳費週期，再由管理員自由調整。

### 2.22 待處理工作（Task）

- 來源含試聽安排/跟進、報名審核、繳費確認、續課異動、年級不符等。
- 狀態：`pending`、`in_progress`、`completed`、`canceled`。
- 採團隊指派 + 個人認領 + 可轉派機制。

### 2.23 預告制自動續課（Pre-Notification Auto-Renewal）

- T-5 預告通知，T-0 自動開單。
- 家長若提異動，該生暫停自動開單並產生任務。
- 逾期且超過寬限期自動 `void`，降低幽靈名單維護成本。

### 2.24 試聽申請（Trial Request）

- 與報名申請獨立。
- 狀態：`pending`、`scheduled`、`completed`、`canceled`。
- 試聽後若要報名，仍需走報名申請流程。

### 2.25 學年與升級（Academic Year & Promotion）

- 使用標準 K-12 年級碼（K、P1-P6、J1-J3、S1-S3）。
- 年度升級時自動 +1，最高年級轉為 `graduated`。
- 續課開單前與升級後都要執行年級不符檢查（Grade Mismatch Check）。

## 3. 角色定義與權限邊界（PRD 第 5 章）

### 3.1 Student（學生）

- **不是登入角色，沒有帳號。**
- **學生是資料實體**，用於承載學籍、出勤、成績、餐費等資料關聯。
- 學生端唯一動作是到班掃碼（Check-in 事件）。

### 3.2 Parent（家長）

- 以查閱為主，可提交試聽/報名/加選/續課異動相關申請。
- 可查看孩子課表、到班、聯絡簿、成績、餐費、繳費紀錄。
- 一位家長可關聯多位學生。

### 3.3 Teacher（任課老師）

- 管理自己任課課堂的教學紀錄（聯絡簿、考試、成績）。
- 可修改自己課堂當天出勤；跨日修正需管理員處理。

### 3.4 Admin（系統管理員）

- 承擔行政與營運管理工作，透過 `admin_permissions` 細分能力。
- 覆蓋範圍：課程與班級、報名與繳費、出勤與請假、任務、人員權限等。

### 3.5 角色兼任

- 同一使用者可同時具多角色（如 Admin + Teacher + Parent）。
- 兼任時需透過「切換身分」進入不同視圖，功能與權限彼此隔離。
