# Gate 網地圖

> **這頁不重複 [[architecture/constitution-enforcement|`constitution-enforcement.md`]]。**
> 那份按**憲法條款**組織（哪條 clause 用什麼機制守），這份按 **gate** 組織 ——
> 因為現在有好幾道 gate **不對應任何 clause**，在那份文件裡沒有位置。
>
> 要查「c6 是誰在守」→ 看 enforcement。
> 要查「這個 repo 到底有哪些自動檢查」或「我該不該再造一道」→ 看這頁。

## 為什麼需要這張地圖

2026-09 這張網長得很快（一天內加了觸控尺寸、c5、page-actions），而它的成長方式是
**一次一道、各自寫在自己的註解裡**。後果是：**沒有人看得到全貌**，於是

- 有人為了已經被守住的東西再造一道
- 有人以為某件事被守住了，其實沒有（各 gate 的能力邊界散在各自的檔案裡）

## 一、這張網有哪些

### 憲法條款的（A 編號，細節看 enforcement）

`A1`–`A18` 對應 c1 / c3 / c6 / c7 / c8 / c9 / c10 / c11 / c12 與 c5、c2。
**編號只增不重用**（A4 不存在，退掉的檢查留著洞）。

### 不對應任何 clause 的（沒有 A 編號）

這幾道守的是**使用者的產品決定**，不是架構不變量 —— 所以它們不該被寫成憲法，
但一樣需要機器守，因為它們都有「不做也不會壞、只會慢慢被磨掉」的性質：

| Gate                       | 守什麼                                | 為什麼需要機器                                                                   |
| -------------------------- | ------------------------------------- | -------------------------------------------------------------------------------- |
| `checkBandContrast`        | 橘帶上的字必須過 AA                   | 近黑降透明度後掉出 AA，**畫面看起來只是淡了一點**，沒有任何編譯期訊號            |
| `checkUsageContrast`       | 文字色與底色的**配對**過 AA           | 每個 token 各自合格、配在一起卻不合格                                            |
| `checkMobileFirst`         | 桌機優先的寫法只准變少                | 遷移會停在「大家都同意要做」然後不動 —— **每次「就這次先照舊寫」都是局部理性的** |
| `checkTouchTargets`（A17） | 自己刻的可點元素有尺寸下限            | 見下方「反向規則」                                                               |
| `checkPageActions`         | 主要行動要進拇指區                    | **手機上按不到這件事，寫的人不會在自己的螢幕上發現**                             |
| `checkOrphanImports`       | 沒用到的 PrimeNG NgModule             | Angular 的 NG8113 只涵蓋 standalone，**NgModule 完全不報**                       |
| `checkDualTrackTables`     | 不要再手刻第二份手機版表格            | 同一份資料宣告兩次，**改欄位時漏掉一邊不會有任何錯誤**                           |
| `W1`                       | 使用者層級 skill 在不在（**只警告**） | 別人的機器裝不裝是他的事                                                         |

> **共同的形狀**：這些全部是「錯了不會壞、只會安靜地變差」的東西。
> 會自己爆的東西不需要 gate —— 測試和編譯器已經在做了。
> **gate 的價值跟「失敗有多安靜」成正比。**

## 二、要新增一道之前，先問四個問題

### 1. 已經有東西在守了嗎

上面那張表 + enforcement 的 A1–A18。**重複造 gate 的成本不是多跑幾秒，
是兩道規則對同一件事有不同意見時沒人知道該信哪個。**

### 2. 它的輸入是「你改的東西」還是「整個 repo 的狀態」

這決定**強制點放哪裡**：

- 輸入是你改的檔案 → 放分支（越左越好，回饋越快）
- 輸入是整個 repo 的狀態 → **強制點放 main**，分支上只警告

錯放的代價不是漏檢，是**每個人都要為別人的改動重生一次產物**。
判例是功能區現況表：它從整個磁碟推導，兩支並行分支各自重生就必然衝突
（2026-08-29 一天內三連撞）。詳見 enforcement 的「現況表的強制點是那個 job」。

### 3. 立法時是零違規，還是有存量

| 情況                   | 做法                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| **零違規**             | **不要 baseline。** 最便宜的立法時機 —— 不必分診舊債，之後任何一筆都是新的（A18 c5 就是） |
| 有存量但都該修         | **ratchet baseline**：既有的進清單只擋新增；修好了提醒重生清單                            |
| 有存量且部分永遠不會修 | **債與豁免分開記**（見下）                                                                |

### 4. 這筆存量是「債」還是「永久豁免」

**混在一起的話「清到零」這個機制永遠跑不完** —— 帳面上永遠有幾筆，
而沒有人知道那幾筆是還沒修、還是根本不用修。

|                                    | 意思                             | 會歸零嗎                              |
| ---------------------------------- | -------------------------------- | ------------------------------------- |
| `allowlist: { 路徑: 數量 }`        | **債** —— 該修但還沒排到         | 會，歸零那天整筆刪掉，gate 自動變全面 |
| `exempt: { 路徑: { count, why } }` | **永久豁免** —— 沒有合規路徑可走 | 不會，所以**必須寫 `why`**            |

判例：c2 的 `orgId` 三處 —— Better Auth 的 API 宣告 `input: false`，**明確拒收**那個欄位。
要求合規等於要求做不到的事，那種規則只會被繞過。所以它走**規則層豁免**而不是清單，
理由是「allowlist 的語意是會還清的債，而這三處永遠不會被修」。

## 三、三條反覆吃過虧的規則

### 反向規則：找「缺少保障」比找「錯誤的值」有效

直覺會把 gate 寫成「宣告了不合格的值 → 報」。**那會漏掉最嚴重的案例。**

老師端 dashboard 那兩顆連結（該頁僅有的導覽動作）改動前是
`padding: 0` + `cursor: pointer` + **零尺寸宣告** —— 20px 純粹是文字行高。
找「小數字」的掃描一無所獲，**因為根本沒有數字可抓**。

所以 A17 的規則是「宣告了 `cursor: pointer` 卻**沒有任何尺寸下限**」。

> 一般化：**問「有沒有保障」而不是「值對不對」。** 沒寫的東西比寫錯的東西更常見、
> 也更難發現。

### 時序規則：各自綠，合起來可能紅

**gate 檢查的是「CI 跑的時候的樹」，不是「合進去之後的樹」。**

2026-09-03 的實例：A17 於 03:42 合併；#186 於 05:27 合併且**它自己的 CI 是綠的** ——
因為那份 CI 跑在 A17 落地之前，樹裡根本沒有這道 gate。兩支各自合法，**合起來 main 紅**。

同一條縫的另一面：兩支 PR 各自綠、動同一個函式，合起來壞。

**處置**：合併前用 `update-branch` 拉一次 main 再看 CI。那同時解掉「gate 比 PR 新」
與「兩支互相衝突」兩種。

### 能力邊界是必寫的，不是加分項

每一道 gate 的註解都必須寫**它看不到什麼**。理由是：

> **綠燈會被讀成「這件事沒問題」，而那幾乎總是比實情寬。**

現有的例子（照抄它們的措辭）：

- 對比 gate：「綠燈的意思是**掃得到的那一半**沒問題」——
  底色來自跨檔案 DOM 祖先的配對它看不到，而那正是最常見的寫錯形狀
- A17 觸控：尺寸由 padding 與行高撐出來的看不到（**那要在裝置上量**）；
  PrimeNG 元件不在範圍；**parent 區沒有人量過**（public 已於 2026-09-04 納入掃描）。
  另外**空殼頁的綠燈沒有意義** —— 一個還沒實作的頁面必然零違規，不是因為它合格，
  是因為它裡面什麼都沒有，所以 gate 會對這種頁面另外發警告
- A18 c5：只看得到路徑層面的直接 import，**經由 `core/` 的間接耦合看不到** ——
  而那是 c5 真正想防的東西之一
- mobile-first：只數 `respond-to` 的出現與否，不判斷寫得好不好

## 四、gate 自己也會壞，而且是安靜地壞

這張網守著別人，**誰守著它**？答案是 `harness.test.mjs`（`npm run harness:test`）——
node 內建 test runner，沒有框架沒有設定。

**規則引擎壞掉時上面那層會安靜地放行**，所以這層是必須的。兩條實際發生過的：

- A17 第一版：頂層 `@use 'x' as y;` 沒清 buffer，跟下一個 selector 黏成一體 →
  selector 解析全毀 → **把已經修好的程式碼誤報成違規**。不報錯，只是比對對不上
- A18 第一版：我掃了實際用法、看到零次 `@features/` 就下結論「沒有這個別名」，
  只擋相對路徑。**`tsconfig.json` 裡它一直都在** ——
  是 self-test 去讀 tsconfig 才抓到這個錯誤前提

**新增 gate 一定配 self-test，而且要含反例**（什麼**不該**被擋）。
誤報的 gate 比沒有 gate 更糟：它會讓人去關掉整個 hook，而 `CLESSIA_STOP_GATE=0` 就在那裡。

## 五、速度是這張網能不能活下去的條件

太慢的 gate 會被關掉。所以每次加東西都要量，並且知道自己在花誰的時間：

| 層               | 誰在等     | 現況                                                         |
| ---------------- | ---------- | ------------------------------------------------------------ |
| PreToolUse guard | 每一次編輯 | 毫秒級（regex）                                              |
| Stop gate        | 每一次收工 | harness + `nx affected -t typecheck/test`；typecheck 約 7 秒 |
| CI verify        | push 之後  | 整套約 1.5 分鐘                                              |

A17 加進 Stop gate 時特別量過 **+7 秒**（`ngc` 冷跑 7.46s、有 nx cache 6.68s）——
不是因為好奇，是因為那個數字決定人會不會把 gate 關掉。
