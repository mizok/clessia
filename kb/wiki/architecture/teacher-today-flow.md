# 老師端收斂成「今日流」

**狀態：設計草案，待計畫席初審 + 使用者批准。批准前不寫實作碼。**

## 為什麼

老師的情境是**站在教室門口、下課十分鐘**。他要的是「現在這堂課、這些人、點完、寫完」。

現在的四頁是照**資料模型**切的（課表 / 學生 / 通知 / 儀表板），不是照情境。
2026-09-02 UX 審查量到的後果：

| 症狀                                            | 數字                                         |
| ----------------------------------------------- | -------------------------------------------- |
| dashboard 兩個導覽連結太小                      | 100×**20** / 72×**20**（44px 基準）          |
| dashboard 今日課堂列不可點                      | 顯示「未點名」卻要繞道課表再找那天           |
| 完整點名任務                                    | **12 步**（#138 後降到 3 步，但入口仍繞）    |
| 兩頁對同一件事說不同的話                        | dashboard「0 還沒點名」vs 課表「2 堂待點名」 |
| dashboard/students/notifications 的 media query | 各 **0** 個；1280 下一列寬 944px             |

## 核心主張：dashboard 完全被課表吸收

dashboard 獨有的東西只有四個數字與兩個連結：

| dashboard 有的   | 課表已經有 / 該去哪                          |
| ---------------- | -------------------------------------------- |
| 今天的課（數字） | 今天那一屏就是答案，不需要數字               |
| 還沒點名（數字） | 橘帶錨點「N 堂待點名」（而且是整週，更有用） |
| 本週課堂（數字） | 橘帶副標「本週 N 堂」                        |
| 我的學生（數字） | 一個沒有行動的數字，刪掉                     |
| 今日課表（清單） | **跟課表今天那一屏完全重複**                 |
| 兩個連結         | 消失（不再需要跨頁跳）                       |

**所以 dashboard 不是「搬移」而是「刪除」** —— 上表那些 20px 連結與不可點的列，
不是被修好，是連同頁面一起消失。這正是工單問的「債怎麼在新構圖裡自然消失」。

> `/teacher` **已經 redirect 到 `/teacher/schedule`**（`app.routes.ts`），
> 課表早就是實質首頁。這一刀只是讓事實與結構一致。

## 收斂後的結構

| 面                 | 路由                     | 角色                                 |
| ------------------ | ------------------------ | ------------------------------------ |
| **今日流**（主面） | `/teacher/schedule`      | 週條 + 大單日 + 點名入口。90% 的使用 |
| **學生**           | `/teacher/students`      | 找某個學生（跨班搜尋）。低頻但真實   |
| **通知**           | `/teacher/notifications` | 非課務類公告（例：期初教學會議）     |

底部導覽從 4 個變 3 個。`bottom-bar` 取 `navItems` 前 4 個當主 tab，3 個剛好全顯示。

### 路由相容：`/teacher/dashboard` 保留成 redirect

**不刪 route，只刪頁面。** 保留 `/teacher/dashboard` → `/teacher/schedule` 的 redirect，
理由是老師可能加了書籤、而且 `RoutesCatalog.TEACHER_DASHBOARD` 被其他地方引用。
catalog 那筆改成 `showInMenu: false`，選單就不再出現它。

`roleGuard('teacher')` 不變，對外路由形狀不變 —— **這一刀不碰授權**。

### 路徑不改名

不改成 `/teacher/today`。改名會讓書籤失效、要動 catalog 與所有引用，
而使用者得到的好處是零 —— 這一刀的價值在結構不在命名。標籤維持「課表」，
它仍然準確：那就是課表，只是單日優先。

## 兩個結構性張力（要決策）

### 張力一：內嵌點名 vs 剛收斂完的共用面板

工單原本的構想是「今天的課堂卡**直接內嵌點名**，不用開 dialog」。有兩個問題：

**1. 它會把剛收斂的東西再拆開。** #169 才把兩套點名實作併成一支
（`attendance-roster-panel`，admin 出勤頁與課堂頁都用它）。內嵌等於再長出第三種形態。
面板目前直接 `inject(DynamicDialogConfig)` / `inject(DynamicDialogRef)`
（`:40-43`、`:230`、`:246`）—— 要能內嵌，得先把它改成 input/output，
再包一層 dialog wrapper 給 admin。那是動一支**剛穩定下來的跨席共用元件**。

**2. 巢狀捲動。** 名單有 `max-height: 55% 視窗高` 的垂直捲動；
今日流的主軌道是**水平 scroll-snap**。把一個垂直捲動區塞進水平 snap 軌道裡，
在觸控上是出了名的難調（滑動意圖判斷、snap 與慣性打架）。30 人的班更明顯。

**建議：不內嵌，改成降低開啟成本。** 課堂卡上的「開始點名」直接就是主要動作
（現在已經是），面板以 **bottom sheet** 形式從下方升起而不是置中 dialog ——
拇指可及、關閉手勢自然、不需要動共用元件的注入方式。

若使用者仍要內嵌，那是**另一刀**：先把面板去 dialog 化（跨席，要 admin-pages 同意），
再處理巢狀捲動。我不建議把它綁進這一刀。

### 張力二：通知要不要收進鈴鐺

工單問「notifications 進鈴鐺？」。**建議不做，理由是它會動到共用 shell。**

`ShellLayoutComponent` 是 admin / teacher / parent 三個角色共用的。
在 header 加鈴鐺會同時改變另外兩個角色的畫面，而那不在這一刀的範圍。
共用元件目前也沒有任何未讀徽章機制（`shared/components` 搜不到 `unread`）。

通知留成一個 tab。真正該修的是**它自己的規格落差**（spec 要求的
「全部標為已讀」按鈕與類型圖示都沒做），那是小刀，可以另排。

## A1（銷假）進來之後長什麼樣

`billing-api` 正在做銷假 API。新構圖要把「**請假學生出現 → 一鍵銷假並標出席**」畫進去：

請假中的那一列目前**沒有任何可操作元素**（這是 UX 審查的阻斷級 A1）。
銷假 API 落地後，那一列會多一顆「他來了」——按下去銷假並標出席。

> ⚠️ **這會觸發一條既有的具名條件。**
> `attendance-roster-panel.component.scss` 的 `&--on-leave` 註解寫著：
>
> > 如果之後給請假列加了任何操作按鈕（銷假／標記出席之類），**這裡的 tint 必須同時加深**。
> > 理由：那顆按鈕會讓請假列跟一般列的結構差異消失，而現在扛九成區別的正是那個差異；
> > 剩下 0.0515 的 tint 獨自撐等於沒有區別。
>
> 做 A1 的人必須同時加深 tint。這不是建議，是前人留下的、條件已經被滿足的承諾。

同時，A1 落地會讓「未標記 → 沒有紀錄」這條路不再是唯一正解，
掛在 A1 上的附帶條件（「沒有紀錄」的語意、報表怎麼算）要一起裁。

### 接法：**A1 先獨立出一小刀，不等這份設計**

API 已完成（#177）。前端**不併進今日流**，理由跟先前那道存檔守衛一樣：
**功能缺口的時程 ≠ 結構重構的時程。** 今日流要等使用者批准、範圍也大；
而 A1 是「學生本人站在教室裡，系統沒有任何方式記錄他來了」——
它只動點名面板的一列，跟 IA 改動彼此獨立。

那一小刀的內容：
1. 請假列加「他來了」→ 呼叫銷假 → 成功後**重抓 roster**
   （學生回到 `status: null + hasLeaveRequest: false` 的可標記狀態，#169 閉環）
2. `droppedAfter` 非 null 時**必須顯示**「後續日期的請假也一併取消，如需請假請重新申請」
3. **同時加深 `&--on-leave` 的 tint** —— 見上方那條具名條件

### 一個已知限制：連坐只能事後告知，不能事前確認

`cancelLeaveForDate` 只有一種情況會損失資料：**今天卡在請假區間中間**
（前後都有日期）→ 截到昨天，今天之後的日子一起沒了。
其餘三種（單日、今天起頭、今天結尾）都是零損失。

問題是 roster 只回 `hasLeaveRequest: boolean`，**沒有請假區間** ——
所以前端無法在老師按下去之前判斷出「這一按會連帶取消三天」。
只能靠 `droppedAfter` 事後告知。

範圍很窄（只有中間那種），而且 #177 已經強制要求顯示，所以**不擋這一刀**。
但如果之後覺得事後告知不夠，解法是 roster 補一個請假結束日，
讓前端在多日請假時先確認 —— 那要 billing-api 加欄位，屬於另一張單。

## 明確不做

| 不做                           | 為什麼                                                           |
| ------------------------------ | ---------------------------------------------------------------- |
| 月曆檢視                       | spec 有，但那是另一種使用情境（規劃 vs 執行）。今日流不需要它    |
| 動 `ShellLayoutComponent`      | 三角色共用，改它等於同時改 admin 與 parent                       |
| 把點名內嵌進課堂卡             | 見張力一。要做是另一刀，且要 admin-pages 同意                    |
| 重寫 `attendance-roster-panel` | #169 剛收斂完，讓它穩定一陣子                                    |
| 改路由路徑名稱                 | 書籤成本 > 零收益                                                |
| 學生頁重做                     | 這一刀只把它降為次要入口；它自己的問題（同一個學生跨班重複出現）另排 |
| 通知頁補規格落差               | 同上，小刀另排                                                   |

## 驗收條件

- `/teacher/dashboard` 導向課表，書籤不壞
- 底部導覽剩三個 tab，沒有 4 個以上才會出現的「更多」
- 390px 與桌機都實測（同源 iframe，見 charter 的量測方法）
- 老師端剩下的三頁**都有斷點** —— 這一刀順手把 students / notifications 的
  0 個 media query 補上（dashboard 消失所以不必補）
- 完整點名任務的步數不高於現在（現在：開 app → 課表已是首頁 → 開始點名 → 全部出席 → 儲存）
