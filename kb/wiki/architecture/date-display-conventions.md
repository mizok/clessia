# 日期顯示的四種形式

Tester 在 M4 詞彙統一（#425）點出全站有三種日期寫法：`2026-09-05` / `09/02` /
`09/01 (週二)`。工單當時就裁了方向：**這一項該訂「什麼情境用哪一種」，不是「統一成一種」**
—— 因為 `09/01 (週二)` 在課堂管理是有意義的（行政要知道星期幾排課）。

盤過全站 49 個日期顯示點（14 個走 `| date:`、35 個直接內插 `date` 欄位）與 27 個
`p-datepicker` 的 `dateFormat` 之後，形式其實只有四種，而且各自回答不同的問題。

## 四種形式

| 形式                    | 回答的問題                   | 用在哪                                                     |
| ----------------------- | ---------------------------- | ---------------------------------------------------------- |
| `yyyy-MM-dd`            | 「是哪一天」——會被引用的事實 | 生效日、起訖日、繳費期限、考試日、對話框確認句裡的課堂日期 |
| `MM/dd` / `MM/dd HH:mm` | 「多久以前」——列表裡的時間軸 | 報名列表、異動紀錄、公告收件匣、點名時間戳                 |
| `MM/dd (週X)` / `M/d`   | 「星期幾」——排課要用到       | 課堂管理列表、老師端週課表                                 |
| `yyyy-MM-dd HH:mm:ss`   | 「先後順序」——稽核用         | 操作紀錄、異動紀錄對話框                                   |

判準是**年份與星期幾是不是問題的一部分**：

- **年份**：這個值會不會被跨年引用？生效日、繳費期限會（可能是去年或明年），
  所以留年份。列表裡「最近發生的事」不會，所以省掉——省掉之後那一欄短很多，
  掃視列表時更容易對齊。
- **星期幾**：使用者拿這個日期去做的下一件事需不需要星期？排課需要，看紀錄不需要。

**秒**只在稽核情境出現：那裡的用途是排先後，同一分鐘內的兩筆要分得出來。

## 分隔符一律連字號

`yyyy-MM-dd`，不是 `yyyy/MM/dd`。這**不是情境選擇，只是一致性**——全站 27 個
`dateFormat` 裡 24 個是 `yy-mm-dd`，顯示端也全是連字號。#425 把三個斜線 outlier
（`notifications` 的發布時間、`attendance` 與 `session-filters` 桌機版的區間選擇器）
對齊掉，之後**全庫斜線歸零**。

## 直接內插不是缺陷，但只對 `date` 欄成立

35 個 `{{ row.effectiveFrom }}` 這種不經 `| date:` 的寫法**不是漏掉格式化**：
那些欄位在 DB 是 `date` 型別，PostgREST 原樣傳出就是 `2026-09-05`，
跟 `| date: 'yyyy-MM-dd'` 的輸出一樣。

**但這只對 `date` 欄成立。** `timestamptz` 欄直接內插會把 ISO 時間戳整串印出來——
`contact-book-entry-dialog` 的「家長已於 {{ signedAt }} 簽收」曾經渲染成
**「家長已於 2026-08-29T12:00:00Z 簽收」**（`signed_at` 是 timestamptz，
`apps/api/src/routes/contact-book.spec.ts` 就斷言了這個形狀），#425 修掉。

> **接一個新的日期欄位到畫面上之前，先查它在 migration 裡是 `date` 還是 `timestamptz`。**
> `date` 可以直接內插；`timestamptz` 一定要過 `| date:`。**兩者在型別上都是 `string`，
> TypeScript 分不出來**，所以這件事沒有任何編譯期訊號。

## 刻意的例外（不要順手統一掉）

判定「不算缺口」要指出它跟哪個既有模式同族，不是只說「我覺得可以」：

| 位置                                 | 用的是  | 為什麼                                                                                                       |
| ------------------------------------ | ------- | ------------------------------------------------------------------------------------------------------------ |
| 老師端週課表週條與日標題             | `M/d`   | 全站最窄的欄位（手機 7 欄）。理由已寫在模板註解裡：裸 `d` 會跟下面的堂數黏成「31 1 堂」                      |
| `session-filters` **手機版**區間選擇 | `mm/dd` | 窄列塞不下 23 字元的長版；且短版用連字號時 `09-01 - 09-30` 會跟 PrimeNG 的 `-` 分隔符撞在一起讀不開          |
| 管理端公告發布紀錄留年份             | 有年份  | 那是「發布過的全部公告」，會跨年；老師端收件匣看的是最近收到的，所以用短版——**同一概念的長短版，不是不一致** |

前兩條的理由都寫在程式碼旁邊而不是只寫在這裡——**PR 會沉，程式碼會被下一個人讀到**。

## 時區

顯示一律走瀏覽器本地時區（`| date:` 不帶 locale 參數），跟 `audit-log-dialog` 同。
`apps/api/src/lib/taipei-date.ts` 是**寫入**用的（決定「今天」是哪一天要進 DB），
跟顯示無關，不要混用。

> `| date: … : 'zh-TW'` 在測試環境會炸「Missing locale data」
> （見 `dashboard.component.ts` 的註解），所以顯示端不要帶 locale 參數。
