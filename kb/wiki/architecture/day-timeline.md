# 一日時間軸元件（day-timeline）

方向 D 內部頁重構的共同裝置之一。橘帶（anchor）裡放的是「一句話 + 一張資訊圖」，
儀表板那張圖就是這條時間軸。樣張見 scratchpad 的 `d-internal-mockups/interior-d.html`。

> 設計於 2026-08-30 批准（PR #99），共同 token 隨 #101 落地後實作。
> 下面標「實作時修正」的段落是實作揭露的、與原設計不同的地方。

## 它取代什麼、回答什麼

儀表板原本用兩張長得一樣的清單（今日課表、今日請假）＋六張長得一樣的數字卡。
「今天 8 堂課」是一個數字，看不出**什麼時候**忙、**哪一段**還沒點名。

時間軸回答的是清單答不了的問題：

- 現在到下一堂之間還有多久
- 沒點名的那幾堂是集中在下午還是散開的
- 今天是連續排滿還是中間有空檔

它**不取代**下方的課表清單 —— 清單負責「逐堂的細節」，時間軸負責「一天的形狀」。
兩者吃同一份資料，所以不會說出不一樣的話。

## 位置與介面

`apps/web/src/app/shared/components/day-timeline/`（`shared/` 而不是 feature 內，
因為橘帶要推到整個內部，課堂管理很可能是第二個使用者 —— 但**先只接儀表板**，
第二個使用點出現時才驗證這個抽象是否成立）。

輸入是**已經載入好的**清單，元件自己不打 API：

| input      | 說明                                                      |
| ---------- | --------------------------------------------------------- |
| `sessions` | `EventSessionSummary[]` —— 儀表板已經有的那份，不另外取數 |
| `date`     | 這條軸代表的日期。等於今天時才畫「現在」標記              |

元件不負責取數，也不負責決定「未點名」的定義（那是 `takenAt` 是否為 null，
由呼叫端的既有邏輯決定）。

## 佈局數學放 pure util，不放元件

`day-timeline.util.ts` + `.spec.ts`，跟 `reports.util.ts` 同一個慣例：
**沒有 TestBed 就能測**，而佈局正是最需要被測的部分（下面的邊界情境全部是
純函式的輸入輸出）。元件只負責把 util 算出的座標畫成 DOM。

兩個函式：

```
deriveWindow(sessions) → { startHour, endHour }
layoutDay(sessions)    → { window, lanes: PlacedSession[][], unplaced: EventSessionSummary[] }
nowMarkerPct(window, date, now) → number | null
axisTicks(window)      → number[]
```

> **實作時修正**：lane 分配沒有獨立成 `assignLanes`。視窗與位置換算是同一組數學
> （lane 要知道百分比、百分比要知道視窗），拆成兩支會讓呼叫端自己串 —— 併成
> `layoutDay` 一次回全部。`deriveWindow` 仍然單獨導出，因為它自己就有測試價值。

### `deriveWindow` —— 視窗要跟著資料長，但不會縮

預設 08:00–22:00。實際視窗是 `min(最早開始, 08)` 到 `max(最晚結束, 22)`，
**只擴不縮**：

- 早上七點的先修班不會被裁掉
- 只有一堂晚上七點的課時，軸仍然是完整的一天 —— 不會變成「19:00–21:00」
  那種看起來排滿了的假象

### lane 分配 —— 同時段的課要並排，不能疊在一起

補習班同一時段會有多間教室在上課。用貪婪區間分割：把課依開始時間排序，
每一堂放進「最後一堂已經結束」的第一條 lane，沒有就開新的 lane。

**軌道高度隨 lane 數長高，不設上限。** 真實的並行數是教室數，通常 2–5 條，
帶的高度可以吸收。設上限反而要處理「放不下的那幾堂去哪」，而任何一種塞法
（疊在最後一條、丟掉、加省略號）都會讓這張圖說謊。

> **已知的界線**：如果真實部署出現 8 條以上 lane，帶會過高。那時候的解法不是
> 加上限，是換一種畫法（例如每半小時一根、以濃度表示同時上課的堂數）。
> **觸發條件寫在這裡，不預先實作**。

## `startTime` / `endTime` 可為 null —— 這是設計問題不是防禦性程式

`EventSessionSummary` 的兩個欄位都是 `string | null`
（`apps/web/src/app/core/attendance.service.ts:73-74`）。三種情況分開處理：

| 情況     | 畫法                                   | 為什麼                                                                                                         |
| -------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 有起有迄 | 一個有長度的方塊                       | 正常情況                                                                                                       |
| 有起無迄 | 一個**點**（固定寬度的標記），不是方塊 | 給它一個預設時長等於憑空宣稱一段我們沒有的資訊。點讀起來是「這個時間有一堂課」，方塊讀起來是「這堂課上這麼久」 |
| 無起     | **不畫**，計入 `unplaced`              | 沒有時間就沒有位置。呼叫端拿 `unplaced.length` 決定要不要在句子裡補一句「另有 N 堂未排定時間」                 |

不畫的那幾堂**不會從句子裡消失** —— 橘帶的句子（「今天 8 堂課」）算的是總數，
時間軸只是畫得出來的那部分。兩個數字不一致的時候要說出來，不是默默對齊。

## 已點名／未點名怎麼表示

- 已點名：實心近黑方塊
- 未點名：中空方塊（近黑外框）

**不用白色**：白對亮橘只有 2.85:1，低於圖形元素要求的 3:1。橘面上的層次一律靠
近黑加降透明度做（見 [[architecture/design-language]] 的橘面規則），而**透明度
不得低於 0.78** —— 近黑壓在漸層深端（`#ff6a3d`）時 0.72 只有 4.00:1。

## 無障礙

這是資料圖形，不是裝飾：

- 每個方塊是**資料圖形而不是連結**（`role="img"` + `aria-label`），accessible name 是
  「09:00–11:00 自然班 C · 劉承恩 · 未點名」—— 滑鼠看到的 tooltip 與螢幕閱讀器
  聽到的是同一句。

  > **實作時修正的設計**：這一段原本寫「每個方塊連到該堂課」。實作時確認點名是
  > 從課堂清單開的 dialog、**沒有單堂路由**，連到清單頁會是個假的 affordance
  > （看起來能點進那一堂，其實只到清單）。所以改成不可互動。

- 「現在」標記是 `aria-hidden`（它的資訊已經在別處）
- 整條軸上方的那句話（「今天 8 堂課，其中 6 堂還沒點名」）就是這張圖的文字替代，
  它本來就在，不需要另外寫 `aria-label` 重複一次
- 顏色不是唯一的區分：已點名／未點名除了實心與中空，形狀也不同（見上）

## 響應式 —— 手機版跟桌機一起設計，不是之後補

軸用百分比定位，**不用 viewport 單位**（c6）。

- 方塊 `min-width: 8px` —— 窄螢幕上一堂 30 分鐘的課只有幾個 px 寬。
  寧可位置稍微不準，也不要一堂課從圖上消失。
- 640px 以下：方塊 18px、刻度 9px、圖例縮排。**刻度數不減少** ——
  刻度是靠 `space-between` 均分而對齊到時間位置的，抽掉其中幾個會讓剩下的
  重新均分，位置就跟時間對不上了。
- 「現在」的標籤放在標記**上方**。放下方會跟時刻文字擠在同一列
  （實測窄螢幕上出現過「12現在14」這種重疊）。

實測（390×844 / 375×667，注入一天九堂含三堂重疊、一堂缺結束時間、一堂完全
沒時間）：8 個方塊、3 條 lane、軌道 106px、無橫向溢出、「另有 1 堂未排定時間」
正常出現。

> 這一段原本寫「等實際量過再決定」。使用者指出**設計時就要考慮手機版體驗**，
> 而不是先出桌機再補 —— 這是對的：延後到「之後再量」的響應式，實務上就是
> 沒有響應式。

## 這個元件不做的事

- **不取數**、不知道 API 長什麼樣
- **不算「未點名」的定義**
- **不負責橘帶本身**（背景、內距、圓角是橘帶的事，由 design-web-2 的共同 token 提供）
- **不做動畫**。內部是 Operate 模式，使用者在做事，不該等畫面演完

## 現況

已實作並接上管理端儀表板。`day-timeline.util.spec.ts` 28 條、
`day-timeline.component.spec.ts` 9 條。

util 的測試做過突變驗證（把 lane 分配退化成「只跟前一堂比」、讓視窗會縮、
讓沒有開始時間的課默默消失），三種都被抓到 —— 第一次寫就全綠的測試不值得信，
要先看它失敗過（見 [[lessons/awakened-tests-bite]]）。

**第二個使用點還沒出現。** 這個抽象是為了「橘帶推到整個內部」而放在 `shared/`，
但只有一個使用者的抽象還沒被驗證過。課堂管理接上去的時候才會知道
`sessions` + `date` 這組介面夠不夠。
