# A6 採用規則

這一頁把使用者對 A6 設計稿（`.design-explorations/973-layout/a6-editorial/`，不進版控）的裁定集中成可引用的條文，給 `tools/a6-conformance` 的 `DEVIATIONS` 與各頁範圍說明當**出處**。裁定原文多半發生在計畫席的對話裡，由計畫席轉記；之後的新裁定也加在這裡，不要散在 PR 留言。

## R1 A6 全採

新版設計全部採用，不做新舊取捨。只有「舊版有、A6 沒畫」的功能才提出來討論。

> 「實際上我要的不是你讓我作取捨，而是我認為新版設計才是好的，所以我要完全採用新版設計。如果舊版設計有但新版設計沒有的，你才該提出來討論」—— 使用者，2026-10-08

推論：稿上畫了的東西，「現況比較好」「差不多」都不是保留舊樣子的理由。

## R2 現況有、稿沒畫的功能：收進「⋯」或篩選面板，不刪

使用者 2026-10-08 裁定的預設：現況有、A6 沒畫的功能預設收進「⋯」（或篩選面板），不刪。同日逐項裁定的四件：作廢留、列印收費單留、催繳備註刪、未開單名單留（帳單頁）。

適用例：列尾「⋯」裡的收款／收據（帳單）、課表副行的未指派／未點名（收進「⋯」並帶數字）、「更多」選單的「公開申請」「到班打卡」。

例外要寫理由：入口收不進「⋯」的（例如課表換週箭頭，#1314 comment 6163635319）。

## R3 可點元素的基底高度 ≥ 44px（A27）

觸控下限只約束**基底**（手機）——見 [[constitution-enforcement]] A27。桌機可以照稿用 `wide:` 縮小，所以桌機高度跟稿不同是**待修**，不是偏離。

## R4 對齊的證據是 conformance 工具報告

> 「為什麼你不先分析 A6 的 html part 來整理出來整體頁面結構應該都有哪些 part，再來比對功能正確性呢？很顯然我們需要一個自動而且具備幾何準確度，還有 uiux 行為準確度的驗證手段」—— 使用者，2026-10-14

宣稱「對齊 A6」要附 `tools/a6-conformance` 的報告：該頁「待修」歸零，「已記錄偏離」每條都能指回本頁或其他 kb 條文。肉眼並排、只驗 class 存在的 spec 都不算。

## R6 鍵盤焦點要看得見

可用鍵盤操作的元素，焦點狀態必須看得見（WCAG 2.2 的 2.4.7 Focus Visible）。A6 稿有定義 `:focus-visible` 樣式時照稿；稿沒有定義時，保留現況的焦點外框，列為偏離並引用本條。**hover 不適用本條**：稿有 hover 樣式就照稿，稿沒有就拿掉現況多出來的 hover 底色，不算偏離。

## R7 ARIA 角色依元件行為，不依稿的標記

稿是靜態 HTML，角色由標記決定；app 的角色要符合元件**實際行為**（WAI-ARIA APG）。例：頂欄搜尋有建議清單＝`combobox`（稿是 `searchbox`）。這類角色差列偏離並引用本條；外觀仍照稿。
