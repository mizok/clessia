# 老師端學生名單的設計

## 先處理一個假的選單項目

`/teacher/attendance` 在選單上叫「點名」，`showInMenu` 是 true，點進去是：

```
Teacher attendance content coming soon...
```

而**真正的點名早就在 `teacher/schedule`**：那頁有「已點名」「點名已截止」的狀態、有共用的
`AttendanceRosterPanelComponent`、還照 org 設定判斷該不該讓老師點、能不能補點。

這跟 `/admin/changes` 是同一類缺陷（選單承諾了頁面不做的事），也跟報名總覽是同一個結論：
**一個功能一個家**。點名的家是課表——老師打開課表，看到今天的課，點進去點名，這是一條動線；
另外開一個「點名」選單項目，等於要老師先想「我要點哪一堂」才能開始。

**決定：刪掉 `teacher/attendance` 頁面與路由，選單項目一併移除。** 不是隱藏
（`showInMenu = false` 會留下一個沒人走的路由和一個沒人維護的元件），是刪掉。

## 範圍：什麼叫「我的學生」

老師 → 學生的鏈路有兩條：

| 來源                   | 意思                   | 採用 |
| ---------------------- | ---------------------- | ---- |
| `schedules.teacher_id` | 固定任課的班           | ✅   |
| `sessions.teacher_id`  | 實際上過的課（含代課） | ❌   |

**用固定任課，不用實際上過的課。** 代課老師臨時代一堂，不該從此在他的學生名單裡多出
30 個他不認識的學生；而他代課當下需要的名單，課表那頁點進去就有。

「我的學生」= `schedules.teacher_id = 我` 的班級 → 那些班的**在籍** enrollment
（`status in (active, pending_payment)`）→ 學生。

退班的學生不出現。要看歷史得去管理端——老師端不是稽核工具。

### 到班只看「我的班」（#1100 #51，使用者 2026-10-23 裁定）

「我的學生」決定老師**讀不讀得到**這個學生；讀得到之後，**到班資料也只算我的班**——
學生在別的班到了沒、缺了幾次，老師看不到。兩個地方照這條縮：

- `GET /students/{id}/attendance-days`：母體（他的報名）先篩成老師固定任課的班，
  格子、統計、下一堂都從縮過的母體算
- `GET /students` 的今日到班（`todayStatus`）：今天的課只取老師任課的班。他的學生今天只有別班的課
  → `null`（今天沒他的課），不是別班那堂的狀態
- `GET /students` 的班名（`classNames`）：只留老師任課的班（計畫席 2026-10-30）。原本照學生全部的在籍報名組，
  老師學生頁又照它分章，他的學生也上別人的班時，畫面多出那些他沒教的班（本機 teacher0004 多 4 班）。
  `contract/students-class-names-scope.contract.ts` 守；管理員照舊

**縮在母體，不是撈了再遮**：撈全部再從回應裡刪，下一個加欄位的人會忘記刪那一欄。

## 任課判定看日期：現任、前任（#2049）

時段可以前後接續（#22：`effective_from`／`effective_to`，`split` 從某天起換老師），所以「他教這班」要看日期。
計畫席 10-28 裁定（R2），判準只有一份：`lib/teacher-scope.ts` 的 `loadTenure`／`tenureOn`。

| 身分       | 怎麼判                             | 能做什麼                                                                                   |
| ---------- | ---------------------------------- | ------------------------------------------------------------------------------------------ |
| 現任或將任 | 這班有一列今天有效或還沒生效的時段 | 整班、**全部日期**，讀寫都可以 —— 接手的人要看得到前任的日誌、成績、聯絡簿                 |
| 前任       | 這班只剩已經結束的時段             | **只讀、只限自己任期內的日期**。沒有日期脈絡的（名冊、學生詳情、以學生為單位的成績）看不到 |

- 星期不細分：一班兩個時段分屬兩位老師，兩人都是現任。
- `taughtClassIds`／`taughtStudentIds` 只回現任：沒有日期的讀取、所有寫入、「還沒寫」這類待辦提示都用它。
- 有日期的列表用 `tenureOrFilter` 組 PostgREST `.or()`（`count` 才會對）；單筆有日期的用 `canReadOn`。
- PUT 原地改 `teacher_id` 不留舊列，舊老師本來就全失；要留任期紀錄，換老師走 `split`（#22 寫入面 web 會提示）。
- 契約 `contract/teacher-tenure.contract.ts` 守：現任看得到換手前後的每一筆；前任只看得到任期內那筆，而且寫入一律 403。

## API：開 `students` 給 teacher，同時鎖範圍

照 [[architecture/role-authorization|`角色授權的設計`]] 講好的做法：**做到哪一頁才開哪一支，
而且開的同時就把範圍限制做完**。先開路、之後才補範圍的話，中間那段時間就是個洞。

- `mount('/api/students', studentsRoute, ['admin', 'teacher'])`
- `GET /api/students` 增加 `taughtByMe` 旗標
- **角色是 teacher（且非 admin）時強制套用**，不管請求有沒有帶 —— 跟
  `attendance/teacher-scope.ts` 同一個模式：只擋 UI 不擋 API 等於沒擋

範圍解析抽成純函式（`students/teacher-scope.ts`），理由跟上次一樣：錯的方式很安靜，
而且無法從畫面上看出來。

## 畫面

依開課班分組，每組顯示班名與人數，組內列學生姓名與年級。加一個班級篩選與姓名搜尋
（`students` API 已經有 `search`）。

**MVP 不做出勤與成績統計。** 規格列了「出席率、遲到次數、平均分」，但那需要跨
`attendance_records` 與 `scores` 的彙總，是另一個切片的份量；而且在老師真的用起來之前，
我不確定他要的是「這個學生的出席率」還是「這個班今天誰沒來」——後者課表已經回答了。
先把名單交出去，統計等他開口。

## 學生面板（TST1，計畫席 2026-10-30 裁定做）

A6 `t-students.html`：點一位學生的名字，開頁內面板 —— 家長聯絡（電話＋複製）、**這班**最近 5 堂到班、
**這班**最近 3 次考試（分數、班平均），底部「到課表點名」。不連管理端的學生檔案（老師沒有那頁）。
這不是上面「刻意不做」的「學生詳情頁」：面板只放最近幾筆原始紀錄、不算比率（2026-08-30 刪統計的裁決照舊）。

**範圍不另做一套**：三份資料都走已經有老師範圍的端點，面板只是讀者。

| 面板區塊                             | 端點                                                    | 老師範圍由誰守                                              |
| ------------------------------------ | ------------------------------------------------------- | ----------------------------------------------------------- |
| 家長（姓名、關係、電話）、年級、學校 | `GET /students/{id}`                                    | `teacherCannotRead`：不是現任任課班的學生 → 403             |
| 這班最近 5 堂                        | `GET /students/{id}/attendance-days?from&to`            | 母體先縮成老師任課的班（#51）；面板再挑這班的那幾天         |
| 這班最近的考試                       | `GET /scores?studentId&classId&type=academy&pageSize=3` | `readableStudentIds`＋任課班的校內考；`classAvg` 已在回應裡 |

唯一的 API 改動是**加法**：`GET /students` 列表每列多回 `classes: { id, name }[]`（跟 `classNames` 同一份在籍報名算出來）。
老師頁依班分章、面板要拿班 id 去查「這班」的考試；現在列表只有班名，靠名字反查 id 會在同名班時配錯。不動授權、不動範圍。

**先寫的守門測試**（紅燈先行）：契約測試，老師 A 任課班 X（學生 S1）、老師 B 任課班 Y（學生 S2，也上 X 以外的課）——

- A 打 S2 的 `/students/{id}` → 403；`attendance-days` → 403；`/scores?studentId=S2` → 空
- A 打 S1：三支都有資料，但 S1 在 Y 的到班與考試**不出現**
- 前端 spec：面板只從名單上的人打開（名單本身已是範圍內的學生），403 時面板寫「讀不到這位學生」，不是空白

**到班格的已知近似**：`attendance-days` 是一天一格（同一天他在老師的兩個班都有課時，格子合併成一種狀態）。
面板依 `sessions[].className` 挑出這班的那幾天；同日兩班都由同一位老師教的情況少，合併後仍是同一位老師的資料，不越權。
要精確到逐堂得另開一支老師可讀的逐堂出勤端點（`GET /attendance` 目前只給管理員，#1098），不在這張。

拒絕的替代方案：

- **新開一支 `/teacher/students/{id}/panel` 彙總端點**：多一個要守範圍的入口，而三份資料現有端點都已守好
- **連到管理端學生檔案**：老師沒有權限，A6 也明寫不連
- **用班名反查班 id**：同名班會配錯（見上）

影響的元件：`teacher/pages/students`（點名字開面板、頁說明句「點名字看家長電話、最近到班與成績」、整列可點）、
新的面板元件（原生 `<dialog>`，照家長端「幫孩子請假」的 overlay-motion 寫法）、`StudentsService`（型別加 `classes`）、
`routes/students.ts` 列表回應。

## 刻意不做

- **出勤／成績統計** —— 見上
- **學生詳情頁** —— 老師端規格沒有；要看個別學生的完整資料是管理端的事（頁內面板見上一節，不是詳情頁）
- **代課老師的學生** —— 見上方範圍段落
- **把 `teacher/attendance` 做成「今日課堂快捷」** —— 那只是課表的子集合，多一個入口不多一個功能
