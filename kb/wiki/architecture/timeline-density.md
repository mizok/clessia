# 時間軸換畫法 —— 每半小時一根，柱高是同時堂數

> **設計稿，不動 `day-timeline.util.ts`。** 依 `clessia-feature-slice` 的 STOP gate：
> 計畫席初審 + 使用者批准之後才寫實作碼。
>
> 承 [[architecture/day-timeline]]〈已知的界線〉：`lane > 3 預設收合` 是止血，
> 這一頁是真解。

## 要解的問題

lane 式佈局的**高度隨並行數長**。2026-09-02 在密集日 seed 上實測（1568×784）：

|          | 1 堂課            | 9 堂課 / 4 條 lane                  |
| -------- | ----------------- | ----------------------------------- |
| 橘帶高度 | 226px（30% 視窗） | **359px（48%）**                    |
| 整頁高度 | ~0.9 螢幕         | **1.76 螢幕**，課表脊椎整段在摺線下 |

每多一條 lane +30px。**課越多，這張圖越擋住使用者要去的地方** —— 而課多正是他最需要
往下看的日子。這個關係反了。

止血做法（`lane > 3 預設收合`，#155 已出貨）讓帶不再長高，但**代價是密集日看不到圖**
—— 恰好又是最需要它的日子。

## 換成什麼

**每半小時一根，柱高 = 那半小時同時有幾堂課。**

```
  ▁    ▃▃  ▅▅▅       ▂▂    ▆▆▆▆      ▃▃      ← 柱區，固定高度
 └──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘
 08    10    12    14    16    18    20    22
                    ▲ 現在                     最忙 5 堂
```

**帶高與課量脫鉤**：柱區固定 64px + 刻度 16px，不論今天 1 堂還是 20 堂。
密集日的帶高回到 226px 那一級。

## ⚠️ 「濃度」不能用透明度做 —— 這是這份設計最重要的一條

工單寫的是「濃度＝同時堂數」。**變數對，編碼不行。**

橘帶上的層次一律靠近黑加降透明度（[[architecture/design-language]] 的橘面規則），
而**透明度不得低於 0.78**（0.72 只有 4.00:1，不合 AA）。所以可用區間是 `[0.78, 1.0]`。
在那個區間裡：

| 透明度 | 對底色（`#ff6a3d`，漸層深端＝最不利） | 與前一階的對比 |
| ------ | ------------------------------------- | -------------- |
| 0.78   | 4.51:1                                | —              |
| 0.82   | 4.85:1                                | 1.08:1         |
| 0.86   | 5.19:1                                | 1.07:1         |
| 0.90   | 5.54:1                                | 1.07:1         |
| 0.94   | 5.87:1                                | 1.06:1         |
| 1.00   | 6.32:1                                | 1.08:1         |

**整個區間兩端互相只有 1.40:1**，而圖形元素相鄰要 **3:1**。

也就是說：**橘帶上連「兩階濃度」都做不出來**，不是「階數受限」而是「一階都放不下」。
`styles.scss:87` 早就寫著這條結論 ——「**橘帶上不能用透明度做層次**（0.80 就是地板），
層次交給字級、字重、字距」。這張圖沒有字級可用，所以交給**長度**。

> 順帶一提，長度本來就是比色彩濃度更準的編碼（位置／長度在感知精度上優於明度）。
> 這裡是無障礙的硬地板剛好把設計推向更好的那一邊。

## 未點名怎麼表示：同一根裡堆疊

一根柱分兩段，沿用 lane 版已經驗證過的語彙：

- **已點名**：實心近黑（`--band-ink`）
- **未點名**：近黑外框、中空

**堆疊而不是並排**：柱高仍然是「同時幾堂」這個唯一的量，狀態是它的內部組成。
並排會讓同一時段變成兩根，柱數就不再是時間軸了。

**未點名放上段**（靠近使用者的視線與「該處理」的方向），已點名沉在下面。

**不用顏色區分**：白對亮橘只有 2.85:1，語意色疊在暖橘上讀不出來（`styles.scss` 的
同一段）。實心／中空是**形狀差異**，符合「顏色不是唯一區分」。

## 尺度：對到當日最大值，並把它寫出來

柱高按「當日最大同時堂數」正規化，旁邊標一行「最忙 N 堂」。

**被拒絕的替代方案**：

- **固定尺度 + 超出截斷** —— 截斷會說謊。8 堂同時的日子畫得跟 5 堂一樣高，
  而那正是最該被看見的日子
- **不標最大值** —— 形狀有了但失去量級。「最忙 5 堂」是一個字串的成本，
  換回絕對數字

這張圖回答的是「**今天什麼時候忙**」，形狀是主角；絕對數字由那行標籤給。

## 失去了什麼（要說出來，不要假裝沒有）

lane 版的每一個方塊是**一堂具體的課**，`aria-label` 與 tooltip 給得出
「09:00–11:00 自然班 C · 劉承恩 · 未點名」。**密度圖沒有這個** —— 一根柱是一個時段的
統計量，不是一堂課。

**這是真的損失，緩解是：**

1. **hover / focus 一根柱**，顯示那半小時的課堂清單（時間 · 班級 · 狀態）
2. **`aria-label` 給統計語意**：「09:30–10:00，3 堂課，其中 2 堂未點名」
3. **逐堂的細節本來就在下面的課表清單裡** —— 時間軸從一開始就不負責身分
   （[[architecture/day-timeline]]：「清單負責逐堂的細節，時間軸負責一天的形狀」）

**這條損失換到的是「密集日也看得到圖」** —— 止血版在那些日子是整張圖收起來的。

## 邊界情境

`EventSessionSummary` 的 `startTime` / `endTime` 都可為 `null`
（`core/attendance.service.ts:73-74`）。密度圖要落 bin，所以三種情況都要有答案：

| 情況         | 落到哪                            | 為什麼                                                                    |
| ------------ | --------------------------------- | ------------------------------------------------------------------------- |
| 有起有迄     | 它涵蓋的每一根都 +1               | 90 分鐘的課跨 3 根                                                        |
| **有起無迄** | **只有起始那一根 +1**             | 給它預設時長等於憑空宣稱一段我們沒有的資訊。lane 版把它畫成點，同一個判斷 |
| **無起**     | **不落任何 bin**，計入 `unplaced` | 沒有時間就沒有位置                                                        |

**`unplaced` 仍然要說出來** —— 呼叫端拿 `unplaced.length` 在句子裡補「另有 N 堂未排定
時間」。句子的總數與圖上的總數不一致時要講，不是默默對齊。

**跨 bin 的計數是「涵蓋」不是「開始」**：09:00–10:30 的課在 09:00、09:30、10:00
三根各 +1。用「開始」計數的話，一整天的長課會只在一根出現，圖就變成「開課時刻分佈」
而不是「忙碌程度」。

**半開區間**：一堂 09:00–10:00 的課**不計入** 10:00 那一根 —— 接續不是重疊
（`leave-covers-session.ts` 同一個判準）。

## 視窗

沿用既有的 `deriveWindow`：預設 08:00–22:00，**只擴不縮**。理由不變 ——
只有一堂晚課時，軸縮成 19:00–21:00 會讓它看起來像排滿了。

預設視窗 = 14 小時 = **28 根**。視窗被早課或晚課撐大時根數跟著增加。

## 手機 —— 柱不能減，刻度可以

390px 下 28 根：每根含間隙約 12px。緊但可行（柱寬 8px + 間隙 4px）。

- **柱數固定不減。** 減根數就是改變 bin 大小，圖的形狀會變 ——
  同一天在手機與桌機上長不一樣的圖，那不是響應式，是兩張圖
- **刻度標籤可以減**（08 / 12 / 16 / 20）。刻度是文字不是資料

> **這一條跟 lane 版的教訓相反，要寫進註解。** `day-timeline` 那邊
> **刻度數不能減**，因為刻度靠 `space-between` 均分來對齊時間位置，抽掉幾個會讓
> 剩下的重新均分、位置就對不上。密度圖不同：**柱本身就佔著時間位置**，刻度可以
> 獨立對齊到指定的柱，減標籤不影響對位。
>
> 下一個人看到兩支元件對「刻度能不能減」有相反的規則，會以為其中一支是 bug。

- 觸控：hover 在手機上不存在，**點一根柱展開該時段清單**，再點收起
- 不用 viewport 單位（c6）

## 這份設計不做的事

- **不做「兩種圖切換」。** 課少時 lane 圖資訊較豐富，但讓同一頁在不同日子長成不同的圖
  是更糟的事 —— 使用者每天早上要重新認一次版面。**一律用密度圖。**
- **不動 `day-timeline.util.ts`。** 這是設計稿。實作要重做 `layoutDay`
  （lane 分配 → bin 計數）與它的 28 條測試
- **不改橘帶的構圖**（一句話 + 一張資訊圖），只換那張圖
- **不處理「同時堂數超過視覺可分辨」的極端**（例如 20 堂同時）。真的出現再說 ——
  那時的問題不是畫圖

## 驗證

1. **帶高與課量脫鉤**：1 堂課與 9 堂課的橘帶高度**相同**（這是這一刀的全部理由）
2. 密集日 seed（9 堂、含三堂重疊）：09:30 那根是全日最高，標籤寫「最忙 3 堂」
3. 90 分鐘的課跨 3 根，每根都算到它
4. 09:00–10:00 的課**不算進** 10:00 那根
5. 有起無迄的課只算起始那根；無起的課不落 bin 但出現在「另有 N 堂未排定時間」
6. 實心／中空的堆疊在 `#ff6a3d` 深端量到 ≥ 3:1（harness 的 `band-contrast` 會擋）
7. 390px：28 根不溢出，點一根展開該時段清單
8. 收合狀態的 localStorage 鍵可以退役 —— 不再需要「課多就收起來」

## 給實作的一句話

`layoutDay` 會從「貪婪區間分割」變成「bin 計數」，**那 28 條測試不是全部作廢** ——
`deriveWindow`、`parseTimeToHours`、`nowMarkerPct`、`axisTicks` 都還在用，
只有 lane 相關的那幾條要換成 bin 相關的。**先讓新的測試紅過再寫實作**
（[[lessons/awakened-tests-bite]]）。
