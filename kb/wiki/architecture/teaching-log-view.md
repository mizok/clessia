# 老師授課紀錄的設計

> 2026-08-12 批准並實作完成。畫面在 `admin/staff` 的列操作選單 →「授課紀錄」。

## 要解決什麼

老師多為鐘點計酬，每個月得有人統計「誰上了幾堂、幾小時」。目前這件事在 Excel 上做，
而系統裡的資料其實比 Excel 完整 —— 只是**沒有任何畫面看得到**。

本畫面**不計算薪資**（見 [[architecture/teaching-history-not-payroll|`記錄授課歷程但不做薪資`]]），
只回答「這個月老師 X 上了哪些課、加起來幾小時、有沒有異常」。

## 資料現況（已驗證）

| 需要的資料                     | 來源                                                               | 狀態 |
| ------------------------------ | ------------------------------------------------------------------ | ---- |
| 每堂課的老師、日期、起訖、狀態 | `sessions`                                                         | ✅   |
| 代課後誰實際上課               | `sessions.teacher_id` **會被改寫成代課老師**（`sessions.ts`） | ✅   |
| 原本排給誰                     | `schedule_changes.original_teacher_id` / `original_teacher_name`   | ✅   |
| 課真的上了的證據               | `events.attendance_taken_at`（首次點名，immutable）                | ✅   |
| 依老師 + 期間查詢              | `GET /api/sessions` 已支援 `teacherIds` / `from` / `to`            | ✅   |

**`sessions` 是「誰實際上了這堂課」的真相，`schedule_changes` 是「原本是誰」的歷史。**
兩者合起來完整可追溯，不需要新 schema。

## 三個行為決策

依「這個系統應該可追溯」的原則決定：

### 1. 代課的課算實際上課的人

時數歸給 `sessions.teacher_id`（代課老師），因為時數要反映**實際勞務**。

但原老師的頁面會另闢一區顯示「**被代課的堂數**」—— 列出來、不計入時數。
理由：他的排課被拿掉這件事必須留痕，否則他自己對不上帳，也無從發現異常的代課頻率。

### 2. 停課列出來，標示，不計入時數

不隱藏。「這週為什麼少兩堂」必須看得到答案；藏起來就失去追溯的意義。

### 3. 時數用排定時間，但標記缺點名證據的課堂

加總用 `start_time`–`end_time`（排定時間），**不用點名時間**。
理由：用點名時間會讓「忘記點名」變成「這堂課不算」—— 把行政疏失轉嫁成薪資損失。

但 `attendance_taken_at` 為 null 的課堂會被**明確標記**。那是「已排定、但沒有上課證據」
的集合，正是需要人去確認的那幾筆。系統負責讓它可見，不負責替人判定。

## 畫面

放在 `admin/staff` 的**列操作選單**（實作時發現 staff 沒有詳情頁，只有操作選單）——
「這個老師上了什麼課」屬於這個人的資料，不是獨立功能區，所以不新開頁面、也不增加空殼數。

```
[ 老師：王小明 ]  [ 期間：2026-08 ▾ ]

  合計 24.0 小時 · 12 堂        ⚠ 2 堂沒有點名紀錄

  日期        時間          班級            狀態
  08/01      19:00-21:00   國二數學 A       ✅
  08/03      19:00-21:00   國二數學 A       ⚠ 未點名
  08/05      19:00-21:00   國二數學 A       🚫 停課（不計入）
  ...

  被代課（不計入時數）
  08/12      19:00-21:00   國二數學 A       → 由李老師代課
```

## 需要的改動

| 層              | 改動                                                                      |
| --------------- | ------------------------------------------------------------------------- |
| API             | **無**。`GET /api/sessions` 已支援所需篩選與欄位                          |
| API（被代課區） | 需要一支依 `original_teacher_id` 查 `schedule_changes` 的查詢 —— 目前沒有 |
| Web service     | `sessions.service` 已有 `list()`，可直接用                                |
| Web UI          | 新元件掛進 staff 詳情；時數加總與分組在前端做                             |

唯一的後端新增是「被代課」那一區的查詢。若要縮小首版範圍，可以先不做那一區
（其餘完全不需要動後端）。

## 刻意不做

- 時薪費率、薪資金額、匯出給會計 —— 需要先凍結薪資規則，見架構決策
- 跨老師的統計總表 —— 那是報表（M6）的範疇
- 修改課堂資料 —— 這是唯讀檢視；要改課去課堂管理

## 這個設計不保證什麼

它呈現的是系統裡有的紀錄。如果有人上了課但沒在系統裡建課堂，這裡就看不到 ——
**紀錄的完整性取決於日常有沒有確實使用系統**，不是這個畫面能解決的。
