# 視覺語言（方向 D：暖橘流場）

> 這一頁是**從建好的世界回頭寫的**，不是先寫規則再去符合它。
> 探索過程與被否決的三個方向留在 `.design-explorations/`（不進版控）。

## 為什麼換

2026-02 定的 Zinc + Sky tokens 被使用者評為「無聊」。診斷不是配色難看，是**收斂循環**：
保守的 token 加上「每個切片都要跟既有一致」的要求，讓每一次改動都往中間靠。

探索了四個方向（時刻表印刷、星圖、點名簿、暖橘流場），使用者選了 D。

## 這個世界的三條規則

### 1. 白底為基，橘是色面不是點綴

橘出現在**入口面**（登入 hero、角色選擇底、之後的儀表板標頭），一次就是一大塊，
不是散在中性介面上的小色點。資料區維持白底，密度與克制不變。

### 2. 橘面上一律近黑字

亮橘 `#ff6a3d` 配白字只有 **2.85:1**，怎麼調都過不了 AA；配近黑 `#1a1614` 是 **6.32:1**。
而且亮橘 + 近黑正是運動品牌那種明快組合，比白字更符合「朝氣」。

**白底上需要橘字時用 `--accent-500`（`#c93f14`，5.31:1）或 `--accent-600`，不要用
`--accent-vivid`。** vivid 那一階是給色面的。

### 3. 動畫只住在入口面

`app-flow-field` 只掛在登入、角色選擇、（規劃中的）儀表板標頭。
**資料表格後面永遠不放持續動態** —— 那會讓需要工作的畫面一直在動。

## Token 映射

值替換、**不改名**。改名會炸掉全站幾百處引用；替換值讓既有頁面自動跟上大部分。

### 中性階：冷灰 → 暖灰

亮度階梯**刻意對齊原值**（每一階 ΔL < 0.035），所以既有頁面的視覺層次完全不變，
只是色溫變暖。

| token        | 舊（冷灰） | 新（暖灰） |
| ------------ | ---------- | ---------- |
| `--zinc-50`  | `#fafafa`  | `#faf9f8`  |
| `--zinc-200` | `#e4e4e7`  | `#ebe7e4`  |
| `--zinc-400` | `#a1a1aa`  | `#a89f99`  |
| `--zinc-500` | `#71717a`  | `#786f69`  |
| `--zinc-600` | `#52525b`  | `#57504b`  |
| `--zinc-900` | `#18181b`  | `#1a1614`  |

（完整十階見 `apps/web/src/styles.scss`。這裡不抄全表 —— 手抄的清單會腐化，c11。）

### Accent：sky → 暖橘

**階的值由用途決定，不是照色票順序硬換。** 換之前先數過每一階實際被拿來做什麼：

| token              | 值        | 為什麼是這個值                                                                  |
| ------------------ | --------- | ------------------------------------------------------------------------------- |
| `--accent-50`      | `#fff0ea` | 27 處拿它當淺背景                                                               |
| `--accent-100`     | `#ffdcce` | 淺邊框與底                                                                      |
| `--accent-400`     | `#ff8557` | 全部是邊框用途，可以亮                                                          |
| `--accent-500`     | `#c93f14` | 混用：15 處文字、10 處邊框、6 處當白字的底色 —— 所以**必須對白 ≥4.5**（5.31:1） |
| `--accent-600`     | `#a8340f` | 40 處純文字色，最深（6.64:1）                                                   |
| `--accent-vivid`   | `#ff6a3d` | **新增。** 大面積色面專用                                                       |
| `--accent-vivid-2` | `#ff8557` | vivid 漸層的另一端                                                              |

`--accent-vivid` 是新增的階：既有的 500/600 被文字對比綁死在深色端，亮橘沒有位置。
新 token 不影響任何既有引用。

## 流場動畫

`shared/components/flow-field`。canvas 2D 手寫，**零新依賴**。

**速度場是某個流函數 ψ 的旋度**（`vx = ∂ψ/∂y`、`vy = −∂ψ/∂x`），所以散度恆為 0，
粒子沿等勢線流動、不會塌進吸子。

第一版把 ψ 的值直接當角度用 —— 那種場有吸子，線會在收斂區擠成一坨，使用者一眼就看出來了。
改成 curl 之後那個行為**從根上消失**，不必偵測匯聚區也不必加粒子斥力（後者還要 O(n²)）。
ψ 只有三項三角函數，導數是解析的，每幀成本跟原本一樣。

可調的五個常數（都在元件內，改一行）：密度分母 1650、透明度 0.7、流速 1.28、
軌跡長度 34、線寬 1.7。

三個非功能要求：

- `prefers-reduced-motion` → 不啟動 rAF，改跑 320 幀後停住，留一張成形的靜態場
- 捲出畫面 / 切到背景分頁 → 停掉 rAF
- 佈局未穩時 `resize()` 會回 false，**重試而不是放棄** —— 直接 return 的話動畫永遠不啟動，
  而且不會有任何錯誤訊息

## 已知債（這支沒動）

- **`--zinc-400` 有 117 處當文字色，對白 2.6:1，不合 AA。** 這在換色之前就存在
  （舊值 `#a1a1aa` 是 2.56:1）。這次刻意維持階梯不動 —— 把它加深會顯著改變全站的視覺層次，
  那是另一件事，不該混進換色系的 PR 裡。
- LINE 按鈕的兩個知情取捨（對比 2.8:1、白底綠框蓋過官方實心綠）見
  [[specs/public/login]]，改之前先確認偏好還成立。
