# 現況表只掃了三分之一的系統

## 發生什麼

`tools/agent-harness/feature-map.mjs` 生成 `kb/wiki/roadmap.md` 的功能區現況表，用來回答
「這個功能區是已接通、空殼、還是未開始」。它被 gate 盯著，每次改動都會重生，
`AGENTS.md` 也明寫「開工前先讀現況表」。

它只掃一個目錄：

```js
const ADMIN_PAGES = join(ROOT, 'apps/web/src/app/features/admin/pages');
```

Clessia 有三個角色（`admin` / `teacher` / `parent`），各自有 `pages/` 目錄。
**teacher 與 parent 從來沒被掃過。** 修正後掃出來：

| 角色 | 頁面 | 真的接了後端 |
| --- | --- | --- |
| admin | 19 | 多數 |
| teacher | 5 | 1（只有課表） |
| parent | 11 | **0** |

家長端整個角色不存在，只有 11 個 18 行的佔位元件。

## 為什麼危險

這不是「報告少了一欄」。表本身是誠實的 —— 它只是**沉默**，而沉默被讀成了「沒有問題」。

實際造成的後果：在排 M3 之後的優先順序時，用這張表得出過
「**這是唯一沒有畫面回答的問題**」這種結論。那個「唯一」的前提是錯的，
因為家長端有 8 個功能區同樣沒有畫面 —— 它們只是不在表上。

自動生成 + gate 讓人**更**信任這張表，不是更少。所以生成器的盲區比手寫文件的錯誤更難
察覺：手寫的東西大家知道會腐化，生成的東西大家假設它完整。

## 現在的作法

頁面一律用 `<role>/<dir>` 稱呼（`admin/attendance` 與 `teacher/attendance` 不會撞名），
表格改成每個角色一欄：

```
| 功能區 | 管理端 | 老師端 | 家長端 | 已掛載 API | 規格 | 狀態 |
```

反向斷言同時擴大：三個角色底下任何沒被藍圖認領的頁面都會讓 gate 紅燈，
所以新增角色頁面時不可能靜默漏掉。

## 帶得走的

- **生成器的掃描範圍就是它的宣稱範圍。** 一個只看部分輸入的工具，輸出必須說清楚它看了什麼；
  說不清楚就會被當成看了全部。
- **問「這張表看不到什麼」比問「這張表說了什麼」更有價值。** 定期對生成器做這個提問，
  尤其是在拿它的輸出做決策之前。
- 這次是使用者問「這是一個多角色系統，不同角色有不同儀表板，你知道嗎？」才暴露出來的。
  **反覆出現的模式：擋下錯誤結論的是領域知識，不是 gate。**
