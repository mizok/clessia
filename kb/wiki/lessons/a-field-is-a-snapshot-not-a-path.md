# 欄位是狀態的快照，不是路徑的證明

## 那次

查 `/api/class-logs` 時看到 `class_logs` 有兩筆真實資料，其中一筆 `published_at` 有值。
而業務規則寫著「`published_at` 是廣播扳機：發布觸發家長端可見 + LINE 推播」。

於是有了一個聽起來很嚴重的推論：**可能有家長收到一則指向不存在畫面的訊息。**

查下去，五個獨立理由每一個都足以否定它：

1. 那兩筆是 **seed 用 `INSERT` 直接塞的**（`seed.sql`）——`published_at` 是被寫進去的欄位值
2. 所以**發布端點對它從來沒跑過**
3. 就算跑了也沒用：`POST /{id}/publish` **只設 `published_at`**，沒有任何通知邏輯
4. 整個 repo **沒有 LINE Messaging 實作**——LINE 在這裡只有 OAuth 登入
5. DB 裡**沒有任何 notification / message / outbox 表**

## 為什麼會錯

`published_at` 這個名字描述的是**一件事發生過**，所以讀到它有值，很自然會讀成
「那件事發生過」。但欄位記錄的只是**某個時刻某個值被寫進去了**——
誰寫的、走哪條路寫的、寫的時候有沒有連帶做別的事，欄位一概不知道。

**「狀態長得像流程跑過之後的樣子」與「流程真的跑過」是兩件事**，
而前者是後者的必要條件，不是充分條件。任何能直接寫那個欄位的路徑
（seed、migration、手動 SQL、另一支端點）都會製造出同樣的快照。

## 同一個形狀的其他三次

- **本頁**：`published_at=true` 讀成「發布流程走過」
- [[lessons/new-field-branches-are-born-untested]]：測試全綠讀成「新分支被測到了」——
  實際是舊 fixture 沒有那個欄位，每支測試都從新分支旁邊走過去
- **聚合值同形**（銷假警告，#258 → #279）：`start`/`end` 看起來像一張長假，
  實際可能是兩張接力——**聚合後的值分不出產生它的路徑**

三者都是**拿一個值去推產生它的過程**。

## 判準

要證明「某條路徑執行過」，去找**那條路徑自己留下的痕跡**：呼叫紀錄、稽核表、
副作用的產物。**不要拿它應該會寫的那個欄位當證據** ——
那個欄位可以被任何人用任何方式寫成一樣的值。

沒有痕跡可查時，退而求其次是**讀那條路徑的程式碼**，確認它到底做了什麼；
上面第 3、4 點就是這樣拆掉的。

## 一般形式：摘要層會讓讀的人補上差額

同一個錯誤不只發生在資料庫欄位上。2026-09-05 review-steward 記錄過一次結構相同的：
`#291` 的標題是「收件匣**抽成共用元件**」，讀的人（包括它自己）推論出「兩端都在用」，
而實際上老師端當時還是自己那一份。

值得注意的是**那不是作者藏東西** —— 元件檔頭原文就寫著「老師端目前還是自己那一份……
不在這支 PR 的範圍」，還指名了負責的席。標題也沒說謊：元件被建出來的那一刻
「抽成共用元件」就是真的。

**是讀者把摘要讀成了全部。**

所以這一族的通則是：**當一層是另一層的有損投影時（欄位之於流程、標題之於 diff、
聚合值之於原始資料），讀的人會自動補上被投影掉的部分，而補的內容來自預期不是證據。**

這跟「防夾帶」是不同的病，**解法也不同**：
防夾帶查的是「作者做了什麼我沒看到」，防這個要查的是
**「我以為的蘊含成不成立」** —— 而後者要回到未投影的那一層去看（原始 diff、
路徑的程式碼、產生資料的那條 INSERT）。

## 投影也會騙走搜尋，不只騙走推論

上一節講的是**讀的人補上被投影掉的部分**。同一件事還有第二種吃法：
**拿未投影那一層的形狀，去搜尋已投影的那一層。**

2026-09-05 的實例：要確認某支修正有沒有部署，我搜線上 bundle 的
`documentElement.style.setProperty` —— **回報 0 處**。

實際上它部署了。minify 把它壓成 `n.style.setProperty`（`n` 是稍早某處
`this.document.documentElement` 的別名）。**我用原始碼的形狀去搜壓縮後的產物**，
而壓縮的定義就是「保留行為、不保留形狀」。

差一點就回報「那支修正沒有部署」——而那會讓一整套真機驗證計畫建立在錯的前提上。

### 判準

**查線上 bundle 要查行為，不查字面。** 搜 minify 動不到的東西：字串常數
（但中文會被逃逸成 `\uXXXX`，直接搜中文一樣是假陰性）、CSS class 名、API 路徑；
或把可疑片段抓出來讀它做了什麼。

這是全席通則「**grep 回空先懷疑 pattern**」的一個新載體，
而且是每個查線上 bundle 的人都會踩一次的那種。

### 同族的另一形：把一個比你以為窄的值當結論

同一天（2026-09-05），計畫席讀 PR 的 `statusCheckRollup`，用
「conclusion 不是 `SUCCESS` 就是紅燈」過濾，得到「五支 PR 全紅」——
**實際五支全綠**，被判紅的那個 `sync-feature-map` conclusion 是 **`SKIPPED`**。

跟 minify 那則的差別只在方向：
一個是**搜一個不保留形狀的產物**，一個是**把一個比你以為窄的值當結論**。
共同點是**中間隔了一層轉換，而我用轉換前的心智模型去讀轉換後的東西**。

### 還有一形：自己的東西最容易憑印象答

同一天我在回報裡寫「v1a 已交付（#346，**OPEN**）」—— 它八個多小時前就 MERGED 了。
我剛在這一頁寫完「查行為不查字面」，轉頭就**憑印象答了自己 PR 的狀態**。

**自己的東西感覺不需要查**，而那個「感覺不需要」就是它逃過檢查的方式。
