# 角色與帳號管理規格

> 討論日期：2026-03-19
> 狀態：部分實作（帳號設定 dialog、家長身份啟用已完成）。
> **root 登入與所有密碼路徑已於 2026-08 移除**，見下方「root 現在登不進去」。

---

## 角色定義

| 角色     | DB 值     | 說明                           |
| -------- | --------- | ------------------------------ |
| 管理者   | `admin`   | 日常營運、系統設定、人員管理   |
| 任課老師 | `teacher` | 課表、點名、學生學習紀錄       |
| 家長     | `parent`  | 查看孩子出缺席、學習進度、繳費 |

一個使用者可同時擁有多個角色（`user_roles` junction table）。

---

## Root 帳號

系統部署時由初始化腳本（seed）自動建立，不透過一般報名/人員管理流程。

### 特性

- `username = root`，無需 email 或手機。**username 已不是登入憑證**（username plugin
  已移除），但欄位仍在用：只有手機的家長把手機存進 `ba_user.username` 當唯一性鍵
  （`parents.ts`），`me.ts` 也用 `username === 'root'` 判斷 `isRootUser`
- 擁有所有管理權限，且**不能被其他人修改或刪除**
- **沒有密碼**（2026-08-28 更正）。`ROOT_PASSWORD` 從來不存在於任何程式碼；
  `seed.sql` 裡曾經硬編一組 scrypt hash，但那對所有客戶是**同一組**，已於 PR #24 移除

### root 現在登不進去

`/login?role=root` 的隱藏入口已隨密碼登入一起移除，而 **`npm run login-link` 對它也無效**：
`seed.sql` 建的 root 的 `email` 是 `NULL`（`ba_user` 允許），而 login-link 是用 email 查人
（`login-link.ts` 的 `where u.email = $1`），管理端的 `POST /api/login-links` 也會直接回
`NO_EMAIL`。

**兩條路都產不出 root 的登入連結。**

這是個**已知且目前無害的缺口**：root 只存在於 `seed.sql`（本機開發），
`bootstrap-org.ts` 開的站根本不會有它。本機要登入請用 seed 的其他帳號。

要修的話有兩條路，都還沒做：

- 給 seed 的 root 一個佔位 email（例如 `root@seed.internal`），它就能走 login-link
- 或讓 login-link 支援用 username 查

### 破窗管道

`root` **不是**破窗管道，而且 `bootstrap-org.ts` 開的乾淨站根本不會建 root。
真正的破窗是 `npm run login-link`：持有 `DATABASE_URL` 的人才產得出連結，
**客戶換掉 DB 密碼就能撤銷供應商的存取**。見 [[architecture/line-oauth-login]]。

## 角色獲得流程

### `admin` 管理者

| 情境           | 流程                                                                      |
| -------------- | ------------------------------------------------------------------------- |
| 第一個管理者   | 由 root 帳號或初始化腳本建立，預設擁有所有權限                            |
| 後續管理者     | 由擁有「**角色管理**」permission 的管理者，在人員管理頁新增並勾選 `admin` |
| 管理者兼任老師 | 由另一個擁有「**角色管理**」permission 的管理者幫他加上 `teacher` 角色    |

### `teacher` 老師

| 情境     | 流程                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 一般老師 | 由擁有「**角色管理**」permission 的管理者，在人員管理頁新增並勾選 `teacher` |

### `parent` 家長

| 情境                            | 流程                                                  |
| ------------------------------- | ----------------------------------------------------- |
| 一般家長（無帳號）              | 公開報名頁自助註冊，建立帳號並關聯子女                |
| 內部人員（admin/teacher）兼家長 | 個人帳號設定頁 → 「啟用家長身份」→ 關聯子女           |
| 已有帳號卻走報名頁              | 系統偵測帳號已存在 → 提示「請從帳號設定啟用家長身份」 |

## 自助規則

| 角色      | 可以自己加嗎？             |
| --------- | -------------------------- |
| `admin`   | 否，只能由他人指派         |
| `teacher` | 否，只能由他人指派         |
| `parent`  | 是，從個人帳號設定自助啟用 |

`parent` 可自助的原因：啟用後只能看自己子女的資料，風險低。

---

## Permission 機制

人員管理表單的「管理權限」勾選項，需新增：

| Permission     | 說明                               |
| -------------- | ---------------------------------- |
| `manage_roles` | 可在人員管理頁修改他人的角色與權限 |

沒有 `manage_roles` 的管理者，人員管理頁只能查看，不能修改角色。

## 個人帳號設定頁（✅ 已實作）

放置於頂部 header 的使用者 dropdown，以 Dialog 形式開啟，包含：

- 基本資料修改（姓名、生日、Email、電話）
- ~~修改密碼~~ —— **已移除**（PR #24）。系統沒有密碼憑證，那顆按鈕點下去必然失敗
- **啟用家長身份**（若尚未擁有 `parent` 角色）

---

## 家長身份啟用流程（✅ 已實作，簡化版）

1. 個人帳號設定 → 點「啟用家長身份」→ 確認提示
2. 系統直接呼叫 `POST /api/me/activate-parent`（無需填入子女資料）
3. API 在 `user_roles` 寫入 `parent` 角色
4. 下次切換角色時，家長選項出現在 `/select-role` 頁面

> **設計決策**：啟用時不強制綁定子女，子女管理延後至家長 Portal 內處理。

---

## 公開報名頁邏輯（待實作）

1. 家長填寫基本資料（姓名、email 或手機）
2. 系統檢查 email/phone 是否已存在
   - **已存在** → 提示「帳號已存在，請登入後從帳號設定啟用家長身份」
   - **不存在** → 建立新帳號，賦予 `parent` 角色，進入關聯子女流程
3. 完成後可登入家長 portal
