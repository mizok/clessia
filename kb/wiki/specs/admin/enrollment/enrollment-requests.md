# 報名審核

> **2026-10-16 現況（#1707）**：這一頁（`/admin/enrollment-requests`）**從來沒有做過**。家長登入後送的報名／試聽申請
> 併進 **`/admin/applications`**，跟公開表單的申請同一頁（使用者裁定 (a)，行政只看一個地方）。
> API 是 `/api/parent-requests`（`manage_students`＋分校範圍）。目前管理端只能**拒絕報名（附原因）**、
> 改試聽狀態；**核准**（開繳費單、建 enrollment）另開 #1726。下面是 2026-03 的原始規格，資料表沒有「來源」欄，
> 來源篩選那段不成立。
>
> **試聽排定日期（#1747，計畫席 10-22 裁定）**：試聽轉「已排定」時，卡片內展開日期、開始、結束欄位，
> 按確定才送（下拉不再直接送出）。**日期必填、時間選填**，後端也擋（缺日期或結束不晚於開始 → 400
> `INVALID_SCHEDULE`）。已排定可以再送一次改期，整組換掉。轉回「待處理」清空三欄，轉「已完成」或
> 「已取消」保留（家長端的已完成用它標日期）。家長端試聽頁直接顯示這份日期，地點用課程所在的分校。

**路徑**: `/admin/enrollment-requests`
**角色**: Admin
**分組**: 報名管理

## 核心目的

審核家長提交的報名申請。

## MVP 功能

### 申請列表

- 篩選：狀態、日期、來源（public_form / parent_portal / add_course / renewal）
- 狀態標籤：
  - 待審核（灰色）
  - 待付款（暖銅橘）
  - 已完成（綠色）
  - 已拒絕（紅色）
  - 已取消（淺灰）
  - 已過期（淺灰）
- 每筆顯示：申請日期、家長姓名、學生姓名、開課班、來源、狀態

### 審核操作

**審核通過**：

1. 查看申請詳情
2. 確認費用（可調整金額，如早鳥優惠、兄弟姊妹折扣）
3. 建立繳費單
4. 系統同步建立 `pending_payment` 狀態的 Enrollment

**拒絕**：

1. 填寫拒絕原因
2. 確認拒絕

### 申請詳情

- 家長資訊
- 學生資訊
- 報名的開課班
- 期望開始日期
- 備註
- 狀態時間軸
