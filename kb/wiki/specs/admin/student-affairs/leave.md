# 請假管理

**路徑**: `/admin/leave`
**角色**: Admin
**分組**: 學務管理

## 核心目的

建立和查詢請假紀錄。請假只能由管理員建立，支援事後補請。

## 請假建立規則（重要）

1. 請假**只能由管理員**建立，老師和家長無此權限
2. **允許事後補請**（已過去的課堂也可以補建請假）
3. 建立請假後，系統**自動將對應課堂的出勤狀態改為 `leave`**
4. 若該課堂出勤已被標為其他狀態（`present`/`late`/`absent`），建立請假後仍需覆蓋為 `leave`
5. **刪除（銷假）請假後**：**以 [[rules/attendance-rules]] §6、§7 為準**（使用者 2026-09-03 定案）——
   銷假＝刪除請假單；請假連動寫的 `on_leave` 紀錄**刪掉**，學生回到「還沒點名」；
   **已點過名的日子不動**（老師點的到課／缺席不會被刪）。

   > **2026-10-02 更正（#1004）**：這一條原本寫「出勤狀態不自動還原（需管理員手動修正出勤）」，
   > 那是 2026-03 的舊規格，已被上述定案取代；程式照定案做（`leaves.ts` 的 DELETE 路徑、
   > `attendance.ts` 點名名單的 cancel-leave 只刪 `on_leave`）。規則只寫在 attendance-rules 一處，
   > 這裡不再複述細節 —— 兩頁各說各話正是這次矛盾的來源。

## MVP 功能

### 分頁切換

- **待處理分頁**：今天或未來的請假申請（需跟進或確認的）
- **全部分頁**：所有請假紀錄，可篩選

### 篩選列（全部分頁）

- 日期範圍
- 學生姓名
- 課程
- 開課班

### 請假列表

每筆顯示：

- 學生姓名
- 請假日期
- 課堂（課程名稱 + 時間）
- 請假原因
- 建立時間
- 建立者

點擊可展開編輯或刪除

### 新增請假 Popup

1. 選擇學生（可搜尋）
2. 選擇請假日期
3. 系統顯示該學生當天「有報名且在生效期間內」的課堂列表，勾選要請假的課堂（可多選）
   - 若當天無符合課堂，顯示「該日無排課」提示
4. 輸入請假原因（可選）
5. 確認建立
6. **系統副作用**：自動將所選課堂的出勤狀態更新為 `leave`

### 批次請假

- 選擇一個課堂 → 勾選多個學生 → 批次建立請假
- 適用場景：全班校外教學、颱風停課補假等
- 批次建立後同樣觸發每位學生對應課堂出勤改為 `leave`

## 管理端頁面 A6 版（#1314 LV，2026-10-10）

- **兩分頁**：「待處理」（預設，`end_date >= 台北今天`）與「全部」；各自帶張數。`GET /leaves` 為此加了兩個可選 query：`endFrom`（`end_date >= `）與 `order`（`created_desc` 預設｜`start_asc`｜`start_desc`，依開始日時再以建立時間、id 收斂）。
- **分章**：待處理依「今天／明天／之後的日期」，**進行中的跨日假歸今天**；全部依開始日由新到舊。章在翻頁時可能從頁首接續。
- **補請**不是欄位：建立日（台北）晚於 `startDate` 就標「補請」。
- **取消請假**的確認文案照 [[rules/attendance-rules]] §6–7：未來假＝不影響任何出缺席；已結束／進行中＝還沒點名的日子回到「還沒點名」、**已點過名的日子不會動**（舊文案寫「同步恢復出勤狀態」，與 API 不符，已改）。
- **課程／開課班篩選**（#1100 #31）：`GET /leaves` 加 `courseId`／`classId`，判準是「學生在那門課（任一班）／那個班有報名」—— 同分校篩選走報名，不看請假單綁的堂次（綁定是選填，沒綁的整天假會漏）。選了課程，開課班下拉只列那門課的班；換課程或換分校會清掉已選的班。
- **取消前的影響預覽**（#1100 #33）：`GET /leaves/:id/impact?mode=truncate|full` 回 `{ revertCount, keptCount }` —— 這個學生在那段範圍內的 `on_leave`，還沒點名的會被刪（回到「還沒點名」）、已點名的不動。範圍與 DELETE 共用 `cancelPlan`（不會預覽一段、刪另一段）；只算已經生成的出勤事件。確認窗把數字接在原本文案後面；讀不到就照原文案開，不擋取消。
- **批次請假**（#1100 #32，計畫席 10-23 裁逐筆）：工具列「批次請假」→ 對話框選一堂課（今天起 14 天、沒停課、頂欄分校）→ 勾這班在學的學生 → 原因（選填）。`POST /leaves/batch { sessionId, studentIds(≤100), reason? }`：每位學生走跟單筆 POST **同一個** `createLeave`（驗證、分校範圍、重疊、出勤連動、通知都一樣），一位失敗不擋其他人，回每位 success／failed＋原因；堂次不在本 org → 整批 404。不是一個交易。有人沒成功對話框不關：列出那幾位與原因、勾選只留他們，可以只對他們重送。通知照單筆現狀：10 位就是 10 則 `leave_for_my_class`（要不要合併另議）。
- **後續項（缺 API／資料，未做）**：列內課堂清單（列帶 `sessions[]`）、年級。
