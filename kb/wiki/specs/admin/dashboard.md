# 管理員儀表板

**路徑**: `/admin/dashboard`
**角色**: Admin

## 核心目的

管理員首頁，快速掌握今日概況與待辦事項。**儀表板是索引不是工作場** —— 每張卡回答一個問題、
可點，動作到功能的家去做。設計理由與拒絕過的替代方案見
[[architecture/admin-dashboard-v1]]。

## v1 已交付

行政區（所有 admin 可見）：今日課堂、未點名課堂、今日請假、成績待登錄。
經營區（需 `view_reports` permission）：在籍學生、本月報名異動。
另有今日課表與今日請假兩份明細清單，資料與對應卡片同一支查詢，不另外請求。

兩個行為上的例外：

- **未點名課堂只在 `attendance_mode = 'per_session'` 時渲染**。日到班模式下
  `daily-checkins` 從不蓋 `events.attendance_taken_at`，整張卡會全部誤報。
  讀不到機構設定時同樣不渲染。
- **本月報名異動的單位是「筆」不是人次**。數字來自 `GET /api/enrollments` 的
  `meta.total`（期間內有異動的報名記錄數），一筆當月插班又退班的報名在這裡是 1，
  在進出總覽頁的事件分類裡是 joined + left 兩筆 —— 兩邊對不上是語意差異，不是 bug。

每支查詢各自吞掉錯誤，一張卡讀取失敗只讓那張卡顯示失敗態，不擋整頁。

### 待開單（#1293，2026-10-04）

系統**沒有排程、也沒有自動開單**（帳單由行政手動跑開單），行政只能在這裡被提醒「下期快到了還沒開單」。

- 卡片「待開單」只給有 `manage_finance` 的人看（開單是財務動作），端點 `GET /api/billing-periods/upcoming-unbilled`
- 判準：期的開始日在**今天之後、14 天以內**（常數，使用者可否決改成機構設定 —— 那要多一支 migration），
  **有該開的**（在讀的期繳報名與這期重疊）**而且還沒開**（這期沒有任何一筆未作廢的學費明細）
- 沒有待開的期就不出現（不是顯示 0）；點進去到餐費頁、直接打開開單對話框並選好那一期
- 開單對話框（餐費頁「月結」）多了「期繳」模式 —— 原本只能月結，期 run 在 UI 上點不到
- 不在這裡：已經開過、之後才有新報名的增量開單；月繳的提醒

## A6 版（#1314 D，2026-10-10）— **取代上面 v1 的卡片配置**

上面 v1 的「六張卡／經營區兩張卡／成績待登錄」已被換掉；留著是因為 v1 的設計理由仍有參考價值。現況：

- **色面**：主標＝機構名（分校只有一個時小字附在後面）；副行日到班講人（「今天 N 人要來，已經到了 M 位」），逐堂點名講堂數。**Hero 時間軸、成績待登錄、「現況」數字卡都移除**（A6 沒畫，使用者 10-10 未異議＝照預設）。
- **日到班機構主段＝「該到沒到的 N 位，先打給家長」**。判定 `missingReason`（`dashboard.util.ts`）只有一份：他今天第一堂已開始、沒到、沒請假、那堂沒停課。還沒到上課時間的人在摺疊的「今天的到班名冊」（依最早一堂分章、有「現在」線）。
- **「打電話」＝ `tel:` 連結＋`POST /api/contact-logs`（channel=phone）**；記成功才把該列換成「已聯絡 HH:mm」，記不成功列不變並提示。載入時 `expected[].lastContact` 已有值的列直接是已聯絡。沒有家長電話／沒有登記家長就不給「打電話」並說出原因。
- **逐堂點名（per_session）機構主段仍是今日課表**（A6 只畫了日到班的形狀）；點名 dialog 不動。
- 灰摺疊三條：到班名冊（僅日到班）、今天的請假（來源＝家長 app／櫃台＋原因）、逾期帳單（僅 `manage_finance`；張數與金額來自 `GET /invoices/summary` 的 `overdue`，列表前 4 筆）。
- 工具列／手機托盤：次要「櫃台代刷到班」（連到 `/admin/checkin` 打卡站）＋主要「登記請假」（開 `app-phone-leave` 面板；列內版預帶該生，`presetStudentId`）。需 `basic_operations`。
- 「臨時狀況？」三連結都連到課表頁（本站沒有各自的情境頁）。
- **不在本頁**：分校切換、頭像圓章、搜尋 placeholder（殼層）。

## 尚未做

自訂卡片排序。**不放假佔位卡** —— v1 清掉的就是那些寫死的 `'—'`。
