# 費用方案管理

**路徑**: `/admin/fee-templates`
**角色**: Admin + `manage_finance` 權限
**分組**: 財務管理

> **本頁於 2026-08-29 依 [[rules/billing-rules]] 重寫。** 原版（2026-02-13）把價目表設計成
> 班級層級、帶生效起訖日與按比例開關 —— 那個模型在訪談後被推翻。被刪除的部分用刪除線保留，
> 讓後來的人知道是決定不是遺漏。

## 核心目的

定義機構的**收費標準**（定價），供報名時挑選。

## 兩個實體，一頁管理

| 實體              | 是什麼                                    | API                    |
| ----------------- | ----------------------------------------- | ---------------------- |
| `fee_templates`   | org 層的定價（名稱 + 計費模式 + 金額）    | `/api/fee-templates`   |
| `billing_periods` | 機構自訂的具名日期區間（「2026 上學期」） | `/api/billing-periods` |

> **判斷（待計畫席裁決）**：收費期間沒有自己的頁面也沒有自己的 spec，但 API 已在 main 上。
> 它是個位數到十幾筆的量級、只有期繳會用到，另開一頁不划算 —— 所以放在本頁當第二個區塊。
> 若計畫席認為該獨立成頁，把「## 收費期間」整節搬出去即可，資料模型不變。

## MVP 功能

### 價目表列表

- 篩選：名稱搜尋、計費模式、是否啟用
- 每筆顯示：方案名稱、計費模式、金額、啟用狀態
- **沒有分頁** —— 一個機構的價目表是十幾筆的量級（API 也沒做分頁）

~~篩選：開課班、生效期間~~ —— **已移除**（2026-08-29 訪談）。價目表是 org 層的，不掛班級；
期間概念獨立成 `billing_periods`。

### 新增/編輯價目表 Popup

| 欄位     | 類型     | 必填 | 說明                                                 |
| -------- | -------- | ---- | ---------------------------------------------------- |
| 方案名稱 | 文字     | 是   | 1–100 字，如「國中主科月繳」                         |
| 計費模式 | 下拉選單 | 是   | 月繳 / 期繳 / 堂數制（見下）                         |
| 金額     | 數字     | 是   | **整數**，台幣沒有小數；定價，不是實收               |
| 啟用     | 開關     | 否   | 預設啟用。停用的不出現在報名選單，但歷史報名仍看得懂 |

### 計費模式（billing-rules 規則 1）

| 值             | 顯示   | 說明                                    |
| -------------- | ------ | --------------------------------------- |
| `monthly`      | 月繳   | 每月一張帳單                            |
| `period`       | 期繳   | 依 `billing_periods` 的具名區間收費     |
| `session_pack` | 堂數制 | 買 N 堂慢慢上完，出席扣堂；小型才藝班用 |

**計費模式是報名層級的選擇，不是班級屬性** —— 同一班可以同時有月繳生與期繳生。
價目表上的模式只是「這個方案適用於哪種收法」。

### 刪除

- 停用（`isActive: false`）是常態；**真的刪除**只在建錯時用。
- FK 是 RESTRICT：**被任何報名引用過就刪不掉**。UI 必須顯示後端回的錯誤，不能做樂觀更新後
  假裝成功。

### 收費期間

- 列表：名稱、起始日、結束日；依起始日降冪。**沒有分頁。**
- 新增/編輯欄位：名稱（1–100 字）、起始日、結束日。
- 驗證只有一條：**結束日不得早於開始日**。
- **期間之間可以重疊，不要擋** —— 過渡期（舊制最後一期與新制第一期）是真實情境，
  擋掉只會逼行政去改日期硬湊。後端的 `isValidPeriodRange` 刻意只看單筆。

## 已否定的功能（保留理由）

- ~~關聯開課班（一個方案綁一個班）~~ —— **已移除**。價目表是 org 層定價；學生實際付多少
  存在 `enrollments.agreed_amount`。
- ~~生效起始日 / 結束日~~ —— **已移除**。價目表沒有生效期間；期間是 `billing_periods` 這個
  獨立實體，且只有期繳用得到。
- ~~按比例計算開關~~ —— **已移除**。插班/退班的比例試算是**開單時的建議值**，行政可改
  （billing-rules 規則 3），不是價目表上的一個開關。
- ~~折扣欄位（早鳥、兄弟姊妹、續讀）~~ —— **從未存在也不會加**（規則 2）。現實裡沒有結構化
  折扣規則，只有議價：「折數看老闆當下心情，每個客人還有可能不一樣。」金額走人工覆寫。
- ~~說明欄（如「含教材費」）~~ —— **已移除**。API 沒有這個欄位；要記備註的是那張帳單的
  調整原因，不是價目表。

## 資料依賴

| 操作 | API                                                  |
| ---- | ---------------------------------------------------- |
| 讀取 | `GET /api/fee-templates`、`GET /api/billing-periods` |
| 寫入 | 兩者的 `POST` / `PUT /{id}` / `DELETE /{id}`         |

兩支都額外要求 `manage_finance` 權限（`apps/api/src/index.ts` 的 mount）—— 沒有這個權限的
管理員連選單入口都不該看到。
