# 繳費紀錄

**路徑**: `/admin/payments`
**角色**: Admin + `manage_finance` 權限
**分組**: 財務管理

> **本頁於 2026-08-29 依 [[rules/billing-rules]] 重寫。** 原版（2026-03-17）建立在一個
> 訪談後被推翻的模型上：結構化折扣、六種帳單狀態、「強制啟用課程」、部分付款指定啟用項目。
> 那個模型假設「沒繳錢就會被擋住」，但受訪公司**從未因欠繳停課** —— 沒有「擋住」，
> 就不需要「強制」。被刪除的部分用刪除線保留，讓後來的人知道是決定不是遺漏。

## 核心目的

開帳單、收款、看誰還沒繳。

## 核心模型

### 一張帳單，多筆收款

分期在實務上存在（「偶爾有家長要求分期」），所以 `invoices` 對 `payment_records` 是一對多。
但**不做排程式的分期計畫** —— 沒有「第 2 期應於 X 日繳 Y 元」這種東西，只有「收到多少記多少」。

### 狀態是推導出來的，不是存的

| 狀態   | 條件                |
| ------ | ------------------- |
| 未繳   | 累計實收 = 0        |
| 部分繳 | 0 < 累計實收 < 應繳 |
| 繳清   | 累計實收 ≥ 應繳     |

**逾期是正交的衍生標記**，不是第四種狀態：過了 `due_date` 且未繳清就是「欠繳」。
一張帳單可以同時是「部分繳 + 逾期」。

### 金額：定價 + 人工覆寫

每張帳單存三件事：**定價**（來自價目表）、**實收**、**調整原因**（自由文字）。
沒有折扣引擎。行政要收多少就填多少，填了就要寫原因。

## MVP 功能

### 帳單列表

- 篩選：狀態（未繳/部分繳/繳清）、是否逾期、日期區間、學生、分校
- 每筆顯示：學生、班級、應繳、已收、狀態、`due_date`
- 逾期用視覺標記（不是狀態欄的第四個值）
- 總筆數取後端 `meta.total`，不要抓單頁自己數

### 開帳單

- 月繳：選月份批次開；期繳：選 `billing_period` 批次開；堂數制：報名時開一次
- 金額預設 = 報名上的 `agreedAmount`，沒有就用價目表定價
- `due_date` 預設 = 開帳日 + org 設定天數（14–21 天，對齊「發袋後兩三週沒回音才催」的節奏），
  每張可改

### 收款 Popup

1. 輸入金額（可小於應繳 —— 部分收款是常態，不需要任何額外確認）
2. 付款方式：**現金 / 轉帳**（現況約 50/50，現金略多）
3. 轉帳時：**上傳一張憑證圖**（家長回傳的截圖）+ 備註（帳號後五碼）
4. 備註（自由文字，如「定金」）
5. 確認

- **不做**銀行對帳單自動對帳。
- 線上金流是**延後不是排除**：付款方式 enum 加值即可擴充。

### 新生定金

系統**不需要「定金」這個概念** —— 報名時就開出第一張全額帳單，定金 = 對它的第一筆部分收款
（備註記「定金」），帳單自動變「部分繳」。`enrollments.pending_payment` 承接「定金未繳」。

### 退費

- 記為**負向收款**（`refund`），不是帳單狀態，也不是另一張帳單。
- 必填原因與經手人。
- 退多少：期中退班按剩餘比例試算（見下），行政可改。

### 插班與退班的比例試算

同一套算法，方向相反：期中插班按**剩餘比例**收，退班按剩餘比例退。

- 基準二選一：**剩餘天數** 或 **剩餘堂數**（堂數按該生實際修的班級課表算，sessions 資料已存在）
- **試算是開單時的建議值，不是死規則** —— 行政可以直接改數字
- ✅ 這是「有邊界條件的計算」，照 charter 先例抽成純函式 + spec（跨月、零剩餘、當天插班）

### 收費袋 = 列印帳單

實體流程沒變：發一個袋子給學生帶回家。系統這邊就是**瀏覽器列印視圖**，發袋時設 `due_date`。

### 收據

收款後可開收據（有編號、瀏覽器列印）。
電子發票**延後不是排除**：收款記錄存齊發票所需資料（金額、日期、付款人、品項），不做串接。

### 催繳：可見性，不強制

- 受訪公司用 LINE／電話追繳，**從未停課**。
- 催繳記錄獨立表 `payment_reminders`（method: line/phone/other、note、created_by）——
  這是業務資料，不塞 `audit_logs`。
- 列表要能篩「逾期未繳」給行政當追繳清單。

### 多子女合繳

一筆轉帳付兩個小孩的錢 → **拆開記**（每筆收款屬於單一帳單），備註寫同筆轉帳。
UX 之後可以加「一筆金額分配到多張帳單」的輔助，schema 不用改。

### 缺課不退不抵

月/期繳缺課不補償；特例走「下期帳單人工調整」。
堂數制唯一的結構化決定：**「請假那堂扣不扣堂」是一個設定值**（org 或班級層級）。

## 已否定的功能（保留理由）

- ~~六種狀態（待付款/部分付款/已付款/逾期/失效/已取消/已退款）~~ —— **已移除**。狀態由累計
  實收推導成三種；逾期是衍生標記；退款是負向收款不是狀態；「失效」預設了欠繳會讓報名失效，
  但訪談確認從未如此。
- ~~強制啟用功能（未付清仍可強制啟用 enrollment）~~ —— **已移除**。欠繳從不擋課，
  沒有被擋住的東西需要強制。
- ~~部分付款時選「本次欲啟用的課程項目」~~ —— **已移除**。同上：付款與上課權利沒有連動。
- ~~折扣 / 調整（結構化）~~ —— **已移除**。只有「定價、實收、調整原因（自由文字）」。
  兄弟姊妹折、續讀折、早鳥折這些規則現實中不存在，存在的是議價。
- ~~寬限期二階段（期限 7 天 → 寬限 7 天 → `void`）~~ —— **已移除**。只有一個 `due_date`
  （預設 14–21 天），過了就是欠繳，沒有第二段計時器，也不會轉成失效。
- ~~「若為新生，系統自動建立家長帳號和學生資料」~~ —— **移到報名流程**。收款不該有建帳號的
  副作用；新生的路徑見下方「相關規則與流程」。

> `/api/invoices`（`ADMIN_ONLY` + `manage_finance`）。狀態由後端推導後回傳
> （`apps/api/src/lib/invoice-status.ts`），前端不重算。管理端頁見
> [[architecture/admin-payments-page]]。
>
> **需求與已交付的 API 之間還有兩個缺口**（2026-08-29 實作時查證，已回報）：
>
> 1. `GET /api/invoices` 的 query 只吃 `studentId` / `overdue` / `page` / `pageSize` ——
>    **沒有狀態、日期區間、分校篩選**。上面「帳單列表」那節列的篩選目前只實現了
>    是否逾期與學生兩項；狀態改用每列的視覺標記呈現。
> 2. 非 `overdue` 路徑的 `meta.total` 回的是**當頁筆數**不是總數（`.range()` 切頁之後
>    才算 `rows.length`）。所以上面「總筆數取後端 `meta.total`」這條原則現在**還套用不了**，
>    管理端頁暫時不顯示總筆數。
