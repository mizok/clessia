# 餐費管理

**路徑**: `/admin/meals`
**角色**: Admin + `manage_finance` 權限
**分組**: 財務管理

> **本頁於 2026-08-29 依 [[rules/meal-rules]] 重寫。** 原版（2026-02-13）把餐費設計成
> 「早/午/晚/點心四種餐別、每筆手動輸入金額」的記帳簿 —— 訪談後確認實際操作是
> **每日名單勾選**：一份便當、一個學生一天一筆。被刪除的部分用刪除線保留。

## 核心目的

行政每日勾選誰要訂餐，月底一次結算成帳單。

**操作者是行政，不是老師** —— 訂餐與點名是兩個不同的動作，不要塞進老師的點名流程
（meal-rules 規則 4）。

## 核心模型：訂餐與出席解耦

> 「有學生天天到班但家長不訂便當。」

- 排課表只產生**候選名單**（今天有課的學生），實際以每日的 `meal_record` 為準。
- 學生有「訂不訂餐」的預設設定（opt-in），決定候選名單上的預設勾選狀態。
- 提前請假 → 請假模組只**提示**行政「別訂他的便當」，**不自動改** `meal_record`。

## MVP 功能

### 每日名單（主畫面）

- 選日期（預設今天）→ 顯示當天的候選學生名單
- 每一列：學生姓名、班級、**訂了沒**（勾選）、**單價**、**收不收費**（開關）、備註
- 單價每筆各自可改，帶預設值 —— 便當價格會變動，所以價格存在每一筆上而不是設定檔
- 已結算的列**鎖住「收不收費」開關**（見下方月結）

### 「收不收費」是人工開關，不是規則

> 「小孩超過下午 N 點才請假，結果便當已經送到了，這種狀況可能會按照當前實際情況決定要不要收。」

**不要自動化 N 點截止邏輯** —— 那是人工裁量。每筆留一個行政可以翻的開關就好。

### 月結

- 動作：選月份 → 加總「要收費且**尚未結算**」的餐記錄 → 生成 `invoice_item`，
  同一 transaction 內把這些餐記錄標上 `invoice_item_id`。
- **這個標記是系統自動的，沒有人工動作** —— 它讓月結**冪等**：遲補的舊記錄下次自動撈進、
  已結的不會重複收。
- 要改已結算的記錄：走帳單作廢（item 刪除 → FK SET NULL 自動解除標記）或下期帳單調整。
- 結算後進 [[specs/admin/finance/payments|繳費紀錄]] 的收款流程。

### 查詢與統計

- 篩選：日期範圍、學生
- 顯示區間內的總金額與筆數 —— **總數取後端的 `meta.total`**，不要抓單頁明細自己加
  （列表 API `pageSize` 上限 100，量大的月份會悄悄少算而且錯得沒有徵兆）

### 匯出

- 依篩選條件匯出 CSV，供對帳用

## 已否定或延後的功能

- ~~餐別（早/午/晚/點心）~~ —— **已移除**（2026-08-29 訪談）。現實是一天一份便當；
  `meal_records` 是每生每日一筆，沒有餐別維度。
- ~~新增餐費 Popup（選日期 → 選學生 → 選餐別 → 輸入金額）~~ —— **已移除**。逐筆手動新增
  不是實際操作方式；主畫面就是每日名單勾選。
- ~~批次新增（多學生 + 同餐別 + 同金額）~~ —— **已移除**。每日名單本身就是批次操作。
- ~~CSV 匯入~~ —— **延後，非否定**。現況記在 Excel，匯入看似能接軌，但訪談沒有確認過這個
  需求，而每日名單勾選已經涵蓋日常。要做的話等有人真的開口。
