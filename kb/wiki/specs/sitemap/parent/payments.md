## 畫面區塊

### 2. 內容區

四選一（`@if` 鏈，順序就是判斷順序）：

| 條件                                   | 畫面                                                 |
| -------------------------------------- | ---------------------------------------------------- |
| `loading() && invoices().length === 0` | 三條 `skeleton-bar`                                  |
| `failed()`                             | 空狀態 `載入失敗 / 沒有讀到繳費紀錄，可能是連線問題` |
| `invoices().length === 0`              | 空狀態 `目前沒有帳單紀錄`（無說明文字）              |
| 其餘                                   | 待付款區 + 已付款區 + 「載入更多」                   |

有資料時分兩段，**各自只在該段非空時才渲染**：

- **待付款**（`groups().pending`）：每列是一顆按鈕 —— `#<id 前 8 碼>`、金額（`total - netPaid`）、
  `期限 <dueDate>`（**只在有 `dueDate` 時**）、狀態標籤
- **已付款**（`groups().paid`）：每列 `#<id 前 8 碼>`、`total`、最後一次付款日期
  （**只在查得到時**）、`已付款`

### 3. 帳單明細抽屜

`p-drawer`，`position="bottom"`、`modal`、`appendTo="body"`。見下方子頁面。

**資料來源**：`GET /api/me/billing?childId=<id>&page=1&pageSize=20`（實測攔到）。

`drawer-auto p-component p-drawer p-drawer-bottom p-drawer-open payments__detail-sheet`。

從畫面底部升起，內容（實測 `#413224d0`）：

> 要另外查。這是「畫面 ⊆ 地圖」容易漏的一類。

**關閉**：按 `關閉` → `.p-drawer` 變成 `null` ✓（`.p-dialog`、`.cdk-overlay-backdrop` 也都是 null）。

### ~~關閉之後 `.p-drawer-mask` 還留在 DOM 裡~~ —— **是量測環境，不是產品**（2026-09-13 結案）

關閉後 7 秒以上，`.p-drawer-mask` 仍然存在，卡在 `p-overlay-mask-leave-active`，
`display:block`、`visibility:visible`、`opacity:1`、`pointer-events:auto`、
尺寸 1504×695（整個 viewport）。**`document.elementFromPoint()` 打在帳單列上回傳的是遮罩，不是列。**

**2026-09-13 證實了：是環境。** 現象在 `parent02@` 上第二次重現（遮罩卡在
`p-overlay-mask-leave-active`、`pointer-events:auto`、`elementFromPoint` 打在帳單列上
回傳的是遮罩），當下量到：

```js
document.visibilityState; // → "hidden"
document.hasFocus(); // → false
```

**對照實驗**（建一個 200ms 的 CSS transition）：

```
rafRan: 0                  ← requestAnimationFrame 1.9 秒內一次都沒跑
transitionendFired: 0
opacityAfter1500ms: "1"    ← 200ms 的 transition 連開始都沒有
```

**背景分頁裡 CSS 動畫不會跑**，而 PrimeNG 靠**離場動畫結束**才移除遮罩 ——
動畫沒跑完，元素就永遠留著。**同一個成因也解釋了整個 session 的「真滑鼠點擊失效」**
（[[specs/sitemap/README|方法頁]]坑 6 → 坑 12）。

**沒有開 issue，而且現在有理由不開**：要在前景分頁重現才算產品缺陷。

### ⚠️ 一個差點被寫成缺陷的「載入失敗」

切到王柏翰之後畫面顯示「載入失敗」，而 DB 明明有 2 張帳單 —— 看起來就是一支缺陷。

**真相是別席在那幾秒間登入了 admin**（auth cookie 是 host 層級、全席共用同一個 Chrome），
`GET /api/me/billing` 回 `403 NOT_PARENT`。**而頂列徽章還寫著「家長 / 林志明」** ——
shell 不會因為 cookie 變了而重繪。重登之後同一支請求對三個孩子全部 200。

**那次量測已作廢並重做。** 教訓寫進 [[specs/sitemap/README|方法頁]]：
**身分斷言要打 `GET /api/me`，不能看畫面。**
