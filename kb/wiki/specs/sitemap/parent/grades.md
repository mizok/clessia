### 2. 篩選列（`grades__filters`）

兩個控制項，**永遠都在**（不受資料多寡影響）：

- **科目下拉**（`p-select`）：placeholder `全部科目`、`[showClear]="true"`。
  選項是 `subjectOptions()` —— **從目前這個孩子的成績裡算出來的科目集合**，不是全校科目表
- **期間切換**（`p-selectbutton`，`[allowEmpty]="false"`）：`近1月` / `近3月` / `近半年` / `全部`（預設 `全部`）

### 3. 內容區

四選一：

| 條件                                  | 畫面                                                 |
| ------------------------------------- | ---------------------------------------------------- |
| `loading() && records().length === 0` | 三條 `skeleton-bar`                                  |
| `failed()`                            | 空狀態 `載入失敗 / 沒有讀到成績紀錄，可能是連線問題` |
| `groups().length === 0`               | 空狀態 `沒有符合條件的成績`                          |
| 其餘                                  | 截斷警告（條件式）+ 依科目分組的清單                 |

**截斷警告**：`只顯示最近 N 筆，共 M 筆。` —— 只在 `total() > records().length` 時出現。
這一頁**沒有分頁 UI**，一次撈 100 筆再前端篩，所以超過就被截斷；
元件註解明寫「**不要把大聲的失敗換成安靜的截斷**」。

每一筆成績：日期、考試名稱，然後是分數或狀態晶片 ——
`status === 'scored'` 顯示 `分數 / 總分`（不及格時加 `pi-exclamation-triangle` 與 `--fail`），
否則顯示 `app-data-chip` 裝的狀態文字。

**資料來源**：`GET /api/me/grades?childId=<id>&pageSize=100`（實測攔到）。

## ⚠️ 缺陷：切換孩子時科目篩選不會重設，而控制項顯示成「沒有篩選」

**已開 issue 給計畫席，本頁只記現況。**

`subjectFilter` 是元件層的 signal，`effect` 只在 `activeChildId` 變動時**重新取數**，
**沒有重設篩選器**（`grades.component.ts` 的 `effect` 只呼叫 `this.load(childId)`）。

於是：

1. 在王柏翰（只有數學）選了科目「數學」
2. 切到盧安琪（只有自然）
3. **清單變成「沒有符合條件的成績」**，而頁首錨點還寫著「1 筆新成績」

**最糟的是控制項在說謊**：`subjectOptions()` 重算之後只剩「自然」，
「數學」不在選項裡，所以 `p-select` 解不出標籤，**退回顯示 placeholder「全部科目」
（`class="p-select-label p-placeholder"`）** —— 看起來就像沒有套用任何篩選。

唯一的線索是旁邊那顆 ✕ 清除鍵**還在**（表示確實有值）。**實測按下去，那筆成績立刻出現。**

> **家長會看到的**：換一個孩子，成績頁說「沒有符合條件的成績」，篩選器寫著「全部科目」。
> 合理的結論是「這個孩子沒有成績」。

| 開科目下拉                       | 浮層開啟（`.p-overlay`），選項只有 `數學`（王柏翰唯一的科目）✓         |
| 選「數學」                       | 標籤變 `數學`，**✕ 清除鍵出現**，清單不變（唯一那筆就是數學）          |

| 按 ✕ 清除                        | `自然 2026-07-21 自然模擬考 49 / 100` 出現 ✓                           |
| 期間 `近1月`                     | **清單變空**（該筆是 53 天前）                                         |
| 期間 `近3月` / `近半年` / `全部` | 該筆都在                                                               |

> **期間切換這一組刻意挑了有鑑別力的資料**：盧安琪那筆是 `2026-07-21`，
> 對 `2026-09-12` 來說**只有 `近1月` 排除得掉它**。
> 若拿王柏翰那筆（17 天前）去測，四個期間的結果**全部相同** ——
> 那種「兩邊一樣」證明不了篩選器有在運作。

### ⚠️ 期間切換那一組的證據等級

按四顆期間鈕的那一次量測，前後的 `GET /api/me` 回的是 **admin**（別席在那期間登入）。

**但這個結論仍然成立**，理由是機制：期間切換是 `filterByTimeRange()`
對已經在 signal 裡的 `records()` 做的**純前端 computed，完全不打 API**，
而那批資料是在**確認為家長身分時**載入的（同一次量測的 `WHO` 是 parent）。

**寫出來是因為它跟其他量測的等級不同** —— 不要把它讀成「在乾淨 session 下驗過」。
