## 畫面區塊

### 1. 頁首

`繳費紀錄` + 副標「開帳單、收款、看誰還沒繳。狀態由累計實收推導，逾期是額外的標記不是另一種狀態。」
右側「操作紀錄」與主要行動「手動開帳」。

### 2. 待開帳提示（`app-todo-banner`）

黃底一整條，**整條可按**：「有 **N** 筆生效中的報名還沒開過帳單」。
數字來自 `GET /api/enrollments?hasInvoice=false&status=active&pageSize=1` 的 `meta.total`。

### 3. 篩選列

由左到右：學生自動完成（`輸入學生姓名篩選`）、帳單狀態下拉、催繳三選一、（有篩選時）「清除篩選」。

- **帳單狀態下拉**：`全部狀態` / `未繳` / `部分繳` / `繳清`（來自 `INVOICE_STATUS_LABELS`）
- **催繳篩選是四選一的單選，不是開關**（`allowEmpty=false`）：

  | 選項   | 送出的參數         | 本機實測筆數 |
  | ------ | ------------------ | ------------ |
  | 全部   | （不帶）           | 37           |
  | 未繳清 | `outstanding=true` | 29           |
  | 快到期 | `dueWithin=7`      | 4            |
  | 已逾期 | `overdue=true`     | 9            |

  > 元件註解寫明**不要改回兩態切換**：舊的「只看欠繳」做的其實是「逾期且未繳清」，
  > 照它催繳會漏掉還沒到期的未繳（#639）。

### 4. 帳單表格

欄位：`學生`、`開立日`、`繳費期限`、`應繳`、`已收`、`尚欠`、`狀態`。

- **整列可按**（`role="button"`、`tabindex="0"`，Enter / Space 也可以）→ 開帳單詳情
- `繳費期限`逾期時套 `payments__date--overdue`；`未設定`是沒有 dueDate 時的字
- `尚欠` > 0 時套 `payments__amount--due`
- `狀態`欄可能**同時**出現兩顆狀態點：帳單狀態（`未繳` / `部分繳` / `繳清`）
  **加上**獨立的 `逾期`。元件註解：逾期是額外標記，塞進同一個 tone 會少掉一半資訊
- 分頁：每頁 20 筆

資料來源：`GET /api/invoices?page=&pageSize=20`，加上上表的催繳參數、`status`、`studentId`。

## 子頁面：帳單詳情

**開啟方式**：點任一列。`width: 720px`、`showHeader: false`。

- 標頭：`<學生> 的帳單` + 帳單狀態；逾期時多一顆 `逾期`
- 數字列：`應繳` / `已收` / `尚欠` / `繳費期限`
- **帳單明細**表：`項目` / `金額` / `說明`（項目型別 `學費` / `餐費` / `堂數包` / `調整`）
- **收款記錄**：兩顆按鈕 + 清單
  | 按鈕                               | 出現條件 | disabled 條件                                  |
  | ---------------------------------- | -------- | ---------------------------------------------- |
  | 記錄收款                           | 永遠     | —                                              |
  | 記錄退費                           | 永遠     | **`payments.length === 0`**（實測到 disabled） |
  | 沒有收款時顯示「還沒有任何收款。」 |
- **催繳記錄**：說明「催繳只留紀錄，不會停課也不會擋住任何東西。」
  一列表單：催繳方式下拉（`LINE` / `電話` / `其他`，預設 `LINE`）+ 備註（`maxlength=200`）+「記一次」。
  沒有紀錄時顯示「還沒有催繳過。」**有紀錄時**一列一次（實測 `LINE / 已用 LINE 提醒一次 / 2026-08-29`）
- 底部：`列印收費單`、`列印收據`（**`receiptNo === null` 時 disabled**，實測到）、`關閉`

### 三件量測方法上的事（都害我差點寫錯地圖）

**1. 關閉對話框之後不要用固定等待去斷言 —— 要輪詢。**
實測 `.p-dialog` 從按下關閉到真的從 DOM 消失要 **1.8–2.0 秒**。我先用 700ms、再用 1200ms
去斷言，兩次都得到「還在」，於是先後懷疑「關閉鍵沒作用」與「✕ 也沒作用」——
**而畫面上它早就關了**。這是 [[specs/sitemap/README|方法頁]]第 1 坑（以為元件壞了）的新變種：
不是按兩次，是**問得太早**。做法：輪詢到消失為止（上限 6 秒），不要 `await sleep(n)` 之後只問一次。

**2. `computer` 工具的座標系不是 CSS 像素。** 本機 `innerWidth = 1504`，但 `computer`
的座標框是 **1568**（比例 1.0426）。直接把 `getBoundingClientRect()` 的中心點餵給
`left_click` 會**穩定地偏左**，落在隔壁元素或空隙上 —— 症狀是「按了完全沒反應」，
而它跟「這個按鈕壞了」長得一模一樣。**先乘 `1568 / innerWidth` 再點。**

**3. 對 `p-togglebutton` 的合成 `.click()` 會送出請求但畫面不跟著換。**
用 JS 依序點三個催繳篩選，network 確實送出了 `outstanding=true` / `dueWithin=7` /
`overdue=true` 三支請求，**但表格與選中狀態都停在「全部」**。真實滑鼠點下去才會整組換掉。
**「有送出請求」不等於「這個控制項被切換了」** —— 兩者都只驗到一半。
