## 畫面區塊

### 1. 橘帶

大標 `家長管理`、副標「管理家長帳號、關聯學生及帳號狀態」。
右側 `匯入` 與 `新增家長` 兩顆，以及**條件式**錨點 `N 位家長 ／ N 啟用中`

### 2. 篩選列

搜尋框 `搜尋姓名、Email、手機...` + 狀態下拉。

狀態下拉選項：`全部狀態`／`啟用`／`停用`／`封存`（**4 項，「全部狀態」是真的選項**
—— 跟 [[specs/sitemap/admin/students]] 的狀態下拉不同，那邊「全部狀態」只是佔位字）。

### 3. 家長表格

表頭：`姓名`｜`手機`｜`Email`｜`關聯學生`｜`狀態`｜（動作，無標題）

- 沒有手機／Email 時顯示 `—`
- `關聯學生`：`parent.studentCount > 0` 時列出姓名
- 列尾 `⋮` 開列動作選單

### 4. 分頁器

**實測資料 16 筆、單頁，所以分頁器不渲染** —— 它是條件式的，不是缺席。

## 驗證紀錄

- **狀態**：已驗
- **前端版本**：`650d257a`，自架 `:4210`（`:4200` 服的是主 checkout）
- **兩向比對**：可見互動元素 **20**（總 21，唯一不可見的是手機版 `page-actions__cta`）
  = 1（匯入）+ 1（新增家長）+ 1（搜尋）+ 1（狀態下拉）+ 16（每列一顆 `⋮`）。**0 差異。**
- **未驗，附原因**：
  - `inactive` / `archived` 兩種列的選單 —— 展示資料 16 位**全部 `active`**
    （`summary.inactiveCount === 0 && archivedCount === 0`）。
    **繫結存在但這輪量不到，是「未驗」不是「不會發生」。**
  - `產生登入連結` 與所有確認鍵 —— **會寫入，地圖驗證不做寫入**
  - 兩個空狀態、`・ 停用 M` 錨點片段
- **量測過程中犯的兩個錯，都被斷言抓到**：
  1. 探完「查看詳情」沒關掉就去探「匯入」，第二支讀回來的內容**一字不差** ——
     不是殘留，是 `querySelector('.p-dialog')` 只回**第一個**，而當時有**兩個**疊著。
     改成 `querySelectorAll` 逐個列舉才看清楚。
  2. 「沒有 X」的機制我判斷錯了兩次，**第二次錯在正控本身**。
     先以為是 `openDetailDialog` 漏傳 `closable: true`；接著拿
     `/admin/sessions` 的「查看異動紀錄」當正控，看到它 header 也空，
     就結論成「這個 app 從不渲染 header 的 `×`」。
     **而那支根本也沒傳 `closable`** —— `sessions.page.ts` 那三處 `closable: true`
     是給別支對話框的。**我拿兩個同類互相比較，它們當然一樣。**
     真正的機制由 #717 找出來：**沒帶 `closable` 就是 `undefined`，
     而 `DynamicDialogComponent` 一律把它綁給內層 `p-dialog`，蓋掉 `p-dialog` 自己的預設 `true`。**
     補做真的正控（`SessionAdvancedFiltersDialog`，確實有傳 `closable: true`）——
     **× 有渲染**。
     這是本 repo 記過的兩條同時命中：**「兩邊一樣」可能是比較分不出來**，
     以及**正控要挑真的具備待測屬性的那個位置**。
