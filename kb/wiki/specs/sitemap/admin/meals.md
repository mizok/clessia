## 這一頁有兩種模式，畫面差很多

工具列第一個元素是一組 `p-selectbutton`：**當日名單** ／ **區間查詢**。
**當日名單可編輯、區間查詢唯讀**，而且**兩種模式的欄位與工具列都不一樣**：

|            | 當日名單                                | 區間查詢                                  |
| ---------- | --------------------------------------- | ----------------------------------------- |
| 日期控制   | 單日 datepicker                         | 區間 datepicker（`readonlyInput`）        |
| 額外篩選   | 無                                      | 學生自動完成（`輸入學生姓名篩選`）        |
| 表格首欄   | —                                       | **多一欄「日期」**                        |
| 「班級」欄 | 有                                      | **沒有**                                  |
| 列上的輸入 | 可編輯（未結算的列）                    | **全部 disabled**                         |
| 表格分頁   | 無                                      | **有**（每頁 50 筆）                      |
| 底部       | 「共 N 位」+「確認名單」+ 人工判斷提示  | 無                                        |
| 摘要句     | `訂 N 份，其中 M 份要收費，合計 X 元。` | `這段期間 N 筆餐記錄…（含已結算的 K 筆）` |

> 摘要句**只在有資料時才出現**（`rows().length > 0`）。**空清單時改由空狀態自己寫出查詢區間**
> （#710 修正後）—— 那是畫面上唯一說明「剛才查了什麼」的地方。

## 畫面區塊

### 1. 頁首

`餐費管理` + 副標「每日勾選誰要訂餐，月底一次結算成帳單。有上課不一定訂餐 —— 課表只給候選名單。」
右側「月結」（`app-page-actions` 的 primary action）。

### 2. 工具列

模式切換 → 日期控制 → （當日模式且有列時）「全部訂」「全部不訂」／（區間模式）學生自動完成。

### 3. 摘要句

見上表。當日模式若有已結算的列，會多一段「（N 筆已結算，鎖住不能改）」。

### 4. 表格

欄位（當日模式）：`學生`、`班級`、`訂餐`、`單價`、`收費`、`備註`、`狀態`。

- `訂餐`：checkbox；**該列已結算就 disabled**
- `單價`：金額輸入（TWD 整數）；**沒訂餐或已結算就 disabled**，預設值是後端回的 `defaultUnitPrice`（本機 65）
- `收費`：checkbox；**沒訂餐或已結算就 disabled**
- `備註`：文字（`maxlength=200`，placeholder `如：素食`）；已結算就 disabled
- `狀態`：三選一
  | 條件                | 顯示     | 備註                                                                 |
  | ------------------- | -------- | -------------------------------------------------------------------- |
  | `settled`           | `已結算` | 帶 tooltip「已經開進帳單。要改得走帳單作廢或下期調整」               |
  | `recordId === null` | `未處理` | **樣式有時間維度**：當天以前是 `overdue`，當天（含）以後是 `pending` |
  | 其餘                | `已確認` | —                                                                    |

### 5. 底部（只有當日模式）

左邊固定提示「「收不收費」是人工判斷 —— 便當送到了才請假要不要收，由你決定，系統不自動判斷。」，
右邊「共 N 位」+「確認名單」。

超過後端一次寫入上限（`MEAL_BATCH_MAX_ROWS = 300`）時，「確認名單」變 disabled 並在下方
多一段紅字提示（**未驗** —— 本機當日最多 22 人）。

| 模式     | 請求                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 當日名單 | `GET /api/meals?date=YYYY-MM-DD`                                                      |
| 區間查詢 | `GET /api/meals?dateFrom=…&dateTo=…&page=1&pageSize=50`（有選學生才多帶 `studentId`） |

寫入只有兩個出口：`POST /api/meals/batch`（確認名單）與月結。

## 已知的落差（記錄現況，不在這裡修）

### 1. ~~區間查詢的空狀態講的是「這天」~~ —— 已修（#710）

> **2026-09-12 更新**：已修。保留原始描述是因為**它解釋了為什麼空狀態要把日期寫進去** ——
> 沒有這一段，下一個人會覺得那串日期是多餘的裝飾而把它拿掉。

**修正前**：切到「區間查詢」而區間內沒有任何餐記錄時，畫面顯示

```
這天沒有候選名單
候選名單來自當天有課的班級 —— 這天可能沒有排課
```

**兩句話都是當日模式的字**。實測當下查的是 `dateFrom=2026-09-01&dateTo=2026-09-12`
（API 回 200、`meta.total = 0`，**不是錯誤**）。而「這段期間 N 筆…」那句摘要
**只在有資料時才印**，所以那個畫面上**沒有任何東西告訴使用者剛才查的是哪一段期間**。

**修正後**：區間模式有自己的空狀態 ——
`這段期間沒有餐記錄` / `<起日> ~ <迄日> 沒有任何學生被登記過餐`。

#### ⚠️ 那串日期是「送出去的那一段」，不是選擇器現在顯示的那一段

元件新增了一個 `queriedRange` signal，**在 `load()` 裡跟送出去的參數用同一個物件**。

理由是 `onRangeChange` **先寫入 `dateRange` 才 early-return**（使用者只選了起日時），
所以那一刻選擇器已經變了、而畫面上的資料還是上一次查詢的結果。
**從 `dateRange` 即時算的話，空狀態會講一段從來沒有被查過的期間。**

有一支測試釘著這件事（「只選了起日（還沒送出）時，空狀態仍然講上一次實際查的區間」）。

### 2. 日期選擇器是英文

`September 2026` / `Su Mo Tu We Th Fr Sa` —— PrimeNG 的預設語系沒有換掉。
這不是這一頁的問題（每一支 `p-datepicker` 都一樣），記在這裡是因為它是這一頁量到的。
