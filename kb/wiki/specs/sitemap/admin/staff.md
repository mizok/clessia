## 畫面區塊

### 1. 頁首

`人員管理` + 副標「管理管理員、老師帳號」。右側「操作紀錄」與主要行動「新增人員」。

### 2. 工具列

搜尋框（`搜尋姓名或 Email...`）+ 四個可清除的下拉：

| 下拉     | 選項                           |
| -------- | ------------------------------ |
| 角色篩選 | `ROLE_OPTIONS`（管理員／老師） |
| 分校篩選 | 分校清單                       |
| 科目篩選 | 科目清單                       |
| 全部狀態 | `啟用中` / `已停用` / `已封存` |

### 3. 統計列（三格，有資料才出現）

`N 位人員`、`N 管理員 ・ N 老師`、`N 啟用中`。

> **管理員與老師刻意合成同一格**，而不是兩塊獨立的磚。模板註解說明理由：
> 一個人可以同時是管理員又是老師，兩邊各算一次，**加起來本來就會比總人數多** ——
> Tester 抓到 `13+89≠101` 讓人以為系統算錯。同一格再加一句「（N 位身兼兩者）」。
> **本機 `13 + 88 = 101`，兼任 0 人，所以那句話不出現**（條件式元素）。

### 4. 表格

`姓名`（頭像字 + 顯示名 + Email 兩行）、`角色`（chip，可多個）、`教學科目`、`服務分校`、
`電話`、`狀態`、每列 ⋮。每頁 20 筆。

- 頭像底色由 `getPersonHue(staff.id)` 決定；管理員多一個 `--admin` 樣式
- `教學科目`只在**該人是老師且有科目**時列出，超出的收成 `+N`（tooltip 是完整清單）；
  否則顯示 `—`
- 電話沒填顯示 `未填寫`，有填是 `tel:` 連結
- 狀態：`啟用中` / `已停用` / `已封存`

資料來源：`GET /api/staff`。

`PopupMenuComponent`。**項目依該人的 `status` 而異**：

| 項目         | 出現條件                | 行為                                                  |
| ------------ | ----------------------- | ----------------------------------------------------- |

> 看起來像複製貼上的錯，其實那個函式**自己依 `status` 分岔**（`inactive` → 走啟用那一支）。
> 讀原始碼時差一點記成缺陷，**進去看第二層才確定沒事**。

## 已知的落差（記錄現況，不在這裡修）

### ~~「授課紀錄」對話框沒有任何關閉控制項~~ —— 已修（#727）

> **2026-09-12 更新**：已修，底部補了一顆 `關閉`。
> 保留原始描述是因為**它解釋了為什麼那顆按鈕要放在所有資料分支外面** ——
> 沒有這一段，下一個人會覺得把它收進 `@if` 裡比較整齊。

**修正前**：`document.querySelector('.p-dialog').querySelectorAll('button').length === **0**` ——
**整個對話框一顆按鈕都沒有**（月份選擇器是 `p-select`）。PrimeNG 標頭的
`.p-dialog-header-actions` 是空的（`<!--container--><!--container-->`），**沒有 ✕**。

`dialogService.open(TeachingLogDialogComponent, …)` 沒有傳 `closable`，
模板底部也沒有「關閉」按鈕 —— 全站其他對話框都有 `取消` / `關閉` / 自畫的 ✕，**只有這一支沒有**。

#### 為什麼標頭的 ✕ 不渲染（機制，#714 查到的）

`DynamicDialogComponent` 一律把 `[closable]="ddconfig.closable"` 綁給內層 `p-dialog`，
而 `p-dialog` 的模板是 `*ngIf="closable"`、**自己的預設是 `true`**。
開啟設定**沒帶 `closable` 就是 `undefined`，把那個預設蓋掉** —— 所以沒帶的一律沒有 ✕。

（**注意**：這不蘊含「帶了 `closable: true` 也不會有 ✕」。那句話曾經被寫進 #714 的工單，
但依據的兩半證據都不成立，見該 issue 的更正留言。）

**還沒能證明的那一半**：`Escape` 與點遮罩本輪都關不掉它，**但這一輪真鍵盤/真滑鼠事件
整片送不進頁面**（`__keys` / `__hits` 全空，換新分頁重試也一樣，見
[[specs/sitemap/README|方法頁]]坑 6），所以那兩條路徑**不算驗過**。
合成的 `Escape`（三個目標都試過、監聽器確認收到）與合成的遮罩點擊都沒有反應。

**修法**：注入 `DynamicDialogRef` + 內容區補一顆 `關閉`（照 `parent-detail` / `invoice-detail`
的形狀），**不是去開 `closable`** —— 這個 app 其餘對話框都是內容區關閉鈕，
而動全域預設會碰到十幾個開啟點。

→ issue #727 已關。**「還沒能證明的那一半」（真實 Escape、真實點遮罩）仍然沒有驗過** ——
補了關閉鈕之後它的嚴重度降到「順手」，但如果有人手上有可用的真滑鼠／真鍵盤，
那兩條路徑值得補一次。
