## 已知的落差（記錄現況，不在這裡修）

**停課的課堂在今日課表上顯示為「未點名」，而且被算進「還沒點名」的數字。**

`GET /api/workbench/today` 實測回：

```
15:00 國小五年級英文班  eventId=NULL  takenAt=no  status=cancelled
17:00 國三國文 A 班     eventId=yes   takenAt=no  status=scheduled
```

畫面上兩列都顯示「未點名」，大標寫「今天 2 堂課，其中 2 堂還沒點名」，現況「今日課堂 2」。

模板的狀態點是 `session.takenAt ? '已點名' : '未點名'`，**沒有停課的分支**。而那一列同時是不可按的
（`canTakeAttendance` 為 false），所以它是一件「畫面說你還沒做、但你點不下去也永遠做不了」的事。

→ 已開 issue 給計畫席（見驗證紀錄）。**這一頁的地圖記的是現況，不是應該的樣子。**

### ⚠️ `read_page interactive` 在這一頁漏了 4 個互動元素

工單的驗證步驟寫「`read_page` 取 `interactive` 的無障礙樹」當作畫面的真相。**在這一頁它不完整**：

|                                                     | 數量   |
| --------------------------------------------------- | ------ |
| `read_page` filter=`interactive` 在 `<main>` 內回報 | **6**  |
| DOM 實際的互動元素                                  | **10** |

漏掉的四個：`在籍學生 69`（→ `/admin/students`）、`本月報名異動 12`（→ `/admin/enrollments`）、
可按的課表列（`<button>`）、以及 `前往管理` / `今日請假` 其中一個。
`find` 工具問「現況那四列是什麼」時，四列都正確回報成 link —— **同一個頁面，兩個工具兩個答案**。

**第三個坑（同一頁撞到的）**：「收合時間軸」收起來之後，那一區是
`height: 0 / opacity: 0` 的 `collapsible--collapsed`，**內容仍在 DOM、仍是
`visibility: visible`** —— 文字傾印與無障礙樹都還看得到它。所以
「畫面上有沒有這個元素」不能只問樹，**收合狀態下看起來存在的東西，使用者是看不到的**。

**而漏掉的樣子跟「本來就沒有」一模一樣** —— 如果只照工單的步驟做，這一頁的地圖會少 4 筆，
兩向比對還是「0 差異」，因為比對的兩邊都來自同一個瞎掉的來源。

→ 方法已改，見 [[specs/sitemap/README|方法頁]]的「元素清單以 DOM 為準」。
