## 畫面區塊

### 1. 橘帶

「管理學生基本資料、家長關聯與學習紀錄」。

右側：`新增學生` 主要動作，以及**條件式**錨點 ——

- 錨點**只在 `!loading() && students().length > 0`** 時出現

### 2. 篩選列

| 下拉 | 佔位字   | 選項                                                     |
| ---- | -------- | -------------------------------------------------------- |
| 年級 | 全部年級 | `全部年級`／小一…小六／國一…國三／高一…高三（**13 項**） |
| 狀態 | 全部狀態 | `啟用中`／`已停用`（**2 項**，「全部」是佔位字不是選項） |

搜尋走 `debounceTime(300)` + `distinctUntilChanged` + `switchMap`（#659／#661）。

### 3. 學生表格

表頭：`姓名`｜`年級`｜`學校`｜`關聯家長`｜`狀態`｜（動作，無標題）

- **姓名**格底下條件式顯示分校名（`student.campusNames.length > 0`）

- **狀態**：`在籍`（`done`）／`停用`（`inactive`）
- **列尾 `⋮`**：開列動作選單（見下）

### 列動作選單（`.popup-menu__panel`）

**不是 PrimeNG 選單** —— 專案自己的 `PopupMenuComponent`，項目是 `.popup-menu__item`，
沒有 `role="menuitem"`。

| 項目                     | 出現／狀態條件                          | 按了之後                                   |
| ------------------------ | --------------------------------------- | ------------------------------------------ |
| `學生詳情`               | 永遠                                    | 導向 `/admin/students/:id`                 |
| `編輯`                   | 永遠                                    | 開學生表單對話框（編輯模式，**無家長欄**） |
| `停用`                   | **只在 `student.isActive`**             | 開確認對話框                               |
| `刪除學生`               | `!student.hasEnrollments`               | 開確認對話框                               |
| `已有報名紀錄，無法刪除` | `student.hasEnrollments` → **disabled** | 不可按（`popup-menu__item--disabled`）     |

> **最後兩列是同一個項目**：`hasEnrollments` 同時換掉標籤與 `disabled`。
> **實測兩種列狀態都取到**（`傅千惠` 有報名 → disabled；`劉靖雯` 無報名 → 可按）。
>
> 這跟 `/admin/courses` 班級選單的「`已有歷史課堂，無法刪除`」是同一個 pattern ——
> **兩頁獨立出現，代表它是這個 repo 的慣例不是個案**（見 [[specs/sitemap/admin/courses]]）。

## 刻意記下

**`清除篩選` 不清狀態篩選。** 它逐字是 `onSearchChange(''); onGradeChange(null)` ——
狀態下拉留在原值。所以「已停用 + 找不到」的空狀態按了清除篩選之後**可能仍然是空的**。
記成現況，未開 issue（`specs/` 的規格沒講這一欄該不該清，**地圖不調和差異**）。
