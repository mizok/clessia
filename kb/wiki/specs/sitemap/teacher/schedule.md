## 畫面區塊

### 1. 橘帶（`app-page-band`）

- 眉標 `教學課務`（來自路由的 group）、大標 `課表`、副標 `2026年8月31日 – 9月6日`
- 右側：上一週 / 下一週 兩顆 icon 鍵
- **錨點數字依「誰負責點名」而異**：
  | 條件                                                                               | 錨點                                    |
  | ---------------------------------------------------------------------------------- | --------------------------------------- |
  | `isTeacherLed()`                                                                   | `N 堂待點名` + 小字 `本週 M 堂`（實測） |
  | 行政負責點名                                                                       | `N 堂課` + 小字 `本週`（**未驗**）      |
  | 註解：行政負責點名時老師**沒有點名入口**，把「待點名」當錨點是在問責他做不到的事。 |

### 2. 週條（`schedule-page__weekbar`）

一列七天，每天一顆按鈕：星期、`M/d`、以及「N 堂」的狀態點或 `—`（沒課）。
左右各一顆上一週／下一週。

> **桌機才顯示**（手機換日靠滑）。**載入中也保留**那兩顆導航鍵（`disabled`）——
> 註解：它們不依賴這週的資料，拿掉會讓骨架寬度跟真正的週條對不上。

### 3. 一日一屏的水平軌道

七個 `section`，每屏一天，靠原生 scroll-snap 換日（**沒有手勢 JS**）。
桌機與手機同構，只是卡片更寬。

每屏標題：`M/d` + 星期 +（有待辦時）一個**聯絡簿未寫的數字**
（`aria-label="N 位學生的聯絡簿還沒寫"`）。

### 4. 課堂卡片

一堂一張，由上而下：

- 時間 `HH:MM–HH:MM`
- 班級名
- 一排 chip：`停課`（`status === 'cancelled'`）、`代課`（`isSubstitute`）、
  `小考`（`examCount > 0`，多場時 `小考 ×N`）、校區名 —— 最後接 `N 人`
- 狀態點（見下）+ **已點名時**多一組 `到 N / 假 N / 缺 N`
- 0～2 顆動作鍵（見下）

資料來源：

| 東西       | 請求                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 課堂       | `GET /api/attendance/sessions?dateFrom=&dateTo=&statuses=scheduled,completed,cancelled` |
| 點名設定   | `GET /api/org/settings`                                                                 |
| 聯絡簿待辦 | `GET /api/contact-book/missing/summary?dateFrom=&dateTo=`                               |

### 狀態點的四種

| 條件                    | 顯示                                |
| ----------------------- | ----------------------------------- |
| `isRetroactiveLocked()` | `點名已截止`（inactive）            |
| 停課                    | `已停課`（實測）                    |
| 未點名且已過            | `漏點名`（實測）                    |
| 已點名                  | `已點名`（實測）+ 到/假/缺 三個數字 |

> 讀不到點名設定時「漏點名」會被降級成中性的「未點名」（`schedule.util.ts`），
> 並在頁面上多一行警語 —— 見「狀態」。

## 子頁面：點名面板

**開啟方式**：課堂卡片的「開始點名」／「修改點名」
→ [[specs/sitemap/_shared/attendance-roster-panel]]

**這個入口與管理端的差別**（本輪實測補上）：副標**只有日期**（`2026-08-31`），
**沒有時段** —— `schedule.page.ts:320` 建的 `RosterPanelSession` 只傳
`eventId / className / eventDate`，沒傳 `timeRange`，而面板的時段是條件式的。
管理端儀表板那個入口有傳，所以那邊看得到 `· HH:MM–HH:MM`。

## 子頁面：教務日誌

**開啟方式**：「寫日誌」

- 標頭：班級名 + 日期（實測 `英文班 B` / `2026-09-01`）
- 兩個 textarea：
  | 欄位     | 說明             |
  | -------- | ---------------- |
  | 教學紀錄 | 內部，家長看不到 |
  | 作業安排 | 家長會看到       |
- 結束動作：`取消`、**`存檔`（實測是 disabled）** —— 兩個欄位都空白時按不下去

> v1a **只有撰寫、沒有發布**（模板註解）：發布不可逆，而家長端讀取與 LINE 推播都還不存在。

## 子頁面：聯絡簿名單

**開啟方式**：「寫聯絡簿」

- 標頭：班級名 + `YYYY-MM-DD　聯絡簿`
- 一位學生一列，右側一顆「撰寫」
- 底部：`關閉`
- 實測 14 位學生（**與課堂卡片上的 `8 人` 不同** —— 卡片是該堂的
  `enrolledCount`，這裡是該班名單）

### ⚠️ 「撰寫」在老師端是壞的

按下去**畫面上什麼都沒發生**。DOM 裡多了一層空的 `.p-dialog`（0 顆按鈕），
主控台是 `NG0201: No provider found for _MessageService`。
→ **已開 issue #733**（未順手修）。根因與修法寫在那裡。

**所以「撰寫」開出來的表單本輪完全沒看到** —— 那一層的內容是未驗。
