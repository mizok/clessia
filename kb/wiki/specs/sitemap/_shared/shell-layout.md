# 外框（ShellLayout）

**元件**：`@shared/components/layout/shell-layout/shell-layout.component`

`/admin/**`、`/teacher/**`、`/parent/**` **全部走這一個外框**（`AGENTS.md` 的角色與授權架構）。
所以它**只寫這一頁**，53 個頁面各自的地圖只寫 `<main>` 裡面的東西。

> **Phase 1 的人請注意**：畫地圖時**不要把左側選單列進頁面的互動元素表** ——
> 那會在 53 份檔案裡複製同一份清單，而它一改就全錯（c11：手抄的清單必然腐化）。
> 頁面地圖只寫 `<main>` 內。

## 畫面區塊

### 1. 頂列

- 左側：`Clessia` 字標
- 右側：角色徽章（`管理員` / `老師` / `家長`）+ 頭像 + 使用者顯示名稱

### 2. 左側選單

第一層是不分組的項目，接著是可展開的群組。**群組數依角色而異**：

| 角色    | 不分組項目       | 群組                                                              |
| ------- | ---------------- | ----------------------------------------------------------------- |
| admin   | 儀表板、通知中心 | 課務管理、學務管理、考務與成績、行政財務、人事管理、系統設定（6） |
| parent  | 儀表板、通知中心 | 學習狀況、行政服務、生活與繳費（3）                               |
| teacher | **未驗**         | 教學課務（1，依 `NavigationGroup`）                               |

選單項目由 `RoutesCatalog` 的 `showInMenu` / `group` / `permission` 決定
（`NavigationService` 會把沒有權限的項目藏起來）。**各路由的值見每一頁地圖的生成區塊。**

## 互動元素

| 元素              | 類型           | 出現條件                                                      | 按了之後         |
| ----------------- | -------------- | ------------------------------------------------------------- | ---------------- |
| 選單項目          | 連結           | `showInMenu === true` 且（若有 `permission`）使用者具備該權限 | 導向該路由       |
| 群組標題          | 按鈕（可展開） | 該群組底下至少有一個可見項目                                  | 展開／收合該群組 |
| 角色徽章          | **未驗**       | —                                                             | —                |
| 頭像 / 使用者名稱 | **未驗**       | —                                                             | —                |

## ⚠️ 收合的群組，它的連結仍然在 DOM 裡

admin 的六個群組在畫面上是收合的（只看得到群組標題），
**但 `read_page` 與 DOM 查詢都會列出底下全部 18 條連結**。

也就是說：**「樹裡有這個連結」不等於「使用者現在看得到它」。**
這是「畫面 ⊆ 地圖」那個方向最容易被灌水的地方 —— 所以頁面地圖不收選單，
而外框這一頁明講這件事。

## 390px

- **量測**：390 × 844 ／ 前端 `3f2197f8`（主 checkout 的 dev server，port 4200）／
  身分 `admin@demo.clessia.app`（量測前後各打一次 `GET /api/me`，兩次都是 `roles:["admin"]`）
- **手段**：同源 iframe 當 viewport（`resize_window` 在這台機器上是空操作，見方法頁 Phase 2 一節）
- 另有 `teacher0003@demo.clessia.app` 的對照量測，見下。

### 版面怎麼變：不是抽屜，是底欄

**唯一的切換點是 `respond-from('mobile')`（`min-width: 640.02px`）**，
而且**側欄與底欄是同一個切換點的兩半**：

| 元件             | ≤ 640px                           | ≥ 640.02px             |
| ---------------- | --------------------------------- | ---------------------- |
| `app-sidebar`    | `display: none`（量到 `0 × 724`） | `240 × 視窗高`         |
| `app-bottom-bar` | `390 × 64` 固定底欄               | `display: none`        |
| `.shell-header`  | `390 × 56`，內距 `--space-3`      | 同高，內距 `--space-6` |

（`sidebar.component.scss` 與 `bottom-bar.component.scss` 各有一個 `respond-from('mobile')`，
註解互相指名對方是同一個切換點。**沒有漢堡鍵，沒有抽屜。**）

**沒有任何一個尺寸在這裡對半切** —— 這是「同一個導覽的兩種實作」，不是「桌機版壓扁」。

### 差集（1504 ↔ 390）

| 只在 390 可見                                         | 只在 1504 可見                             |
| ----------------------------------------------------- | ------------------------------------------ |
| `app-bottom-bar` 的 5 顆 tab（各 `78 × 63`）          | `app-sidebar`：2 條可見連結 + 6 個群組標題 |
| 底欄的**「更多」面板**（`.bottom-bar__sheet`，14 條） | —                                          |

**兩邊都有但形狀不同：導覽本身。**

| 路由                                | 1504                   | 390                |
| ----------------------------------- | ---------------------- | ------------------ |
| `/admin/dashboard`、通知中心        | 側欄第一層             | 底欄前兩顆         |
| `/admin/courses`、`/admin/sessions` | 側欄「課務管理」群組內 | 底欄第三、四顆     |
| 其餘 14 條                          | 側欄五個群組內         | **「更多」面板內** |

底欄的切法在 `bottom-bar.component.ts`：
`navItems.length > 4 ? items.slice(0, 4) : items`，多出來的收進「更多」。
**所以前四顆是 `RoutesCatalog` 的順序決定的，不是挑出來的**。
實測 teacher（3 項）就是 3 顆、**沒有「更多」**。

「更多」面板的 14 條（各 `84 × 73`）：課務異動、學生管理、家長管理、報名進出、
學生請假管理、聯絡簿、考試管理、成績總覽、費用方案管理、餐費管理、繳費紀錄、
營收報表、人員管理、系統設定。

### 水平溢出

**無。** `documentElement.scrollWidth === innerWidth === 390`，撐出界的元素 0 個。
768 / 1024 / 1504 亦同。

### 觸控目標 < 44px

| 元素                                 | 量到                    | `(pointer: coarse)` 有沒有接住                                    |
| ------------------------------------ | ----------------------- | ----------------------------------------------------------------- |
| `.bottom-bar__tab` × 5               | `78 × 63`               | —（本來就夠）                                                     |
| `.shell-header__user`                | `136 × 42`              | **有** —— `shell-layout.component.scss` 的 coarse 區塊把它抬到 44 |
| `.sidebar__item` × 18（≥640 才出現） | `223 × 34` / `211 × 34` | **沒有** —— 平板用手指點時仍然是 34px                             |
| `.sidebar__group-header` × 6（≥640） | `223 × 33`              | **有** —— `sidebar.component.scss` 抬到 44                        |

> `.sidebar__item` 是**唯一一個在可觸控寬度下看得到、而沒有任何 coarse 規則接住**的外框元素。
> 側欄只在 ≥ 640px 出現，所以它實際影響的是**平板**，不是手機。
> **記現況，不在這裡判定是不是缺陷。**

### 鍵盤可達性

- **全頁沒有正數 `tabindex`**（390 / 768 / 1024 / 1504 都查過）→ Tab 序列 = DOM 序。
- **焦點看得見**：`outline: auto 1px rgb(0, 95, 204)`（瀏覽器預設環，專案沒有自訂），
  `:focus-visible` 命中。
- **Tab 序列（外框部分）**：

  | 寬度              | 可 Tab 到的外框元素                                        |
  | ----------------- | ---------------------------------------------------------- |
  | 390               | 儀表板 → 通知中心 → 課程管理 → 課堂管理 → **更多**（5 個） |
  | 768 / 1024 / 1504 | 儀表板 → 通知中心（**2 個**）                              |

- ⚠️ **`<div>` 帶 `(click)` 而沒有 `tabindex`，鍵盤到不了**：

  | 元素                         | 後果                                                      |
  | ---------------------------- | --------------------------------------------------------- |
  | `.sidebar__group-header` × 6 | 六個群組只能用滑鼠展開 → 側欄 18 條裡 **16 條鍵盤到不了** |
  | `.shell-header__user`        | 帳號設定與登出只能用滑鼠（各寬度皆然）                    |

  **所以桌機的外框鍵盤可達 2 條路由，手機的外框鍵盤可達 5 條** —— 方向跟直覺相反。

### 768 / 1024 的差集

**與 1504 零差異**（元素集合、可見性、尺寸全部相同）。變的只有兩處內距：
`.shell-header` 的 `--space-3 → --space-6`、`.shell-header__user-name` 的
`max-width: 100px → none`，兩者都在 `respond-from('mobile')`，所以**在 768 已經是桌機的樣子**。
