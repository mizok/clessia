# 科目管理（共用元件）

**元件**：`@shared/components/subject-manager/subject-manager.component`

## 使用點（3 個）

| 使用點                                     | 形態                            | 路由渲得到嗎                       |
| ------------------------------------------ | ------------------------------- | ---------------------------------- |
| [[specs/sitemap/admin/settings-subjects]]  | **內嵌**（`isDialog = false`）  | ✓ `/admin/settings/subjects`       |
| [[specs/sitemap/admin/staff]] 的人員表單   | **對話框**（`isDialog = true`） | ✓ 表單裡的「管理科目」按鈕（實測） |
| [[specs/sitemap/admin/courses]] 的課程表單 | **對話框**                      | ✓（**本席未實地開過**）            |

> 依 [[specs/sitemap/README|方法頁]]的「≥ 2 個開啟點就獨立」抽出來。
> 三個使用點都確認過那條路由是 `loadComponent` 而不是 `redirectTo`（#709 的教訓）。

**`isDialog` 是唯一的差別**：為真時多畫一個 `dialog-header-inline` 標頭（`科目管理` + ✕），
底下的內容一模一樣。

## 畫面區塊

一列一個科目，每列：

- **科目名稱**
- **常駐的使用中提示**（有被引用才出現）：`已被23 個課程、2 場校內考使用中，無法刪除`
  - 組法：`courseCount > 0` → `N 個課程`；`academyExamCount > 0` → `N 場校內考`；用 `、` 串
  - 元件註解：**常駐文字不是只靠 tooltip —— hover 在觸控裝置上摸不到**
- ✏️ 改名、🗑 刪除

清單底下一條分隔線，再一列「新增」：文字輸入（`新增科目名稱`）+「新增」按鈕。

資料來源：`GET /api/subjects`。

## 互動元素

| 元素            | 類型      | 出現條件           | 按了之後                                                           |
| --------------- | --------- | ------------------ | ------------------------------------------------------------------ |
| ✏️（改名）      | icon 按鈕 | 每一列             | **該列就地換成編輯模式**（見下），不開對話框                       |
| 🗑（刪除）       | icon 按鈕 | 每一列             | 開 [[specs/sitemap/_shared/confirm-dialog]]（標頭 `確認刪除科目`） |
| 新增科目名稱    | 文字輸入  | 永遠               | 打字；Enter 也可送出（`onNewNameKeydown`）                         |
| 新增            | 按鈕      | 永遠               | 新增科目（**寫入**）                                               |
| ✕（對話框標頭） | 按鈕      | **只在對話框形態** | 關閉                                                               |

**`[disabled]` 一共三處，全部實測到：**

| 元素       | disabled 條件                         | 實測                                          |
| ---------- | ------------------------------------- | --------------------------------------------- |
| 🗑          | `deleteBlockReason(subject) !== null` | **8 個科目全部 disabled**（每個都被課程引用） |
| 新增       | `!newSubjectName().trim()`            | 輸入框空白時 disabled                         |
| 全部控制項 | `saving()`                            | **未驗**（要真的送出）                        |

> 🗑 的 tooltip 就是那句擋住的理由（沒被擋時是 `刪除`）。

### 行內編輯模式（實測）

按 ✏️ 之後**那一列**變成：文字輸入（值 = 原名）+ ✓（確認，success）+ ✕（取消）。
按 ✕ 回到顯示模式、名稱不變。Enter / Escape 也接（`onEditNameKeydown`，**未驗**）。

**這一列在編輯模式下不再有 🗑** —— 清點元素時每列的按鈕數會從 2 變 2（✓ 與 ✕），
但**意義不同**，別把它讀成「刪除鍵消失了」。

## 390px


> ⚠️ **2026-09-13 訂正：上面的對話框尺寸是在 ResizeObserver 失效的環境下量的。**
> `--shell-layout-body-height` 靠 `InheritSizeDirective` 的 ResizeObserver 寫入，
> 而**它在 MCP 的背景分頁 iframe 裡不觸發** —— 於是 `styles.scss:721-722` 的
> `max-height: calc(var(--shell-layout-body-height) - …)` 的 `calc()` 無效，
> **computed 值是 `none`，對話框不受限**。
>
> **真實瀏覽器裡對話框會被限制在 `shell body 高 − 24px`（本輪環境是 `700px`），
> 超出的部分由 `.p-dialog-content` 捲動。** 上面的高度數字要照這個重新讀：
> **矮於 700 的那些是真的，高於 700 的只會出現在這個量測環境裡。**
> 全文與正控見[方法頁](../README.md)的「ResizeObserver 在這個環境完全不觸發」。
