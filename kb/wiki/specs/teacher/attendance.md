# 點名

**路徑**: `/teacher/schedule`（課表點進課堂即點名）

> 漂移修正 2026-08-19：`/teacher/attendance` 的頁面與路由已於 2026-08 刪除 ——
> 它是選單上叫「點名」但內容是 coming soon 的空殼，而真正的點名早就在課表。
> 見 [[architecture/teacher-students-view]]。
>
> **漂移修正 2026-08-30：出勤狀態機與「僅限當天」兩處都是錯的**，見下。
> 錯誤的狀態機已經擴散過一次（P1 A2 的工單也寫「present/late」），這一頁就是源頭。

**角色**: Teacher

## 核心目的

查看和修改課堂的出勤狀態（可修改的範圍見「補登窗」）。

## MVP 功能

### 今日課堂列表

- 顯示今天自己任課的所有課堂
- 每筆顯示：時間、開課班名稱、出勤摘要

### 學生名單與出勤狀態

- 展開課堂後顯示學生列表
- 每位學生顯示：姓名、目前出勤狀態

### 修改出勤

- 每位學生兩顆 toggle：**出席 / 缺席**（選中態有 `aria-pressed`）
- **預設零預選** —— 沒有紀錄的學生不預先標成任何狀態。
  一度預設成 `absent`（而「缺席」是實心選中態），老師點開面板全班看起來已被標缺席，
  直接存檔就是全班記缺席（#138 修）
- **標了一部分不准存** —— 後端第一次批次就蓋「已點名」，半途存下去會讓沒標到的人
  永遠沒有紀錄、也不再出現在漏點名清單（#169 帶進共用面板）
- 可修改的範圍是**補登窗**（見下），不是「僅限當天」

### 請假的學生（#153 / #177 / #185 之後）

- 紀錄上就是 `on_leave` 的那一列**鎖住**，顯示「請假」chip
- **只有請假單、紀錄還沒套用**的那種**不鎖** —— 那是後端「請假連動寫不到後生成的 event」
  造成的縫，老師仍該能標記。鎖的條件只有 `status === 'on_leave'`，不含推導值
- 請假的學生今天出現了 → **「他來了」一鍵銷假**並回到可標記狀態。
  **只有當天的課可以銷**（銷假的依據是「他人就在我面前」），管理員不受限
- 跨日的假在按下去**之前**就先講「銷假將一併取消到 X 的請假」。**會不會連坐由後端算**
  （`cancelDropsLeaveUntil`，#265）—— 逐張假跑 `lib/cancel-leave-for-date.ts`，
  跟銷假動作**共用同一份實作**，所以不會「預覽說會、按下去卻不會」。不連坐就什麼都不顯示
- **前端不做任何推導。** 曾經有兩版是前端自己推：先用 `leaveEndDate`（過度警告），
  再加 `leaveStartDate` 判斷（拿掉「今天才開始」那一類假警告，但仍分不出「一張長假」
  與「兩張接力」，文案因此只能說「可能」）。兩版都是在猜後端會做什麼 ——
  **猜對了也還是猜**，欄位一到就整段換掉
- 附帶一提：**兩張假接力其實造不出來** —— `POST /api/leaves` 的重疊檢查是日期層級的，
  共用一天就 409，而全 repo 只有那一支會 insert。但這個不變量沒有 DB 約束也沒有測試守，
  所以 UI 不建立在它上面
- 已請假卻被標成缺席 → 亮旗標「這位學生已請假，不需點名」（那是誤操作，不是資料矛盾）

> **狀態只有三種。** `attendance_status` enum 是
> `('present', 'absent', 'on_leave')`（`20260330000003_create_attendance_records.sql:4`）——
> ~~遲到~~ **從來不存在**。原版 spec 寫的四段式狀態機是虛構的，而它已經擴散過一次：
> P1 A2 的工單照抄成「扣堂 = attendance present/late」，實作時才被查出來。

### 補登窗（不是「僅限當天」）

可修改的範圍由 `organizations.attendance_retroactive_days` 決定。

**`0` 代表無限制，不是「只有當天」**（欄位的 `COMMENT` 就是這樣寫的，
`20260401000001_attendance_operations.sql:21`）。而且現行的前端規則還有第二個條件：
**只有 `attendance_responsible = 'teacher'` 的機構才鎖**
（`teacher/schedule.page.ts:122-127`）—— 行政負責點名的機構，老師本來就不該被這個窗擋。

設計意圖是「昨天忘記點的今天要追得到，更久以前的漏點名是報表該查的異常」。

**2026-08-30 裁決：這個窗由伺服器強制。** 在此之前它只在前端讀
（`teacher/schedule.page.ts`），老師直接打 API 可以改任何日期的出勤 —— 前端隱藏不構成
限制，跟 c1 的道理一樣。

### 快速標記

- **全部出席**：一鍵把所有非請假學生標成出席。最常見的情況是全班都到，
  而逐一點過去是 N 次點擊 —— 沒有這顆，最常見的情況剛好是最貴的操作
  （8 人班從 12 步降到 3 步）
- **請假的人不受它影響** —— 一鍵到課不該覆蓋掉行政登記的請假
