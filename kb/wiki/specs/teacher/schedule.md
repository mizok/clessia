# 課表（我的課表）

**路徑**: `/teacher/schedule`
**角色**: Teacher

## 核心目的

查看自己任課的課堂，進入課堂詳情。

## MVP 功能

### 視圖設計（2026-09-03 起）

**手機與桌機同構：週條（灰帶）＋單日清單。**（#1314 TS-A，2026-10-14 對齊 A6 `t-schedule.html`）

- **週條**：hero 正下方的**滿版灰帶**（`bg-zinc-100`），所有寬度都在、手機可橫捲。每天＝星期（今天尾巴加「· 今天」）／M/d／狀態點＋堂數；**選中日＝底線**（不是方框）；換週鈕（白底框方鈕，手機 44px、桌機 40px）在灰帶兩側，**橘面裡不再有換週鈕**。週區間文字在灰帶右上小字。查詢失敗整條灰帶不畫；載入中畫骨架。
- **日標題**：「10/14（三） 今天」22px（桌機 28px）粗體，星期只寫單字，底下一條細線；右側「N 則聯絡簿未寫」（0 則不印）。
- **課堂列**（#1314 TS-B，A6 `.card`）：無外框的分段列（`border-b`），只有「接下來那堂」是 1.5px 黑框。左＝時間 xl 粗＋狀態字（「上課中 · 還有 N 分下課」「還有 N 分開始」「已上完」「已停課」，別天只說「還沒開始」／「已上完」）、班名、chip＋分校＋「N 位學生」底線連結（連 `/teacher/students`）、點名狀態點與到／假／缺；右欄＝動作鈕（桌機直排、手機橫排全寬，皆 ≥44px 高）。主要動作「開始點名」亮橘底＋深字，其餘白底框。動作的出現條件（老師／行政負責、補登窗、停課、日誌／聯絡簿二選一）沒變。停課列時間與班名畫刪除線。
- **時鐘**：這頁的「今天」與「現在」來自 `SystemClockService`（跟伺服器對過），轉成台北牆上時鐘（`taipeiWallClock`）再餵給所有本地欄位判斷；不依賴瀏覽器時區。spec 的假現在是 2027-03-05 12:00 台北，刻意不同於真實日期。
- **稿有、本版沒做**：每堂「聯絡簿還差 N 則」（API 只有整天的數字）、「第四次小考成績未登錄」（稿標新、成績 API 尚無）。

### ~~月曆區塊~~ —— 不做

月曆回答的是「規劃」的問題（這個月哪幾天有課），而課表這一頁回答的是「執行」
（現在這堂課、這些人）。今日流刻意不含它，見 [[architecture/teacher-today-flow]] 的
「明確不做」。真的需要月檢視時另開，不要塞進今日流。

### 課堂列表區塊

- 一屏一天，**日期標題在每一屏裡面**（所以不需要追蹤捲動位置）
- 每筆課堂顯示：時間、開課班名稱、標記、狀態點

### 課堂卡片標記

- **待處理標記（●）**：暖銅橘色小圓點
  - 觸發條件：過去課堂尚未填寫聯絡簿，或有關聯考試但成績尚未登錄
- **[有小考]**：該課堂有關聯考試
- **[代課]**：自己代課（非原任課老師）
- **課務異動標記**：調課/停課等

### 圖例說明

- ● 待處理：聯絡簿未填或成績未登錄（聯絡簿那半用 `GET /api/contact-book/missing`）
- [有小考] 該課堂有安排考試
- [代課] 代課課堂
- 灰底 = 已停課

### 教務日誌（v1a，2026-09-05）

課堂卡上的「寫日誌」開同樣形狀的 bottom sheet。**一班一天一篇**
（`class_logs` 的鍵不含時段），所以同一班同一天兩場課會開到同一篇。

- **入口只在日誌模式的班**：`usesContactBook = false`。聯絡簿模式的撰寫端
  **刻意不做**（v1c），不是遺漏
- **判準不含 `eventId`** —— 日誌掛班×日期，不掛出勤事件，所以停課以外一律可寫，
  包含未來的課（規則明說老師會先寫作業、下課後再補教學紀錄）
- **開啟時預載既有內容** —— 這是資料遺失的防線，不是便利功能：`PUT` 是 upsert，
  第二場課的老師若看到空白表單，存檔就會蓋掉第一場寫的
- **兩欄的可見性標在欄位名旁邊**（教學紀錄內部／作業家長會看到）——
  寫錯欄位的代價是內部溝通外洩，而那是寫入當下就決定的後果
- **發布（v1b）**：按鈕**只在有既有日誌且至少一欄有內容時出現**，已發布後不再出現 ——
  不是灰的（灰著的按鈕仍然在承諾功能存在）。二次確認說死「家長就會看到作業安排、收不回」，
  **不提 LINE 推播**（P4，repo 至今沒有實作）。**先存再發**，否則發出去的是編輯前的版本

設計與 v1a/v1b/v1c 邊界見 [[architecture/teacher-class-log]]。

### 聯絡簿名單（v1c，2026-09-05）

聯絡簿模式的班（`usesContactBook = true`）在同一個位置開的是**學生名單**，
不是日誌表單 —— **兩型是兩條資料模型**（`studentId+entryDate` 一則自由文字
vs `classId+logDate` 兩欄），刻意不做成一支元件的 if/else。

- 只列**還沒寫的**：`GET /api/contact-book/missing?date=`（已對老師收斂）。
  「列出全班」需要 `GET /api/contact-book` 加 `classId` 篩選，尚無
- **點開之前先查一次那位學生當天有沒有已經被寫過** —— `/missing` 在載入那一刻是準的
  但會過期，直接用空白 draft 開會讓老師蓋掉別人剛寫的、而兩邊都不會知道
- 撰寫用的是 `shared/components/contact-book-entry-dialog`（原本住 admin，
  v1c 提進 shared —— feature 之間不得互相 import，c5）

設計見 [[rules/contact-book-rules]]。

### 依分校出勤模式分流（#1314 TS3，計畫席 2026-10-22 批准）

A6 `t-schedule.html`：**每一堂依它所在分校的出勤模式**決定卡片長相與入口。
模式判準一律走 `apps/api/src/lib/attendance-mode.ts`（分校 `campuses.attendance_mode`，
null 沿用機構預設）；**前端不自己推** —— 老師打不到 `GET /api/campuses`（ADMIN_ONLY），
而且自己推等於多一份判準。

**現況的錯**：入口只看「誰負責點名」（`isTeacherLed()`），日到班的分校老師也看得到「開始點名」，
而日到班的出席是掃碼推算的（rules/attendance-rules 1.1），老師逐堂點名會跟掃碼互相蓋。

| 模式   | 卡片狀態句                                                   | 動作鈕                                                   | 開出來的         |
| ------ | ------------------------------------------------------------ | -------------------------------------------------------- | ---------------- |
| 日到班 | 「日到班 · 掃碼 到 a／n」；今天的課加「· 還沒到 x · 請假 y」 | 「到班名單」（上課中＝亮橘主鈕，其餘白框；未來的課不給） | 到班名單 sheet   |
| 隨堂   | 維持現況（已點名＋到／假／缺、點名已截止、漏點名還來得及補） | 維持現況（開始點名／修改點名／補點名／看名單）           | 現有共用點名面板 |

**橘帶統計**「N 堂待點名」→ 改「N 堂待點名（隨堂）」：日到班的課不計入（`weekAnchor`、`daySummary`
的「漏點名」tone 同理排除，日到班的課沒有「該點沒點」這回事）。

**到班名單 sheet**（新元件，住 `features/teacher/pages/schedule/arrival-roster-sheet/`，跟
class-log-sheet 同形狀的 bottom sheet；**不塞進共用點名面板做 if/else** —— 兩型是兩條資料：掃碼紀錄 vs 逐堂紀錄）：

- 標題「到班名單」，副行「10/1 17:40 班名 · 分校 · 日到班：掃碼就算今天的課都到了」
- 摘要「到 a／n · 請假 y」；每列＝學生名＋小字「16:12 掃碼到」／「還沒到」（今天）／「沒有到班紀錄」（過去）／「請假」
- 今天的課，「還沒到」的列有「他到了」（見後端 ③）；按下去列變「17:40 到班（老師標記）」
- **到班來源**（#1100 #52）：小字照 `daily_checkins.source` 寫 —— `scan`＝「16:12 掃碼到」、`manual`＝「16:20 到班（人工標記）」（行政在儀表板標的也是這種）、這次自己按的＝「到班（老師標記）」、`NULL`（欄位出現之前的舊紀錄，不 backfill）＝只寫時間，不猜。來源由伺服器決定、不信前端：機台一律 scan、老師名單「他到了」一律 manual、行政 `POST /daily-checkins` 照 `source` 參數（掃碼站帶 scan；沒帶當 manual）。「他到了」時剛好已有人打過卡，照回應的 `checkInSource` 寫那一筆的來源。

**後端（保留類：授權＋寫出勤，開 PR 前報計畫席讀 diff）**

1. `GET /api/attendance/sessions` 每列加 `attendanceMode`，以及日到班列的 `checkedInCount`（在籍學生中當天有
   `daily_checkins` 的人數）。模式用 `attendance-mode.ts` 新增的批次版（同一支 `pickAttendanceMode`，一次撈本頁
   出現的分校）。**到班數不用 `presentCount` 代**：掃碼只替「當下已存在的 event」寫紀錄，event 是列表時才補建，
   兩者會分岔；卡片與名單要讀同一個來源（`daily_checkins`）。
2. `GET /api/attendance/roster/{eventId}` 加 `attendanceMode` 與每位學生的 `checkedInAt`（nullable）。
   授權沿用 `teacherCanReadEvent`（老師只看自己任課／代課的課堂）；**順手補分校範圍**（現在只有 org＋老師檢查，
   受限分校的管理員可讀範圍外課堂的名單 —— 同 #1800 那一族）。
3. 「他到了」：`POST /api/attendance/roster/{eventId}/check-in` `{ studentId }`。限制：老師須任課／代課該堂、
   **限當天**（台北日期）、學生須在該堂在籍、該堂分校是日到班；寫入**共用 `POST /api/daily-checkins` 的同一段邏輯**
   （抽成 lib，不寫第二份），`checked_in_by` = 老師。`/api/daily-checkins` 的掛載角色不動（老師不開放打整支）。

**裁定（計畫席 10-22，三題都採預設）**

1. 「他到了」要不要跟「誰負責點名」走：預設**要** —— 行政負責時老師只看名單、不給「他到了」
   （日到班的掃碼會寫 `attendance_records`，等同出勤寫入，rules 第 3 節）。
2. 分校範圍補在 roster GET：預設**一起做**（同支 PR，範圍外回 404）。
3. 日到班的課沒有「修改點名」：例外修正（掃了卡卻其實沒上某堂）留給管理端，老師端不給。

### 點名面板（手機是 bottom sheet）

點課堂卡上的「開始點名」開啟。**手機從下方升起、桌機置中** ——
老師站著單手用，置中會把「儲存點名」推到拇指構不到的地方（實測距螢幕底 143px → 33px）。

**沒有內嵌進課堂卡**：那會把已收斂的共用面板（admin 出勤頁也在用）再拆開，
而且垂直捲動的名單塞進水平 snap 軌道在觸控上難調。見 [[architecture/teacher-today-flow]]。

原版寫的「課堂詳情 Popup」內容如下，**多數尚未實作**：

- 基本資訊（開課班、日期時間、分校）
- 學生名單與出勤狀態
- 修改出勤（僅當天）
- 編輯聯絡簿按鈕 → 開啟聯絡簿編輯 Popup
- 查看/建立小考
