## 1. 表單內容（照 A6）

兩頁共用同一套版面（A6 `.pf`），掛在既有的 `PublicShellComponent` 右面；手機 ≤1024px 是 A6 的兩面切換（`.ps`，左面品牌、右面表單，`#form` 直接落在右面）。

| 想報名的開課班 | checkbox 多選    | ✔    | 「至少選一個開課班」。每列：班名、學費、週X 起訖、剩 N 位；**額滿的照樣可勾，寫「已額滿 · 勾選即登記候補」**（API 回 `waitlistClassIds`） |

**A6 的班級列有老師名，目錄 API 刻意不回老師**（計畫席先前裁示，`CatalogClassSchema`）—— 照 API，不顯示老師。這是唯一一處不照稿，理由是對陌生人公開員工姓名。

### 送出

- **送出鈕不停用**（A6 notes:95）。按下去：逐欄標紅、按鈕旁寫「還沒填好：…」並抖一下、捲到第一個錯的欄位並 focus；之後每次輸入即時重驗。
- 送出中：按鈕換「送出中…」＋12px spinner（A6 處理中樣式，同 `app-reload-veil`）。
- **成功**：換成結果畫面（不是另一頁，資料還在記憶體裡）。
  - 試聽：「試聽申請已送出」、摘要、「接下來」三步、`tel:` 電話與營業時間、「再幫另一個孩子申請」（保留家長、清掉孩子和課程）、「已經是我們的家長？用 LINE 登入」。
  - 報名：「申請已送出」；全部額滿時改「已登記候補」，部分額滿加一句「其中 X 已額滿，已為您登記候補」；四步（審核 → 繳費單 → 付款確認 → 一次性登入連結＋LINE 綁定）。
- **失敗**（A6 只畫了速率限制，其餘照同一個位置與語氣補）：`role=alert`，**填的資料都留著**。
  - 429：「送出太多次了，請 {N} 分鐘後再試，或直接打 {電話}。你填的資料都還在。」—— **N 讀 HTTP header `Retry-After`（秒）換算、無條件進位**（API 只放 header，body 沒有秒數：`trial-applications.ts:78`、`enrollment-applications.ts:92`）；讀不到 header 時不寫分鐘數，只寫「請稍後再試」，不照稿寫死 10 分鐘（實際限制是每小時 5 次、同聯絡方式每天 3 次，寫死會說謊）。
  - 400（驗證）：照欄位標紅；前端驗證和 API 同一套規則，正常不會走到。
  - 404 `PUBLIC_DISABLED`：整頁換成「這個補習班目前沒有開放線上申請，請直接來電」—— 自架的部署可以不開公開頁（c12）。
  - 網路／500：「沒送出去，請再試一次」＋重試，資料留著。

## 2. 家長登入後看得到公開申請嗎？—— **看不到**，維持現狀

- 公開申請**不建家長、學生、帳號**（[[rules/enrollment-rules]]：家長與學生在首次收款時才建），所以送出時沒有任何東西可以把它掛到一個家長帳號上。
- 行政在 `/admin/applications` 處理，「建立家長」開預填表單、不自動轉檔（同規則）。轉入之後，家長登入看到的是正式的報名／試聽紀錄，不是原本那張公開申請。
- A6 也這樣畫：公開頁 notes 寫明「沒有申請紀錄可以追」（`D/pub-trial.html:90`、`D/pub-enrollment.html:102`），家長端 `p-trial`／`p-enrollment` 的紀錄都是家長端自己送的。
- **兩邊的差別刻意保留**：家長端是單選班、開始日期必填、可取消；公開端是多選、開始日期選填、不能取消（沒有身分可以驗證是本人）。

## 3. 多分校

A6 公開稿**沒有分校選擇**（單一分校的假設）。系統是一個組織多個分校，目錄每一班有 `campusName`。

提案：**不加分校這一步，改在選項上標分校** —— 只有一個分校時什麼都不顯示（跟稿一樣），多於一個時：

- 報名：每一列開課班的時間後面加「· {分校名}」；分組維持依科目。
- 試聽：課程的簡介列出有開這門課的分校（「XX 校、YY 校」）。試聽申請只記到課程，**由行政打電話時約分校和班**（試聽流程本來就是 pending → scheduled，見 [[flows/trial]]）。

拒絕的替代方案：「先選分校再列課」—— 多一步，而大部分家長是看住家附近那一校，課程列表上直接看得到；也省掉一個「選錯分校之後課程清單整份換掉」的狀態。

**外洩面**：公開目錄只回開課中、未結束的班（`is_active` 且未過 `end_date`），欄位是班名、年級、課程名與簡介、科目、分校名、時段、名額、預設學費；不含老師、學生、內部備註。**沒有「這一班要不要公開」的旗標** —— 開課中的班就是可以報名的班。若要隱藏某些班（例如內部包班）是另一張單，見 Q5。

## 4. 缺口

### 4.1 試聽的「與學生關係」

API 的共用欄位規定 `parent.relation` 必填，`public_applications.parent_relation` 是 `NOT NULL`；A6 試聽稿沒有這一欄。

- **提案 A（建議）**：試聽表單照 A6 不放這一欄，前端送 `relation: 'other'`。不動 API、不動 DB。代價是試聽申請的關係欄永遠是「其他」—— 行政頁顯示時，`kind=trial` 不顯示關係。
- 提案 B：放寬成選填。要一支 `ALTER COLUMN parent_relation DROP NOT NULL` 的 migration（使用者按 Approve），API 拆兩份 schema。為了一個試聽時不重要的欄位，多一支 migration 不划算。
- 提案 C：試聽頁補這一欄。不照稿，A6 全採下不選。

→ **Q1**

### 4.2 成功畫面的電話、地址、營業時間

稿的成功畫面與失敗訊息都要「補習班電話」，試聽還要「分校地址」。公開端現在拿不到：目錄只回 `campusName`。

提案：`GET /api/public/catalog` 回應多一個 `campuses: [{ name, phone, address }]`（只含有開課中班級的分校）。這三欄本來就是對外的聯絡資訊（分校頁的 `tel:` 連結）。營業時間系統沒有欄位 —— **不顯示**，不為它加欄位。
多分校時成功畫面列出申請涉及的分校；試聽沒選到分校，列出有開這些課的分校。

### 4.3 個資保存期限（**要使用者裁**）

A6 的個資聲明寫「保存 6 個月，可以打電話要求查詢／更正／刪除」。**現在沒有任何東西執行「6 個月」**：kb 查不到保存政策，`public_applications` 存的是還沒成為客戶的陌生人的姓名、電話、孩子學校。聲明寫了做不到，就是對使用者說謊。

選項：

| 選項                                                                                                                                   | 成本                                                                 | c12                                     |
| -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | --------------------------------------- |
| a. **pg_cron 每天刪除超過 6 個月、且不是「已轉入」的申請**（已轉入的資料已經變成正式家長／學生，原申請只剩稽核意義，一併刪或去識別化） | 一支 migration（`create extension pg_cron`＋排程），使用者按 Approve | ✔ Postgres 擴充，自架 Postgres 也裝得到 |
| b. 行政頁加「清除 6 個月前的申請」按鈕，靠人記得按                                                                                     | 前端＋一支 API                                                       | ✔                                       |
| c. 聲明不寫期限，改「申請處理完畢後刪除」，由行政在不受理／垃圾時手動刪                                                                | 改文案＋刪除 API                                                     | ✔                                       |

repo 已有 pg_cron 的前例（`20260222000002_session_cleanup_cron.sql`、`20260223140000_schedule_audit_log_cleanup.sql`），不是新依賴。
不選 Workers Cron Trigger：那是 Cloudflare 專屬能力，c12 不允許程式依賴它。
**建議 a**：唯一不靠人記得的做法，而且「刪資料」本身就屬於使用者親自裁的那一類。查詢／更正／刪除請求仍走電話，行政在申請詳情上手動處理（刪除單筆要不要做成按鈕，跟著 a 一起裁）。

→ **Q2、Q3**

### 4.4 機器人驗證（captcha）（**要使用者裁**）

現況：honeypot＋Postgres 速率限制一直開著；Turnstile **可選**，部署沒設 `TURNSTILE_SECRET_KEY` 就不檢查。Turnstile 免費，但它是 Cloudflare 的服務 —— 能關掉，所以不算綁定，不過自架到別處的客戶等於只有 honeypot＋速率限制。

不接受付費服務（工單）。免費、可自架的選項：

| 選項                                                         | 使用者看得到嗎            | 自架                       | 說明                                                         |
| ------------------------------------------------------------ | ------------------------- | -------------------------- | ------------------------------------------------------------ |
| a. **只靠 honeypot＋速率限制（現況，不設 Turnstile）**       | 看不到                    | ✔                          | 零成本；擋得住大部分亂槍打鳥的 bot，擋不住針對這一站寫的腳本 |
| b. Turnstile（現況已支援，設金鑰就開）                       | 大多無感                  | ✗（Cloudflare 服務，可關） | A6 稿畫的是這個（「已通過機器人驗證」那一列）                |
| c. ALTCHA（MIT，工作量證明，伺服器端只要一把 HMAC 金鑰驗算） | 無感，送出前算約 0.5–2 秒 | ✔ 不連外                   | 程式碼裡已註明是日後替代方案；前端是一個 web component       |
| d. 自己出題（算數題）                                        | 看得到、要作答            | ✔                          | 對家長是摩擦，對 bot 擋不了多少。不建議                      |

**建議：預設 a，b 和 c 都留成部署可選**。ALTCHA 等真的出現濫用（`/admin/applications` 的「垃圾送件」變多）再做 —— 速率限制已經把單一來源壓在每小時 5 筆。
前端在 a 的情況下**不顯示**「已通過機器人驗證」那一列（沒有驗證卻寫通過，是說謊）。

→ **Q4**

## 6. 明確不做

- 公開申請自動轉成家長／學生／報名（規則：行政手動轉入）。
- 家長登入後看到自己先前的公開申請（§2）。
- 申請人自己取消或查進度（沒有身分可以驗證）。
- 寄確認信或簡訊、LINE 通知（LINE Messaging API 已否決）。
- 「這一班不公開」的旗標（Q5 若要，另開單）。
- 顯示老師名字（§1）。
