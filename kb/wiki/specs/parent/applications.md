## 1. A6 長什麼樣（A6 全採）

三頁 A6 都畫了完整頁（計畫席已裁 A）。重點：

- **報名（p-enrollment）**：分頁「新增申請／申請紀錄」。**不用頁首孩子切換器**：表單裡選孩子（1 個孩子只顯示名字）、紀錄混列所有孩子。選班依課程分組、可搜尋；孩子已在班上、已在申請中的**列出但不能選、寫原因**；剩 3 位以下紅字；額滿的班送出鈕變「登記候補」。狀態色只編碼嚴重度：待付款琥珀、已拒絕紅字無底、已完成綠字、其餘灰。詳情有時間軸（沒到的步驟空心點）；待付款顯示繳費資訊；已拒絕顯示原因；取消有 toast＋復原。
- **試聽（p-trial）**：同樣兩分頁、表單選孩子。選課程可多選；推薦的一組放最前；**孩子已在上的課不出現**；額滿的班仍可申請試聽（業務規則待使用者裁，A6 先畫可申請）。已安排不用藍，灰框標籤＋把日期寫在列上。取消：詳情放分校電話＋複製，沒有取消按鈕。
- **加選（p-add-course）**：用家長端共用的**孩子切換器**（不加「新增孩子」，新孩子走公開報名頁）。工具列：科目、星期幾、關鍵字；**直接標出撞時間的班**（琥珀字「跟 ○○ 班撞時間」）；依年級篩、排除已報名、推薦優先；0 筆寫「目前沒有適合的可加選課程」＋清除篩選。卡片：推薦、課程與班名、時間、老師、剩餘名額、費用；額滿寫「已額滿 · 可登記候補」。詳情 →「加選此課程」→ 繳費週期、開始日期、備註 → 送出；送出後對話框「繼續瀏覽／查看申請狀態」（→ 報名頁的紀錄分頁）。

「我的申請」（#1727 的說法）**就是報名、試聽兩頁的「申請紀錄」分頁**，A6 沒有獨立的一頁（Q6）。

## 2. 設計

### 2.1 前端（一般類）

- 三頁照 A6 結構，conformance 工具登記 `p-enrollment`／`p-trial`／`p-add-course`（家長登入態），PR 附 `compare`。
- 送出表單沿用 A6 `form()` 的形狀（#1740 的共用請假表單已建立這個模式：原生 `<dialog>`＋`overlay-motion`、「還沒填：…」、錯誤留在表單）。
- 錯誤碼一律留在表單或就地顯示：`CLASS_FULL`（改問要不要登記候補）、`ALREADY_ENROLLED`、`DUPLICATE_REQUEST`、`CLASS_NOT_OPEN`／`COURSE_NOT_OPEN`、網路失敗。
- 「已在申請中」由前端用申請列表算（同一個孩子、同一班、`pending`／`waitlist`／`awaiting_payment`）。

### 2.2 後端

- **#1731 通知**（保留類）：`notifyNewApplication` 的去重鍵改成呼叫端給（公開表單維持 `application:<id>`），收件人規則不變（班或課程的分校、`manage_students`）。家長端路由拿不到原始 client（A19），做成 `childDb` 的窄能力：先確認這些申請都屬於 scope 內的孩子才發（同 `notifyLeave`）。**沿用 `application_received`，不加 enum、不需要 migration**。
  - **同一次送出合成一則**（Q7 (b)）：試聽一次送多門課是多筆申請，管理員只收一則「送出 N 門試聽申請」。去重鍵用那次送出的識別碼：`parent_request:<kind>:<那次送出寫入的第一筆 id>`（同一次的 id 排序後取最小，重送同一批不重複）。
- **繳費週期**（Q1 (b)）：`enrollment_requests.billing_mode`（沿用 `public.billing_mode`、nullable、不加 CHECK，#1745）。API **只擋 `session_pack`**（堂數制行政議定），月繳／期繳都收，行政核准時再對（計畫席 10-19 B (b)）。**不對照班級的預設範本**：`default_fee_template_id` 只用於顯示，拿它當硬性限制等於給它多一個沒有的語意。前端：班有啟用中的預設範本時預選那個方式，家長可以改。
- **試聽日期**（Q2 (b)）：`trial_requests` 加日期／時間欄（migration 獨立一張 PR）。管理端填日期、家長端顯示日期**另開單**；這一版家長端列表寫「已安排 · 補習班會跟你聯絡時間」當過渡。**#1747 已做**：管理端轉已排定時日期必填、時間選填（規則見 `specs/admin/enrollment/enrollment-requests.md` 開頭）；過渡文案只剩舊資料（已排定但沒日期）會看到。
- **待付款的帳單與帳戶**（Q3）：**(b) 併入 #1726**。目前沒有任何路徑會把申請變成待付款（管理端只能拒絕，`routes/parent-requests.ts:17-21`）；核准怎麼開帳單、帳單怎麼連回申請是 #1726（金額路徑）要設計的，現在照推測的鏈寫等於替沒定的設計寫程式。**過渡用 (a)**：待付款寫「已核准，請到繳費頁付款」，連到 `/parent/payments`。
- **目錄補兩個欄位**（Q5 (a)，保留類：家長端讀取路徑）：每個班加 `enrolled`（這個孩子已在班上，active／pending_payment）與 `conflictsWith`（跟孩子現在哪個班的每週時段重疊，回班名或 null）。以 `childId` 計、走 childDb。

## 6. 原題與建議（留存）

**Q1　加選的「繳費週期」存哪？** `enrollment_requests` 沒有這個欄位。
(a) **建議**：這一版不問，詳情只顯示班級預設範本的參考價與週期（目錄已有 `fee.billingMode`），行政核准時再定。不動 schema。
(b) 加欄位（migration，保留類），家長選月繳／期繳，管理端收件頁顯示。

**Q2　試聽「已安排」的日期？** `trial_requests` 沒有日期／時間／地點欄，管理端排試聽也沒有地方填。
(a) **建議**：這一版列上只寫「已安排 · 補習班會跟你聯絡時間」，不寫日期。
(b) 另開單：加欄位＋管理端填日期，家長端顯示（A6 的樣子）。

**Q3　待付款的申請詳情要顯示什麼？**
(a) **建議**：寫「已核准，請到繳費頁付款」＋連到 `/parent/payments`（那頁已有帳單與帳戶資訊）。
(b) 照 A6 在詳情裡直接顯示帳單金額、期限、帳戶（申請 API 要 join 帳單，保留類）。

**Q4　額滿的班能不能申請試聽？**（A6 先畫可以、標「待使用者裁」）現在 API 不擋。
建議：**維持可以**（試聽不佔名額），請使用者確認。

**Q5　「已在班上」「撞時間」怎麼來？**
(a) **建議**：目錄 API 加 `enrolled`、`conflictsWith`（拆單 2，保留類）。
(b) 不標撞時間；「已在班上」改由前端用申請列表＋另一支讀孩子班級的 API 推。

**Q6　「我的申請」要不要獨立一頁？**
建議：**不要**，照 A6 放在報名、試聽兩頁的「申請紀錄」分頁；加選送出後「查看申請狀態」→ 報名頁的紀錄分頁。

**Q7　試聽一次送多門課，管理員收幾則？**
(a) **建議**：一筆申請一則（去重鍵 `parent_request:trial:<id>`），跟管理端收件頁一筆一列一致。
(b) 同一次送出合成一則「送出 N 門試聽申請」。

**Q8　候補（waitlist）能不能取消？** A6 寫「只有待審核可以取消」，但 A6 畫的時候還沒有候補；API 允許 `pending` 與 `waitlist` 取消。
建議：**兩個都能取消**（照 API）。
