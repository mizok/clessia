## 1. A6 長什麼樣（A6 全採）

**入口**：`p-attendance.html` 的工具列右邊，「幫孩子請假」（`.tbar__act`，一顆一般按鈕，帶請假圖示）。
只在有選中的孩子時出現（`kids.active`；多個孩子時是**目前選中的那一個**）。

**表單**：A6 共用的 `forms.leave`（`a6.js`），**跟管理端的「登記請假」是同一支**，差別只在家長端不出現「學生」欄，學生固定是目前的孩子。

| 欄位               | 型別                   | 預設        | 必填 |
| ------------------ | ---------------------- | ----------- | ---- |
| 開始日期／開始時間 | date／time（半寬並排） | 今天／17:00 | 是   |
| 結束日期／結束時間 | date／time（半寬並排） | 今天／21:00 | 是   |
| 原因（選填）       | 文字，提示「請假原因」 | 空          | 否   |

- 標題「登記請假」，副標「{孩子名} · 這段時間的課都會標成請假」。
- 外框是 A6 的 `form()`：桌機置中對話框、手機深灰底部面板；底部「取消」＋「送出請假」（cta）。
  必填沒填時，送出鈕旁邊寫「還沒填：…」。
- 送出：按鈕寫「送出中…」→ 關閉 → toast「已登記 {孩子名} {M/D} 請假」→ **範圍內的課就地改成「請假」**（列表重畫，不用重新整理）。
- 展開一堂請假的課：A6 寫「請假：{原因}（{誰}・{管道}）」，家長自己送的寫「家長從這裡送出」。

**選課的範圍**：A6 是**時間區間**，不勾堂次。區間內、這個孩子有報名的課全部變請假。

### 跟管理端 `leave-form-dialog` 共用到什麼程度

管理端的請假表單（`admin/pages/leave/leave-form-dialog.component.ts`）欄位跟 A6 一樣：學生、開始日期＋時間、結束日期＋時間、原因（選填），也不勾堂次。

- **決定：把表單本體搬進 `shared/`**，加一個可選的 `student` 輸入。有給就不出現學生欄（家長端），沒給就是現在的學生挑選器（管理端）。
- **理由**：A6 就是一支表單兩邊用。feature 之間不能互相 import（c5），兩個角色要用同一支，只能放在 `shared/`。
- **拒絕的方案**：家長端另外寫一支表單。這樣會出現兩份欄位、兩份驗證、兩份時間預設，而這個 codebase 已經為了這種分岔收斂過三次（點名、成績登錄、`page-actions`）。
- 搬家本身是**非保留類**的前端改動，可以跟家長端畫面放在同一張 PR。管理端的行為不應該改變，要有 spec 守住。

## 3. 後端（保留類：授權面）

### 路由

`POST /api/me/leaves`，跟其他家長端路由一起掛在 `routes/me.ts` 底下（`/api/me/attendance`、`/api/me/enrollment-requests` 等），路由檔是 `routes/parent/leaves.ts`。**不開放 `/api/leaves` 給家長**：那支是管理員的，有分校範圍、`basic_operations` 權限、編輯和銷假，跟家長的授權判準完全不同，混在一起只會讓兩邊互相放寬。

Body：`{ studentId, startDate, endDate, startTime, endTime, reason? }`。家長端**不收 `sessionIds`**（A6 不勾堂次）。

### 授權（c1，獨立判斷，不沿用管理員那套）

1. **角色**：沒有 `parent` 角色回 403，照 `routes/parent/attendance.ts` 的寫法。
2. **自己的孩子**：`isChildAllowed(childScope, studentId)` 不通過，回 403 `CHILD_OUT_OF_SCOPE`。
3. **孩子實際有報名的課**：只有區間內、這個孩子有**有效報名**的班的課堂才會被寫成 `on_leave`。`applyLeaveAttendance` 本來就是用報名區間過濾，所以這一條由共用核心保證，不是家長端另外再算一次。
4. **組織**：`org_id` 用 context 的 orgId，不吃 body。
5. 寫入一律經過 `childDb`（A19）：`leave_requests`、`attendance_records` 都有 `student_id`，可以走 scoped 的 insert／upsert。
   `childDb` 新增 `upsert`，範圍檢查照 `insertMany`：**任何一列的學生不在 scope 就整批不送**（計畫席 10-17 (A)）。家長端不寫 `leave_request_sessions`（不勾堂次），所以不需要替這張沒有 `student_id` 的表開例外。

### 跟管理端共用建立請假的核心

- **決定**（計畫席 10-17 (A) 定案）：**共用的是判準，不是讀寫**。「這張假蓋到哪幾堂、要寫哪些 `on_leave`」的純函式（`coversEvent`、`buildLeaveAttendanceUpserts`、報名區間過濾）抽到 `lib/`，兩邊共用；讀寫各走各的入口：
  - 管理端照舊用原始 client
  - 家長端全部走 `childDb`：課堂照 `routes/parent/sessions.ts` 的寫法（`pluck` 孩子的 enrollments → `fromScopedIds('sessions', 'class_id', …)`），重疊檢查與寫入用 `from('leave_requests'|'attendance_records', 'student_id')`
  - **通知**是寫別人（老師、管理員）的 `notifications` 列，`childDb` 依設計做不到 —— 新增一個窄能力 `childDb.notifyLeave(leaveId, sessionIds)`：先確認這張假的學生在 scope 內，才在 `lib/` 內部用原始 client 發老師的 `leave_for_my_class`（之後也發管理員的 `leave_received`）。家長端路由**拿不到原始 client**，A19 不開例外
- **理由**：出勤連動已經有五條寫入路徑（見 `20260902020758` 檔頭），再複製一份就是第六條，而「請假蓋到哪幾堂」的判準不同步，症狀會出現在扣堂和月結，離原因很遠。
- **拒絕的方案**：
  - 家長端路由自己寫一份：理由同上。
  - 家長端路由直接呼叫管理端的 handler：會把管理員的分校範圍和 `basic_operations` 檢查一起帶進來，然後家長端又得繞過它們。
- **要守的不變量**（spec 要有，而且要做突變驗證）：
  - 別人的孩子回 403，而且不寫任何資料
  - 沒報名的班的課不會被寫成請假
  - 管理端的行為不變：既有的 `leaves.spec.ts` 全綠
  - 家長送的單 `submitted_by_role = 'parent'`
  - 重疊回 409，不寫入
  - 已經開始或上完的課照樣寫成請假（Q1 更正：可以補請）
  - `childDb.upsert` 混一列 scope 外的學生 → 整批不送（突變）
  - `childDb.notifyLeave` 帶別人的 leaveId → 不發任何通知（突變）
  - 區間內沒有課回 400、不寫入（Q4）
  - 寫入成功之後跑 #1732 的連續請假偵測（[[specs/admin/finance/leave-streak-waiver]] §3）：偵測掛在這個共用核心之後，管理端與家長端只掛一次。#1732 還沒實作時這裡留一個「寫入成功後」的掛點，#1732 接上

## 4. 通知（#1693）

**送出成功、交易寫完之後**才排入通知，失敗不會留下孤兒通知（#1693 的實作要點）。

| 收件人 | 種類                                                                                                                                         | 誰                                                                                                               | 內容（草案）                                                                                                                                                |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理員 | **新增** `leave_received`（需要一支 `ALTER TYPE … ADD VALUE` migration，保留類，使用者 Approve；10-17 批准時定名，原稿寫 `leave_submitted`） | 這個學生**被請假的那幾堂課所屬分校**、有 `basic_operations`（或 `*`）的管理員（Q5）                              | 「{孩子名}的家長請假：{M/D（週）} {班名}…，原因：{原因}」，連到 `/admin/leave`；**蓋到已經開始的課時標題加「補請」**（Q1 更正：沒有人核對，方便行政事後看） |
| 老師   | 沿用 #1696 的 `leave_for_my_class`                                                                                                           | 被請假的課堂的**任課老師**（以那一堂課堂紀錄上的老師為準，代課時怎麼算跟 #1696 `leave_for_my_class` 的推導一致） | 「{孩子名} 請了 {M/D} {班名} 的假（家長送出）」                                                                                                             |

- **補請**：這張假蓋到的課只要有一堂已經開始（開始時間 ≤ 送出時間），就是補請；管理員那一則標「補請」，老師那一則照舊。
- 去重：`dedupe_key = leave:<leave_id>:<user_id>`。同一張假，一個人只收一則，不管蓋到幾堂。
- 不推播：老師和管理員第一版不推播（#1693，`push_status = skipped`、`ROLE_PUSH_DISABLED`）。
- 家長自己不收通知：畫面上的 toast 和列表就地變化就是回饋。
- 收件人照分校範圍或任課關係推導（c1），不吃 body。

## 6. 待裁題（10-17 12:43 全部照建議裁定，#1700 留言）

裁定：Q1 **可以補請**（12:48 更正，原本是「只能請還沒開始的課」）；Q2 第一版不設截止時間；Q3 第一版不能撤回；Q4 時段內孩子沒有課就擋下；Q5 通知分校範圍內有 `basic_operations` 的管理員；Q6 照 A6 選時間區間、不勾堂次。以下保留原題與理由。

**Q1　家長可以替已經上過或正在上的課請假嗎（事後補請）？** —— **裁定：可以**（12:48 使用者更正，下面是原本的建議，未採用）
建議：**不行，只能請還沒開始的課**（開始時間晚於現在）。區間裡如果包含已經開始的課，那幾堂不動，toast 寫明「已經開始的課沒有改，要補請請聯絡補習班」。
理由：管理員可以事後補請，是因為有人核對過。家長事後補請會把「缺席」翻成「請假」，影響扣堂（看各班設定）、本月缺席數，以及家長端「本月缺席」的大數字，而且沒有人核對。

**Q2　要不要「開課前 N 小時」的截止時間？**
建議：**第一版不設**，開課前都可以請。A6 沒有畫，要設的話就變成機構設定（像 `billing_reminder_days`）加一個欄位，屬於另一張單。

**Q3　家長可以撤回自己送的請假嗎？**
建議：**第一版不行**，A6 沒有畫撤回。現在的銷假是刪單，只有管理員能做（`DELETE /api/leaves/:id`）。家長送錯的話，在展開的列裡寫「要取消請聯絡補習班」。要做的話另外開單：只能撤回自己送的、還沒開始的課。

**Q4　區間裡這個孩子一堂課都沒有，要擋下來嗎？**
建議：**擋下來**，回 400，表單裡寫「這段時間 {孩子名} 沒有課」，不建單。管理端的行為不變（管理員可能是預先登記）。

**Q5　管理員的通知要給誰？**
建議：**分校範圍涵蓋被請假的課的管理員，而且要有 `basic_operations`（或 `*`）**。請假管理是 `basic_operations` 在做的事（`/api/leaves` 的寫入權限就是它），沒有這個權限的管理員收到也處理不了。
另一個選項是範圍內的管理員全部都給，比較吵。

**Q6　表單要不要勾堂次？**
建議：**照 A6 不勾**，用時間區間。管理端現在的表單也不勾。勾堂次（#1114）目前只在課表頁的路徑上用到。
