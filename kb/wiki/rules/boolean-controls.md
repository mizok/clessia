# 布林控制項三分法

> 2026-09-05，design-web 席，依 tester 評測報告 M7「布林值控制項不統一」訂規則。
> 三個現有落差(餐費同列兩種控制項、費用方案的顯示狀態看不出開關、聯絡簿同病)
> 已照這條規則修完，不是先訂規則、實作留給下一個人。

## 判準：值活在哪個結構裡，不是「感覺像不像開關」

三種控制項對應三種不同的「這個布林值屬於誰」：

| 控制項                               | 值屬於                                                         | 例子                                              |
| ------------------------------------ | -------------------------------------------------------------- | ------------------------------------------------- |
| **checkbox**                         | 一列資料的一個欄位（表格情境），或一個集合裡的成員資格（多選） | 餐費表格「訂餐」「收費」；人員表單的角色/權限多選 |
| **toggle switch**                    | 正在編輯的**單一實體**的設定欄位（表單/對話框情境）            | 班級表單「啟用/停用」、費用方案表單「啟用/停用」  |
| **filter chip**（`app-filter-chip`） | **不是資料，是檢視**——縮小畫面上顯示的範圍，不會被送出存檔     | 「只看未簽收」「顯示停用方案」                    |

三者的判斷順序：先問「這個值會不會被存進某一筆紀錄」——不會，就是 filter chip；
會，再問「這筆紀錄現在是不是正在被編輯的那一個實體」——是（表單/對話框脈絡）用
toggle；不是（表格裡的一列，或多個選項要挑）用 checkbox。

**不是「看起來像設定就用 toggle」**——「收費」讀起來很像一個決定/設定，
但它是餐費表格裡某一列的一個欄位，跟「訂餐」是同一種結構（表格列的布林事實），
所以兩個都該是 checkbox。

## 三處落差與修法

1. **餐費管理「收費」**：`p-toggleswitch` → `p-checkbox`，對齊同一列的「訂餐」
   （`meals.component.html`）。原本用 toggle 大概是因為「收不收費」讀起來像一個
   決定，但它活在表格列裡，跟判準用的是「結構」不是「語感」。
2. **費用方案「顯示停用方案」**：原本是 `p-button` 只換 label/icon 文字，視覺
   不變（tester：「看不出是不是開關」）。改用 `app-filter-chip`，`active` 直接
   驅動視覺（邊框/底色/字色）與 `aria-pressed`，文字可以照舊換，但不再是唯一的
   狀態線索。
3. **聯絡簿「只看未簽收」**：同一種病（`[outlined]`/`[severity]` 有換但不夠
   明顯），同樣改用 `app-filter-chip`。

## `app-filter-chip`

`shared/components/filter-chip/`。內容投影承載文字（跟 `app-todo-banner` 同一個
理由——每個呼叫端的措辭不一樣，不用字串 input 統一格式）。`active` 驅動
`filter-chip--active` 視覺（邊框/底色/字色轉成 accent 色調，跟 class-view 既有的
「待登錄」chip 是同一套視覺語彙——這是這個模式第三個實例，收成共用元件的時機到了，
不是提前抽象）。`aria-pressed` 讓螢幕報讀器聽得出目前的開關狀態，不只是靠顏色。

**這支只管檢視篩選，不是通用 toggle 元件**——單一實體的設定欄位（啟用/停用）
繼續用 PrimeNG 的 `p-toggleswitch`，不要為了「反正都是布林」把兩種脈絡的元件
合併掉；合併會讓「這是設定還是篩選」這個語意判斷從元件消失，回到每個呼叫端自己猜。
