# 餐費規則

> 來源：2026-08-29 內部人訪談（[[summaries/interview-insider-2026-08-29]]）。
> P1 `meal_records` schema 的設計輸入。現況記在 Excel、由行政操作（與老師點名是不同動作）。

## 1. 訂餐與出席解耦

- **有上課 ≠ 有訂餐**：有學生天天到班但家長不訂便當。
- 學生有「訂不訂餐」的預設設定（opt-in）；排課表只產生**候選名單**，實際以每日 meal_record 為準。
- 提前請假 → 當天不訂他的便當（行政操作，見規則 3）。

## 2. 每生每日一筆，月底結算

- meal_record：日期、單價（存在每筆上，有預設值 —— 便當價格可能變動）、訂了沒、**收不收費**。
- 月結 = 加總「要收費且**尚未結算**」的筆數金額 → 生成 invoice_item，同一 transaction 內
  把這些餐記錄標上 `invoice_item_id`（**結算標記**，系統自動，無人工動作）。
  月結因此冪等：遲補的舊記錄下次自動撈進、不會重複收。已結算的記錄鎖住「收不收」開關，
  要改走帳單作廢（item 刪除 → FK SET NULL 自動解除標記）或下期 adjustment。
  進 [[rules/billing-rules]] 的收款流程。

## 3. 「收不收費」是人工開關，不是規則

> 「小孩超過下午 N 點才請假，結果便當已經送到了，這種狀況可能會按照當前實際情況決定要不要收。」 — raw/sources/interview-insider-2026-08-29.md

- **不要自動化 N 點截止邏輯** —— 那是人工裁量。每筆餐記錄留一個行政可翻的開關。
- 請假模組只**提示**行政別訂便當，不自動改 meal_record。

## 4. UI 定位

- 餐務是**管理端**獨立頁面（每日名單勾選），操作者是行政 —— 不塞進老師的點名流程。
  對應既有的 `admin/meals` 空殼頁。
