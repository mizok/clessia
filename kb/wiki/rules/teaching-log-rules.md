# 教務日誌與作業廣播規則

> 來源：2026-08-29 內部人訪談（[[summaries/interview-insider-2026-08-29]]）—— 受訪者列的四大痛點之一，**本次訪談最大的發現**。
> 注意：repo 已有 `teaching-log-dialog`（staff 頁），實作前先盤點它現在涵蓋什麼。

## 現行流程（要被取代的是「人工轉貼」）

1. 各科老師把教務日誌寫在**該分校×該年級共用的一本紙本**上：當天教學紀錄 + 作業安排
2. 下班拍照 → 傳到公司 LINE 群組的相簿
3. 行政再把作業安排**人工轉貼**到「該分校×該年級」的**小孩私群**
   （更正：作業的受眾是小孩私群，不是官方群組 —— 官方群組是家長溝通用，
   行政還要手動給每個家長標記分校+年級+小孩名稱）
4. **國中家長沒有私群權限** —— 現實中家長完全看不到作業與日誌

**既有 bug**：廣播粒度是「分校×年級」，不是「班」。小孩沒修自然課，但同年級有開自然課
→ 也收到自然課作業。

## 系統規則

1. **教務日誌是班級×日期層級**（一堂課一篇：教學紀錄 + 作業安排）。
   與聯絡簿（學生×日期、自由敘述）是**兩個不同的東西**，見 [[rules/contact-book-rules]]。
2. **LINE 群組保留，不取代**（2026-08-29 補充，產品擁有者定調）：
   **學生自己在私群看作業** —— 受眾不只家長，還有沒帳號的學生本人。
   通知必須**系統與 LINE 兩邊都有**。
3. **發布一次，雙通道送達**：
   - **站內通道（精準）**：作業自動出現在**該班學生**的家長端 + LINE 推播。
     粒度 = 班級名冊，直接治掉「自然課誤報」—— 精準投放只有這條通道做得到。
   - **LINE 群組通道（廣播）**：系統透過 LINE Messaging API（bot 進群組）
     **自動組稿發到小孩私群**（分校×年級），訊息按班級分段標示。群組成員結構
     天生是年級粒度，錯發治不掉，但至少行政不再人工轉貼、格式一致。
4. 被消滅的是**行政的人工轉貼**，不是 LINE 通道本身。教學紀錄供內部（管理端）
   查閱，作業對家長與群組可見。
5. **一般廣播共用同一機制**：補習班常需要廣播其他資訊給學生（非作業）。
   既有的公告（announcements）功能接上同一個「站內 + LINE 群組」雙通道出口。

## Schema（grilling 定案）

- `class_logs(class_id, date, teaching_record, homework, last_edited_by, published_at?)`，
  class+date 唯一 —— 對齊紙本現實（一班一天一篇），不掛 session。
- 表名刻意避開既有的 teaching-log（那是**授課時數統計**，完全不同的東西）。
- `published_at` 是廣播扳機：NULL = 草稿；發布觸發家長端可見 + LINE 推播。
- **作業安排家長可見；教學紀錄預設內部** —— 紙本傳的是公司內部群組，
  老師會寫不給家長看的話。兩欄分開存，可見性之後可做開關。
- 國中家長因此獲得現實中不存在的能力：在家長端看到自己小孩修的班的作業
  （按報名精準過濾）。

## 提案價值

before/after 故事：紙本→拍照→相簿→人工轉貼→錯發，變成**寫一次、兩邊自動到**、
站內精準到班。LINE 那側家長學生的使用習慣完全不用改 —— 這對「怕系統」的客戶是賣點。

## 待確認的外部依賴

- LINE Messaging API 的 bot 要能被拉進官方群組發訊息；群組訊息的免費額度上限
  要在 P4 實作前查證（與推播共用同一個 channel 的額度）。
