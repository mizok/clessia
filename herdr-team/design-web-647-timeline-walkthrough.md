## 一句話

**工單傾向的方向（一堂課畫成一條橫跨數格的區塊）＝ lane 佈局，而那正是這張圖被造出來取代掉的東西。**
真正的機制小得多：**柱與柱之間那 2px 的縫**。

---

## 一、實際量到的（跟工單描述有出入）

今天的展示資料是**一堂 90 分鐘的課 → 3 根**（工單寫 4 根是舉例）。

| 量到的       | 值                                                              |
| ------------ | --------------------------------------------------------------- |
| 總 bin 數    | 28                                                              |
| 有課的 bin   | 3（17:00–17:30 / 17:30–18:00 / 18:00–18:30）                    |
| 每根寬       | 36.4px                                                          |
| 每根高       | **62px（滿高）** —— 因為 `maxTotal = 1`，任何非零 bin 都是 100% |
| **柱間 gap** | **2px**                                                         |
| 空 bin       | 仍畫出 2px 殘根（中空 seg 的 `border-top` 撐出來的）            |
| 軌道高       | 64px（固定）                                                    |

⚠️ **量測陷阱**：`.day-timeline__bar` 是滿高的 flex 容器，28 根量起來**全都是 62px**。
真正的高度在 `.day-timeline__seg` 上。第一次量錯節點，是「28 根數字一模一樣」才發現的。

## 二、機制：那 2px 的縫

現場把 `.day-timeline__bars { gap }` 設成 0，17:00–18:30 **立刻變成一塊連續區塊**，
跟標題「今天 1 堂課」一致。

用同一份模擬的忙日（高度序列 1,2,2,1,1,1,3,2）對照：

- `gap: 2px` → 讀起來是**八個離散的東西**
- `gap: 0` → 讀起來是**一天的輪廓**（階梯在高度變化處清楚可見，等高處連成平台）

**這個修法不動佈局模型**：仍是 64px 固定高、28 格、長度編碼、不碰透明度。

## 三、⚠️ 沒人提過的並發症：中空盒有自己的左右框

`.day-timeline__seg--untaken` 是 `border: 2px solid`（`border-bottom: 0`）的**中空盒**。
所以 `gap: 0` 之後 **未點名那一段仍然是一格一格的** —— 而未點名正是儀表板上最該被看見的狀態。

今天的資料 `untaken = 0`，**剛好測不到這件事**。是模擬出來才看到的。

三個候選都在真頁面上用真 CSS 試過：

| 候選                                                           | 結果                                                                                                                                |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 中空只留 `border-top`                                          | **變成懸空的橫線**，跟下方實心脫節                                                                                                  |
| 相鄰柱 `margin-left: -2px`                                     | **最接近** —— 實心連續、中空是坐在上面的封閉盒；但相鄰中空之間仍留一條分隔線                                                        |
| `.bar--filled + .bar--filled .seg--untaken { border-left: 0 }` | **CSS 表達不了** —— 選擇器只看得到「這根有沒有課」，而一根可以「有課但 untaken = 0」，於是第二個 run 的左框被錯誤拿掉（實測看到了） |

> **結論：run 邊界要在元件裡算**（資料在它手上），不能用 CSS 兄弟選擇器猜。

## 四、建議的修法（未實作）

1. `.day-timeline__bars { gap: 0 }` —— 實心 run 合成連續輪廓
2. 元件為每個 bin 算 `joinLeft`（**前一根的 `untaken > 0` 且這一根也 > 0**），
   模板加 modifier，SCSS 對它 `border-left: 0` —— 中空 run 也合成一塊
3. 圖例 `最忙 N 堂` → **`最忙同時 N 堂`**
   （現在「已點名 1 / 未點名 0 / 最忙 1 堂」三個數字並列而量綱不同）

**不要做**：不改佈局模型、不改 bin 邏輯、不動 `layoutDay` 的測試。

## 五、為什麼不照工單的傾向做

`day-timeline.component.scss:11-14`：

> **固定高度，不隨課量長。這是換畫法的全部理由**：lane 式佈局每多一條 +30px，
> 4 條時橘帶佔 48% 視窗、課表整段掉到摺線下。

`kb/wiki/architecture/timeline-density.md`：

- 「lane 版的每一個方塊是**一堂具體的課**…**密度圖沒有這個**…**這是真的損失**」
- 「**不做『兩種圖切換』**…一律用密度圖」

**「一堂課畫成一條橫跨數格的條」就是 lane。** 那不是新方案，是被替換掉的那個。

## 六、順帶查到：設計文件的緩解 1 從來沒實作

同一份設計列了三條緩解，第一條是「**hover / focus 一根柱，顯示那半小時的課堂清單**」，
驗證項第 7 條寫「**點一根展開該時段清單**」。

**查證：`day-timeline` 零 click / output handler**，只有 `title` 與 `aria-label`。

**那是獨立的一單**，不在 #647 範圍內，但它是這個「一根柱不是一堂課」問題的正式緩解。

## 七、驗收條件的一個訂正

工單寫「修完之後一個第一次看到的人要能說出今天有幾堂課」。

**那個問題標題已經回答了** —— 「今天 1 堂課，全部點完了。」是大字，就在圖的正上方。
**真正的問題是圖在跟那句話唱反調**，所以要修的是那個矛盾，不是再加一個數字。
