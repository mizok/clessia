## 一、「並排截圖」是這一段的驗收單位 —— 怎麼拍才不騙自己

- **腳本骨架**（`.pw-regression/` 不進版控，照 2120 §五重建）：A6 稿用 `file://` 開、本機頁用 `storageState`，同寬（1440、360）各截一張，轉 base64 塞進 `page.setContent` 的兩個 `<img>` 再截一張並排。**本機頁要用高視窗（我用 2200）截**：shell 的 `.shell-content` 是內層捲動，`fullPage` 只截得到首屏。
- **高視窗的副作用**：A6 稿的**手機登入頁橘面板是撐滿視窗高**的，2200 高就變成 1900px 的橘面——那是截圖視窗造成的，不是稿的設計。比手機首屏高度時要用真實高度（780）重拍。
- **唯讀盤點沒按任何動作就要寫明**；差異清單的證據欄「實際按過的動作」留空是誠實的，不要用截圖假裝按過。
- **清單裡凡寫了「手機（360）」就必須實看過那張圖。** 我一則 fee-templates 的手機欄憑結構推測寫了（「滿版橘長條」「無明顯版面 bug」），看圖後全錯，得貼一則更正。**沒看過就寫「未逐項讀」。**
- **稿標「新」的區塊是新功能，不是視覺**（enrollments 的學生／開課班篩選與「直接報名」、dashboard 的五塊、學生檔案的到班方塊與數字區）。盤點時分開列，否則視覺對齊 PR 會被拖進後端。

## 二、dev server 的假紅燈：「vite-error-overlay intercepts pointer events」

多檔改動途中截圖，Playwright 會被 vite 蓋的錯誤遮罩擋住點擊（2120 §二也寫了）。**這一輪新踩到的版本：build 早就綠了，遮罩還在**——dev server 重放它記住的最後一個錯誤（截圖上的錯誤訊息是已經改掉的舊狀態）。判斷：`web.log` 最後幾行是 `Application bundle generation complete`、遮罩上的行號對不上現在的檔案 → **殺掉自己的 `nx serve web`（`lsof -ti tcp:4200`，確認 cwd 是自己的 worktree 再 kill）重啟**，不要再等。

## 三、新增共用元件目錄要同步三件事，harness 才不會漏看

1. **`apps/web/src/tailwind.css` 的 `@source`** —— 沒列的目錄，Tailwind 不掃它的 class。**dev 看起來對是假象**：同樣的字串（`wide:text-[44px]`）別的目錄也有時，正式 build 才會缺。PR-A 的 `chapter-head` 我就漏了，PR-B 補。
2. **`npm run harness:write`** 更新 `scan-scope.json`（`@source` 變了 gate 會紅「掃描範圍變了」）。
3. **A27 要求可點元素的 class 是靜態字串**：`[class]="btn"`（`@let` 變數）它**看不到**，報「沒有 ≥44px 高度下限（class：（沒有 class））」。三顆鈕就寫三份完整 class，別為了少打字去綁變數。

另：`harness` 的 A27 對 `button` 還有「全庫沒有任何 SCSS 定義」那條，Tailwind 頁靠 `@source` 才算有定義 —— 同一件事（#1）的另一個症狀。

## 四、`page-actions` 現在是浮起托盤，語意改了

手機＝浮起托盤（左右內縮 12px、圓角、陰影、離底 12px），**次要在左、主要在右，最多兩顆**（型別上放不進第三顆）；桌機標頭也各渲染一份。原本「只收一顆主要行動」「全寬貼邊列」的理由留在元件註解裡標成**歷史**（2026-10 前的決定，A6 推翻）。**因為桌機與手機吃同一份宣告，桌機的主次色會跟 A6 不同**（A6 桌機的橘色鈕是「開立帳單」，托盤主要是「全部提醒」）—— 計畫席接受這個差異，要完全一致得讓兩處各自宣告（那是當初拿掉的「同一個行動宣告兩次」）。`shell-content` 的底部留白是 `92px + safe-area`，托盤高度改了要同步改它。

## 五、這一輪「實機才抓得到」的三個 bug（spec 全綠、CI 全綠）

- **章底下重複列出全部課程**（courses，#1431 起就有）：每章右側的迴圈寫成 `courseGroups()`（全部）而不是 `chapter.groups`。demo 資料幾乎全是國文，單一章看不出來；兩個科目就每門課每章各列一次。**抓到的方式是看「只看這幾個班」的截圖時發現國文章與數學章底下是同樣兩門。** 修法一個字、spec 一條，**並且驗過 spec 在舊碼上會紅**（還原修正跑一次）。
- **計數只數目前這一頁載入的東西**（`interventionCount` 數 `courses()` 底下的班，而 `courses()` 是分頁的）：按「只看這幾個班」前 1 個班、按下去 2 個班。**凡是「摘要數字」都要問它的母體是不是跟按下去之後的畫面同一個**；實機驗法是切換前後讀同一個數字，並用 API 在 node 裡對帳。
- **`band-anchor` 的金額沒千分位**（`94590`）：同頁列內金額一直有 `| number`，只有色面那個沒有。共用的 `band-anchor` 被傳計數也被傳字串，所以不在元件裡套 pipe，在呼叫端套。

## 六、「提醒」＝記錄一次催繳，**不是**發送

`POST /invoices/:id/reminders`（與 `/reminders/batch`）寫的是 `payment_reminders` 一筆（method＝`line`／`phone`／`other`），**系統不會發 LINE**。A6 稿的「提醒」「已用 LINE 提醒 9 位」是原型，照做會讓行政以為家長收到了。所以：按鈕叫「提醒」、點下去先選方式、**toast 寫「已記錄 N 筆催繳」不寫「已通知」**、批次先開確認視窗（文案明寫「不會自動通知家長」）。**LINE 推播有排時才把「記錄」換成「發送」。** 批次的 N＝畫面上這一頁的 id（API 設計就是送畫面上那批），逾期超過一頁時不是「所有逾期」，鈕上要寫張數。`lastRemindedAt` 是 UTC 時間戳，換**台北日期**再跟 `today` 算日數（`remindedText`，spec 有「UTC 前一天晚上＝台北今天凌晨」的邊界）。

## 八、PR 與流程小事

- **「一次一支 ready」是真的在管**：我一度手滑把兩支同時轉 ready，立刻改回 draft 並回報。**draft 可以多支並行，ready 只能一支**；等前一支合了再轉。轉 ready 後把 head sha 回報計畫席。
- 範圍說明寫「做什麼／不做（與理由）／待裁」三欄，**待裁要附我的預設**——計畫席回「過」就等於採預設，不必再來回。
- 單一元件被用在多頁時，改它之前先把**每個使用頁**列出來（PR 描述的「波及頁」逐頁截），別只拍你在改的那頁。
- `rebase` 只用在**還沒推的分支**（PR-B 在 PR-A 合併後 rebase 解了一個 imports 衝突）。
- 一次改完再存：多檔改動中途存檔會讓 dev server 編譯錯誤（2120 §六）。
