## 一、「自己的」端點不能用 `resolveTeachingScope`

- `resolveTeachingScope` 對 **admin 角色回 `teacherStaffId: null`＝全校**，而 `roles` 是帳號的**全部**角色、
  不是 active role。demo 有同時是 admin＋teacher 的帳號（teacher0001）→ 用它做「我的課」會變全校。
  「自己的」語意一律直接用本人 `staff.id` 再套 `taughtClassIds`（#1488）。管理員要全部走 admin 路由。
- 老師端要讀 admin 才有的資料：**開獨立 mount 限 `['teacher']`**，不要鬆開原路由的 `ADMIN_ONLY`。

## 二、契約測試要用「走得到查詢」的身分打

- 範圍型端點在身分沒有可見資料時會**提前回空 200**，根本沒打到後面的查詢，形狀錯也綠。
  契約測試要挑一個真有資料的身分與區間（#1488：取一筆 `schedule_changes` 的課堂之老師與日期）。
- 契約測試在本機要 `npm run test:contract`（讀 `supabase status`）；新增 GET 端點不用改表，
  但角色／身分特例加在 `ROLE`／`ALWAYS`。
