## 這一任踩過的坑（下一任先讀這節）

### 1. PR 的 CI 綠可能是**舊 main** 的綠

#1884 在共用 `app-select-field` 加 `hideLabel`，同時 #1834 也加了同名 input 並先合 → 合起來 TS2300 重複宣告，CI 卻是綠的（跑在 #1834 之前）。
**送審或回二讀前，在暫存 worktree 把分支併進最新 `origin/main` 跑 typecheck＋相關 spec。** 動 `shared/`、全域樣式、共用型別時一定做。記憶：`feedback_author_test_merge_latest_main`。

### 2. 二讀會跑突變，spec 要守得住「拿掉這行會壞」

review2 每張都跑十幾支突變。這一任被退的模式：

- jsdom 沒有 ResizeObserver／WAAPI／visualViewport → directive 一進來就 return，測試永遠綠。**替身要 stub 到那條路真的會走**。
- 假的 `offsetHeight` 不理 `maxHeight` → 「量測前先清 maxHeight」那行拿掉也綠。**替身要跟真的一樣會被限住**。
- 只測「留下方」→ `above` 少扣 offsetTop 也綠。**每個參數至少一支會改變結果的案例**。
- Promise reject 的分支：`flush` 之後要 `await Promise.resolve()` 再 `detectChanges`，不然看到的是 reject 前的畫面。
- 自己先跑突變：**在暫存 worktree**（席位 worktree 會被 Stop hook 驗），作者改過替身就全部重跑。腳本範例：`scratchpad/mut1875.py`。

### 3. 本機 dev server 的脾氣

- **切分支之後 4240（席位 worktree 的 web）常卡在舊編譯錯誤**（vite-error-overlay 擋住點擊）→ 殺掉重起。這一任寫了 `restart4240.sh`。
- **wrangler 從會切分支的 worktree 起，檔案一變就重載、常常重載完就退出**（8797 掛了三次）。改成從一個專用、不切分支的暫存 worktree（`apiwt`）起，就穩了。共用的 8787 中途也掛過，不是我們停的。
- 「修改前」的對照 server（4241）要跟著 `origin/main` 更新，不然對照的是開席時的舊 main。
- web 的 API 網址寫死 8787；截圖腳本在 Playwright 的 context 層把 8787 轉到自己的 API（同 `tools/a6-conformance/lib/capture.mjs`）。
- `route.fetch({ url, method })` 會沿用原請求的 body —— 要另外抓資料用 `ctx.request.get`。

### 4. 截圖替身

本機 seed 缺資料時（三種身分的帳號、公開表單的申請、已繳清的舊申請），在瀏覽器層換 API 回應，**不寫入共用 DB**，PR 裡註明哪幾張是替身。寫入動作（記收款）一律用替身回應，不真的寫。

### 5. 全量測試在負載下會有 1–3 支不穩定的紅

每次紅的不一樣（課堂頁、開班表單、儀表板）。單獨跑那幾個檔、在 main 對照跑一次，都綠才算是不穩定；**照實寫進 PR**，不要說成全綠。

### 6. 模擬器重現不了的東西要講清楚

Playwright WebKit 的 iPhone 模擬**重現不了 iOS 聚焦放大**（main 上也是 scale 1）→ 那個數字不能當證據，要實機。寫進 PR 讓計畫席去請使用者。

### 7. 小東西

- zsh：`echo ==` 會被展開、`$C:r` 是修飾子（寫 `${C}`）、`--include=*.html` 要加引號。
- prettier 會順手重排無關的模板（class-view 那次），diff 裡有無關改動就還原那段。
- `.clessia-filter-search` 在 legacy layer 是 `flex: 1`（basis 0）—— 手機要獨佔一列得加 `basis-full`。
- `app-popup-menu` 的 item 只吃 `command`，不吃 `routerLink`。
