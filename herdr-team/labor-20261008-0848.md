## 一、計數交給 DB 的兩種寫法（接 1048 §五）

- **能下成 filter 的計數 → head count**，每組一支、`Promise.all`，error 回 500 不回 0。
  嵌入表的條件也能下：`select('id, invoices!inner(org_id, voided_at)', { count: 'exact', head: true })`
  配 `.eq('invoices.org_id', …).is('invoices.voided_at', null)`，count 跟著嵌入條件縮
  （#1377 本機實打：`voided_at=not.is.null` → `*/0`，忽略條件的話會是全數）。
- **同一個判準被兩支端點用，就抽成同檔私有函式**：`billing-periods.ts` 的
  `countOverlappingEnrollments`（列表的 `overlappingEnrollmentCount` 與「待開單」的 `pending`）。
- **推導值數不出來（帳單狀態）→ `.range()` 翻到底**：每頁 1000（＝`max_rows`）、`order('id')`、
  拿到不足一頁就停（`GET /api/invoices/summary`）。ponytail 天花板是 O(全部列)，量大時升級 SQL view／RPC。
  陷阱：把翻頁改成「撈一頁就停」要紅在 `1000 ≠ 1001`。
- `withMaxRows`（模擬 `max_rows` 的 Proxy）已搬進 `test-utils/multi-org-db.ts` 共用；`multi-org-db` 補了 `gt`，
  `is` 改走巢狀 `field()`（`is('invoices.voided_at', null)` 才篩得到）。
- **列表的「附帶資料」要對本頁撈，不要先撈全 org id**：`GET /parents` 原本先撈全部家長 id 再撈關聯，
  破千時被截斷、後面的人孩子數靜默變 0（PA2 順手修）。

## 二、帳單相關的定義（裁過的，別再問一次）

- **家長「本學期已繳」**（PP1，計畫席 10-08 10:13）：本學期＝涵蓋台北今天的 `billing_periods`
  （重疊取 `start_date` 最晚，沒有 → null）；已繳＝**明細 `billing_period_id` 掛在本期**的非作廢帳單之
  `netPaid`。**不是收款日落在期內** —— 開學前先繳的要算、期內補繳上一期欠款的不算。跨期帳單整張算進來。
- **帳本彙總**（P1／P2）：狀態、`isOpenInvoice`、逾期全借 `lib/invoice-status`／`invoice-overdue` 既有判準；
  「本月」＝台北本月開立的非作廢帳單，應收＝明細合計、已收＝至今淨收，比例前端除。不重用 `/reports/revenue`
  （那支要 `view_reports`，帳本頁是 `manage_finance`）。

## 三、這輪看到、還沒修的範圍缺口

- **`invoices.ts` 整支沒有分校範圍**（#1381）：受限的 `manage_finance` 管理員看得到、改得到全 org 帳單。

## 四、EN5 的資料形狀（#1379）

- 狀態變更原因寫 `enrollments.status_reason`，**不再覆寫 `notes`**（使用者可否決點）；`status_changed_at` 每次都寫
  （恢復也寫、原因清成 null）。所以期間篩選的暫停項要配 `status.eq.suspended`，否則恢復的列也會被篩進來。
- PostgREST `or` 字串的巢狀 `and(status.eq.x, col.gte.y)` 解析正確 —— 新欄位還沒套時，用既有欄位代打同形狀驗語意。
