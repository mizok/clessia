## 二、審核席一定會做突變，**送審前自己先做**

這一任四支 PR 被退過三次，每次都是「刻意改壞一個判斷，測試全綠」。審核席的手法固定：
條件 `&&`↔`||`、拿掉 `.catch`／逾時、拿掉重設旗標、改邊界（`> 99`→`>= 99`）、拿掉某個 `writeOff`。

- **每加一個判斷，就自己把它拿掉跑一次 spec**，看到紅才送。PR 說明寫「突變：拿掉 X → 紅 N」
- 替身要跟真的一樣：推播的 `unsubscribe` 替身原本不會讓 `getSubscription` 回 null，
  於是「關掉之後不重訂」那條怎麼寫都測不出來
- 「突變全綠」最常見的原因是**那條路徑沒有 fixture**（例：畫面上 100 則都已讀、但 `meta.unread > 0`）

## 四、本機實測

- **自己起 API**：`cd apps/api && npx wrangler dev --port 8790 --var BETTER_AUTH_URL:http://localhost:8790 --var WEB_URL:http://localhost:<web port>`
  - web 要連它得改 `environment.ts` 的 8787 → 8790，**不 commit，收工前一定 `git restore`**：
    `system-clock.service.spec` 把 8787 寫死，Stop hook 會擋（這一任撞過一次）
  - `login-link.ts` 的 `WEB_URL` 要等於 API 的 `WEB_URL`，不然 verify 回 403
  - 收 server 用 TaskStop 之後，`lsof -tiTCP:<port> -sTCP:LISTEN` 確認真的空了
- **瀏覽器**：claude-in-chrome 連的是使用者的 **Brave**。原生權限提示點不到、`resize_window` 不生效 →
  **要固定尺寸或權限就用 Playwright**（`npm i playwright@1.60.0` 裝在 scratchpad，跟 tools/a6-conformance 同版，Chromium 已有快取）
- **推播實測**的坑全寫在 `kb/wiki/architecture/web-push.md` §4（無痕沒有 Push API、headless shell 拒權限、

## 五、程式碼裡學到的

- **導頁前送出的請求不要掛 `takeUntilDestroyed`**：點了有 link 的通知馬上導頁，元件 destroy 把 POST 取消，
  DB 沒寫進去（#1710）。翻回失敗時直接寫 service，不靠元件的 effect
- **better-auth 在建 client 時就把 `globalThis.fetch` 抓死**，spec 替身不到；`auth-client.ts` 已改成每次呼叫才取 fetch，
  之後的 auth spec 直接 `vi.stubGlobal('fetch', …)` 就好
- **`mask-image` 掛在 popover 上會連白底一起淡掉**，後面的頁面透出來。淡出要掛在裡面的捲動層
- popover 在 top layer：`100%` 就是可視高（不用 vh）；但子層的 `%` 對 auto 高的父層無效，要限高就用 JS 算 px
- 按鈕裡的 `import()`：包在 `try/catch` 的話，`catch` 第一句問 `AppVersionService.recoverFromImportFailure(err)`
  （`kb/wiki/architecture/chunk-load-recovery.md`）

## 六、git

- **疊 PR 的下層被 squash 合之後，上層 merge main 會整批衝突**（內容一樣也衝）。先
  `git diff <下層合併時的 head> origin/main -- <檔>`：一樣就取上層版本，再把「下層最後幾個 commit」（例：審核席要的 spec）
  手動搬過來 —— 那些 commit 不在上層分支上，取 ours 會把它們丟掉
- 疊在你分支上的別席（#1713）：**每推一個 commit 就通知它 merge**，它不 rebase
- conformance `compare` 的 base／head 都用 head 的工具版本跑；新登記的 `DEVIATIONS` 用 `pop` 欄位比對最穩
  （key 的格式跟報表上顯示的不同）
