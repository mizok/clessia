# 家長端 v1 前置構圖提案 —— 出缺席／成績／繳費 + 孩子切換器

> 2026-09-05，design-web 席。**提案，不是規格** —— 給 admin-pages 當 02/03 片的輸入，
> 做完後由這席做輕量二審（前置比事後便宜十倍，計畫席 #326 後裁定）。
> 依據：`kb/wiki/specs/parent/{attendance,grades,payments,dashboard}.md`（規格權威不變，
> 這份只補「排出來長什麼樣」）+ 這席 charter §三／§五的既有判準。
> 互動細節（Popup vs 展開 vs 底部抽屜）標的是**建議**，不是覆寫 spec ——
> 需要 admin-pages／使用者確認才落地，design-web 不動業務邏輯只動構圖。

## 使用情境（判準來源）

**單手、跟老師講電話時查。** 兩個推論：

1. 預設畫面就要有答案，不能靠互動才看到——近 10 天列表、待繳總額這類「一眼版」優先於摺疊
2. 減少需要精準點擊或雙手操作的互動（小 icon、需要瞄準的彈窗關閉鈕），
   優先用「展開／收合」取代「開新彈窗」——展開失敗的代價（多滑一段）遠低於誤觸彈窗外的代價

## 全域決定：孩子切換器不是新元件，是既有互動形狀的第三個實例

`shell-layout` 已經有「角色徽章 + `p-popover` 清單」在做身分切換（切角色）。
孩子切換器**答的是同一種問題**（我現在看的是哪個 scope），所以**複用同一個互動形狀**：
header 上一顆徽章顯示目前孩子姓名，點開 popover 列出其他孩子。

- 只有一個孩子時**不渲染切換器**，直接顯示姓名（同角色徽章「單角色不給切換」的先例）
- 徽章放在三頁共用的 `app-page-band` 左側身分區（eyebrow 位置），**不要放進每頁內容區重複造**——
  三頁 scope 相同，切換器應該是「進了家長殼層就看得到」的東西，不是每頁各自的元件
- 這是新的視覺詞彙嗎？**不是**——沿用角色徽章的形狀（badge + popover），色相走中性
  （不是身分色也不是嚴重度），不需要過 §三 的擴張詞彙兩道關卡

## 帶（band）的用法：三頁一致，錨點各自答自己的問題

`app-page-band` 的規則是「帶高與內容量脫鉤」——**帶只放身分＋一個錨點數字，
列表本身永遠在帶以下的白底區**，不會因為列表長就把帶撐高。三頁的錨點選「最可行動的那個」：

| 頁面   | 錨點候選                    | 選哪個、為什麼                                                                                                                                    |
| ------ | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 出缺席 | 到班率 / 本月缺席＋請假次數 | **本月缺席＋請假次數**——到班率是總結性數字，不會讓人做任何事；次數 > 0 才會讓家長想「要不要問一下」                                               |
| 成績   | 新成績數 / 平均分           | **新成績數（NEW 標籤數）**——平均分跨課程沒有意義（不同考試滿分不同，呼應 admin 端「棄百分比化」的同一個理由），新成績數直接對應「有沒有東西要看」 |
| 繳費   | 待繳總額                    | 沒有第二個候選，跟 admin 端 invoice 卡片的既有先例一致                                                                                            |

**這三個都是提案，不是我拍板**——尤其出缺席的錨點涉及「要不要把請假也算進需要關注的數字」，
這是業務判斷，麻煩 admin-pages／使用者過一次。

## 三頁構圖

### 出缺席 `/parent/attendance`

```
┌─────────────────────────────────┐
│ [孩子▾]  出缺席          本月請假 │
│                          缺席 2  │  ← 橘帶，錨點=次數不是率
├─────────────────────────────────┤
│ 篩選：近10天 / 近30天 / 選月份    │  ← chip 群，預設近10天已展開
├─────────────────────────────────┤
│ 9/5（五）                        │
│  ✓ 已到班 08:12                  │
│  ● 數學（陳老師）  出席            │  ← 狀態用 status-dot 不是 data-chip
│  ● 英文（林老師）  請假            │     （見下方「色相」一節）
├─────────────────────────────────┤
│ 9/4（四）今日無課                 │
├─────────────────────────────────┤
│         ↓ 捲動載入更多            │
└─────────────────────────────────┘
```

**互動建議**：spec 寫「點課堂開 Popup」。單手情境下建議改成**列內展開**（accordion，
點了在原地長出詳情，不是跳出遮罩）——跟成績頁「點考試展開詳情」的既有 spec 選擇一致，
兩頁互動形狀對齊，使用者不用學兩套手勢。**這條請 admin-pages 或使用者拍板**，
不是我單方面改 spec。

**色相判斷**：出席／遲到／請假／缺席四態**帶嚴重度**（缺席比遲到需要更多關注），
落在 §三「色相只編碼嚴重度」的规则里——**用 `app-status-dot`（形狀×色相雙軸），
不要用 `app-data-chip`**（data-chip 是中性身分，沒有嚴重度語意，這裡誤用会踩坑 12
「分類要看值域不是看標籤」：這四個字看起来像標籤，但值域上是有序的狀態）。

### 成績 `/parent/grades`

```
┌─────────────────────────────────┐
│ [孩子▾]  成績              NEW  │
│                             2   │  ← 錨點=新成績數
├─────────────────────────────────┤
│ 篩選：全部課程▾  本學期▾          │
├─────────────────────────────────┤
│ 數學                              │
│  9/3 段考一         88  [NEW]    │  ← 及格/不及格用底色，同 dashboard 既有規則
│  8/20 小考三        缺考          │  ← 缺考/補考用 app-data-chip（身分不是嚴重度）
├─────────────────────────────────┤
│ 英文                              │
│  9/1 單字測驗        45          │  ← 不及格淡紫底，呼應 dashboard spec
└─────────────────────────────────┘
```

**色調延續 dashboard spec 已定的四態**（滿分金／及格綠／不及格紫／今天橘），
不要在這頁另造一套——同一個數字在 dashboard 卡片與這裡的列表應該長一樣，
不然家長會覺得「怎麼換頁顏色意思不一樣」。

**缺考／補考用 `app-data-chip`**：這兩個是「發生了什麼事」的分類，不是「這個分數好不好」——
落在同一個坑（12）的另一邊，值域上它們跟分數高低無關，硬套色相編碼反而製造假的嚴重度訊號。

### 繳費 `/parent/payments`

```
┌─────────────────────────────────┐
│ [孩子▾]  繳費            待繳    │
│                        $3,200   │  ← 錨點=待繳總額
├─────────────────────────────────┤
│ 待付款（優先）                    │
│  發票 #1024  數學班  $1,600      │
│  期限 9/10（紅框，3天內到期）     │  ← 沿用 dashboard spec 既有的到期色階
├─────────────────────────────────┤
│ 已付款                            │
│  發票 #1018  英文班  $1,600  ✓   │
├─────────────────────────────────┤
│ 已取消（收合，預設不展開）         │  ← 「可收合收圖不收錨點」：
└─────────────────────────────────┘     已取消筆數本身若要當錨點就不能被收掉，
                                          這裡沒有把它當錨點所以整組可收

```

**互動建議**：發票詳情 Popup 內容偏長（明細＋付款方式＋補習班帳戶資訊），
建議用**底部抽屜**（`styleClass="drawer-auto"`，courses 頁與成績登錄的分數編輯器已在用
同一個 class）取代置中 dialog——單手在底部抽屜上滑動比伸手點置中 dialog 的關閉鈕更順手，
而且這個 class 已經修過 `--window-height` 的抽屜高度 bug（#282 系列），直接繼承那個修復。
**桌機版維持置中 dialog 或跟著變抽屜，這是可以晚點再談的分歧**，构图先只处理手机。

## 「可收合收圖不收錨點」怎麼用在這三頁

三頁都遵守：**帶上的錨點永遠可見，可收合的是帶以下的內容**（篩選 chip 群展開/收合、
已取消繳費單分組展開/收合）。沒有一處是「收合會把錨點數字一起藏起來」的設計——
這條在繳費頁最容易踩：如果之後有人想把整個「待付款」分組做成可收合，
要記得那個分組本身可能是另一個潜在錨點的來源，收合前先確認錨點沒有依賴它。

## 左右分欄：三頁都不需要

判準：分欄是「兩件事需要同時看」時才成立（如儀表板的今日課表＋推薦課程）。
這三頁都是「一件事、一直往下滑」的單一資料流，手機寬度也放不下有意義的第二欄——
**單欄，不分欄**。桌機寬度若要加寬，加的是列表本身的欄位密度（例如成績頁多顯示描述欄），
不是開第二欄。

## 學生帳號線（03 後排）：同頁換 scope 時的差異點

`herdr-team/backlog.md` 記著「學生帳號線已立項，排 03 後，同頁換 scope」——構圖時先記錄
差異點，不用現在做：

- **繳費頁整頁不出現在學生 scope**（學生看不到自己的繳費資訊是業務決定，
  不是這席拍板——如果之後真的要做，選單與路由層面擋，不要做成「頁面存在但顯示空狀態」，
  那會讓學生以為系統壞了）
- **出缺席／成績頁的孩子切換器在學生 scope 下不渲染**——`scope` 只含自己一個人，
  沒有東西可切，跟「單一孩子不渲染切換器」是同一條規則的另一個實例，
  **不需要為學生 scope 另寫一次「不渲染」的判斷**，切換器元件的既有邏輯（成員數 ≤1 不渲染）
  天然涵蓋這個情況
