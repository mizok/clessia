## 一、證據法升級：逐元素「計算樣式傾印」比截圖可靠（計畫席說進 charter）

截圖像素差會被日期、hover、動畫吃掉，也抓不到「看起來一樣、屬性不同」。每支 PR 改用：前後各跑**同一支** Playwright 腳本，對消費處的每個相關元素傾印 `getComputedStyle` 的 30–60 個屬性＋`getBoundingClientRect`，存 JSON 逐字比。

- 傾印要涵蓋**狀態**：hover（滑鼠移上去再傾）、展開、`hasTouch`＋`isMobile`（`pointer: coarse`）、容器／視窗邊界寬（例如 640／641、768／769）。
- 比的時候**忽略位置、只比尺寸**（`rect.slice(2)`）——整體位移（關閉鈕 +12px）會讓後面每個元素 x/y 都變。
- 用**攔截回應注入**拍不到的狀態（`page.route`，前後同一份）：清空 `data` 陣列拿空狀態、塞假資料拿有資料態、把 `workbench.mode` 改 `per_session` 讓儀表板點名列可點；PR 一律寫「注入的不是真資料」與「沒拍到什麼」。
- **同元素切 severity／tone**：示範庫只有一種態時，在頁面上把 modifier class 換掉（`classList.replace`），前後兩邊同樣有效，一支腳本量四種 severity。
- **喚醒比對要加一道精確 grep**：`@tailwind/oxide` 新增 selector 後，對「不在 `tailwind.css` `@source` 清單的所有 `.html`／`.ts`」做**完整 token 比對**（`(^|[\s"'`])token($|[\s"'`])`）；不要 grep 子字串（`max-h-[340px]` 會誤中 `h-[340px]`）。

## 二、這一輪傾印才量得出的坑（CI 全綠、截圖也過，只有傾印抓得到）

1. **`shadow-[…rgba(…)]` 會被當成「有色 shadow」編成全透明**。任意 box-shadow 一律寫 `[box-shadow:…]`（popup-menu，截圖差 ~1%）。
2. **PrimeIcons 的 `.pi { display: inline-block }` 是未分層的**，贏過 layer 內的 `inline-flex`。圖示要改 display 用 `inline-flex!`（important 才贏得過未分層）。font-size 沒這問題。
3. **未分層的全域規則贏過所有 `utilities`**：`responsive-table` 的 `.responsive-table__cell { color }` 蓋掉投影進 `td` 的 `text-[…]`（audit-log 的時間欄要 `!`）。凡是投影進未分層元件的 class，先傾印確認有沒有生效。
4. **BEM 雙底線在任意變體裡變空白**（1408 §九）再踩一次：`[&.popup-menu__item--disabled]` 編成 `.popup-menu item--disabled`。要寫 `[&.popup-menu\_\_item--disabled]`，並看喚醒比對輸出的 selector 確認。
5. **斷點差 0.02px**：原 SCSS 的 `respond-from(...)` 編成 `min-width: 值+0.02px`，Tailwind 的 `sm:`／`md:` 是整數。**恰好等於斷點的寬度前後相反**。寫 `min-[640.02px]:`／`min-[768.02px]:`；傾印要含邊界寬。
6. **`border-solid`／`border-b border-solid` 沒有 preflight 時四邊都出邊框**（3px）。只要某一邊寫 `border-b border-b-solid border-b-<色>`；`border-0` 只清寬度，要 `border-none` 才清樣式。
7. **transition 動不到 Tailwind 的 `translate-*`**（它寫的是 `translate` 屬性）：原本 `transition: transform` 就寫 `[transform:translateX(2px)]`。

## 三、「原規則從未生效」的四個實例——先量、再決定搬不搬

Angular 的 encapsulated SCSS 會把每個複合選擇器加 `[_ngcontent-x]`，所以**打不到投影內容（`<ng-content>`）與第三方元件內部**。看起來寫了、其實從沒命中：

| 規則                                                                       | 為什麼沒命中                                 | 處置                                                                                   |
| -------------------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------- |
| `todo-banner__text strong { font-size/weight }`                            | `<strong>` 是消費頁投影的                    | 不搬（搬了高度 +1px）                                                                  |
| `.page-actions__cta { width:100% }`（`styleClass` 掛 PrimeNG 內部 button） | 內部 button 沒有這個元件的 content attribute | 計畫席裁**修**（#1363，`w-full justify-center`）；手機 dock 按鈕原本是靠左 114×42 小鈕 |
| `page-band__aside > :only-child { margin-top:auto }`                       | 投影節點                                     | 不搬（第一版搬了，傾印 `margin-top 0→76px`）                                           |
| `band-anchor__sub b`、`:host` in `ViewEncapsulation.None`                  | 投影／None 下 `:host` 不命中                 | 不搬／原樣保留                                                                         |

做法：**搬之前用傾印量「換版前」該元素的計算樣式**；沒生效就不搬、PR 寫明，是否修好另裁（修的話走小單或同分支補一顆 commit，PR 寫「1:1 原則的例外」與證據）。

## 五、prettier 與 textContent（1200 §一的延伸）

長 class 會讓 prettier 把 `<p>…{{ x }}…</p>`／`<h3>` 折行，**前後空白進了 `textContent`**。元素文字用 `.trim()`／`toContain` 斷言的不在乎；**傾印比對 `textContent` 才抓得到**（empty-state 描述）。有疑慮就 `<!-- prettier-ignore -->` ＋ 元素與插值同一行；已折行的要手動拉回來（ignore 只保留現狀）。

## 六、作業守則（這一輪的違規與教訓）

- **只 `git add` 指名路徑，不用 `git add -A`／`git add .`**：我的 wip commit 把整個 `.pw-regression/`（90+ 支腳本、+2087 行）帶進 #1355，計畫席擋下來；補一顆 `git rm -r --cached` ＋ `.gitignore` 才收尾。`.pw-regression/` 現在在 `.gitignore`。
- **推過的分支不 `-f`**、不 rebase；落後 main 且衝突時用 `git merge origin/main`（Z11 的 #1369）。我在 Z6 對尚無 PR 的分支用了 `-f`，計畫席寬容但規則照舊。
- **`git checkout --detach origin/main` 拍「前」之前，工作樹要乾淨**（先 commit）；不然 checkout 失敗被 `| tail` 吞掉，你拍的「前」其實是「後」。每次切換都重啟 `nx serve web`。
- **`nx serve api` 與 `nx serve web` 不要同時起**（nx daemon 的 SQLite 鎖，`DatabaseBusy`）；一個一個起。
- **這個環境的分類器擋 `rm -rf` 與對 `/tmp` 的刪除**：快照目錄每次換新名字（`snapz1`、`snapz2`…），不要刪。
- **zsh**：`"<$sel[ >]"` 會被當陣列索引報 `bad math expression`——寫腳本用 bash；`echo "====="` 會被當指令。
- **session 額度**：每支 PR 約吃 3–4% Session；撞上限前把當下這支推成 draft 就好（計畫席的指示），訊息會排佇列。Ctx 這一輪 45% 走完 12 支。
- 一次只一支 ready；PR ready 後在**新分支**繼續下一支，不要結束 turn 等「過」（1200 §八）。
- 每次回報「證據」一行：PR 編號、head sha、CI 結果＋傾印／截圖結論；**自己抓到的問題與「沒拍到什麼」寫進 PR**，計畫席讀的是描述不是對話。

## 七、Z12 的 A 方案與 T4 的接口

- `responsive-table` 沒有 utility 化：樣式是**同目錄 `responsive-table.component.css`，內容＝原 SCSS 的 sass 編譯輸出**（`ViewEncapsulation.None`、**仍未分層**、`styleUrl` 載入）。原因：帶 class 的元素由 3 支 directive（`HostBinding`／`renderer.addClass` 約 15 處動態 DOM）與 5 個消費頁模板自己掛；未分層讓它贏過 layer 內的 utility，進 layer 會喚醒消費頁 `td` 上本來被蓋掉的 `py-8` 等 5 頁的 utility。
- **「編譯驗」怎麼做**（可重用到任何「SCSS→CSS 原樣搬」）：`npx sass --no-source-map --style=expanded --load-path=apps/web/src/app <原 scss>`，輸出與新 `.css`（去掉檔頭註解）都過 `prettier --stdin-filepath x.css` 後 `diff`，**對 `origin/main` 的原檔與對新檔各驗一次**，兩次都要空。連從未生效的 `:host`（None 下不命中）也原樣留著，不然 diff 就不空。
- **T4（進 layer 的那支）接口**：要把這份 `.css` 放進哪個 layer，先決定消費頁 5 個 `td` 的 utility（leave 的 `py-8 text-zinc-500` 等）要不要生效——放 `utilities` 以下就會生效（視覺變動），要不變就得放在 `utilities` **之後**的新 layer（要同步 `tailwind.css`、`styles.scss`、`app.config.ts` 三處 layer 順序，A26 守）。連帶：Z8 `audit-log-dialog__time` 的 `text-[color:…]!` 在規則進 layer 並排序後可以拿掉。
- 全站 `.scss` 只剩 `app.component.scss`、`styles.scss`、`shared/_breakpoints.scss`（S 批／T4），`harness.test.mjs` 的 `unmigratedPageDir` 已 fallback 到 `app/shared`、`app`，這兩個遷完要再改。
