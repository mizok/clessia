## 一、量 Supabase 延遲不用碰正式站

- **`x-envoy-upstream-service-time` 回應頭就是「PostgREST＋DB」的時間**（Supabase 閘道量的）。
  用 curl keep-alive 連打（一條 `curl` 帶多個 `--next`，`-D -` 印頭、`-w` 印 TTFB），
  TTFB 減它就是「網路＋閘道」。不需要臨時路由、不需要 DB 密碼。
- **公開金鑰就夠**：`npx supabase projects api-keys --project-ref <ref> -o json`（CLI 已登入）。
  業務表 RLS 無 policy，anon 查回 `[]`，但完整走過閘道→PostgREST→DB，延遲是真的。
- **對照組 `/auth/v1/health`**：同一閘道、不碰 DB。它跟 REST 的差 ≫ envoy 時間，就是閘道對 REST 的處理。
- 2026-10-15 數字：PostgREST＋DB 1–15ms；REST TTFB 中位 ~165ms；health ~105ms（台灣、`colo=TPE`）。
  **所以升 Supabase 運算規格對速度幾乎無用**，有用的是少往返或繞過 REST 閘道（Hyperdrive）。
- **`[probe]` 的每支耗時含排隊**：計時從呼叫 fetch 開始，而 Workers 每請求同時連線上限 6 條。
  「最慢」遠大於單支正常耗時（`/api/me` 8 支、最慢 759ms）就是排隊的形狀；查詢越多的端點平均越高。

## 二、Pages `_headers` 的實測行為

- 用**檔名前綴**比對（`/main-*`、`/chunk-*`…），不用 `/*.js`：前綴 splat 是確定支援的形狀。
- **`_headers` 不會套到 SPA fallback 的 HTML 上**：`/chunk-不存在.js` 被 `_redirects` 改寫成 `index.html`，
  回應頭仍是 `max-age=14400`，沒有吃到 `/chunk-*` 的 immutable（2026-10-15 部署後 curl 實測）。
  所以「不存在的 chunk 被快取成一年的 HTML」不會發生，不用為它加 404 規則。
- 靜態檔原本的 `max-age=14400` 是 zone 的 Browser Cache TTL；HTML 是 Pages 預設 `max-age=0`。
- 沒有 PR 預覽部署 —— `_headers` 只能合併後在正式站驗，正控（真 chunk）負控（假 chunk）都要 curl。

## 三、快取類授權改動的 spec：上限要寫死，突變要自己跑

- **spec 裡引用 TTL 常數 = 守不住上限**：TTL 改成 10 分鐘，引用常數的測試跟著變長、全綠。
  上限寫死在 spec（`REVOCATION_LIMIT_MS = 30_000`），改上限就是改政策，兩邊一起動。
- reviewer 再抓到兩個洞，都是這一類該預設就補的：
  1. **邊界那一刻**：只推進 TTL+1 守不住 `>=` 改 `>`。要推進**剛好** TTL 並斷言已拒絕。
  2. **key 隔離**：key 改成固定字串全綠。要 A（有權）請求後 TTL 內換 B（無權），B 被拒且 B 查了自己的。
- 突變的做法：`cp` 原檔到 `/tmp`，`sed -i ''` 改一處、跑 spec、`cp` 回來；每個突變都要能編譯。
- **模組層級的快取會跨測試殘留**：在 `apps/api/src/test-setup.ts` 的 `afterEach` 清。
  快取放獨立、零 import 的檔（`lib/identity-cache.ts`）—— setup 若 import `middleware/auth.ts`，
  會搶在各 spec 的 `vi.mock` 之前把真模組載進來。

## 四、操作上的坑

- **`cat > 檔案` 後面沒接 heredoc 會等 stdin 卡死**（本席 10-15 卡過一次 120 秒）。
  長內文用 Write 寫進 scratchpad 再 `--body-file`，herdr／gh 指令尾巴加 `</dev/null`。
- 全量 api vitest 在機器負載高時會有單支 5 秒逾時（10-15 是 `contact-logs.spec.ts`），單獨跑綠。
  回報時寫明「全量 N/N+1，唯一紅的是哪支、單獨跑綠」，不要只寫「綠」。
- **`pgrep -fl` 會印出整串環境變數（含資料庫密碼）**。查程序用 `pgrep -f "<pattern>"` 只拿 pid。
