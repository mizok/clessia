## 二、會騙人的東西

- **暫改 `environment.ts` 的 api port 會讓 `system-clock.service.spec.ts` 變紅**（spec 硬寫 `localhost:8787`）——Stop hook 會擋「這一輪弄壞了 1 支測試」，而你沒碰那支。換 port 取證只在截圖那幾分鐘改，**commit／跑測試前一定 `git checkout apps/web/src/environments/environment.ts`**。
- **突變驗證必須能編譯**：拿掉一個 signal 欄位或 `if (false)` 只會造成 TS／lint 錯誤，spec 沒有「紅」只有「跑不起來」，不算數（我第一次兩次都栽在這）。用 `>` 改 `>=`、`> 1` 改 `> 0`、`&& false` 這類型別不變的改法；還原後再跑一次確認回綠。reviewer 會問，先做。
- **跑多個 web 單檔 spec**：每個 `--include='**/x.spec.ts'` 要單引號，否則 shell 展開、輸出什麼都沒有（我一度以為在跑）。
- **A6 稿的對話框有持續動畫**：`locator.screenshot()` 會卡在「waiting for element to be stable」逾時。改 `page.screenshot({ animations: 'disabled' })`（視窗截圖）。稿內選擇器：班級列 `[data-cid]`、學生列 `[data-sid]`、批次鈕 `[data-absent]`／`[data-add]`／`[data-revert]`。
- **`<dialog>.showModal()` 的 top layer 會蓋住 body 層的 overlay**：`student-autocomplete` 原本沒有 `appendTo`，放進 `<dialog>` 候選清單看不到。已加可選 `appendTo` input（預設不變）；要在對話框裡用它，用 PrimeNG `p-dialog`（自己管 z-index）＋傳 `appendTo="body"`，照 A6 做置中對話框（#1521）。**不要用原生 `<dialog>`**。
- **疊 PR 在「被 squash 合併」的分支上**：base 分支合進 main 後，疊的分支直接 `git merge origin/main` 會在同一檔衝突（兩邊都有 G11 的內容）。處理：`git diff <疊的前一個 head> <我的 head> -- <檔案> > patch`，`git checkout --theirs <檔案>`（取 main 版）、`git add`，再 `git apply --3way --index patch`。

## 三、設計決定（下一個做同類頁會再問）

- **「其餘標記缺考」排除補考列**：`status:'makeup'` 且沒分數是「等他補考」，不是「沒來」——reviewer 在 #1520 抓到。凡批次改狀態的動作，先列出每個狀態值逐一問「這批人該不該被動」。
- **加進編輯器的新列不算未存變更**：沒輸入分數就沒東西可存；存一筆空分數的 scored 是假資料（API 對 `score:null＋scored` 會刪列，也拿來清測試資料）。輸入分數或標缺考後才 dirty。
- **班級篩選用 `classIds.includes`，班外學生沒有 classIds**：加入時要清掉篩選，否則剛加的人立刻被篩掉。
- **「第 1 名／1 人」沒有資訊量**：`classSize ≤ 1` 不寫名次，只寫班平均。
- **A6 稿與全站慣例衝突時慣例贏**（1910 §四）在這輪的實例：A6 的「新」徽章不放（不是長期該有的標記）。**但「加入」標要放**：它標的是班外學生，有資訊量，跟「新」不同類；放畫面（`ScoreRow.added`），不寫進備註欄。

## 五、家長端課表（#1523）讀 diff 抓到的兩種資料歸屬錯誤

- **「後回來的就贏」是兩個 bug 不是一個**：①別週切孩子，Hero 用的是「本週資料」那個 signal，它只在**本週**才重查，所以切到別週再換孩子，Hero 還是前一個孩子的「下一堂」。②快速切週／切孩子，先送出的慢回應晚到會蓋掉後送出的。**任何「依孩子（或依週）載入」的頁面**：回應存成 `{childId, data}`、讀的時候比對現在的孩子；請求走 `Subject＋switchMap`，不要在 `effect` 裡直接 `subscribe`。
- **要有「舊資料不能殘留」的 spec，而且要看標題與列表兩處**：新孩子的請求用一個**不 complete 的 Subject** 卡住，斷言畫面不含舊孩子的班名；`forkJoin` 要等 `complete()`，測試裡 `next()` 之後記得 `complete()`（HTTP 會自己 complete，Subject 不會）。
- **突變驗證要確認每個防護真的有用**：我第一版把「週別」也綁進去，拿掉比對全綠 —— 因為週曆只畫 `days()` 內的日期，別週資料本來就畫不出來，那段是死碼，刪掉。防護拿掉仍綠＝要嘛 spec 有洞、要嘛防護是多餘的，兩種都要處理。
- **別拿「同一天、同班名」當比對鍵就收工**：作業比對一度只比日期，spec 的 fixture 把別班那篇排在後面，`find` 先撈到對的所以綠；**把會誤中的那筆排最前面**才抓得到。
- **app-child-switcher 是兩段式**（點 pill 開 popover、再點 `.child-switcher__list-item`），腳本不能直接 `getByRole('button', {name: 孩子名})`。parent03 的三個孩子：張品妍（沒課）、張宇軒（有停課、小考、請假）、范芷寧（只有過去的課＋一堂停課）。
- **今天是週六、示範庫沒有代課堂**：「上課中」「代課」chip 實機看不到，只能靠固定時鐘 spec；PR 要明寫「實機未驗」。
- **「資料還沒回來」不能被說成「沒有」**（#1524）：Hero 在新孩子資料回來前一度寫「接下來兩週沒有課」——**載入中、失敗、真的沒有是三種狀態**，各有各的字（載入中…／只寫名字＋body 的失敗訊息／沒有課）。判斷靠「資料是不是這個孩子的」（`heroReady`），不是靠陣列是不是空的。
- **spec 的 `beforeEach` 要把共用 mock 重設回預設實作**：前面的測試用 `mockImplementation`／`mockReset` 換掉它，會漏到後面的測試，新寫的測試因此「拿不到卡片」而炸在 `undefined.click`，看起來像自己的 bug。reviewer 把 `homework$` 的 `switchMap` 改 `mergeMap` 仍全綠——**每條 `switchMap` 都要有一條「先送出的慢、後送出的快、快的先回」的 spec**，不是只守某一條請求流。
