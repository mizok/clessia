## 一、Playwright 的 `:visible` 不等於點得到 —— 要看祖先（#1257，自己的誤報）

`:visible` 只看元素**自己**有沒有尺寸。課程列表收合的課，班級列自己 91px 高，但祖先 `overflow-hidden` 高 0、外層 `inert` ——
`app-class-row:visible` 照樣選得到它，點下去被「課程標頭」攔截。我據此開了一張「⋯ 被擋」的單，**真機驗才發現是收合**。

- 要判斷「使用者點得到」：對元素中心點 `document.elementFromPoint`，命中的是它自己或它的子孫才算。
- 截圖腳本選「展開中的」列：`section:has(button[aria-expanded=true]) app-class-row`。
- **開單前先在真機或用命中測試驗一次**，Playwright 的 `intercepts pointer events` 只說「有東西蓋著」，不說「使用者也被蓋著」。

## 二、頁面接頂欄分校的四種形狀（#1138，1552 charter 一的延伸）

| 頁面形狀                       | 接法                                                                                                                                                                         | 實例                                        |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 手動 `load()`                  | `campusId = campusCtx.id`；`toObservable(id).pipe(skip(1))` → 回第一頁重查                                                                                                   | changes、enrollments、reports、staff、leave |
| 已有 effect 監看 `listQuery`   | 只在 `toObservable(skip(1))` 把頁碼設 1，**不要再自己 load** —— 同一輪變更 effect 只跑一次，用 `HttpTestingController` 驗只發一支                                            | exams                                       |
| **必須選一間**（沒有「全部」） | `campusId = computed(() => ctx.id() ?? local())`；頂欄有值就收起頁內下拉；`toObservable(campusId).pipe(filter(Boolean))` 觸發載入（**不 skip**，預設值落地那次就是初次載入） | 成績總覽・班級                              |
| 手機篩選對話框也有分校         | 對話框的分校欄、snapshot 的 `campusId` 一起拿掉；必選頁則傳空 options、模板 `@if (options?.campusOptions?.length)` 藏欄                                                      | exams、student-view、class-view             |

- **「清除篩選」不動分校**（全站 context，計畫席裁）；所以空狀態要說明範圍：`<app-empty-state campusScoped>` 或自訂空狀態放 `<app-campus-scope-note />`（只在當頁 `use()` 且選了分校時出聲）。
- 分校清單另有用途（表單、名稱對照）時 `CampusesService` 照留，只拿掉篩選（staff）。

### 盤點的坑：選項長得像篩選，不代表它是篩選

- 「有『全部分校』選項」≠ 列表篩選：notifications 的「分校範圍」是**發公告的對象**，值進 `create({ campusId })`。
- 「選項清單裡沒有『全部』」≠ 必選：student-view 的下拉 `[showClear]`、空值不帶參數，跟頂欄同形。
- **盤點時要追到值最後被送去哪**，不能只看模板。我兩頁都判錯，各花一則更正留言。

## 三、spec 的三個坑（接頂欄時都會撞到）

- 載入改由 `toObservable` 觸發後，`onCampusChange()` 之後要先 `fixture.detectChanges()` 請求才會出去。
- 測試先手動塞 `courseGroups` 再 `detectChanges` → 觸發的那次真載入會把塞的資料蓋掉。先讓載入跑完並 flush 掉，再塞資料。
- `vi.fn(() => of(x))` 沒宣告參數，`mock.calls[0][0]` 編不過（TS2493）：`mock.calls as unknown as [Record<string, unknown>][]`。
- API 參數名各支不同：校內考是 `campus_id`，學生、報名、人員是 `campusId`。斷言前先查 service。

## 四、大批 SCSS → Tailwind 用 fork 平行（C3：十一支 dialog、1,699 行）

- 依行數分三批給 fork，**`tailwind.css`、`tools/agent-harness/*`、commit 都留給自己**。fork 各自跑自己那批的 spec 和 tsc，主 session 再收 `@source` 與 `harness:write`。
- **A27 要 44px 寫在基底**：原本只在 `pointer: coarse` 才放大的鈕會變成全裝置 44px（關閉鈕、刪除鈕）。截圖前後比較時，這就是唯一的差異來源（整體下移 2–3px）。
- `[class.x]` 帶不了 `[ ]` 的條件樣式：用 `aria-pressed` 搭配 `aria-pressed:`／`group-aria-pressed:`，順便補語意；hover 要寫 `not-aria-pressed:hover:`，因為 Tailwind 把 aria 排在 hover 前面。
- 前後比較的做法：同一支截圖腳本在分支與 `git checkout --detach origin/main` 各跑一次（中間要重啟 dev server），再用 canvas 做像素差與並排圖。PrimeNG 的 DynamicDialog **按 Escape 關不掉**，要點 `.dialog-header-inline__close` 或「取消」。

## 五、小坑

- **auto mode 會擋 force push**：推上去的分支不要 rebase。開 PR 前用 `git merge-tree --write-tree origin/main <分支>` 確認無衝突即可（計畫席同意）。
- `npm run harness:write` 可能重排 `kb/wiki/roadmap.md` 的表格空白：不是你的改動就 `git checkout --` 還原，再跑一次 harness 確認仍綠。
- 屬性寫法的布林 input（`<app-empty-state campusScoped>`）要 `input(false, { transform: booleanAttribute })`，否則 typecheck 報 string 不能給 boolean。
- 甘特課塊是固定高度：標籤換行就被裁掉、一個字都看不到。照 A6 `.gb__tags` 改成一行（`[&>span]:flex-nowrap`），長字 `truncate` 並把全文放 `title`（#1194）。
- 一次只開一支 PR，但下一頁可以先在本機做完、推上分支；上一支一合就開，計畫席讀得很快，佇列不會停。

## 六、疊 PR 在 squash 倉庫裡解衝突：自動生成的帳面不要手合（grades G1→G2a→G2b→G3）

下層 squash 合併後，上層分支上還留著下層的原始 commit，`merge origin/main` 一定撞到三個地方：
`tailwind.css` 的 `@source`、`scan-scope.json`、`scss-ledger-baseline.json`（偶爾還有 `dual-track-baseline.json`）。

- `tailwind.css` 手合：只留**最終形狀**（例：exams 已收成一行目錄，就丟掉另一邊的八行單檔）。
- 自動生成的三支 JSON **不要逐行合**：`git checkout origin/main -- <那幾支>`，再跑 `npm run harness:write` 重生成，最後 `git diff origin/main --stat` 確認只剩本片的檔。
- `harness:write` 會順手重排 `kb/wiki/roadmap.md` 的表格空白：`git checkout -- kb/wiki/roadmap.md`。
- 加 `@source` 的錨點行要選 main 上**一定在**的那行（例：`dashboard`），不要選上一片還沒合的那行 —— python 的 `assert` 會擋，但會讓整串指令後半跑在錯的狀態上。

## 六之二、fork 平行轉換的收尾（sessions 8 支、grades G1／G2a／G2b）

- **分工固定**：fork 只動自己那幾支元件；`tailwind.css`、`tools/agent-harness/*`、commit、PR 一律留給主 session。每批 fork 的提示都寫明「不要碰另一支 fork 的目錄／外殼」。
- **主 session 不用乾等**：fork 跑的時候先做它們不碰的事 —— 收 `@source`、清 `mobile-first-baseline`／`aria-icon-button-baseline`／`CONTRAST_EXEMPT` 的過期條目。`harness:write` 只寫帳面，**fork 還在跑時也可以跑**（Stop hook 紅燈時就靠它轉綠）。
- **等的訊號**：背景跑 `until [ -z "$(find <目錄> -name '*.scss')" ]; do sleep 20; done`。SCSS 刪光不代表 fork 跑完 spec 了，**全套驗證要等每支 fork 的完成通知都到**。
- fork 回報「外殼的 spec 紅」時，先看是不是主 session 正在改那支 —— G2a 就是，fork 照實回報、主 session 自己修。
- 斷線（額度）可能把 fork 切在半路：復活後先 `git status` 加 `find … -name '*.scss'` 加 `grep styleUrl`，確認每支 fork 的結果都在工作樹裡，少的自己補，再跑驗證。
- 收尾**只開一支 PR**、喚醒比對整支跑一次（計畫席裁定），截圖前後比對逐張看並排圖，不能只看差異百分比。

## 七、頁內三選項離開對話框（成績登錄 Q3）

- `canDeactivate(): boolean | Promise<boolean>`，路由那行的型別要跟著改；開 `<dialog>.showModal()`、把 resolve 存起來，三顆鈕各自 settle。
- 「儲存後離開」：呼叫存檔，**在 `savingChange(false)` 之後 `setTimeout` 再判斷 `dirty`** —— 成功時 `saved` 會先把 dirty 清掉；失敗時 dirty 還在 → 留下來。不要只聽 `saved`，失敗時它不會來，Promise 永遠不 resolve。
- jsdom 沒有完整的 modal `<dialog>`：spec 裡把 `HTMLDialogElement.prototype.showModal／close` 換成只切 `open` 的替身。
- 放行時把 `dirty` 設回 false，不然 beforeunload 的 effect 還會攔。

## 八、截圖腳本的三個新坑

- **PrimeNG `p-inputnumber` 失焦才提交**：Playwright `fill()` 之後要 `press('Tab')`，否則畫面上的數字不算改過（合計、儲存列都不會動），而「按返回時跳出對話框」反而會因為點擊造成的失焦而出現，看起來像對話框比儲存列先到。
- 挑一場考試做實打時，**先篩「進行中」**：本機示範資料大半已結束，已結束的頁是唯讀，填不了分數。
- 預設分校可能沒有學生（學校考試頁）：腳本依序換分校選項，直到清單有列。
- 喚醒比對命中 0 時，若新增的 utility 裡有 PrimeFlex 常見名（`flex-row`、`ml-1`、`p-12`、`m-auto`、`md:block`），**手動 grep 一次**確認命中的都在 `@source` 範圍內 —— 腳本只看 `class="…"`／`styleClass`／`[class.x]`，漏網的寫法它看不到。

## 九、herdr：對方輸入框不是空的就**等**，不要「在開頭說明」

計畫席的輸入框裡常有**使用者正在打的字**（`❯ 1225 1240 … merged`）。這一席有一次照舊送出，兩段被接成一則，計畫席還得去查「1225 merged」是不是事實（不是）。
做法：送之前用迴圈等輸入框清空（`herdr agent read … | tail -7 | grep -q '❯ *$'`，每 20 秒一次、上限 10 分鐘），清空了才送。
