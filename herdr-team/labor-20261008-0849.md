## 三、`.scss`→`.css` 搬家的三個坑

1. **`//` 註解 sass 會丟**（只留 `/* */`）。先在 `.scss` 上把整行 `//` 機械轉 `/* */`（宣告零改動），再編譯。副作用：`/* */` 夾在巢狀規則中間，sass 會把一條規則**拆成兩條相鄰同選擇器**（語意不變）。所以「編譯輸出 diff 為空」要先**去註解 → 合併相鄰同選擇器 → 刪空規則 → prettier → `diff -B`**（`postcss` 十幾行腳本，見 PR #1386 描述）。
2. **gate 讀檔路徑改了不會報錯，只會空轉**。這一輪抓到的真陷阱：`styleCarriers()`（ghost-token 的 `defined`、usage-contrast 的載體）只走 `.scss` 與 inline `.ts`，`styles.scss` 一刪，**token 定義和全域對比配對整批消失，gate 仍綠**。能發現是因為 `--app-header-height` 的幽靈 token 提醒憑空消失。**搬家後必做**：把新檔逐項改壞、跑 `check-harness`、每道都要紅（寫成 `harness.test.mjs` 一條整支測試，6 項）。這對「改了 `recordScope` 的 exts 卻漏改實際走檔邏輯」的盲點通用。
3. **`unmigratedPageDir` 這類「挑一個還沒遷的目錄當對照」的測試前提會消失**。全部遷完後改成固定的非 `@source` 目錄（`app/core`），需要「同目錄別的 .scss」就在測試裡暫放一支。

c6（viewport 單位）**不是**陷阱：`check-harness` 與 `pre-guard.rules.json` 在 T1 就有 `.css` 載體。我在設計說明裡誤判成「會靜默失守」——**寫「X 會壞」之前先跑一次 X**（這次是改壞 `styles.css` 加 `100vh` 才證實本來就紅）。

`package.json` 沒有 sass 依賴：`npm ls sass` 顯示 `sass@1.97.1` 是 `@angular/build` 自己的相依，不用拆。

## 五、Tailwind 4 與優先序的幾個一手事實

- **`hover:` 變體編出 `@media (hover: hover) { .x:hover {…} }`**（`@tailwindcss/node` 的 `compile(css,{base})` 編本專案 `tailwind.css` 實證）。後果：**觸控裝置上 hover 底色不再黏住**——舊 SCSS 的 `&:hover` 在觸控模擬下會黏。傾印印證（觸控手機＋hover 態前後差一筆）。1:1 搬家時這是預期差異，PR 要寫。
- **未分層元件 CSS 贏過 `legacy`**，`legacy` 贏 `primeng`，`utilities` 贏 `legacy`。所以 T4 後 `utility 第一次生效` 的清單要事先列：leave 空狀態 `py-8`（列高 44.5→84.5）、ops-log 時間欄 `text-zinc-500`、invoice-detail 金額表頭 `text-right`、parents／staff 列 `transition-colors`（120ms→150ms）。**這類「模板作者早寫好、被未分層規則蓋掉」的樣式是搬 layer 的主要視覺變動**，PR 要逐項列給使用者看。
- `transition-colors` 贏過 `transition: background-color .12s, box-shadow .12s` 後，被丟掉的是 box-shadow 過渡（該列本來沒有 shadow 變化）。
