## 二、「拿小樣本的『沒有』推論整個資料集的『沒有』」—— 我犯了兩次

| 我寫進地圖的                             | 實際                                                                    |
| ---------------------------------------- | ----------------------------------------------------------------------- |
| 「整個本機資料庫**沒有任何一筆**餐記錄」 | `select count(*) from meal_records` = **18**。我抽查了 5 個日期都是空的 |
| 「本機**沒有**已收款的帳單」             | 37 張裡 **9 張** `netPaid > 0`。我**只點開了第一列**                    |

**這兩句話的殺傷力不在於它們錯**，而在於它們**關掉後面的人補驗的路** ——
讀到「本機一筆都沒有」，下一個人就不會再去找。

**可操作版本**：宣告「本機沒有 X」之前，**問資料庫不要問畫面**：

```sh
psql "$DATABASE_URL" -c "select count(*) from <表> where <那個條件>"
```

寫「未驗」時把這一步的結果寫進去 —— **「查過 DB，全庫 0 筆」與「我看的那幾筆沒有」
在地圖上長得一模一樣，強度卻完全不同。**（已收進方法頁坑 11。）

> **同一個形狀在 labor-5 身上也出現了**：它寫「三個孩子的帳單全是 unpaid」——
> 對 parent01 成立，對全庫不成立。**這不是誰粗心，是這個工作天生的形狀**：
> 你永遠是從某一個帳號、某一天、某一列開始看的。

## 三、seed 造展示狀態的三條判準（#746 的產物）

### 1. 加法優先，但真正的規則是「不要翻掉某個狀態的最後一個實例」

初版我寫「既有資料一列都不動」，後來因為 c2 的 gate 做不到（見下），改成翻既有列。
**兩者都不是規則本身**：

- 翻 2 位家長（共 16）、2 位人員（共 101）→ active 那邊還有 14 與 99 個實例，**兩種狀態同時存在**
- 把 >100 筆成績塞給某個孩子 → 截斷警告永遠掛在他身上，**那一頁的「正常清單」狀態在他身上消失**

**第二個才是不行的那種。** 這條是 labor-5 擋下我原本的做法時提出的，我把它推廣到全部 24 筆。

### 2. 為了驗一個狀態去毀掉另一個已驗狀態 —— 淨損，不做

兩個實例（都寫進地圖標成「不值得」）：

- **公告空狀態**：全庫唯一那則家長公告是全 org，要做出「目前沒有公告」只能刪掉它 ——
  而「有公告」是已驗狀態
- **`attendance_retroactive_days` 0 → N**：會讓老師課表上所有舊課堂變「點名已截止」，
  把剛驗完的「開始點名／修改點名」整批換掉

### 3. seed 靠名字找既有資料 → 一定要加「大聲失敗」的保險

這一段的失敗模式是**靜默**：上游 seed 改了名字，我的區塊什麼都不做而 `exit 0`，
**seed 看起來成功、展示狀態一個都沒造出來**，下一個人打開頁面看到的跟以前一樣，
然後把「未驗」再抄一次。

做法：檔案最後一段 `RAISE EXCEPTION` 點名（依賴的既有資料 6 項 + 產出 8 項），
**塞陷阱驗過它會紅**。

## 四、c2（`ba_*` 不得直寫）在 seed 裡的邊界

**`supabase/seed.sql` 對 c2 有 9 筆永久豁免，那個數字是上限不是額度。**

我第一版為了「多重角色 / 停用家長 / 單孩家長」建了 8 個新帳號 → `ba_*` 寫入變 11 筆 →
**harness 紅**。計畫席的裁示是「改做法不是改豁免數」。

**零新帳號的做法**（可直接複用）：需要 `user_id` 的東西全部掛到**既有 demo 帳號**上，
只寫 `user_roles` / `parents` / `staff` 這些業務表。

- 多重角色 + 只有某個權限的管理員 → **同一個帳號**（給一位沒帶課的老師加 admin 角色、
  權限只給那一項）
- 單孩／無孩家長 → 給老師帳號加 `parent` 角色與 `parents` 列
  （`parents.user_id` **沒有唯一約束**；`staff` 有 `UNIQUE(user_id, org_id)`）

> ⚠️ **已知的耦合**：這樣做出來的「單孩／無孩家長」同時是多重角色帳號，
> 驗它們要先過 `/select-role`。**沒有更好的做法** —— seed 造的每個帳號都已經是
> admin/teacher/parent 其中之一，而替代方案（拔既有家長的關聯、拿掉老師的 teacher 角色）
> 會留下更難解釋的殘骸。**理由寫在 `seed.sql` 的註解裡。**

**試跑才會發現、讀原始碼看不出來的兩個約束**（寫 seed 必踩）：

1. `leave_requests.submitted_by`、`attendance_records.recorded_by`、
   `academy_*.created_by`、`meal_records.created_by`、`invoices.created_by`…
   **全都 FK 到 `ba_user`** —— 填 `'seed'` 這種字串會炸，要填真的 user id
2. `sessions_assignment_consistent_chk`：`assigned` 必須有 `teacher_id`、
   `unassigned` 必須沒有，**兩者不能混**

**驗 SQL 不要靠重跑 seed**（而且 `npm run db:reset` 可能被權限擋下）：

```sh
printf 'BEGIN;\n\\i /tmp/xxx.sql\nROLLBACK;\n' | psql "$DATABASE_URL" -v ON_ERROR_STOP=1
```

## 五、「元件原始碼寫了什麼」與「使用者看到什麼」之間隔著一層版面計算

方法頁坑 10 的來源。兩個實例都在 `_shared/audit-log-dialog`，**兩句都讀起來像量過的事實**：

| 原始碼上看到的                                        | 實際畫面（1504px）                                                                                                                            |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `expandControlPosition="start"` → 「每列可展開」      | **一顆展開鍵都沒有** —— 由 `responsive-table` 的 `hasCollapsedColumns()` 決定，四欄 min-width 合計 640px、對話框內容區塞得下 → 不收合就不產生 |
| `currentPageReportTemplate: '顯示 {first} - {last}…'` | **顯示 `第 1 / 2 頁`** —— 容器 ≤ 768px 時切 compact 分頁器並改寫樣板；800px 寬的對話框正好落在門檻內                                          |

**判準**：元件有 `ResizeObserver` / `containerWidth` / `collapsible` / `compact` 這一族字眼，
**就不要從原始碼下結論**，去量；反過來量到的也要標寬度。

## 七、跨席協作：三個具體的坑

### 1. 改共用資源之前也要發訊息，不只改完發

我對 labor-5 說「資料就位，可以開始驗」之後，因為 gate 退回又改了庫 ——
它正在量，`demo.*` 帳號整批消失，它登入成功的下一次呼叫就變 403。
**如果它沒去查 DB，這會變成一支「新家長帳號登入後被踢回 /login」的假缺陷。**

**約定**：改共用狀態前發一則、改完發一則「FROZEN」。

### 2. 同儕的「狀態宣稱」保鮮期極短，技術判斷通常可信

labor-5 說「`teacher/schedule.md` 在 main 上還是 seedling」→ 查了是 `developing`
（它讀的是自己 detached HEAD 的本地檔）。它說「#737 已修」→ 查了是 **OPEN**。
**但它三個 `grep` 的技術判斷全部正確。**

**分法**：技術判斷自己跑一次它引用的指令；**狀態宣稱一律自己查**
（`gh pr view <n> --json state`，一次呼叫的事）。

### 3. 登入窗口要排，因為 auth cookie 是 host 層級不分 port

**任何一席登入都會把其他席踢掉。** 做法：一次登入跑完一整批，
**每次量測前打一次 `get-session` 斷言身分**，不對就重登再量。
被踢了自己重發連結（**在 worktree 根目錄**，`WEB_URL` 要自己補，
`.dev.vars` 只在主 checkout）：

```sh
set -a; source <主 checkout>/apps/api/.dev.vars; set +a
WEB_URL=http://localhost:4200 LOGIN_EMAIL=admin@demo.clessia.app \
  npx tsx apps/api/src/scripts/login-link.ts
```
