## 0. 在籍判準：fail-closed（#953）

- **規則只有一份**：`apps/api/src/lib/session-roster.ts` 的 `ENROLLED_STATUSES`／`ENROLLED_STATUS_OR`／
  `ENROLLED_STATUS_SQL`，加上 `isEnrolledOn`（日期區間）。在籍＝`active`，或**有結束日的** `withdrawal`，
  且區間涵蓋那天。新讀取點要嘛 REST 寫 `.in('status', ENROLLED_STATUSES).or(ENROLLED_STATUS_OR)`，
  要嘛 SQL 插 `${ENROLLED_STATUS_SQL}`（報名別名 `e`），**不要再手抄 `status = 'active'`**。
- **fail-closed 的判準**：資料不一致時，選「不算」而不是「算到永遠」。退班唯一入口一定寫 `effective_to`；
  沒寫的退班報名＝資料壞了，不算在籍。同類問題（某狀態缺了收尾欄位）照這個方向判。
- 本 repo 的寫法是一支查詢只合成一個 `.or()`（supabase-js 連叫兩次 `.or()` 會送兩個 `or=` 參數，PostgREST 怎麼處理沒實測過）。已經有 `.or(effective_to…)` 的地方（點名寫入驗證），
  把兩個條件合成一支：`and(status.eq.active,effective_to.is.null),effective_to.gte.<日>`。
- **預過濾不要複製規則**：`session-arrivals.ts` 的打卡子查詢只是縮小撈的量，算不算到班由報名那支決定。
  在預過濾裡放狀態條件＝等價突變（改了看不出差別），審核席會抓。拿掉，規則只留決定結果的那一支。
- 改判準時，**舊契約的 fixture 也是資料**：`pg-reads-2230` 的干擾生是「退班沒結束日」，新判準一上就紅。
  先 `grep -l withdrawal src/contract/` 把含這類 fixture 的契約一起跑（11 支，2–3 分鐘），別等 CI。

## 1. 課務異動列表的 SQL 與範圍寫法（#1314 S3）

- `lib/change-log-sql.ts` 一支 CTE：`f`（條件）→ `g`（分組、各組最新 created_at）→ `page`（對組 limit/offset）→
  回那幾組的全部列。**分頁單位是「則」**；`meta.total` 數則、`meta.rowTotal` 數列（堂次，「停課 N 堂」用它）。
- **範圍寫法**：`org_id` 條件寫在每個 join 上（`s.org_id = sc.org_id`、`cl.org_id`、`st.org_id`）；分校用
  `($5::uuid[] is null or cl.campus_id = any($5::uuid[]))`。`campusIds` 在路由算：指名的那間，否則自己的範圍，
  null＝不受限。**空陣列要原樣傳**（`[]` 自然 0 列）—— 用 `campusScope?.length` 判會把空範圍當成不限。
- **指名範圍外的 `campusId` 由全域 `campusRequestGuard` 擋**（`middleware/auth.ts`、掛在 `index.ts`）。
  路由不要再寫一份 —— 寫了也是死碼（突變存活就是這個原因）。只有「沒指名時收斂到範圍」要路由自己做。
- **合成分組鍵要跟前端逐字一致**：前端 `[a, b, c].join('|')` 把 null 寫成空字串；SQL 用 `concat_ws` 會**略過** null，
  `(null, X)` 跟 `(X, null)` 撞成同一組。用 `a || '|' || coalesce(b, '') || …`。時間戳轉 UTC 到秒，
  對前端的 `createdAt.slice(0, 19)`。
- json 欄位用 `json_build_object` 組，`timestamptz` 出來是 ISO 字串（同 PostgREST），`::text` 會變成空格分隔，別用。
- 從 REST 換成 pg 之後，原本用 REST 替身的 spec 沒有意義（替身照查詢形狀回答）。整支搬成真 DB 契約，情境逐條搬。

## 2. 驗證腳本的做法（這席踩過的）

- **疊單一次驗**（計畫席的叫法是「合併驗證」；審核席的 `cmpstack.sh` 是另一件事 —— 讀解衝突後的 merge commit、跟原審三點 diff 比，別混用）：兩張 PR 改不同區塊時，一個暫存 worktree `merge origin/main <B> <C>`
  一起跑全套一次；compare 各自對同一個 base（`git merge-base B C`）跑。合併後先 `git grep -c` 數關鍵宣告，
  確認沒有段落變兩份。
- **突變一律在暫存 worktree**，腳本寫成「基準 → go 每個突變 → `git checkout -- src` 還原」，最後一條把路由換回
  main 版跑同一份契約當反證（要紅）。**別在座位 worktree 用 `git checkout HEAD -- <檔>` 還原**：
  未 commit 的改動會一起被吃掉（這席吃過一次，重做了 4 個檔）。腳本開頭檢查 `git status --porcelain` 乾淨才跑。
- **compare 讀的是座位裡的 `tools/a6-conformance`**：跑 compare 時不要切座位分支。要邊跑邊改別張，開暫存 worktree。
- compare 一側報 `connection-error` 而另一側正常：多半是 API 剛好忙，單獨重跑 compare 一次就好（不用重跑全套）。
- `npx prettier --write <目錄>` 會順手重排目錄裡**別人沒格式化的檔**（這席遇到 3 次）。只給檔名，跑完看
  `git status` 把無關的 `git checkout --` 掉。
- `git reset --soft origin/main` 整理 commit 前先確認 origin/main 沒前進；前進了就 reset 到**分支自己的 base sha**
  （不然 commit 會夾帶 main 新進來的反向 diff，這席出現過 669 行刪除）。
- 契約裡會走「寫入」的情境（補登出勤），日期要用**真的過去**（未來課堂會被「未開放點名」擋下，作廢那條會誤綠），
  未來用 2099。斷言錯誤訊息本身，不要只斷言 400。
- jsdom 的 `Blob` 沒有 `text()`：用 `FileReader.readAsText` 包一層 Promise。

## 3. 疊單衝突的兩種形狀

- **R5 表**（`kb/wiki/architecture/a6-adoption-rules.md`）：幾張 PR 都在檔尾加列，merge 時同一區塊衝突。
  兩邊的列都留、依日期排；標題欄寫短（比既有欄寬長的話 prettier 會重排整張表，diff 幾百行）。
  prettier 有時會順手對齊既有幾列的補白 —— 內容沒變，PR 內文寫一句即可。
- **spec**：兩張 PR 在同一個 `describe` 的同一個錨點（例如 `sessions.page.spec.ts` 的某個 `it(` 前）插測試，
  merge 會把兩段疊在一起或衝突。解完 `grep -c "it('<新測試名>"` 確認各一份；共用的 helper（`byStatus` 之類）
  如果兩邊各加一份，會 TS2300 重複宣告 —— 留一份。

## 4. 小東西

- 全站 toast（`app-toast`）認 `data.undo`：給「復原」鈕、自己出「已復原」。要復原的地方只要在 `messageService.add`
  帶 `data: { undo }`，undo 裡只打反向 API＋重抓，失敗才報錯。不要另做元件。
- CSV：伺服器出的走 `apps/api/src/lib/csv.ts` 的 `toCsv`（已擋公式前綴、BOM、CRLF）；前端自己組的只有管理端餐費的
  `csvCell`。新的前端 CSV 盡量改走伺服器；真要前端組，複製 `csvCell` 的規則（含前置空白）並加 spec。
- 對話框擋重送：`submit()` 開頭 `if (this.isSubmitting()) return;`。spec 要數兩件事：按一下 `submit` 只被叫一次
  （抓「送出鈕另綁 click」）、送出中再送一次表單 API 仍只打一次（抓「拿掉守門」）。
