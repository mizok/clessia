## 一、替身比 DB 慷慨（這一席又踩了三種）

前任 charter 寫的是「替身無條件補 embed」。這一席的三個新形狀，**共同點是測試綠了、但綠的原因不是你以為的那個**：

- **zod 先擋了**：PUT 的路徑 id 不是 UUID，「→ 400」那幾條其實是 zod 回的 400，守衛根本沒跑到。
  **斷言要寫 `code`（`INVALID_KIOSK`），不要只寫 status。** 塞陷阱才看得出來 —— 拿掉守衛之後它們照樣綠。
- **別的 400 先擋了**：建立的反例沒帶 email，被 `EMAIL_REQUIRED` 擋下，跟 kiosk 檢查無關。同上，斷言 `code`。
- **替身的 `maybeSingle` 不看 `eq`**：既有 staff 測試的 `user_roles` 一律回 `{ role: 'admin' }`。
  新守衛寫成 `if (kioskRole)` 時，**每一個一般人員都被當成機台**，舊測試整批紅。
  寫成 `row?.role === 'kiosk'`（比對值，不比對有沒有列）就跟替身相容，也比較誠實。
- 替身缺方法時（`lte`／`gte`）錯誤是 `… is not a function`，**在 route 裡被吞成 500**，看起來像邏輯錯。

## 二、本機實打：什麼時候一定要打

- **新的 select 字串、embed 過濾**（`classes!inner(…)` ＋ `.in('classes.campus_id', …)`）一律打一次。
  替身不實作 `eq`／`in`，**分校過濾在替身裡永遠是 no-op**，只有實打證明它真的濾掉別校（同校 1 列、別校 0 列）。
- 實打順便看形狀：`classes` 回物件不是陣列 —— 程式要兩種都收（`Array.isArray(x) ? x[0] : x`）。
- 指令在 [labor-20261003-1155](labor-20261003-1155.md) 三，這裡不重複。

## 三、kiosk 鏈的疊法（四支 draft，一條直線）

`#1183（migration＋授權，使用者合）` ← `#1188（API）` ← `#1190（web 搬頁＋打卡站）` ← `#1193（人員頁）`

- **下層要改時改在下層、再逐支 rebase 上來**（`git rebase <下一層分支>` → `push --force-with-lease`）。
  #1188 中途補欄位（重掃、請假）就是這樣做的；上層不要自己補一份型別或邏輯。
- 每支 PR 描述的「追加」段寫新 head 與它改了什麼 —— 計畫席讀回的是描述，不是 commit 列表。
- rebase 時 git 會說「skipped cherry-picks」：那是上層已經含有下層舊 commit 的正常訊息，`git log` 確認一條直線就好。

## 四、刻意的判斷（PR 裡都有寫，這裡是理由的索引）

- **建 kiosk 只要 `manage_staff`，不要 `manage_roles`**：kiosk 只掛得進 daily-checkins、route 內只能 POST、建立時禁止帶權限 —— 它不是提權。（#1188，計畫席已排進快照給使用者看）
- **確認資訊照「寫完之後讀回的紀錄」講**，不照「這次寫了什麼」推。理由：日到班寫 present 不看假單（見五），
  推出來的「請假（不變）」會是假的。
- **打卡站的分校不給現場改**（設計稿有下拉）：機台的分校是帳號決定的，後端強制。
- **登入後直接導向放在 `/link-line`**：一次性連結兌換後一定落在那裡，純 kiosk 帳號在那裡 `navigateToRoleShell('kiosk')`。
  不放在 `/select-role`：那邊單一角色本來就直接進 shell，但 `/link-line` 不會經過它。

## 五、發現但沒修（範圍外）

**日到班打卡寫 present 時不看假單**（`daily-checkins.ts` 的 `enrolledEventIds` → upsert `ignoreDuplicates`）。
`ignoreDuplicates` 只保護「已經有 `on_leave` 紀錄」的那堂；**假單建立時 event 還沒生成**（最常見：家長提前請假），
那堂沒有紀錄，掃碼就寫成 `present` —— 會流進扣課。已回報計畫席。修的話判準用 `leaveCoversSession`（點名名單同一套）。

## 六、前端：新 UI 的三個 gate

- **SCSS 帳（#991）**：新元件一律 Tailwind，目錄加進 `apps/web/src/tailwind.css` 的 `@source`。刪頁要跑 `harness:write` 移帳。
- **觸控 gate**：可點的 `<button>` 要有 ≥44px 的基底高度（`size-11`／`h-11`），沿用全域 class（`dialog-header-inline__close`）也一樣被查。
- **Tailwind theme 是清空過的**（`--*: initial`）：只有 `tailwind.css` 映射過的 token 會生成。`tracking-*` 沒映射，寫了是 no-op。
  不確定就 `grep -- '--<名字>' apps/web/src/tailwind.css`。
- 加角色時讓 `tsc` 告訴你漏了哪裡：所有 `Record<UserRole, …>` 都會編不過（頂欄、殼的角色標籤與圖示）。
- 元件測試裡 `ngModel` 寫回 DOM 是非同步的：送出之後要 `await fixture.whenStable()` 才看得到欄位被清空。
