## 量「改前改後」：兩個 port、同一個 cookie、逐字比對（#957）

1. main 開一個 detached worktree 在 scratchpad，`node_modules` 用 symlink 指回本 worktree（依賴相同時），兩邊各 `wrangler dev --port 879x`。
2. 一次 `login-link.ts` 換一個 cookie jar，兩個 port 都能用（cookie 不分 port）。
3. **同一批請求打兩邊、扣掉刻意新增的欄位後比 JSON**。再做**反向對照**（拿不同頁或竄改一個欄位去比，要看到 False），否則「全部相同」可能是比對本身壞了。
4. 輪數用**不 commit 的診斷補丁**：在 `supabase-latency-probe.ts` 記每支呼叫的起訖，加注入 50ms 讓平行呼叫重疊；「上一輪全結束後才開始」算新一輪。量完 `git restore`。
5. TTFB 每邊暖身 1 次＋5 輪，報中位數與跨度；注入與不注入各量一次。

## PostToolUse 的 prettier 會順手重排「原本沒格式化」的段落

`staff.ts`、`attendance.ts`、`herdr-team/*.md`、部分 `kb/` 頁在 main 上**本來就不是 prettier 格式**。用 Write／Edit 改它們時 hook 會整檔重排，diff 會混進無關 hunk。

## seed：依賴展示資料的段落要放在最後，而且要有 guard（#977）

`seed-demo.sql` 的段落有先後依賴。「今天的到班打卡」的母體（今天有課、在籍、沒請假）依賴後面才建的課堂、報名、請假單。
第一版放在中間，db-reset 席量到「同一人既已打卡又請假中」（11 筆 vs 10 筆）。這是 #838／#916 同一個形狀的第三例。
修法是**移到整支檔案最後，並緊接一個 RAISE guard**。guard 要**先在舊產物上驗它會觸發**（唯讀 `begin read only` 查一次），再看新順序通過。

## GitHub Actions 帶 secret 的 workflow（#968 審查學到的）

- repo 是 public。`workflow_run` 的 `branches:` 比的是 head_branch，**fork 可以把分支取名叫 main**。入口要同時比 `workflow_run.event == 'push'` 與 `head_repository.full_name == github.repository`。
- **帶 secret 的 job 不執行 checkout 下來的程式碼**：拆成「帶 secret 只跑內建工具」與「跑 repo 腳本但沒 secret」兩個 job，用 job outputs 傳文字。
- 頂層 `concurrency` 的同一 group 只留一顆排隊中的，中間的會被丟（#603→#613）。**只序列化真正需要互斥的那個 job。**
- 結構測試用標準庫依縮排切 job（`tools/agent-harness/migrate-workflow.test.mjs`），**拿修正前的版本跑一次看它紅**。

## 拋棄式 spike（#995）

- scratchpad 裡 `ng new` 時 npm 10 會在 peer 解析崩潰（`edgesOut`）。改用 `npx npm@11 install`，**不要** `--legacy-peer-deps`（會讓依賴解析跟真實情況不同）。
- 驗 Tailwind 行為用 `@tailwindcss/node` 的 `__unstable__loadDesignSystem`（`getClassList()`、`candidatesToCss()`）與 `compile().build()`：**窮舉比列舉可靠**。第一版評估三處錯，都是列舉出來的。
- 文件寫進 repo 之前先問：**這段文字會不會被某個掃描器當成原始碼？**（Tailwind 的自動偵測會把 `kb/` 裡的 class 產生進 bundle。）
