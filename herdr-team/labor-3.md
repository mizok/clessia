## `switchMap` 管線的 `catchError`（#689）

**形狀**：`catchError` 掛在 `switchMap` 的 project function **回傳值裡**，回 `EMPTY`，
toast 與 `loading.set(false)` 收進去；**外層 `subscribe` 只剩 `next`**。
掛在 `loadRequests.pipe()` 那層一樣會終止整條管線。

留著外層的 `error:` 分支比刪掉更糟 —— **它讓人以為還有人在接，而那一刻管線已經死了。**

### 對照組不是 `origin/main`

**README 已有這一則**（搜「那條測試的對照組不是『修改前』」），要用的時候去讀它。
這裡只記本席的操作結論：**七支合進 main 之後 main 自己就是對照組**，
所以流程是「先在 main 現況上跑那條新測試 → 看它紅 → 才套 `catchError`」，
不必自己做拋棄式版本。七支拿到的紅燈逐字相同：`expected 2 times, got 1 times`。

### 斷言要量請求次數，不是量結果

那條測試斷言的是 `expect(service.list).toHaveBeenCalledTimes(2)` ——
**不是「畫面上有幾筆」也不是「有沒有跳 toast」**。

理由：管線死掉之後畫面**停在上一次的結果**，而那一份結果是對的、看起來完全正常。
**「畫面沒變」與「畫面不該變」在斷言上長得一模一樣**，只有「第二發請求有沒有離開」
分得出來。同理 toast —— 它在兩種情況下都會出現一次。

> 一般化：**要驗「某個機制還活著」，去量那個機制的輸出，不要量它下游的狀態** ——
> 下游停在正確的舊值時，看起來跟正常沒有差別。

### 巢狀管線：位置比其他六支講究

`grades/overview/student-view` 先撈第一頁，再用 `forkJoin` 撈其餘分頁。
`catchError` 要掛在 `switchMap(firstPage => …)` **之後**才同時涵蓋兩半；
**掛在最內層那支 `list({ page: 1 })` 上，`forkJoin` 那半的失敗收不到**。

**而這件事只有第二條測試看得見**。拋棄式突變證過：把 `catchError` 搬回最內層 →
**恰好分頁那條紅、第一頁那條綠**。也就是說只寫第一條的話，那個洞會安靜留著、
而且有一支綠燈替它背書。

> 判準：**一支管線有幾個「請求會發出去」的地方，錯誤處理就要驗幾次。**
> 巢狀 / `forkJoin` / `mergeMap` 都算，`grep -c 'service\.' ` 那個 `switchMap` 區塊最快。

### 三支 spec 的替身餵不出在途請求

`courses` / `campuses` / `fee-templates` 的替身是立即完成的 `of(...)` ——
**做不出「已發出、還沒回來」的請求**，所以那條測試在它們身上根本寫不出來。

處置是各開一個 `describe`，在自己的 `beforeEach` 換成回 `Subject` 的替身
＋ `vi.useFakeTimers()`，`afterEach` 換回去（同檔其他測試不受影響）。
`staff.page.spec` 與 `students.page.spec` 已經有這個骨架，照抄。

> 這是 README 那條「替身的寬容度決定了它遮得住哪一種突變」的鄰居：
> **`of()` 替身遮住的不是某一類突變，是整個「時序」維度** ——
> 凡是要驗「兩發請求之間發生了什麼」的測試，在它底下都寫不出來。

## 表單預設值會製造沒有人會回報的髒資料（#666）

人員表單預設 `roles: ['teacher']`，於是**每一個純行政都被靜默記成老師** ——
建立者不會發現，他只是沒去取消一個預先勾好的框。實測兩筆（可用性測試席建的
兩個純行政）都變成「老師 + 管理員」，而頁首統計把他們算進「90 老師」。

> **一個預設值省的是一次點擊，錯誤成本是一筆要人工發現才修得掉的資料。**
> 而它不會被回報，因為**畫面上沒有任何一刻是錯的** —— 勾選框顯示的就是實際會存的值。

修法只動預設值。**驗證與「科目欄位只在勾了老師時出現」那兩層本來就綁著角色**
（PR #664 的 ② 段查證過）—— 這種工單容易順手「連驗證一起修」，先去讀那兩層。

## ⚠️ `PUT /api/staff/{id}` 只帶 `roles` 會靜默清掉 `permissions`

清理那兩筆髒資料時第一發就踩到：只送 `{"roles":["admin"]}`，
回應裡 `permissions` 變成 `[]` —— 原本的 `basic_operations` / `manage_students` 沒了，
**沒有任何錯誤**。補帶 `permissions` 重打才救回來。

前端一定會兩個一起送，所以 UI 上踩不到；**寫腳本的人很容易只帶 `roles`**。
記在 PR #677 的描述裡，**沒有開單**（計畫席當時未裁）。

> 下一個要用 admin API 補資料或寫 seed 腳本的人：**送 `PUT` 之前先 `GET` 一次，
> 把不打算改的欄位原樣帶回去。**

## 實機驗證的前置

**全部在 README 的「本機實機驗收的三件前置」那一節**（`:4200` 服的是誰的程式碼、
magic link 自產、`callbackURL` 的信任條件）。**那一節的第三點在 2026-09-12 被更正過，
去讀更正後的版本** —— 本席當時走的是被標為「次佳解」的繞道 4200，
因為我從 403 推論成「只信 4200」而沒把「頂層導覽沒有 `Origin` 標頭」那一層講出來。

本席只補一件 README 沒寫的：**按下按鈕之後要等滿 4 秒再截圖。**
