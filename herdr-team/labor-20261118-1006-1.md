會再踩到的：

- **better-auth 1.7 起初始化就驗 schema（含 production），缺欄位 → 所有認證請求 `SchemaMismatchError`。**
  升 better-auth 前先用同版 CLI（`auth@<版本>`，`@better-auth/cli` 停在 1.5 beta）對 DB 乾跑
  `auth check schema`／`auth generate`。
- 1.7 的 `unlink-account` 只吃本地 `account.id`、要 24h 內的 session（`SESSION_NOT_FRESH`）；
  magic-link 兌換到 `emailVerified=false` 的帳號會**刪光它的 ba_account 與 session**
  （`revoke-unproven-account-access`）。我們靠「第一次兌換就設 true」避開，契約守著。
- **根目錄 npm 10.9 對沒安裝的 optional peer 誤報 ERESOLVE**（better-auth 的 `@sveltejs/kit ^3` 要 vite 8）。
  用 `npx npm@11 install` 解 lock，再用 npm 10.9.3 `npm ci` 驗可重現。不用 `--force`／`--legacy-peer-deps`。
- **Angular 家族彼此精確 peer**，在既有 lock 上 install／update 整組都會 ERESOLVE（arborist 依序放置時舊版還在）。
  做法：暫存 worktree 依序 `npm uninstall` 整組 Angular（含 primeng／angularx-qrcode／@nx/angular）再裝回；
  事後檢查 `primeng` 範圍與 `@nx/angular` 精確釘被 npm 改掉沒有。
- **`npm audit fix` 不要用**：根 lock 翻了 3.6 萬行還引進新警告，撤回過。
- 推 >1MB（vendor tarball 2.4MB）HTTPS 回 400 → 單次 `git -c http.postBuffer=157286400 push`。
- **audit 剩下的**：`picomatch ≤4.0.7`（4.0.7 是最新版，**沒有修補版**；audit 建議把 vitest 降到 3.x，不採）。
  連帶 `fdir`／`tinyglobby`／`vite`／`vitest` 同一條鏈。都是建置／測試期，不進瀏覽器 bundle。上游出版再定向 `npm update`。

## 3. #2545 any（已結，兩片）

- #2565 `attendance.ts` 47→0、#2566 `leaves.ts` 30→0；型別在 `routes/attendance/rows.ts`、`routes/leaves/rows.ts`。
- **零行為變更的證明法**：改前改後 `npx esbuild <file> --format=esm --minify-whitespace` 位元組相同
  （改前那份要放**同檔名**，esbuild 依檔名命名 default export）。中途抓到過我多加的 `?? null`。

  `leaves/rows.ts` 不含 `campus_id`，不需要（加了反而紅：帳本只降不升）。
- **sessions.ts 拆檔不做**（計畫席裁，另議）：issue 的「route 主檔明顯縮小」那條驗收沒做。

## 8. 踩過的工具坑

- **zsh 不分詞 `$F`**：多檔參數用 `${=F}`；`bash -c` 裡含 `rm` 的腳本會被安全檢查擋（不要繞）。
- 從 main 切到別的分支後，**`apps/api` 也要 `npm ci`**（獨立 lock）—— 只重裝根目錄會冒出上百個 hono 型別錯誤。
- 生成的 KB 索引（`index.md`、`_moc.md`）與大表格的頁**不要跑 prettier**，會整頁重排；kb-wiki `map` 會帶進別人的漂移，只手補自己那頁。
