## 二、坑（本席新踩的）

0. **`waitUntil` 背景裡用不到請求的 pg pool**：`authPoolCleanup` 在 `await next()` 回來就 `pool.end()`。背景要大量 id 時改用「少量的上層 id（班級）＋巢狀 embed」，再 `fetchAllPages` 翻到底。
1. **簽收時間判「簽收後有修改」**：PostgREST 寫不了 `now()`，用 JS 時間一定跟 trigger 的 `updated_at` 不等 → 走 pg 一句 `signed_at = now()`（同交易時間）。
2. **讀取失敗不能吞**：測「回 error」要讓替身**回 `{ error }`**，不是丟例外（丟例外照樣 500，守不住「忘了檢查 error」）。#2012 被二讀抓到。
3. **給家長讀的端點就算不在 `routes/parent/**`，也要先限範圍再撈**（`childDb.pluck` → `fromScopedIds`），不要原始 supabase 撈了再遮。
4. **疊 PR 被 squash 後衝突**：merge main，kb 的 add/add 衝突先 `diff` 確認 main 那份每行都在分支版裡再取分支版。
5. **兩支 PR 各自幫同一個型別加必填欄位**（#44 `campusPhone`、#26 `usesContactBook`）：merge 時兩邊都留，select 字串要合成一句，spec 工廠函式會出現重複 key（TS1117）。
6. **`cd ../..` 從 `apps/api` 會跑到主 checkout**：驗證指令一律用絕對路徑 cd 到 worktree。
7. `list-endpoints` 契約遇到「要家長身分＋真的有那筆資料」的新 GET：在 beforeAll 插一筆、afterAll 刪（delete 要帶 `org_id`，harness 會擋），每支端點打完還原 `userId`／`studentScope`。
