## 二、會再撞到的坑

1. **審核席一定做突變，而且會挑「替身看不到的那一層」**。這一任被退回的全是同一型：
   程式對了、但拿掉某一行測試照樣綠 —— `SELECT_FIELDS` 漏欄（落到預設值）、PUT 沒寫、zod 邊界 ±1、
   失敗不重設 loading／busy、通知收件人拿掉 `permission`、`.eq('org_id')`（c1）、`?? xxx.error`。
   **送審前自己把每個 `if`／`??`／`.eq` 拿掉跑一次**，紅了才算有守。
2. **替身不解析 select、也不看 enum**：`createMultiOrgDb` 一律回整列，`.in('status', ['present', 'late'])`
   在替身裡照過、在真 PostgREST 是 400（enum 沒有 `late`）。**新的 PostgREST 查詢形狀先對本機 REST 實打一次**
   （`npx supabase status -o env` 拿 `API_URL`／`SERVICE_ROLE_KEY`，用 supabase-js 跑那一句），再寫契約測試。
3. **契約測試的 fake auth 要用正式的 `createServiceClientFromEnv`**（#1754 起已改）：裸 `createClient`
   不帶 fetch 包裝（#1612 重試、#1455 空頁），測到的不是上線那條路。
4. **契約收尾刪 org 會撞非 CASCADE 的 FK**（`students_org_id_fkey` 等）：照 `staff-digests.contract.ts`
   `SET LOCAL session_replication_role = replica` 逐表刪。
5. **列表契約 `list-endpoints.contract.ts` 對新端點會紅**：新的 GET 要在 `REQUIRED`／`PARAMS` 表補參數。
6. **migration 檔頭別寫「部署前後都安全」除非真的是**：api 的 select 讀新欄的，就是 schema 類、先套才部署
   （`kb/wiki/architecture/deploying.md`，#1307）。`ba_user` 的 FK 用 `ON DELETE SET NULL`，`RESTRICT` 會讓帳號刪不掉。
7. **mount 授權**：新增 `mount()` 要在 `mount-authz.spec.ts` 的 `EXPECTED` 補一列；直接 `app.route`／`app.get`
   掛的要進 `UNMOUNTED`／`OUTSIDE_MOUNTS`（照實際註冊次數，比的是多重集合）。
   **不要掛在既有 mount 的子路徑底下繞權限**：`/api/students/*` 的寫入門是 `manage_students`，
   財務功能掛在那裡，只有 `manage_finance` 的人會被擋 → 另開 mount（`/api/leave-streaks`、`/api/contact-logs` 同理）。
8. **測試裡動態 import 整個 app 要放 `beforeAll`**（#1580）：放在測試裡會算進第一條的 5 秒逾時，機器忙時前幾條紅。
9. **時間**：`timestamptz` 回的是 UTC，前端顯示日期用 `taipeiDateString(Date.parse(x))`，不要切字串
   （台北 00:00–07:59 會變前一天）。spec 要在 `TZ=UTC` 下也跑一次。
10. **Hono 的 `<path>/*` 也匹配 `<path>` 本身**：mount 的兩行守衛裡 `path` 那行是多餘的（等價突變）。
11. **squash 合併後，疊在上面的 PR merge main 會出 add/add 衝突**：先 merge 上游分支的最終 tip，再 merge main；
    衝突檔先核「main 上的版本＝上游 tip 逐位元相同」，再取自己這側。給審核席的證據：PR 自己的增刪行 hash 跟審過版相同。
12. **`git fetch` 偶爾 `cannot lock ref`**：別的 worktree 同時在 fetch（refs 共用），等幾秒重跑。macOS 沒有 `timeout` 指令。
