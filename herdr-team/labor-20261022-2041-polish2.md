## 二、#1928（長 `.in()` → 414／max_rows 截斷）的做法

- **先在 main 上逐行確認**，第一個 commit 一律「讀取失敗回 5xx」（不回空 200）。前端在 check-conflicts 失敗時本來就照存，所以 5xx 不擋存檔。
- **能用 join 就不撈 id 清單**：`classes!inner(org_id, …)` ＋ `.eq('classes.org_id', orgId)`；三層 `students!inner(… enrollments!inner(… classes!inner(…)))` 一樣能套範圍，翻頁與 `count: 'exact'` 照舊。**範圍條件搬進 join＝保留類**。
- **`.in` 的清單如果本來就短（今天有課的班）**，用 `lib/fetch-all-pages.ts` 翻到底就夠（每頁一個 subrequest）。
- **契約測試自建大 org**（`contract/check-conflicts`、`leaves-scope`、`today-attendance`）：用 `pg` 塞資料、測完整個 org 刪掉，**一定要拿同一支契約對舊寫法跑一次看到紅**才算數。
  - 本機跑契約：`set -a; source apps/api/.dev.vars; set +a; SUPABASE_SERVICE_ROLE_KEY=$SUPABASE_SECRET_KEY CONTRACT_REQUIRED=1 npx vitest run --config vitest.contract.config.mts <檔>`（`supabase status` 在 worktree 取不到值）
  - 建資料的坑：`courses.subject_id` 必填；`schedules` 有 `(class, weekday, start)` 唯一鍵；`staff` 一人一 org 一筆（第二位老師用別的既有 `ba_user` id，**只讀**，c2）
- **替身不解析 select**：`!inner` 寫沒寫、join 條件有沒有下，單元只能攔「送出去的字串」；真正的隔離要契約守，而且契約資料要讓「拿掉 `!inner`」與「拿掉某個條件」**各自**有一筆會漏進來的列（review3 在 #1951 抓到）。
- **等價突變要說明**：check-conflicts 拿掉 `.in('teacher_id')` 契約仍綠，因為路由迴圈本身再比一次 teacher_id。

## 三、介面細修學到的

- **工具列高度只住在 `--tbar-control`**（#1903／#1915）：手機與觸控 44、`(width >= 861px) and (pointer: fine)` 40。A27 harness 認得 `tbar-control`。
- **`clessia-filter-search` 的 `flex: 1`（basis 0%）在直向 flex 會蓋掉 height**，所以同時寫了 `min-height`。
- **Tailwind 的 `tracking-normal` 等預設刻度在本 theme 不一定存在**（#1948 才補）。utility 沒產生不會報錯，量 computed style 才看得到。
- **`[class.wide:flex]` 這種帶冒號的綁定不可靠**，整串 `[class]` 或 data 屬性＋`data-*:` variant。
- **a6-conformance**：
  - 列的「簽名」吃 class 清單，四格統計要同一串 class（桌機才顯示的用 data 屬性藏）。
  - 稿在 `main` 外、按鈕名帶「新」的，用 config 的 `mapping` 手動配對。
  - app 的手機托盤（fixed）會被認成「列」→ 工具限制，登 deviation。
  - `compare` 自己會開 worktree 與 web，但 **API 要活著**：本機 8787／8796 常被外部收掉，跑之前在同一支指令裡起 API、跑完收掉。
- **`WindowSizeDirective` 量到 0 不寫**（#1905）；共用 `page-open` 的 `nameSize` 手機行高 1.2（稿的 `.open__title` 蓋過 `--name`）。
