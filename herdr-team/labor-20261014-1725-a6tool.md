## 一、工具的每個規則都是被一次誤報逼出來的 —— 改之前先看 spec 在釘什麼

`lib/normalize.test.mjs` 每一支 spec 的標題就是一次真實誤報（帳戶浮層名字、#1593 的「⋯」連帶、
課表軸列錯配…）。**新規則一律「先寫會紅的 fixture → 實作 → 把規則拿掉看 spec 有沒有紅」**。
這輪有兩次突變沒紅：一次是 fixture 太簡單（只有一列，最短後綴本來就唯一，新規則根本沒被用到），
一次是規則本身不需要（拿掉後也沒有任何情境擋得住 → 刪掉）。**突變沒紅＝fixture 錯或規則多餘，不是過關。**

fixture 要長得像真資料：我寫過一個 app 端 `row~2` 的 fixture，但真實抽取裡列會合併成一個 `row`，
那支 spec 驗的是不存在的形狀。**拿 `~/.cache/clessia-a6-conformance/out/<頁>/{a6,app}-d.json` 的真 key 來寫。**

## 二、配錯對象是最貴的誤報，而且看起來像真差

這幾種都發生過，報告上的長相就是一條「樣式差」或「位置差」，沒人會懷疑：

- **代表取錯**：列合併後取「第一個出現的」—— 稿第一列是軸列、第一個課塊剛好「上課中」。改眾數。
- **弱後綴**：剩下沒配上的 part 很少時，`text:span` 這種不帶文案的後綴會「剛好唯一」，配到別的列去
  （帳單 Δy −1491）。**Δ 大得離譜（幾百、上千 px）先懷疑配錯，不是頁面錯。**
- **參考容器範圍不同**：app 的 main 包住色面，拿 main 當參考，色面的高度差灌進每一條。
- **相對位置混用不同列**：兩邊代表取自不同列（稿資料列、app 軸列），列內 Δy 其實是「第幾列」的差。

查法：`diff-<w>.json` 找那條的 `a6`／`app` key，再到兩邊的 `*-d.json` 看 box —— 一眼就知道是不是同一個東西。

## 三、會騙人的環境

- **別席的 8787 會停**（10-14 傍晚停過）。不要改 `environment.ts`（`system-clock` spec 會紅）：工具在瀏覽器層
  把 8787 轉到 `A6_API_URL`。自己起 `wrangler dev --port 8887 --inspector-port 9339 --var WEB_URL:… BETTER_AUTH_URL:http://localhost:8887`。
- **magic link 的 callbackURL 必須是 API 信任的 origin**，不然 verify 回 403。用 `context.request.get(link, { maxRedirects: 0 })`
  換 cookie，不要讓瀏覽器跟 302（callback 指向沒人聽的 port 會變 chrome-error、goto 被打斷）。
- **app 被導離目標路由**（登入失效、API 掛了）時頁面看起來是正常的公開首頁 —— 工具會直接報錯，別拿去比。
- **稿的翻頁膠囊**（`.proto-pill`／`proto-all`）是設計稿導覽，不是頁面；抽取與開彈出物都要排除。
- **本機日期換日**會改資料（課表「今天」幾堂、列數）：跟別席對數字前先對「量的那天」。
- **新 worktree 冷編譯 > 300 秒**（`compare` 第一次逾時就是這個）。

## 四、Python 改 JS 的坑（這輪踩了五、六次）

PostToolUse 的 prettier 會在每次編輯後重排檔案，**下一次用字串比對的替換常常就對不上了**，而 `str.replace`
對不上時**靜默不改**。extras.md 少一欄就是這樣：表頭改到了，資料列那段沒改到，我只核摘要數字沒逐欄看。

- 每個替換都 `assert old in s`；沒命中就停下來看格式化後的樣子。
- 被 deny 擋掉的指令串，**整串都沒跑**（包括前面的 python 編輯）—— 不要以為「至少改檔那段跑了」。
- 產出物要逐欄驗（表格每列格數＝表頭），寫成 spec，不要只看總數。
