## 一、gate 的前提要先對資料驗，不要照抄

- **「資料有 `signedBy`」是錯的**：聯絡簿的 `signedBy` 是 `ba_user.id`（`text REFERENCES ba_user`），前端沒有姓名可顯示。做法＝API 的 `SELECT` 加 `signer:ba_user!signed_by(name)`（跟既有 `editor:ba_user!last_edited_by(name)` 同一個寫法，只讀，c2 允許），回應多 `signedByName`，`toContactBookEntryResponse` 與 spec fixture 一併補。**沒有家長簽收端點，真實資料多半是 null**——畫面要有「沒姓名退回『已簽收 20:06』」的分支，PR 要寫明「目前只有示範庫那一筆會顯示姓名」。
- 所以**接到「前端加某欄」的 gate 先 `grep` 欄位在 API 回應與 DB 的型別**（id 還是名字、nullable 與否），再貼「開工＋切法」。這輪 C2 因此多了一層 API，要主動跟計畫席講。

## 二、M2「寫入 payload 一個字不改」怎麼證明

- **不動 `draftToBatchRows`／`save()`**，spec 用 `toEqual` **逐欄比對** batch 的 `{ studentId, ordered, chargeable, unitPrice, note }`，並且**從畫面驅動**（`input.click()`、`dispatchEvent(new Event('change'))`）而不是呼叫元件方法 —— 這樣控制項換成原生元件後，「勾了真的進 payload」才有人守。
- **原生單價輸入**：用 `(change)`（失焦／Enter）不用 `(input)`，打到一半不會洗掉欄位；只收非負整數（`replace(/\D/g, '')`），**清空或沒數字要還原成目前單價**（不送 null 給後端）。門檻 fixture：`'0'`（合法）、`'1'`、`''`、`'65元'`。
- **確認列「有修改才出現」不能只看 diff**：沒處理的列（`recordId === null`）帶的是預設值，沒人動也要能確認，所以條件是 `changed > 0 || unhandled > 0`（A6 同）。diff 用「載入當下的快照」（四個可編輯欄位壓成字串），**改了又改回原值＝沒改**、已結算不算；存完重載要換快照，不然確認列收不起來。
- **載入改 `Subject`＋`switchMap` 時**，`load()` 內先組好 `request`（一個 Observable）再 `next` 給 Subject；`catchError(() => of(null))` 放在 `switchMap` **裡面**，舊請求晚到的失敗才不會污染新結果。亂序 spec 用兩個 `Subject` 手動控制誰先 `next`，一條測「舊成功晚到」、一條測「舊失敗晚到」。
- **起訖原生日期欄**：清空→還原不查；起日晚於迄日→把**另一端**拉到同一天（起訖同日合法）。`>`↔`>=` 的突變會存活，因為相等時兩邊賦值結果相同＝**等價突變**，不要為它硬補 spec。
- **突變腳本 17 項抓 14，存活 3 項要逐一判**：等價（相等時賦值相同）、多餘程式（`showSaveBar` 的 `!isRange()`——模板本來就只在當日分支渲染，**刪掉程式碼而不是補測試**）、真漏測（翻頁上界）。

## 三、R2 比例條「改裁」要明講

- A6 的列比例條是 **`g.billed / billed`（這組已開帳佔整體幾 %）**，本機舊的是「這組自己的收款比例」。我照 A6 做，**PR 描述專開一段「請裁的語意變動」**並說明還原只需改 `shareOf()`。**語意變動不要藏在逐區塊表格裡**。分母取後端 `summary.billed`，整體 ≤ 0 → 0、夾 0–100（顯示用除法，不是加總）。
- A6 列序是「模糊桶最後、一般列依已開帳大到小；月份新到舊」，後端是依名稱排。**列序在前端 `sortGroups` 換，只換順序不動數字**；突變要涵蓋「模糊桶排序拿掉」「排序反向」「模板改回未排序的 `groups()`」三條。
- **`responsive-table` 換成語意 `<table>`＋Tailwind**：`tr` 手機 `grid grid-cols-2`、桌機 `wide:table-row`，`td` 手機 `flex justify-between`、桌機 `wide:table-cell`，手機用的標籤 `<small class="wide:hidden">`。**實測 computed display 才算數**（桌機 `table-row`／`table-cell`、手機 `grid`／`flex`），寫進 PR。
- 換掉元件後**舊 spec 會有已不適用的**（例：「分校欄不可摺疊」依賴 `RtColDefDirective`）——刪掉並在 PR 寫明原因，不要留著改成假綠。`routerLink` 渲染進模板後，既有 spec 的 TestBed 要補 `provideRouter([])`，否則 `NG0201 ActivatedRoute`。
- 純 `<a>` 可點也要 `min-h-11`（harness 會擋），代價是有連結的名稱列比數字低約 10px，列成小殘差即可。

## 四、環境與程序（這輪踩到的）

- **`pkill -f "wrangler dev"` 範圍太廣**：會停掉別席的 wrangler。**只殺自己 port 的 pid**：`for pid in $(lsof -ti tcp:<port>); do kill $pid; done`。啟動前 `lsof -ti tcp:8787`，有別人的就**沿用不要再起**（資料庫是同一份）。
- **wrangler 會自己崩**（log 結尾 `wrangler dev exited with non-zero status`），症狀是 Playwright 一開頁被導到登入／公開首頁。先 `curl -s -o /dev/null -w "%{http_code}" localhost:8787/api/health`（401＝活著）再查別的。
- **機器負載高（load average 30+）時 api 套件會有冷啟動逾時**：`contact-logs.spec.ts` 第一支測試 5000ms 逾時，與本 PR 無關。**停掉自己的 dev server 再跑一次；仍紅就在 PR 照實寫「哪一支、幾秒、在什麼負載」**，不要假裝綠。
- **突變腳本寫法**：Python 腳本放 scratchpad、`signal` 處理 SIGTERM/SIGINT、`finally` 還原，**不要用 `rm $VAR/*`**（安全檢查會整條擋掉，連同前面的步驟都沒跑）。背景跑完才改同一個檔案——腳本結尾會把檔案還原成**啟動時的內容**，中途手改會被蓋掉。
- **Stop hook 的 harness 會在突變期間看到壞檔**，但 `min-h-11` 這類是真的違規（跟突變無關），看清訊息再判斷是假警報還是真問題。
