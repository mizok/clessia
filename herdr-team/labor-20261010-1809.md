## 一、「家長資料面」＝回應鍵集合要有 spec 釘住

家長端 API 是 allowlist（見 `kb/wiki/architecture/parent-read-endpoints.md`）。**要多給家長一個欄位的 PR 一律標「家長資料面」**，並在該路由的 spec 加一條 `Object.keys(...).sort()).toEqual([...])`：
之後誰再加欄位（尤其 `note`／`recordedBy` 這類內部欄位）會在這裡紅燈。範例：`routes/parent/billing.spec.ts`（只多 `className`、`invoiceNo`）、`routes/parent/grades.spec.ts`（只多 `className`）。
**先查 API 是不是早就有**：成績頁我預設要加 `recordedAt`，讀碼才發現 `createdAt` 本來就回了，只是前端型別沒宣告 —— 省掉一個對外欄位。

## 二、fake 少實作一個鏈上方法 → TypeError → 500 → 「回 500」的測試假綠

`childDb.from(...).select().in().eq()` 的鏈上，測試替身若漏了 `.in()`，會丟 TypeError，路由照樣回 500 —— **「查詢失敗要回 500」的 spec 在你拿掉那行 error 檢查後仍然綠**（#1497 reviewer 抓到的）。
做法：**失敗的替身每個鏈上方法都回自己、最後 `await` 才吐錯**；寫完做一次**反向驗證**（暫時拿掉 `xxx.error` 檢查，這條必須紅）。
另一個形狀：同一張表有兩支查詢（`enrollments` 被帳戶資訊與班名各讀一次）時，**只讓你要測的那支失敗**（用 select 字串分辨），否則另一支的 error 在撐這個 500。

## 三、`Record<StatusTone, …>` 的窮舉會擋住你加 tone

`status-dot` 加一個 tone，所有 `Record<StatusTone, string>`（例：老師端 `ATTENDANCE_TONE_LABELS`）都編譯失敗。這是刻意的（窮舉防掉進 default），**補一格並註明「這個領域沒有這個狀態」**，不要放寬型別。
`soon`（快到期）與 `overdue`（逾期）同色相、**形狀不同**（中空 vs 實心）—— 灰階下也分得開，是這個元件的設計軸（形狀＝還在不在等、色相＝嚴重度）。

## 四、一場考試掛多個班；班名要用「孩子報名過的班」過濾

`academy_exam_classes` 是多對多。家長端成績的 `className`＝考試的班 ∩ 孩子的 `enrollments`（含退班）；沒交集（段考、沒掛班的展示資料）→ null，畫面歸「學校段考」組。**不過濾會把別班名字送給家長。**
