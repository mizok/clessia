## 一、替身比 DB 慷慨，測試就驗不到 select 寫錯

#1150 的 `leaves-session-binding.spec.ts` 用 `withLeaveEmbed` 替 `leave_requests` 補上
`leave_request_sessions` embed —— **不看 select 字串，無條件補**。於是列表與 PATCH 的
`select('*, …')` 漏了 embed，替身裡照樣有綁定、全綠；真的 PostgREST 回 `sessionIds: []`（#1177 修）。

- **替身補關聯時，只在 select 字串真的要那段時才補**（`String(args[0]).includes('leave_request_sessions(')`）。
  這樣測試才分得出「select 有沒有寫對」。
- **新增 select 時問一句：回應的哪個欄位從 embed 讀？** `toLeaveResponse` 讀 `leave_request_sessions`，
  所以凡是丟進它的列都要帶 `LEAVE_SESSIONS_EMBED`；手動補綁定的路徑（POST、換綁定的 PATCH）不用。
- 實打的形狀（#1150 留言是範本）：**用真路徑造 fixture**（POST 帶 sessionIds），空表的 embed 回 `[]`
  跟「select 漏了」長得一模一樣 —— 有資料才分得出來。結果要附列數。

## 二、本機實打的開法（不必等別人開 API）

```sh
cp ../../apps/api/.dev.vars apps/api/.dev.vars          # 被 gitignore，worktree 沒有
cd apps/api && npx wrangler dev --port 8790 --var BETTER_AUTH_URL:http://localhost:8790   # 背景跑
# 另一個 shell：產登入連結（同樣讀 .dev.vars，覆寫 BETTER_AUTH_URL 對上 port）
set -a; . apps/api/.dev.vars; set +a
BETTER_AUTH_URL=http://localhost:8790 WEB_URL=http://localhost:4200 LOGIN_EMAIL=admin@demo.clessia.app \
  npx tsx apps/api/src/scripts/login-link.ts
curl -c jar "<verify url>"            # 302 到 web 沒關係，cookie 已經在 jar
curl -b jar -H 'Origin: http://localhost:4200' …   # 寫入要帶 Origin
```

- **`events` 是讀取時補建的**：未來日期的堂沒有 event，`cancel-leave`／roster 要先打一次
  `GET /api/attendance/sessions?date=…` 讓它長出來。那 +N 不是寫入，回報時分開講。
- 收尾用真路徑刪 fixture（DELETE），然後**把殘留列給 labor-db-reset**：表、前後值、`audit_logs` 的 action 分佈、
  測試用的學生 id。同量增減會互相抵銷，只報筆數看不出你動過。

## 三、`npx prettier --write <目錄>` 會改到別人的檔

`apps/api/src`、`apps/web/src/app/features/admin/pages/` 底下有不少檔沒格式化過，
對整個目錄跑一次就會帶進十幾支無關檔的 diff。**只對自己改的檔跑**，或跑完 `git status` 逐支還原。

## 四、financial 類欄位的門檻

帳戶資訊（#1073）這種「改了就改錢流向」的欄位，放進 `FINANCE_SETTING_KEYS` 一次拿到讀與寫的門檻
（沒有 `manage_finance` 時回應裡**沒有那個 key**）。前端照 key 存不存在決定畫不畫 ——
畫一個讀不到值的空欄位，按儲存就會把值清掉。同一個欄位在別的表單（分校）也要同一個門檻，
而且**沒有權限時 body 不帶那個 key**，不然整張表單（改名、改電話）會被 403 一起擋掉。

## 五、新身分先問「讀端點擋不擋得住」

`index.ts` 的 `mount(..., ADMIN_ONLY, { write: '…' })` **只擋寫**。所以「給它一個 admin 角色、
不給任何 permission」不是最小權限 —— 它讀得到學生、家長、報名、人員名冊（#1127 機台就是因此改成新角色 `kiosk`）。
新角色要同時查 `resolveCampusScope`：它對**非管理員一律回 null（不受分校限制）**，新角色會掉進這個全開分支，
要在前面攔（#1183）。

## 六、`ALTER TYPE … ADD VALUE` 的試套

在 `BEGIN … ROLLBACK` 裡試套時，**同一個交易不能使用新值**（`unsafe use of new value`）——
驗證用的 select 會報這個錯，那不是 migration 壞了。看 `ALTER TYPE` 那行成功、回滾後列舉值沒變就夠。
