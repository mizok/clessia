## 一、prettier 折行會改變 `textContent`，而 spec 常用 `textContent`（P2 第一次 CI 紅燈）

`.html` 加了一長串 utility 之後，prettier 會把 `<h2 class="…">文字</h2>` 折成前後換行。**瀏覽器對 block 內的前後空白折疊，所以截圖看不出差**，但：

- spec 用 `textContent` **全等**（`grades__subject-title` 讀到 `" 數學 "`、payments 的 `section-title` 斷言 `['待付款','已付款']`）→ 紅。
- 元素有 `white-space: pre-line`（grades 的考試描述、payments 的管理員多行帳戶資訊）→ 折出來的前後換行**會被渲染成空行**，截圖看得到、spec 不一定。
- 解法：該行前面放 **`<!-- prettier-ignore -->`（註解內文必須恰好是這幾個字，多寫一個字就失效）**，把元素與插值寫在同一行；說明另外放前一則註解。
- **開 PR 前先看 spec 斷言怎麼取值**（`textContent` 全等 vs `trim()`／`toContain`），不是只 grep 選擇器——1408 §三的 grep 只管選擇器。去 class 逐字比對腳本會把這種差異報成「只差空白」，**這個結論對 `textContent` 全等的斷言不成立**。

## 二、44px 觸控下限：列表列直接長高，單顆徽章用負邊距吃掉

- gate 要求基底 `min-h-11`。原 SCSS 是 `min-height:40px`＋`@media (pointer: coarse)` 44px，所以**桌機會多 4px、真實手機不變**。Playwright 預設 `pointer:fine`，截圖的 390 寬**不是**手機觸控——要在 PR 寫明，不要說「手機沒變」。
- 單顆徽章／彈層選項（child-switcher）用 `min-h-11 -my-0.5 pointer-coarse:my-0` 讓版面高度不變；代價是**彈層錨點多 2px**。列表列（attendance／payments 的 `__row`）**不要**用負邊距：44px 的盒子會吃掉列間 gap，視覺間距變小，不如接受 +4px。
- 抽屜裡「關閉」鈕原本內容撐出 43px、新的 44px，整張抽屜 +1px——這種「原本不是剛好 40」的要先量（`getBoundingClientRect`）才知道差多少。

## 三、Tailwind 任意變體寫相鄰兄弟：`[p+&]:mt-1`、`[&+&]:mt-2`

SCSS 的 `p + p {}`、`&__account + &__account {}` 對應 `[p+&]:mt-1`（編出 `p + .x`）與 `[&+&]:mt-2`（編出 `.x + .x`）。**1408 的喚醒比對腳本擷取 selector 用 `[.#]` 開頭，會漏掉 `p + .x` 這種**；擷取要放寬成「非 `@`、非 `}` 開頭」。腳本是拋棄式的（`.pw-regression/wake.mjs`，不進版控），用 `@tailwindcss/node` 的 `compile`＋`@tailwindcss/oxide` 的 `Scanner`，兩份 `git archive` 快照各編一次取差集。

## 四、本機沒有的狀態，用 route 攔截注入，兩邊同注入，並寫明

示範庫常常拍不到要驗的狀態（payments 20 張全是待付款、成績沒有帶描述的、考試沒綁班）。做法：Playwright 的 `page.route('**/api/…', async (r) => { const res = await r.fetch(); const j = await res.json(); …改 j…; r.fulfill({ response: res, json: j }) })`。

- **「前」「後」兩邊必須同一份注入腳本**；PR 描述寫「以攔截回應注入，不是真資料」，並寫明哪些情況**只有 spec 覆蓋、沒有實機畫面**（誠實比好看重要）。
- 用筆數保護（`if (d.length < 6) return r.fulfill(...)`）：切孩子前會先打一次別的孩子的請求，不保護會對空陣列寫 `d[1].status` 而炸。
- 家長端要拍有資料的畫面：**預設孩子可能沒資料**（parent03 的第一個孩子近 10 天無課），要用切換器選有資料的孩子，attendance 還要點「近30天」。示範資料：`parent03@demo.clessia.app`（孩子張宇軒，出缺席與 100+ 筆成績）、`parent04`（四個孩子）；老師端 `teacher0001@demo.clessia.app` 有 27 位任課學生，`teacher0005`／`0006` 沒有（會走「目前沒有任課班級的學生」那個空狀態，不是 bug）。

## 五、截圖腳本的環境小坑（macOS）

- `login-link.ts` 要的環境變數：`set -a; . apps/api/.dev.vars; set +a; WEB_URL=http://localhost:4200 LOGIN_EMAIL=… npx tsx apps/api/src/scripts/login-link.ts`。**只帶 `LOGIN_EMAIL` 會先報缺 `DATABASE_URL`，補了又報缺 `WEB_URL`**。`login.mjs` 的第二個參數是角色（parent／teacher／admin），單角色帳號會直接落在該角色首頁。
- macOS 沒有 `timeout` 指令。
- 像素差用 `pngjs`（repo 有裝）；`canvas` 沒裝，別 import。
- **殼是內部捲動，`fullPage: true` 截出來等於視窗高**，所以像素差只涵蓋首屏；列表被點擊後會捲動，前後捲動位置不同會讓整排差 4px 而看起來全錯——先量元素間距再下結論（payments 作廢展開 8.22% 就是這個）。
- 開 PR 前 `nx serve web` 要重啟才吃得到新的 `@source`；`git checkout --detach origin/main` 拍「前」之後記得切回分支，每次切完都重啟 web。

## 六、harness 自我測試會在「最後一個頁面目錄遷完」時紅（P3）

`tools/agent-harness/harness.test.mjs` 的 `unmigratedPageDir` 要找「不在 `@source`、底下有 `.scss` 的 `features/*/pages/*` 目錄」當 A20／A24 的對照；**最後一個遷完的那支 PR 會讓它丟「全站遷完時這兩條測試要改寫」，本機 `npm run harness` 看不到、CI 的 harness self-test 才紅**。現在改成頁面目錄找不到就找 `app/shared/components/*`（Z 批）。**shared 的 SCSS 也遷完時要再改一次**（那時才是真的「全站遷完」）——先跑 `npm run harness:test`。

## 七、型別：列表專用欄位放 `…ListItem extends 基底`，不要加在基底型別

API 的計數／關聯欄位（`inUseCount`、`overlappingEnrollmentCount`、`classes[]`）只在 `GET` 列表的 schema 有，create／update 的回應沒有。前端型別加在基底會讓：(a) 型別說謊；(b) 所有 `const x: AcademyExam = {…}` 形狀的 spec fixture 在 typecheck 失敗——**而本機 typecheck 被分類器擋，只能等 CI**。做法：`FeeTemplateListItem`／`BillingPeriodListItem`／`AcademyExamListItem` 只掛在 `list()` 的回傳；元件的 signal 型別換成 ListItem，spec 的 fixture 工廠換成 ListItem 並補欄位。**先 grep 誰在建構這個型別**再決定放哪。

## 八、佇列行為（額度撞到、計畫席暫時不回）

- 計畫席的訊息只有在我**有一個執行中的 turn** 時才會跟著工具結果送進來；PR ready 回報完之後如果我結束 turn，下一則「過」要等到下一次 turn 才會被看到。**這一輪 13:19 的「過」就這樣被我晾了近 40 分鐘**，直到 13:58 計畫席主動問才動。守則：**回報完「等你過」之後，一律在新分支準備下一件事（讀碼、寫設計、跑 harness），不要結束 turn 等**；收到「過」的下一個動作就是開分支。
- 計畫席說「額度上限到了、可能暫時不回」時，照舊：做完一支就回報、等授權、不自己合、不開第二支 ready；**期間不要停手**，在準備中的分支上把下一支做到「只差開 PR」。
- **開下一支前 `git fetch`；分支還沒推過就 `rebase origin/main`，推過的不 rebase**。兩支不碰同一檔時，「從合併前的 main 切出」不影響 PR（GitHub 用合併後的結果跑 CI），不必為此重做。
- 每次回報的「證據」一行寫：PR 編號、head sha、CI 結果、驗證證據；有**第一次 CI 紅燈**就照實寫原因與修法（P2 的 textContent、P3 的 harness 測試），不要只寫最後的綠。
