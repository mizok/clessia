## 二、動態的坑（全是實測出來的）

- **VT 動畫期間點擊一律打到 `<html>`**（W3C §7.1.1）。連點型控制項（換週箭頭、分頁）不能用 VT。
  `::view-transition { pointer-events: none }` 救不了（實測）。
- **新的 `startViewTransition` 會把進行中的那個 skip 掉，但舊的 `finished` 晚於新的寫屬性才 resolve。**
  任何「VT 開始時寫屬性、`finished` 時拿掉」的寫法都要用遞增序號比對（#1642 審核席抓到）。
- **zoneless 下 VT callback 裡要 `appRef.tick()`**，否則新快照是舊畫面。
- **`view-transition-name` 全頁唯一**，撞名整個 VT 被跳過。只在需要的元素、需要的時候給名字；
  換頁時不想讓它脫離內容區，用 `:root:not([data-vt=…]) .x { view-transition-name: none !important }` 蓋 inline style。
- **`::view-transition-new(*.cls):only-child`** ＝新出現的那一列、`old…:only-child` ＝消失的那一列。
- **大部分列表增刪後是「整份重抓＋@if(loading) 換骨架」**（盤點見 #1641 留言）—— 直接加 `animate.enter` 會每次全部重播、刪除的那列沒機會離場。
- **`track $index` 的列表刪中間一列，Angular 移掉的是最後一個節點**；不能 `track item`（immutable 更新會讓輸入框失焦），要前端穩定 key。測試寫「刪中間後第三列的 DOM 節點 `toBe` 原本那個」，`$index` 會紅。
- **VT 本身的成本小**：換頁凍結的主體是新頁渲染（有 / 無 VT 對照只差 15–25ms）；20 列帶名字在 CPU 降速 4 倍多約 20ms。

## 六、5b 的坑

- **新的 shared 元件用 Tailwind 要在 `tailwind.css` 加 `@source`**，否則 class 不產生、**靜靜地失效**（veil 的變淡實測停在 opacity 1）。加了之後 `npm run harness` 會說掃描範圍變大，刻意的就 `npm run harness:write`。
- **價目表是悲觀刪除（例外）**：計畫席 10-16 14:3x 裁定 —— 方案幾乎都被報名引用、`IN_USE` 太常見，樂觀版會常常「先淡出又回來」像壞掉。所以等伺服器確認才淡出補位（動畫照舊），失敗時那一列一直都在。**其他頁看到同樣「失敗是常態」的刪除，先問計畫席要不要也比照，不要自己決定。**
- 重抓期間**不能先把資料清掉**，否則 veil 留著的是空畫面。
