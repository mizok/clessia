## 一、一個目錄一支 PR 的固定流程（十一支走下來的樣子）

1. 讀 A6 稿的「規格 vs 現況」表＋現況目錄，**先貼範圍說明到 #991**（STOP gate），格式：同形狀／形狀不同（A6 要什麼｜現況｜建議）／這支 PR 做的／後續項（`#`｜A6 要什麼｜現況為何沒做｜依賴｜狀態，照 #1314）／待裁。**計畫席回「過」才動工**——「繼續 X」不等於過（有一次它早於 gate，問清楚後才動）。
2. `git fetch` 後 `checkout -b <內容取名> origin/main`；子代理（Sonnet）各做一個目錄或一批，主 session 收 `@source`、`harness:write`、PR。
3. gate 順序：`@source` 加一行 → `npm run harness:write`（`git checkout -- kb/wiki/roadmap.md`）→ `npm run harness`。它會逐項報：觸控 `min-h-11`、icon-only `aria-label`、對比、過期的 `TOUCH_TARGET_EXEMPT`／`aria-icon-button-baseline`。
4. 開 draft PR → 等 `gh pr checks <n> --watch` 的 `verify` → 做喚醒比對＋前後截圖 → 留言 → `gh pr ready`。**一次只一支 ready**；等的時候在新分支準備下一支。
5. **本機 `nx typecheck`／`nx test` 會被 auto mode 分類器擋**（先是 `--skip-nx-cache`，後來連一般 `nx affected` 都擋）。計畫席裁：不繞（不改用 tsc 或別的指令），**以 CI `verify` 為證**，PR 寫「本機 typecheck／test 未跑（分類器擋），以 CI 為證」。`nx serve` 與 playwright 不受影響。
6. 合併後 main 會前進：開下一支前 `git fetch`，分支若落後就 `rebase`（沒推過的才可以）；自動生成的 `scss-ledger-baseline.json`／`scan-scope.json`／`check-harness.mjs` 衝突時，`git checkout origin/main -- <那幾支>` 後重做，不要逐行合。

## 二、「`.ts` 只刪 `styleUrl`」邊界與它的三個例外

換版不換資料的證明方式（二讀逐項比）：`.ts` 只刪 `styleUrl`、頁面加 `PageOpenComponent` 的 import／imports；spec 零改動；模板**去掉 `class="…"` 後與 origin/main 逐字相同**：

```sh
norm(){ perl -0pe 's/\s+class="[^"]*"//g; s/\s+/ /g; s/> </></g; s/ \/?>/>/g'; }
diff <(git show origin/main:<檔>.html | norm | tr '>' '\n') <(norm < <檔>.html | tr '>' '\n')
```

整頁換外框時，頁首與工具列的差異會出現，再用第二支腳本抽「全部插值＋綁定＋控制流＋label」排序後比，**只多出新增的 `aria-label` 就算過**：
`perl -0ne 'while(/(\{\{.*?\}\}|\[[A-Za-z.%]+\]="[^"]*"|\(\w+(?:\.\w+)?\)="[^"]*"|\*?@(?:if|for|else)[^{]*\{|\blabel="[^"]*"|aria-label="[^"]*")/gs){$x=$1;$x=~s/\s+/ /g;print "$x\n"}' | sort`。

三個例外（都得在 PR 寫明）：
- **元件內嵌模板／樣式**（leave 的請假表單 dialog）：`.ts` diff 是模板內 `class`＋刪 `styles`，邏輯零改動，要另外證明。
- **條件 class**：`[class.foo--x]="cond"` 換成 `[class.text-zinc-500]="cond"`＋`[class.line-through]="cond"`，條件表達式必須同一個；一個 BEM modifier 拆成幾個 utility 時各寫一個綁定。
- **`PageOpenComponent`** 進 `imports`：prettier 會順手重排 `.ts` 的其他地方（`audienceOptions` 被換行過一次）——**不要對 `.ts` 跑 prettier**，只對 `.html` 跑；已被重排的手動還原。

## 三、spec 掛勾：開 PR 前「對整個目錄的 spec 全 grep 一輪」（兩次 CI 紅燈的教訓）

spec 常用 BEM class 當 DOM 標記（`.permission-item__label`、`.settings-page__textarea`、`.admin-notifications__composer`、`.staff__stat-value`、`.teaching-log__metric-skeleton`、`.settings-shell__title`…），換成 utility 之後 class 名消失 → spec 紅，**但本機不能跑 spec**，所以只能事前 grep。

```sh
grep -rnoE "['\"\`][^'\"\`]*\.[a-z][a-z-]*(__|--)[a-z-]+[^'\"\`]*['\"\`]|By\.css\([^)]*\)|querySelector(All)?\([^)]*\)|closest\([^)]*\)|classList[^;]*" <目錄> --include='*.spec.ts' | sort -u
```

- 讀到的 class 名**原樣留在模板上**（與 utility 並存，成為無樣式的 DOM 標記）；不要改 spec（邊界）。
- **掛不上 class 的地方**：`app-page-open` 內部的 `h1` 掛不了 class → 在 `openTitle` 裡包一層 `<span class="settings-shell__title">`。
- **grep 要涵蓋整個目錄**（含 `*.component.spec.ts` 等子元件）：settings 第一次只 grep 了殼，漏掉「一般」頁的 `textarea.settings-page__textarea`，CI 才抓到。

## 四、inline styles 寫在 `.ts` 裡，會同時躲過兩件事（leave 請假表單）

`@Component({ styles: [`…`] })` 的純 CSS 字串：
- **token gate 只掃 `.scss`**，所以這裡的 `var(--不存在的)` 沒人報。
- **SCSS 式巢狀 `&__x { … }` 在原生 CSS 裡不合法**（`&` 不能接字尾）→ 那些規則**從來沒生效**，畫面其實是預設樣式。換成 Tailwind 之後「原稿意圖」才第一次生效，高度 −14px。計畫席接受不改回；PR 要寫明原因與數字，別讓 reviewer 以為是回歸。
- harness 的 A24 對「列進 `@source` 的目錄底下還有 `.scss`」會紅，**inline styles 的元件也算**（錯誤訊息指向那支 `.ts`）——所以帳面剩 2 筆的目錄要找「第二個」，可能是 `.ts` 不是 `.scss`。

## 五、金額相關目錄（fee-templates、meals、reports）的審查寫法

計畫席裁為非保留類的前提：`.ts` 零邏輯改動＋模板去 class 逐字相同＋**金額欄位逐欄對照表**（PR 描述列：位置｜pipe／格式｜與 main 比）。

- 金額欄位只有幾處：列表 `{{ x.amount | number }}`、表單 `p-inputnumber mode="currency" currency="TWD" … [ngModel] (ngModelChange)`、摘要句裡的合計。**`p-inputnumber` 整個元素原本就沒有 class 時，前後 diff 為空**，直接寫「逐字相同」。
- **分章（依模式／依狀態）需要 `.ts` 的 `computed`，或在模板裡把含金額的列複製成三份** —— 與「零改動／逐欄比」衝突。fee-templates 我撤回了自己的「分三章」建議，改列後續項。範圍說明寫完要回頭用這條檢查。
- reports 另加「不新增任何前端加總」：用抽取腳本證明前後**全部**插值／綁定相同；A6 的流向帶／合計列都是前端加總，列後續項等後端。
- 一個 class 同時帶「紅色＋字重」時（`amount--overdue`），拆成兩個 `[class.*]`，條件表達式一字不改。

## 六、喚醒比對與前後截圖的腳本做法（每支 PR 都做，腳本拋棄式放 scratchpad／`.pw-regression/`）

- **喚醒比對**：`git archive origin/main apps/web/src` 與 `git archive HEAD apps/web/src` 各解到快照目錄、`ln -s node_modules`；用 `@tailwindcss/node` 的 `compile` 與 `@tailwindcss/oxide` 的 `Scanner` 對兩份 `tailwind.css` 各產一次 CSS，取 selector 差集；差集 token 對「不在任何 `@source` 範圍」的 `.html`／`.ts`（排除 spec）找 `class="…"`、`styleClass`、`[class.x]`。命中 0 之後仍要**手動 grep 差集裡的 PrimeFlex 常見名**（`mb-5`、`gap-8`、`pr-5`、`mt-0`…）。
- **截圖**：同一支腳本在分支與 `git checkout --detach origin/main` 各跑一次（中間 `kill $(lsof -tiTCP:4200 -sTCP:LISTEN)` 重啟 web），`canvas` 做像素差＋並排圖。登入：`cp ../../apps/api/.dev.vars apps/api/.dev.vars`（gitignored）、`npx nx serve api`、`LOGIN_EMAIL=admin@demo.clessia.app npx tsx apps/api/src/scripts/login-link.ts`、`.pw-regression/login.mjs`。
- **像素差怎麼讀**：整頁換色面＋灰工具列 20–40%（預期）；dialog 尺寸前後相同且 <1% 是理想；**dialog 高度 +12px＝關閉鈕 `size-11`、+10px＝按鈕 `min-h-11`**（A27），都是預期，在 PR 寫出來。
- **本機示範庫沒資料時**（當月沒有報名進出）截圖只剩空狀態：寫明「文案比對靠腳本、不靠截圖」，不要宣稱看過表格列。
- 截圖要讀 `sbs-*.png` 並排圖；**差異百分比不能代替目視**。

## 七、子代理（Sonnet）分工的提示詞骨架

每個目錄一個子代理、背景跑；提示詞固定包含：分支與目錄、**不碰** `tailwind.css`／`tools/`／spec／commit、**不跑 nx**、`.ts` 邊界、spec 掛勾先 grep、外框做法（`app-page-open`＋灰工具列＋`page-wrap`）、Tailwind token 規則（字級只到 `text-3xl`、spacing 乘數 4px、禁 viewport 單位）、驗證指令、回報格式（去 class diff 完整差異、無法 1:1 處）。

- 子代理**會編文案**（leave 頁首副標「管理學生請假紀錄」）、**會順手加 `aria-label`**：收回報時逐條看「無法 1:1 對應處」，編的文案刪掉。
- 子代理**不知道 gate 的細節**：觸控 `min-h-11`、對比、`@source` 都在主 session 跑完 `harness` 才看得到，最常見的紅燈是「全域 legacy class 一進 `@source` 就被 A27 看到」（`import-dialog__*`、`dialog-header-inline__close`）。
- 判斷「子代理做完了」：`until [ -z "$(find <目錄> -name '*.scss')" ]; do sleep 5; done` 之後再 `sleep` 一會兒等它收尾回報；Stop hook 會在它做到一半時報紅，那是預期。

## 八、小坑

- **BSD sed**：`sed -i '' …`；位址語法（`sed -i '115,116d'`）漏了 `''` 會把整條指令吃成 label 錯誤而**什麼都沒刪**，之後 harness 照樣報舊的紅燈（和 `silent-tool-failures` 同一類）。
- **heredoc 裡有 `$(…)`、反引號、`\|` 時**，zsh 可能 parse error；PR 描述改用 `<<'EOF'` 寫佔位符、再用 python 取代。
- **`cd` 失敗後的 `;` 會繼續**：一支截圖腳本因此被寫進 `apps/web/src/app/`，差點進 commit。要寫檔先 `pwd` 或用絕對路徑。
- **herdr 送訊息前看對方輸入框**：`… | tail -6 | grep -c '❯ *$'` 為 1 才是空；為 0 時訊息會排在對方佇列，不會混進它正在打的字，但最好等。
- **PR 描述的「合併」時序**：reviewer 代合很快，**你在回「修」之前 PR 可能已經合了**；往已刪的分支推會報 `cannot lock ref`。先 `gh pr view <n> --json state`，合了就從新的 `origin/main` 開新分支 cherry-pick。
- **我曾說錯事實**：「手機工具列沿用現狀」沒對照前版，實際是換版造成的回歸（置中窄寬）。**回報「與前版相同」之前先看前版截圖**。
- `sidebar` 以外的剩餘 SCSS（`app.component`、`select-role`、`role-picker`、`account-settings-dialog`）是殼／入口頁（S／Z 批），**不派給執行席**。
