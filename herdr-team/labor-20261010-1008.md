## 一、「章 × 篩選」頁（名冊／人員／費用方案）的共通做法與四個會咬人的地方

做法照 parents／courses：`app-chapter-head`＋右側列、`app-filter-toggle [always]`＋面板、`app-page-actions`。三頁共通的版面骨架（section 的 grid、`wide:grid-cols-[13rem_minmax(0,1fr)]`、列的 grid）彼此是複製的，**改一頁的間距要三頁一起看**。

1. **章名張數的來源要問「它吃哪些篩選」。** 學生 `byGrade`：吃搜尋、狀態、今天，**不吃 `grade`**（所以選了年級其他章名照樣對）。人員 `byRole`：**不吃 `status` 篩選**——選「已停用」時章名寫 2、底下只有 1 列（實機對 API 才抓到）。可操作：**明確選了某個維度，而摘要不吃那個維度時，章名改數列**（列表是一次取全部時最簡單），並寫 spec、**還原修正驗它會紅**。
2. **後端「只有第一頁才算」的欄位（學生 `summary.today`）翻頁會回 null。** 前端要記住上一次算到的（`todayCounts`），而「這個分校不支援」只能在**第一頁**回 null 時判定，翻頁回 null 不能改判。否則翻到第 2 頁篩選面板的人數會消失、或「今天」那列被誤灰掉。
3. **搜尋的去重不要用 `distinctUntilChanged`，對照「目前生效的查詢」：** `filter(v => v !== this.searchQuery())`。「清除篩選」會直接把 `searchQuery` 清掉，而 `distinctUntilChanged` 記的是上一次輸入——清除之後再打同一個字會被吞掉。清除一次清搜尋＋所有篩選、**只重查一次**。
4. **「預設不含封存」這類 A6 預設，API 不支援時前端濾。** 人員 `status` 是單一值：`live`（啟用中＋已停用）與 `all` 都不帶 status 取全部，`live` 在前端濾掉封存；停用章張數用 `summary.inactiveCount`（`byRole` 那桶把封存也算進去）。

**把伺服器搜尋改成前端過濾時**（費用方案，API 無分頁、十幾筆）：搜尋的 debounce／`switchMap` 管線跟它的 race spec 一起拿掉（輸入不再打請求），**取數管線（儲存後重整）與 `catchError` 要留**。要先在範圍說明裡寫「為什麼」（色面要含停用的數字）並列為待裁。

## 二、page-actions 在 flex-wrap 工具列裡的排列

桌機把 `app-page-actions` 放進工具列時，面板（篩選）若 `basis-full` 又排在它前面，**新增鈕會被擠到第二行**。用 `order` 管：`wide:order-2` 給 actions、`wide:order-3` 給面板（`wide:contents` 攤平容器之後 `order` 才作用在同一層）。手機要「搜尋＋圖示鈕同列、chip 第二列」就給 chip 外包一個 `order-3 w-full wide:order-2 wide:w-auto`。**托盤的 `secondary` 在桌機標頭也會渲染**，所以「新增期間」這類次要行動桌機會同時在標頭與章頭右側各一顆——範圍說明裡列成「接受重複」待裁，別為它改共用件。

## 三、實機對帳的腳本形狀（比並排圖更能抓到邏輯 bug）

- **API 在 8787，不在 4200**：`ctx.request.get('http://localhost:4200/api/…')` 回的是 SPA 的 HTML（`Unexpected token '<'`）。用 `storageState` 的 context 打 `http://localhost:8787/api/…`，cookie 照樣帶。
- 腳本骨架：`api(q)` 取真值 → 在畫面上按 → 同時讀「畫面列數／章名／色面標題／篩選鈕文字」與 API 的 `total`／`summary` 逐項對。**每按一個鈕就印一行「畫面 X＝API Y」**，PR 描述直接貼。
- **首屏圖比全頁圖好用**：`fullPage` 的 1440＋360 並排縮到看不出差異。另寫一支 `top.mjs`（`vd.mjs` 複製、視窗 1440×900／360×780、`fullPage:false`）逐次比對；全頁圖留給 PR 附檔。
- **PrimeNG 對話框的關法**：有 `.dialog-header-inline__close` 的點它；表單對話框（沒有 X）點「取消」；`Escape` 在這個專案的 `p-dynamicdialog` 上不可靠，**沒關掉就會讓後面所有點擊被 mask 擋住**（錯誤訊息是 `p-dialog-mask … intercepts pointer events`）。
- **示範庫沒有的狀態用 `page.route` 注入並明寫**：例如費用方案的重疊期間（示範庫兩個期間不重疊）——攔 `**/api/billing-periods` 改回應再拍，PR 標「注入的不是真資料」，真資料由 spec 驗。

## 四、驗證別人還沒合的後端依賴

名冊要等 #1473（依年級排序）才章連續。**不要等、也不要把它 cherry-pick 進自己的分支**：把那支 PR 的 `apps/api/src/routes/xxx.ts` 做成 patch（`git diff origin/main...origin/<他的分支> -- <檔> > $TMPDIR/x.patch`）、`git apply` 在工作樹上驗，**commit 前 `git apply -R` 還原**，`git add` 只加指名路徑（本來就是鐵律）。PR 描述寫「依賴 #N，我是臨時套它驗的（未 commit）」並先開 **draft**。

## 五、分支與 PR 的操作細節

- **已推的分支吃 main 用 `git merge origin/main`，不 rebase**（規矩）；**還沒推的 WIP 要整理成一個 commit 時**：先 `git merge origin/main`、再 `git reset --soft origin/main`、`git add` 指名檔、一次 commit。多支 PR 輪流做時，換分支前把未完成的做成本地 WIP commit（`wip(...)`），切回來時 `git checkout` 即可；**dev server 跟著 worktree 的分支走**，切分支會觸發重編譯。
- **一次一支 ready 是計畫席明確在管的**：新 PR 一律先開 draft（描述末尾寫理由「#N 在 ready，它合了我轉 ready」），前一支合了才 `gh pr ready` 並回 head。計畫席說「#X 合了，轉 ready 併 main」＝ **merge main 進分支、跑 web typecheck＋test、push、ready、回 head**（不是 rebase）。
- macOS 的 `sed -i` 要 `sed -i ''`；沒有 `PIL`、`sips -c` 的 offset 語意跟直覺不同——**切圖改用 Playwright 直接截首屏**，不要在 shell 裡裁。

## 六、harness 的對比 gate 會誤判「條件式 class」

`class="… bg-zinc-100"` 加 `[class.bg-zinc-900]="a" [class.text-white]="a" [class.bg-zinc-100]="!a" [class.text-zinc-800]="!a"` 在同一個元素上，gate 把四個 class 當同時成立，報「text-white 疊在 bg-zinc-100 上對比 1.11」。**拆成 `@if`／`@else` 兩個各自帶靜態 class 的元素**（不同分支各自完整）。同族：A27 要靜態 class（0854 §三）。

## 八、範圍說明與回報的格式（計畫席回「過」一次就過的那一種）

三欄：**做什麼（表格，編號）／不做（附理由）／待裁（每條附我的預設，「回過＝採預設」）**；再加「現況有 A6 沒畫」「驗證計畫」。**待裁 = 我真的要它裁的事，不是我懶得查的事**——先 `curl`／讀碼查完（例如「`status` 是不是單一值」「API 有沒有分頁」）再寫預設。PR 描述的證據段：**逐區塊差異（一致／例外）、實際按過（＋與 API 對帳的數字）、沒拍到（含「注入的不是真資料」）**。額度：**Ctx 讀不到精確值**（工具沒給），被問時照對話量估並標「請以 ops-warden 巡檢為準」；超過 60% 就只做範圍說明、實作交下一席。
