## 一、「對齊 A6」前先問：稿的規則到底在哪一行

## 二、會騙人的東西

- **「稿有、頁沒有」常常是「頁沒接線」不是「頁漏做」**：頂欄分校下拉只在頁呼叫 `CampusContextService.use()` 才出現（#1138 H2 的過渡期設計，避免「頂欄選 A、這頁還是 B」）。**不要在殼層強制顯示。** 接線前先查該頁用到的每支 API 有沒有 `campusId` 參數（students ✅；parents／invoices／billing-periods ❌ 只依授權範圍；fee-templates／meals 根本沒有分校概念；dashboard 一半有一半沒有 → 裁定整頁等 API，**DB-campus** 後續項）。**一頁裡一半卡片跟頂欄、一半寫「全部分校」比整頁不接更糟。**
- **全站搜尋只查學生**（`global-search.component.ts` 打 `studentsService.list`）。稿的 placeholder 寫「…、帳單」，**照抄會讓使用者搜帳單搜不到**——placeholder 是承諾。要加得先做結果分組與點擊去向。
- **帳單搜尋 API 有（`invoices` 的 search），但前端 `campusId` 沒有** —— 兩件事別混在一起說「invoices 支援分校」。
- **手機頂欄分校顯示名字會把帳戶鈕擠到第二列**（360，頭部 93→137px）。試做、量到、退回，註解寫在模板裡。下次有人想「手機也顯示名字」先看那行註解。
- **dev server 在同一個 worktree 換分支會即時換掉內容**：我為了拍「合併後」的 main 用 `git checkout --detach origin/main`，4201 的 server 隨即熱換。拍完要確認自己現在在哪個分支（`git branch --show-current`），**別把截圖標成 A 分支、實際拍的是 B**。
- **`npx nx test web --include=...` 的輸出有 ANSI 色碼**，`grep "Tests "` 可能一行都抓不到、看起來像「沒跑」。加 `NO_COLOR=1`；**而且單檔 glob 一定要引號**（zsh 會展開）。突變驗證時「沒輸出」不是綠，是沒跑。
- **zsh 的 `--include=*.html` 沒引號會 `no matches found`**，整條指令不執行。`grep -rn ... --include='*.html'`。

## 三、設計決定（下一個做同類頁會再問）

- **頭像圓章取字**：`displayName().trim()` 的第一個「字元」（`Array.from`，不拆代理對），空名退 email，都空顯示「?」。jdenticon 元件**沒刪**（成績對話框還在用），只是殼層不用了。
- **`page-actions` 的 `secondaryOnDesktop`**（預設 `true`）：章頭已有同一個動作時傳 `false`，只影響桌機標頭；**手機托盤不受影響**。逐頁對稿結果：只有 fee-templates 真的重複，payments／dashboard／student-detail／staff 的 secondary A6 工具列都有放，維持。**判斷「重複」用 `getByRole('button',{name})` 數頁內出現幾次**，比看圖準。
- **托盤高度維持 44px**（A27 觸控下限），稿是 40px；**托盤底色稿是淺灰、本機是白**——兩項都**沒做**，列為殘差。
- **只有 primary 的使用頁**（手機托盤一顆）：parents、students、courses、meals、leave、campuses、exams；有 secondary：payments、dashboard、student-detail、fee-templates、staff。改托盤版面是同一處 class，**不會有頁面各自覆寫**（grep `page-actions__(dock|cta|secondary)` 只有元件本身）。

## 四、測試的坑

- **切換「頂欄分校」的 spec 要清 `localStorage.removeItem('clessia.campusContext')`**，否則上一條選的分校漏到下一條（`staff.page.spec.ts` 有範本，`students.page.spec.ts` 照抄）。`CampusContextService.use()` 會呼叫 `ReferenceDataService.loadCampuses()` → spec 要 mock，不然打真的 HTTP。
- **亂序 spec 的寫法**：mock 的 `list` 回自己控制完成時機的 `Subject`，把每次呼叫的 `params` 記進 `pending[]`；換兩次分校後**先讓第二個 `next`、再讓第一個 `next`**，斷言畫面是第二個的資料。`pending[0]` 是初次載入，要用 `[, first, second]` 解構。
- **`clearFilters` 之類 `protected` 方法，spec 要 `(component as unknown as { clearFilters: () => void }).clearFilters()`**，直接呼叫會 TS2445（而且報在編譯階段，整支 spec 都不跑）。
- 頭像取字的 spec 要換 `auth.profile.set(...)`／`auth.user.set(...)` 後 `detectChanges`（stub 的 signal 可寫）；`'𠮷野'` 那條釘代理對。
- **突變驗證這輪做了八次**，全是 `skip(1)→skip(0)`、`set(1)→set(2)`、`@if (x)→@if (!x)`、`justify-end→justify-start`、加回 `w-full` 這類型別不變的改法；每次先 `cp` 備份、跑完還原、再跑一次確認回綠。
