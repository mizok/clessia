# 管理端可用性測試 —— 任務清單

> **給誰**：一個**不讀原始碼**的席位，只透過瀏覽器操作管理端。
> **目的**：找出「主任會卡在哪裡」，不是「這個介面好不好看」。
> **可重跑**：UI 改過之後再跑一次，比較卡點有沒有變少。

## 硬性規則（違反的話這份報告沒有價值）

1. **不准讀原始碼、不准讀 `kb/`、不准 grep、不准看 API 回應。** 只能看畫面。
   **執行機制**：這一席要在 **repo 以外的目錄**啟動，讓它讀不到，而不是靠自律。
2. **不准問「這個功能在哪」。** 找不到就是一個發現，直接記下來。
3. **每個任務最多 10 分鐘**，超過就標記**未完成**並記下卡在哪。不要硬做。
4. **記錄事實，不要寫感受。**

   | 寫這個 ✅ | 不要寫這個 ❌ |
   | --- | --- |
   | 「找新增學生的入口，試了 3 個地方才找到」 | 「介面有點雜亂」 |
   | 「按儲存後畫面沒有任何變化，我不確定成功了沒」 | 「回饋感覺不太夠」 |
   | 「錯誤訊息寫『驗證失敗』，沒說是哪一欄」 | 「錯誤處理可以更好」 |

   **感受是模擬出來的，卡點是觀察到的。** 只有後者是證據。

## 每個任務要回報的四件事

- **做完了嗎**（完成 / 未完成）
- **走過哪些頁面**（照順序）
- **在哪裡停下來想**，以及**為什麼**
- **有沒有做了之後才發現走錯**（回頭重來的次數）

## 任務

**這些是用行政語言寫的，不是系統語言。找出該去哪、該做什麼，是任務的一部分。**

### 一、招生與入班

1. 有個新學生今天要來上國三數學，家長姓陳，電話 0912-345-678。**把他排進去，並讓系統知道要收費。**
2. 陳媽媽打來問：**這個月要繳多少、什麼時候繳。** 回答她。
3. 有五個學生要一起加入同一個班（暑期招生）。**不要一個一個建。**

### 二、每天的課

4. **今天有哪幾堂課、分別是誰上的？**
5. 今天下午那堂國二理化，**點名**。有一個學生沒來，家長沒請假。
6. 王老師明天請假。**明天他那兩堂課要有人上。**
7. 下週三是國定假日，**那天的課全部停掉**，並且**讓家長知道之後會補**。
8. 承上：**把停掉的那堂課排一個補課。**

### 三、家長來電

9. 林媽媽說孩子明天要看醫生，**幫他請假**。
10. 林媽媽問：**孩子這個月缺席幾次、上課狀況如何。**
11. 有家長想知道**孩子上次月考考幾分、跟上次比進步還退步**。

### 四、成績

12. 這次校內模考的成績單來了，**把國三數學班的分數登進去**。
13. **找出這次考最差的三個學生**，準備通知家長。

### 五、錢

14. **這個月有誰還沒繳費？** 列出來。
15. 承上：**通知他們。**
16. **這個月收了多少錢？**

### 六、管理

17. 新來一個行政助理，**只讓她看得到某一個分校的資料**。
18. **李老師這個月上了幾堂課？**（要算鐘點費）

---

## 報告格式

**一個任務一段，開頭就寫完成 / 未完成。**

最後加三節：

- **完全找不到入口的功能**（最重要的一節）
- **做完之後才發現走錯、要回頭重來的地方**
- **同一件事有兩個以上入口、而它們行為不一樣的地方**

**不要寫改善建議。** 找出卡在哪就好 —— 怎麼改是下一步，而且由看得到程式碼的人決定。
