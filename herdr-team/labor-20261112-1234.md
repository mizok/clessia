## 1. 讀 `jump.mjs` 的數字：單幀最大很吵，要配一個不受掉幀影響的指標

- screencast 只在畫面有變時出幀，負載高時常有 **250ms 左右沒有幀**的空檔。滑動落在空檔裡，就會被併成一大步。
  同一頁同一份程式碼，單幀最大可以是 41～192。
- **工具的 `timeline` 只留「有變化的幀」**（`changes()`），所以兩筆之間隔很久，**分不出是掉幀還是畫面本來沒變**。
  後者是真的跳（例如瞬間冒出來的區塊），前者是假值。要判斷就得有每一幀的時間：
  暫時複製一份 `jump.mjs`，在回傳物件加 `allFrames: frames`，再看「最大那一步的前一幀隔多久」。
  前一幀 ≤34ms 的最大一步才是真的。#1859 儀表板桌機的 341 就是這樣判成假值（現在 15／18／17，前一幀都在 25ms 內）。
- **使用者在意的是「可點的東西在動畫中移位」**，所以另外算：用 `--sel` 標出列（例如 `.payments__section`），
  取「它第一次畫出來的頂端」到「最後的頂端」的差。這個不受掉幀影響，修前修後一眼看得出來（211 → 0）。
- 同一個 web 交替切檔量 main 與分支：先把改動 commit 成 wip，`git checkout origin/main -- <頁面檔>` 讓 dev server
  熱重載成 main，量完再 `git checkout HEAD -- <頁面檔>`。不用再起第二個 web。

## 2. 量「載入中 vs 完成」最準的方法：把那支 API 卡住

逐幀量測之前，先用 playwright 把那一頁的資料 API **卡住**（route handler 裡 `await` 一個 promise），
對載入中的畫面量 `getBoundingClientRect()`、截圖，放行後再量一次。幾秒就知道「誰長高了多少」，也能驗證佔位是不是剛好等高。
修完家長繳費是 401→406（剩 5px）、家長成績是完全等高。

- 腳本要放在 `tools/a6-conformance/` 底下才 import 得到 playwright（跑完刪掉）
- web 打的是 build 進去的 `http://localhost:8787`，要 route 到自己的 API port
- 家長頁的資料端點：`/api/me/children`、`/api/me/billing`、`/api/me/grades`（不是 `/api/invoices`）

## 3. 家長頁的量測坑

- 家長端**一律選孩子清單第一個**（`ChildScopeService` 不記住選擇）。parent03 的第一個孩子張品妍在本機 seed
  **沒有帳單也沒有成績**；有資料的是張宇軒（帳單 28、成績 107）。不指定就量到空狀態，數字很小但不是真的沒問題。
  `jump.mjs --child 張宇軒`（#2435）把指定的孩子排到第一個。
- 量完要再用沒資料的孩子量一次：佔位的代價會出現在那裡（色面從骨架高度縮回去）。

## 4. 頁首色面資料晚到撐開：佔位的寫法與取捨（#2435、#2436）

- `bandPending`：第一次的資料回來（或失敗）之前為 true；換孩子時不回到 true（色面留著上一個孩子的字）。
  「沒有孩子」與孩子清單讀取失敗要排除，不然骨架會一直轉（下面是 child-scope-gate 的說明，不會有資料）。
- 色面裡的字用 `.skeleton.skeleton--on-band`（同儀表板），**照資料版的結構畫**：兩行標題、副行、數字列，
  數字放在 `dd` 裡，標籤照寫，這樣才會等高。
- 色面**外面**的東西（灰帶篩選列）不在 page-open 的 `appHeightFollow` 裡：先畫出來並 `inert`，
  外面再包 `<div appHeightFollow appHeightFollowGrow><div>…</div></div>`，收掉的時候才會滑。
  `appHeightFollow` 預設**不滑從 0 長出來／收回 0**，要 `Grow`。
- 取捨：沒資料的孩子會往回縮，單幀數字變大，但下面只有空狀態、沒有可點的東西。照使用者「只有點擊目標會移位才預留」
  的方向，這是可以接受的那一邊。PR 要寫出來，不要只貼好看的那組數字。
- `--arrive` 前快後慢：200ms 的滑動，16ms 就走了 33%，33ms 走 60%。所以 heightFollow 的滑動在數字上常像跳；
  判讀時別把它跟真的跳混在一起（看第 1 節）。

## 5. 雜項

- 單檔 web spec：`npx nx test web --skip-nx-cache --include='**/<目錄>/*.spec.ts'`。
  直接 `npx vitest run` 會報 `PlatformLocation needs to be compiled using the JIT compiler`（web 走 `@angular/build:unit-test`）。
- 負載高時本機 wrangler 會自己死掉（log 最後是 `Logs were written to …`），之後每一頁都 networkidle 逾時。
  量測前先 `kill -0 $(cat <api.pid>)`；`pgrep workerd` 找到的可能是別席的（看 cwd），不要動。
- 對話框換殼（#2290）的盤點判準：元件的 `.html`＋`.ts` 有 `app-dialog-frame`；另外用
  `grep -rhoE '\.open(<[^>]*>)?\(\s*[A-Z][A-Za-z]+'` 撈出所有 DialogService 開的元件逐一核。例外形狀
  （永遠貼底的 p-drawer）只換標頭：h2＋`ariaCloseLabel="關閉"`。
