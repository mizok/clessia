## 動工前先知道的兩件事

### 1. 讀取 API 還不存在

migration ✅（`20260906083827_add_session_makeup.sql`）、寫入端點 ✅
（`PATCH /api/sessions/:id/makeup`，`sessions.ts:1171`），**但沒有任何 list / detail
的 `.select()` 帶 `makeup_for_session_id`**（2026-09-06 查證：整支 `sessions.ts` 只在
PATCH handler 內部 `:1207` 出現一次，做驗證用）。

這跟設計文件的交付順序一致（API 是第 3 片），**不是有人漏做**。

### 2. 方向 B 需要一個設計文件沒編列的欄位

設計文件的「影響的既有元件」寫著「`mapSession` 多回**兩個**欄位」——那只夠方向 A。

方向 B（「已於 X/X 補課」）是**反向查詢**，而且**必須只算有效的補課**（決策 5.1 寫死）。
建議多回一個：

```ts
madeUpOnDate: string | null; // 有效補課那一堂的日期；沒有有效補課就是 null
```

**是 nullable date，不是 boolean 也不是 count。** 畫面要印日期，回 boolean 等於逼前端
再打一次；回 count 等於把「多數時候相等」那個陷阱送回前端手上。**`null` 就是「沒補回來」**，
一個值同時是答案和判斷式，**沒有第二種算法可以寫錯**。

## 三端的構圖

### 方向 A —— 補課那一堂：`app-data-chip`，文案 `補 11/03 停課`

三端同一顆中性膠囊，**零新元件、零新 tone、零 API 變更**：

| 端             | 位置                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| 老師端課卡     | `session-meta` 的 chip 列（`schedule.page.html:161`，與 `停課`/`代課`/`小考`/`校區` 同列）            |
| 家長端出缺席列 | 既有的 `sessionChipLabel()` 那個位置（`attendance.page.html:66`，該處註解已明寫它刻意抄老師端的形狀） |
| 管理端課表     | 班級欄的 meta 行                                                                                      |

**不算擴張詞彙**：兩道關卡守的是 `app-status-dot` 的**封閉 enum**（`StatusTone`），
而 `app-data-chip` 的介面是 `<ng-content />` —— **開放集合**。而且補課跟 `代課` 同族
（都在說這堂課的來歷），不是新的一類。

**日期用 `MM/dd`**（依 [`date-display-conventions.md`](../kb/wiki/architecture/date-display-conventions.md)：
列表列的年份由上下文決定）。

### 方向 B —— 被補的那一堂：**不加第二個標記，改寫既有那一顆**

```
現況      ：[停課]                [中山校區]  18 人
提案      ：[停課・已補 11/10]     [中山校區]  18 人
不建議    ：[停課] [已於 11/10 補課] [中山校區]  18 人
```

**理由不是美學。** 兩個版本在渲染上都沒問題（實測：停課卡 `opacity` 是 1，
只有班級名 `line-through`，chip 顏色與正常卡相同），密度也不能分勝負（兩版在 320px 都單行）。

**真正的理由是「不建議」那版會長出一個很自然而且錯的實作**：

```ts
@if (makeups.length > 0) { <app-data-chip>已於 … 補課</app-data-chip> }   // ← 數錯了
```

那正是決策 5.1 警告的計數（該數「有效的」不是「全部的」），而它
**多數時候相等，相等的時候你不會發現自己用錯了那一個**。

一顆 chip 的寫法讓那個 bug **寫不出來**：文字由 `madeUpOnDate` 這一個 nullable 值決定，
`null` → `停課`、有值 → `停課・已補 X/X`。**退化方向天生正確**（補課也被停掉 → 欄位變 null
→ 自動退回「停課」，正是「就是沒補回來」）。

> 這是這一席既有的判準：**當「可以表達錯的東西」本身就是問題時，載體的價值在於
> 讓那個錯誤變成不可表達的**（同 `app-data-chip` 刻意沒有 severity 參數、
> `app-page-band` 的 `frozen` 刻意不做成 input）。

**家長端不做方向 B**（載體不對稱，設計文件決策 3 已裁）。

### 密度：最壞是**五個** chip，390px 與 360px 會變兩行

⚠️ **`停課` 與 `補 X/X 停課` 會同時出現。** 決策 5.1 允許「補課那堂又被停掉、連結保留」
（語意是「本來要補，結果補課也停了」）。所以最壞情況是
`停課 / 補 11/03 停課 / 代課 / 小考 ×2 / 大安校區` ＋ `18 人`。

實測（真的元件 SCSS 編出來、真的 chip 樣式）：

| 卡片寬    | 四個 chip | **五個 chip**                         |
| --------- | --------- | ------------------------------------- |
| 430px     | 單行      | 單行（20.5px）                        |
| **390px** | 單行      | **兩行（46.5px）—— `18 人` 被擠下去** |
| **360px** | 單行      | **兩行（46.5px）**                    |
| 320px     | 兩行      | 兩行（49.0px）                        |

**都沒有溢出。不建議為此改設計** —— 這一列本來就是 flex-wrap、換行是預期行為，
而為一個四重罕見態砍 chip 會傷害常態。**常態（補課那堂正常上）仍是單行。**

> 量的方法：**高度才是可靠訊號**（單行 20.5、兩行 46.5）。
> 用「不同的 top 偏移數」數行數**會被 baseline 騙** —— 430px 明明單行卻數出 2，
> 因為 `18 人` 字級不同、top 就不同。

**未解**：`[停課] [補 11/03 停課]` 並排讀起來需要想一下。正確意思是
「這堂**本來要補** 11/03，**結果它自己也停了**」，字面容易被讀成「11/03 停課、這堂補它」
而漏掉後半。要不要為它做特別文案（例如 `補 11/03（已停）`）**未裁** ——
它會動到「一顆 chip」那條原則。

### 異動紀錄頁

`CHANGE_TYPE_LABELS` 補 `makeup: '補課'`（設計文件決策 4 已寫，篩選是黑名單所以會自動出現）。

⚠️ **設計文件抓到了標籤那一處，漏了同一族的第二處**：

| 位置                                    | 現況                                                    | 後果                   |
| --------------------------------------- | ------------------------------------------------------- | ---------------------- |
| `sessions/change-log.ts:8` `ChangeType` | 沒有 `makeup`（值從 DB cast 進來，**TS 不會抱怨**）     | —                      |
| 同檔 `:67` `summarise()`                | 沒有 `makeup` 分支 → `default: return '異動'`（`:101`） | **摘要欄顯示「異動」** |

補完標籤之後那一列會是**類型欄對了、摘要欄還是錯的**，而且不拋錯。
建議摘要 `補課：補 11/03 停課`（同 `代課：X → Y`、`調課：A → B`）。

**但日期目前只存在 `reason` 這個自由文字裡**（`sessions.ts:1278` 寫
`` reason: `補 ${target.session_date} 停課` ``），`original_session_date` 沒被填。
要組出摘要只有「parse `reason` 字串」（會腐化）或「寫入時一併填 `original_session_date`」
（乾淨，跟 `reschedule`/`time_change` 用同樣欄位）。**後者要動已進 main 的寫入端點，未裁。**

> `reason` 存機器產生的字串**是符合慣例的，不是誤用** —— `classes.ts:2472` 的批次停課寫
> `'批次停課'`、`:2841` 寫 `'班級停用'`。同一欄位在別的路徑（12 處 `body.reason ?? null`）
> 才是人填的。**這個欄位本來就是混用的。**

## 可補清單的挑選器

### 控制項：重用 `session-substitute-dialog` 的形狀

`session-op-form` 的骨架**在 `styles.scss:1424` 是全域的**，四支對話框
（assign / reschedule / cancel / substitute）已經在用，提供 9 個元素：

```
__field  __footer  __label  __required  __row  __textarea  __time  __upload-area  __warning
```

各元件只加自己的局部（substitute 加 `__count` `__hint`）。**補課對話框要新寫的只有
`__hint`（空清單文案）與選項模板的時段那一行 —— 不是複製一份表單。**

> 量這個時踩過一次坑：`grep "session-op-form__"` **回零筆**，因為 SCSS 是巢狀 `&__x`，
> 完整字串在原始碼裡不存在（README 記過兩次的 BEM 盲區）。**差一點據此說「全域那份是空殼」。**

### 選項文案

```
11/03 (週一)          14:00–15:30
```

**逐字就是 `session-list.component.html:69` 現在渲染的格式** —— 行政在列表看到的字串
跟在選單裡看到的完全一樣。帶星期是有理由的：排課是 weekday 驅動（班級 `schedules`
就是 weekday 1–7）。

### API 回應形狀（billing-api 已收下，無異議）

```ts
{
  id: string;
  sessionDate: 'yyyy-MM-dd';
  startTime: 'HH:mm';
  endTime: 'HH:mm';
}
```

**刻意不要的三個，理由各不相同：**

| 不要                       | 為什麼                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `className` / `courseName` | 候選依定義全同一個班（決策 2 的查詢就是 `class_id = <這堂課的班>`）。每列印同一個班名是噪音，還會讓人以為可以跨班補 |
| `weekday`                  | 從 `sessionDate` 推得出來，前端已有 `getDayLabel()`（`session-list.component.ts:116`）。多送一份等於多一份真相      |
| **任何計數**               | 決策 2 已把「已有有效補課的」排除在清單外，**清單裡每一筆都必然可補**。多送計數就是把那個陷阱從後端搬到前端再賭一次 |

**排序**：`session_date` 升冪、`start_time` 次之 —— **不是新決策**，`sessions.ts:794-795`
的列表端點就是這樣。升冪同時也是對的：清單已濾掉「補過的」，每一筆都是還沒還的債，
而設計文件明訂**不做補課時限**，降冪會讓舊的永遠沉底。

**分頁**：不要 cursor。**這個答案是從控制項推出來的不是從資料量** —— 下拉選單本來就翻不了頁，
N 真的大到要分頁時正解是**換控制項**（改成 `student-picker-dialog` 那種清單式），
那是構圖變更不是加參數。建議回傳全部 + 硬上限（100）當**安全閥**。

> **N 沒有實測值。** `seed.sql` 零筆 `cancelled`；billing-api 查了本機真 DB：
> `sessions` 19 筆、`cancelled` 1 筆、`makeup_for_session_id` 非空 0 筆 ——
> **本機量不出分布。** 「典型 0–5、最壞約 20」是**推論**。那個 100 是安全閥不是容量規劃。

## 入口該放在哪 —— 未裁

`sessions.page.ts:293` 的 context menu 是狀態閘控的：`scheduled` 有調課/代課/指派/停課，
`cancelled` 只有取消停課。

照資料模型（`PATCH /api/sessions/:id/makeup`，`:id` 是**補課那一堂**），入口只能加在
`scheduled`：**「設為補課」**。

**但行政的心智模型是從停課那一堂出發的**，而他在那個時刻通常還沒有補課那一堂可以指定
（見下一節）。三個選項：

| 選項          | 內容                                                 | 代價                                      |
| ------------- | ---------------------------------------------------- | ----------------------------------------- |
| A（最小）     | 只在 `scheduled` 加「設為補課」                      | 行政在停課那堂找不到入口，也不知道去哪找  |
| **B（傾向）** | A ＋ 在 `cancelled` 放不可點的說明或導向「產生課堂」 | 要想文案；多一個入口要維護                |
| C             | 停課 chip 在還沒被補時可點                           | 跟「死路 chip」判準衝突，除非它真的有去處 |

## ⚠️ 這個系統做不出「額外的單堂課」

**逐字查證過（2026-09-06）：**

| 半                                            | 證據                                                                                                                                                                                             |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 全 API 對 `sessions` **只有一條** insert 路徑 | `classes.ts:1797` `.upsert(plan.toInsert, …)`（generate 端點內）。`attendance-session-events.ts:183` 是 `.update({event_id})`、`courses.ts:500` 是 `.update({status})`                           |
| generate **只產生班級排程星期上的日子**       | `domain/session-assignment/session-generation-planner.ts:46-56`：逐日走 `from`→`to`，`if (schedule.weekday !== weekday) continue`。端點 body 只收 `from`/`to`/`excludeDates`/`includeUnassigned` |

**所以「補課」在目前系統裡只能是**：把一堂**已排定、落在班級正常時段上**的課，
指定成某堂停課的補課。**做不到幫週一的班在週六排補課。**

**它不是缺陷**（1:1 的 FK 設計本來就只是指定），**是一個沒有被寫下來的隱含前提**。
端點語意是**指定**不是**安排**，命名與錯誤訊息要對得上。

> 這一條已升到 issue #592（使用者當初的原話是「課堂可以**加入**並且標記是要補哪一堂
> 停掉的課」，而「加入」那半做不到）。**如果使用者要的是「另外找時段補」，
> 那是一個獨立的新功能，補課只是它的第一個使用者，端點語意會不一樣。**
