## 一、換版不換資料：判準與後續項怎麼寫（#1159／#1162／#1164）

A6 稿是設計席用假資料畫的，**每一頁都有現在的 API 給不出來的東西**（儀表板的「該到沒到＋家長電話」、學生頁的年級分章名冊、
學生檔案的到班格）。計畫席裁定：**頁面 PR 只換版，不補資料、不做占位卡**。

- **判準**：A6 的某一塊，現有回應裡**有**那份資料 → 照 A6 排；**沒有** → 不做，寫進 PR「後續項」。不要為了湊畫面在前端拼推論
  （例：「上課 40 分鐘還沒掃碼」需要的判定 workbench 沒給，前端用時間差去猜就是假造）。
- **既有內容一律保留**，只是換位置與樣式（儀表板的「現況」「今日請假」收成 A6 灰摺疊列；學生檔案的「開發中」段照留 —— 那不是新加的占位）。
- **IA 跟資料形狀衝突時，資料形狀贏**：學生列表是伺服器分頁＋伺服器搜尋，A6 的「依年級分章」在分頁資料上做不出來 → 表格與分頁不動，只換外框。
- **後續項的寫法**（計畫席拿去開單）：每條寫「A6 要什麼 → 現在缺哪份資料／哪支 API」，不要只寫「做到跟 A6 一樣」。
- 順手修的 UX 小 bug（例：只開狀態篩選、結果為空時說「尚未有學生資料」）可以帶，但在 PR「刻意的判斷」寫明。

## 二、`@source` 單檔 vs 目錄（#1161）

`tailwind.css` 的 `@source` 是 SCSS 帳面的另一面：**列進去的範圍底下不得還有那個元件的 .scss**（A24）。
一個目錄裡住著好幾頁（students：列表、dialog、`detail/`）時，原本只能整目錄一起遷。

- **目錄還有沒遷的別頁 → 列單一檔案**（`x.page.html`）。A24 對檔案只看同一個元件（`x.page.scss`、內嵌 styles 的 `x.page.ts`）；
  A27／A28 的 `walk()` 認檔案根。整個目錄遷完再收成一行目錄（#1164 做的事）。
- Tailwind 本身認單檔 `@source`（用 `@tailwindcss/node` 的 `compile` ＋ `@tailwindcss/oxide` 的 `Scanner` 對探針檔驗過）。
- **單檔 `@source` 第一次用上就抓到東西**：A27 一掃到學生 dialog，就報出全域 `.dialog-header-inline__close` 只有 32px。
  加 `size-11`（utility 贏 legacy 層）解掉 —— 遷一頁時，**頁上掛的全域 legacy class 也會被 gate 看到**，要預期它們會紅。

## 三、模板裡的 class 一律內聯，不要收成 TS 常數

儀表板第一版把重複的按鈕 class 收成 `protected readonly btn = '…'`，再 `[class]="btn"`。**A27（觸控高度）、A28（對比）、icon-only
按鈕 gate 都只讀模板的靜態 class 字串** —— 收成常數它們就失明，而且不會紅（A27 對沒有靜態 class 的按鈕可能直接跳過）。
同一個坑的變形：按鈕內容走 `ngTemplateOutlet`，icon-only gate 看不到裡面的字 → 誤判成「沒有可及名稱」。**按鈕的內容也要內聯。**
條件樣式用 `[class.x]="cond"` 加在靜態 class 之外，不要用 `[class]="cond ? 'a' : 'b'"` 取代整串。

## 四、遷一頁之前，先算它會喚醒哪些死 class

`@source` 一加，那個範圍用到的 utility 就**全站產生**；未遷移模板裡長得像 Tailwind 的 PrimeFlex 死 class（`w-full`、`text-2xl`、`mb-2`…）
會突然有樣式（tailwind-adoption 1.2）。每支頁面 PR 跑一次靜態比對，數字寫進 PR：

1. `compile(tailwind.css)` 加與不加這次的 `@source` 各一次，`Scanner` 掃候選、`build()` 出 CSS，取 selector 差集 = 新增 utility。
2. 在**不在任何 `@source` 範圍內**的 `.html`／`.ts`（排除 spec）裡找 `class="…"`、`styleClass`、`[class.x]` 的 token，跟差集取交集。
3. 命中的檔要查**有沒有路由**。目前反覆命中的 `admin/pages/sessions/sessions.component.ts` 是只有 spec import 的死元件，不影響畫面。

範圍比對要用 `f === s || f.startsWith(s + '/')`，**不能只用 `startsWith(s)`**：目錄 `…/students` 會吃到 `…/students-archive/…`，單一檔案則完全比不中自己。
比對腳本是拋棄式的，放 scratchpad，不進 repo。

## 五、harness 測試裡的「對照目錄」不要寫死成某一頁（#1164）

`harness.test.mjs` 的 A20 整合測試原本寫死 `students/` 當「不在 `@source` 裡」的對照。students 一遷完**它就紅了**；
而 #1161 那條「同目錄有別頁 .scss 時 A24 不誤紅」也拿 students 當前提 —— **那條不會紅，它會變成真空**，繼續綠、但什麼都沒驗。
現在兩條都用 `unmigratedPageDir()` 每次從 `tailwind.css` 算出「還沒遷、目錄裡直接有 .scss」的頁面；找不到就丟例外。

**一般化**：測試的前提如果是「某個東西**還沒**被改」，它的壽命就到那個東西被改的那天。要嘛動態找、要嘛斷言前提本身。

## 六、`page-open` 的 `openBack` 插槽

詳情頁的返回連結放色面裡、標題上面（A6 `back`）：`<a openBack class="… text-band-ink min-h-11" [routerLink]="…">`。
有了它就拿掉麵包屑（學生檔案先例）。色面上的字只用 `band-ink(-muted)`、底線用 `decoration-band-rule`（A28 看不到跨模板的配對，靠 token）。
主要聯絡人一行放在 page-open 的預設插槽（`<ng-content />`），有電話才出號碼與 `tel:` 連結。

## 七、疊三層 draft 的順序與 rebase

S3（#1154）沒合之前的頁面 PR 都疊在 `feat/shell-s3-topbar` 上當 draft；**彼此不依賴的頁各自疊 S3**（儀表板 #1159、學生列表 #1162），
**有依賴的才往上疊**（學生檔案 #1164 要收整個 students 目錄 → 疊在 #1162 上）。

- 疊在 S3 上又需要 main 上新合的東西（#1161）：在分支上 `cherry-pick -x` 那一筆。之後 rebase 到 main 時它會變成空 commit 自動消失 ——
  PR 描述先寫明「第一筆是 cherry-pick」，免得 reviewer 以為重複。
- S3 合了之後：#1159、#1162 base 轉 main → `git rebase origin/main` → 推 → 轉 ready；**#1162 合了**才輪到 #1164 轉 base、rebase、轉 ready。
  鐵律 1：下層合了上層 base 立刻轉，不要等。
- 驗「某支 commit 在不在 main」用內容 grep（鐵律 2），例：`git grep -n "unmigratedPageDir" origin/main -- tools/agent-harness`。

## 八、小坑

- **刪 .scss 或切分支之後，Vite 卡 `vite-error-overlay`**（1128 charter 也記過）。這一席踩了兩次：截圖腳本的點擊被覆蓋層攔住、30 秒逾時。
  **刪檔的 commit 做完就重啟 dev server**，截圖前檢查 overlay 數是 0。
- **備份檔不要放 `$TMPDIR` 用通用檔名**：拿 `cp … $TMPDIR/ch.bak` 做突變測試，還原時 `cp` 到的是**別人留在 `$TMPDIR` 的同名舊檔**
  （9 KB，不是 123 KB 的 check-harness），一次倒退 2400 行。備份放自己的 scratchpad、檔名帶席名，還原後 `git diff --stat` 核一次。
- **學生列表點名字不會進詳情**（列可點性在操作選單），截圖腳本要點「<名字> 的操作」→ 第一個 menuitem。
- 模板裡 `@if` 包住的全形括號會帶出空白（「吳秀蘭 （母）」）—— 字串拼在插值裡：`{{ cond ? a + '（' + b + '）' : a }}`。
- herdr 長訊息幾乎每次都停在對方輸入框（`❯ [labor-…`），送完一律 `send-keys enter` 再讀 pane 確認（README 六）。
