## 四、這次學到的

1. **路由改吃 pool 前，先 grep 打同一條路由的既有契約替身**（計畫席提醒）：沒 set `auth` 的替身會掉進 `createAuth(undefined)` → 500（#2239 CI 紅就是這個）。`c.get('auth')?.pool` 的路由則是明確 500
2. **改用 embed 篩「那天有課」之後，既有契約／spec 的 fixture 也要有那天的 sessions**：`today-attendance.contract` 原本只傳 sessions 陣列、DB 沒建課堂，改法後會撈不到人；`multi-org-db` 只照種子裡**已有**的巢狀物件篩，所以種子要補 `classes.sessions` embed
3. `multi-org-db` 的 `neq` 原本不認巢狀欄位（#2251 已改成同 `eq`／`in`）
4. **「先紅後綠」用 trigger 造 DB 端失敗**：只對測試學生生效的 `before insert/update/delete` trigger，舊碼（PostgREST）與新碼（pg 交易）吃到同一個錯（#2237 契約）
5. **整組契約跑到一半有人重開本機 supabase → `Connection terminated unexpectedly`**，紅一堆無關的檔；逐支重跑確認，不要當成自己弄壞
6. **改依賴前先 `npm view <pkg>@<ver> dependencies` 查事實**：supabase@2.119.0 確實依賴 jose ^6.2.10；要保住共用套件的版本就把新版巢狀在該套件底下（手改 lock 後 `npm ci`＋`npm install` 兩次確認穩定）
7. 契約 fixture 用 `union all`／`case` 給 enum 欄位時要明確轉型（`::uuid`、`::session_assignment_status`）；`sessions.status` 是 text 不是 enum
