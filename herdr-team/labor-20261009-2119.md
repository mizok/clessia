## 一、PostgREST：替身看不出來的三條

- **對 to-one embed 排序，欄位要選進那個 embed**：`order('subjects(sort_order)')` 而 select 只有
  `subjects(name)` → 400「column courses_subjects_1.sort_order does not exist」。#1423 上線即壞、#1430 修。
  替身現在會擋（#1436 `embedOrderProblem`），契約測試也會擋（#1435）。
- **top-level `or` 比不到巢狀欄位**（`or=(sessions.classes.name.ilike…)` → PGRST100）。要「班名 OR 老師名」：
  先撈名字符合的 id，再多嵌一個 alias（`class_match:sessions(id)`）下 `class_match.class_id=in.(…)`，
  `or` 裡寫 `class_match.not.is.null` —— embed 被篩掉就是 null（#1412／#1421）。空的 `in.()` 合法、回零筆。
- **`or` 字串裡放使用者輸入要先剝 `,()*%"\`**，剝光了回空，不能退化成「不篩」。

## 二、實打要用程式碼裡那一串

- #1423 我「實打驗過」—— 但 probe 裡的 select 是自己重打的 `subjects(name, sort_order)`，程式碼是 `subjects(name)`。
  **驗的是形狀，不是那一行。** 之後 probe 一律從原始碼檔抽字串（`readFileSync` + regex）或先 `includes` 斷言那一行沒變
  （#1432 留言有範本）。契約測試（`npm run test:contract`）走路由本身，是更好的做法。
- **陷阱還原用 `git checkout --` 之前一定要 commit**（0848 §五的同一顆，這輪又踩：#1430 修正沒 commit 就塞陷阱，
  checkout 把修正一起還原，差點推出空 PR）。

## 三、替身 `multi-org-db` 這輪的改動（用之前知道）

- `order` 可疊多鍵（原本第二次 `.order()` 蓋掉第一次）、數字比數字、`a(b)` 當巢狀欄位取值（#1423）。
- 補 `lt`、`%x%` 形狀的 `ilike`（其他 pattern 丟）。
- `select()` 記下字串，`order('x(y)')` 時檢查 `x(...)` 那一層有沒有 `y` 或 `*`（#1436）。
- **fixture 用模組層計數器產 id 時，每次 `seed()` 要歸零**，不然同一個測試裡兩次 seed 的 id 對不上。
- 「字串比較」的替身抓不到無效日期（`2026-13-01` 在替身裡是合法上界，真 PG 會報錯）—— 陷阱要挑合理的錯法。

## 四、契約測試（#1435）怎麼用

- 本機：`npm run db:start` 後 `npm run test:contract`；沒起 Supabase 就 skip 並印警告。
- 端點清單從 app 的 OpenAPI 文件取（GET、path 無 `{param}`），**新端點的 required query 沒進 `REQUIRED` 表就紅**；
  走另一條查詢分支的參數放 `BRANCHES`；邏輯上要求但文件沒標的放 `ALWAYS`；非 admin 才能打的放 `ROLE`。
- `/api/me/*`（家長）與 `/api/public/*` 還沒涵蓋 —— 要 seed 的家長／孩子與 `PUBLIC_ORG_SLUG`，下一輪補。
- **本機 DB 漂移會讓它紅**（這輪本機缺兩支 migration，`/api/enrollments` 500）—— 先 `supabase migration list --local`
  看 remote 欄空白的那幾支，再請 db-reset。

- **CI 綠 ≠ 跑過**：有觸發條件的 job（diff 沒動到某路徑就整支 skip）跳過時照樣是 success；測試「沒環境就 skip」也是
  success。#1437 連兩跑假綠：只改 workflow → 整支跳過（5 秒）；排除 `gotrue` 後 `supabase status` 沒有 API → 環境空、
  測試 skip。**看 job 秒數與 log 裡的 `Tests N passed`**；CI 上用 `CONTRACT_REQUIRED` 這種旗標讓「拿不到」變紅；
  改觸發條件時把 workflow 檔本身列進去。

## 五、批次寫入與稽核

- 批次端點逐筆 `logAudit` 會變成 2N 個 subrequest（每筆查一次 profile）→ 撞 Workers 上限。用 `utils/audit.ts` 的
  `logAuditMany`：一次 profile、一次 insert，仍是每個資源一筆（#1432）。
- 寫入的 insert **要接 error**：單筆催繳原本不接，失敗照回 201＋寫稽核（#1432 順手修）。

## 六、做法的索引（理由在 PR／issue）

- 匯出不開新端點：列表加 `issuedMonth`，Excel 前端用已裝的 `xlsx` 產（#1314 P4、#1426）。
- 「全部帳單」不含作廢 —— 可否決點（#1314 P4 gate）。
- 章節計數與列表共用篩選 helper（`courses.ts` 的 `withChapterFilters`，同 staff 的 `withSummaryFilters`），不吃 subjectId（#1428）。
- `subjects.sort_order` 預設 0 且不唯一 → 依科目分章要多一鍵 `subject_id`，章節那支 subjects 查詢同順序（#1423）。
