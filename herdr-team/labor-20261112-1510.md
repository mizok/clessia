## 一、PostgREST：「沒有符合的子列」用反連接，不要先撈 id

- **`alias:child(...)` ＋ `.is('alias', null)`＝反連接**（PostgREST v14 實測）：留下「沒有任何符合的子列」的父列，跟 `count: 'exact'` 相容。
  子 embed 裡再放 `!inner` 的巢狀條件，篩的是**子列**，所以能表達「範圍內學生 0 筆成績」：
  `todo_hit:school_scores(students!inner(enrollments!inner(classes!inner())))` ＋ `.in('todo_hit.students.enrollments.classes.campus_id', ids)` ＋ `.is('todo_hit', null)`（`school-exams.ts` 的 `applyTodo`）。
- **空 embed `rel!inner()` 只篩不回資料**，payload 不變長。巢狀空 embed（`a!inner(b!inner(c!inner()))`）也行。
- 驗語意最快的是直接 curl 本機 PostgREST（`apps/api/.dev.vars` 有 URL 與 key），先設一組「範圍＝不存在的分校」「範圍＝全部分校」看筆數兩端對不對，再寫契約。

## 二、`multi-org-db` 替身跟 PostgREST 不一樣的地方（寫法要遷就替身時）

- 替身對 embed 路徑的 `in/eq` 是**篩父列**；PostgREST 對**非 `!inner`** 的 embed 是**篩子列**。所以「`enrollments(count)` ＋ `.in('enrollments.status', …)`」在真 DB 是對的、在 spec 會把父列整個濾掉。
- 遇到這種情況，與其改替身，不如換一個兩邊語意一致的寫法：#2453 的目錄名額改成「整個 org 的佔名額報名只撈 `class_id`，`fetchAllPages` 撈齊在記憶體數」，不帶 id 清單、也不靠 embed 篩。
- 契約仍要寫：替身綠不代表真的對（#2453 的 main 在 260 班時公開與家長目錄都 500）。

## 三、範圍檢查的位置：先判範圍，再做任何會回資訊的檢查

- 範圍外要**跟不存在一樣**（404），而且要排在**名額（400 帶 quota）、撞課（409 帶時段）**之前，不然錯誤碼本身就洩漏了別校班的資訊。#2443 一開始只修了寫入，計畫席二讀才補「撞課先回 409」與「copy-from-class 的來源班沒看範圍（可讀別校名冊）」。
- **連帶要看的不只目標**：會「讀一個班的東西再寫到另一個班」的路由（複製名冊、轉班），來源也要判範圍。
- harness gate 會擋「檔案碰 `campus_id` 但沒用 `applyCampusFilter`／`campusFilterIds`」。手寫 `scope.includes(cls.campus_id)` 本機可能沒跑到 harness 就推了，CI 才紅。範圍判斷一律走 `applyCampusFilter`；套在 supabase builder 上會 TS2589，照 `courses.ts` 轉成結構型別（`enrollments/validation.ts` 的 `findClassInScope`）。

## 四、驗證腳本與機器

- **web 的 test target（`@angular/build:unit-test`）不吃 `--maxWorkers`**：`nx run-many -t test --maxWorkers=2` 會讓 web 直接報「'maxWorkers' is not found in schema」、**沒有跑任何測試**，而 api 照跑，摘要只看得到 api 的綠。要限 worker 就分開跑：`nx test api --maxWorkers=2`、`nx test web`。
- 機器負載高時全套會出現 hook 30s／test 5s 逾時（mount-authz、student-form 等），跟改動無關；把紅的那幾支在同一個暫存 worktree 單獨重跑，綠了就報「負載逾時，單獨重跑 N/N 綠」。
- **暫存 worktree 刪之前先 `npx nx daemon --stop`**：只做 `git worktree remove` 的話 daemon 變孤兒（ppid 1）一直吃 CPU，目錄刪了之後也叫不到 `--stop`，只能用 `lsof -a -p <pid> -d cwd` 確認是自己的再 kill。
- **關 `wrangler dev` 要整串收**：殺 workerd 會被 wrangler 的父行程立刻重起（換新 pid 又聽回同一個 port）。用 `lsof -a -p <pid> -d cwd` 列出 cwd 在自己座位的 wrangler／workerd，一次 `kill -9`，再確認 port 沒人聽。
- 起自己 port 的 API 給別的 web origin 用：`wrangler dev --port 8793 --inspector-port 9293 --var ALLOWED_ORIGINS:http://localhost:4293`。產登入連結要帶 `BETTER_AUTH_URL=http://localhost:8793 WEB_URL=http://localhost:4293`，不然連結指向別席的 8787。

## 五、a6-conformance 的兩個坑

- **家長頁的登入態路徑寫死在 `lib/config.mjs` 的 `PARENT_STATE`**（`state-parent03.json`，共用檔）。要用自己產的檔只能暫改那一行；**改了工具 compare 表頭會標「有未提交的修改，不可重現」**。共用的 `state-parent03.json` 其實是 DB session，對任何席的 API 都通（先 curl `/api/me` 帶它的 cookie 確認 200），能用就別改工具。
- compare 表頭的「登入」原本印預設值（state-admin），不是頁面實際用的登入態（#2459 修了）。舊的 compare 報告看到 state-admin 不代表量錯身分。
- 改動只影響「載入中」畫面時，compare 的 base／head 數字會完全相同 —— 那是預期的（compare 量的是資料到齊後），跳動的證據靠 jump.mjs。
