## 一、家長端讀取：一次只看一個孩子

- **`studentScope` 是「這個家長的所有孩子」，不是「這次查的孩子」**。只靠 scope 查會把兄弟姊妹的資料混進來
  （不越權，但張冠李戴 —— `class-logs` 就這樣錯了一陣子，#1145 修）。`childDb.from(…).pluck()` 的 `studentId`
  因此是**必填**；用 `select()` 的地方自己補 `.eq('student_id', childId)`。
- 只拿來「排除／判斷」、不拿去查別的表的清單，用 `select()` 就好，不需要 `pluck()` 的 `ScopedIds`。
- 名額這類「別的學生的資料」只能在 child-db 內**聚合成數字**才交出去（`activeEnrollmentCount(s)`）。

## 二、改一個判斷函式的形狀：讓漏傳編不過

#1114 給 `leaveCoversSession` 加「綁定堂次」時，`LeaveWindow.boundSessions` 設成**必填**，
`SessionWindow.sessionId` 是 `string | null`（null＝日層級查詢）。`tsc` 直接列出全部 5 個呼叫點。
如果設成 optional，漏撈綁定的呼叫點會**靜靜退回舊語意**（一張只請一堂的假被讀成整天），沒有任何訊號。
讀取欄位與轉換也收成一份（`LEAVE_WINDOW_COLUMNS`＋`toLeaveWindow`），各呼叫點不各寫各的 select。

## 三、驗證：替身測不到的東西

- **select 字串一律在本機 PostgREST 實打一次**（唯讀）。#1118 的 `courses(subject)` 替身全綠，
  實打才發現欄位早就改成 `subject_id → subjects(name)`。
  ```sh
  eval "$(npx supabase status -o env | grep -E '^(API_URL|SERVICE_ROLE_KEY)=')"
  curl -s "$API_URL/rest/v1/<table>?select=$(node -e '…encodeURIComponent(去空白的 select)…')&limit=1" \
    -H "apikey: $SERVICE_ROLE_KEY" -H "Authorization: Bearer $SERVICE_ROLE_KEY"
  ```
- **新 migration 先在交易裡試跑**（`db:reset` 被 deny 擋著，也不該動共用的本機 DB）：
  `(echo BEGIN; cat <migration>; echo ROLLBACK) | psql -v ON_ERROR_STOP=1 postgresql://postgres:postgres@127.0.0.1:54322/postgres`。
  它驗得到 SQL，**驗不到 PostgREST 的 embed**（schema cache 裡沒有那張表）—— 這一半要等合併後重置再補。
- `multi-org-db` **不做巢狀關聯**：路由靠 embed 讀的關聯（例如假單的綁定列）在替身裡讀不回來。
  在那支 spec 裡包一層，讀那張表時從替身自己的表補上 embed（`leaves-session-binding.spec.ts` 的 `withLeaveEmbed`），
  不要動替身本體。替身已補：`gte`／`lte` 吃巢狀欄位（#1145）、`or()` 吃 `is.null`（#1150）。

## 四、陷阱測試的還原方式

**塞陷阱前先 `cp` 備份，用 `cp` 還原，不要 `git checkout -- <檔>`。** 本席踩過：還沒 commit 的修改跟陷阱在同一支檔，
`git checkout` 把兩個一起還原掉了（`git diff --stat` 變空才發現）。
