## 二、頁面怎麼把標題交給色面：投影，不是 service

A6 稿是每頁傳 `title／sub／stats` 給 `shell()`。Angular 版**由頁面自己在模板最上面放 `<app-page-open>`**，
用 `<ng-container openTitle>`／`openSub` 投影。理由：標題常是頁面算出來的（changes 的「10 月 N 則異動」），
放進殼要一支「頁面寫、殼讀」的 service，還要處理離開頁面時清掉；投影零狀態。

- **殼怎麼知道這頁要全寬出血**：main 上的 `has-[app-page-open]:…`（Tailwind `has-*` variant），沒有 route data 旗標。
  遷移的頁只要放元件就對了。舊頁內距用 `not-has-[app-page-open]:p-3 …` 保留原值。
- 頁面本體包 `page-wrap`（`tailwind.css` 的 `@utility`，A6 `.wrap` 欄寬 1120）。**頂欄也是 page-wrap**，
  所以遷了的頁左緣跟頂欄對齊；沒遷的舊頁是滿版寬，桌機上左緣對不齊 —— 過渡期現象，遷完自然消失。
- ⚠️ **A28 看不到色面上的標題**：文字在頁面模板、`bg-*` 在 page-open 模板，跨模板配不起來。色面上只用
  `band-ink(-muted)`，那兩個 token 的透明度地板在 `styles.scss` 有明文，靠的是 token 不是 gate。

## 三、`:has()` 在元件 SCSS 裡會不會被 encapsulation 改寫

S1 時殼還有 SCSS，寫了 `.shell-content:has(app-page-open)`。擔心 emulated encapsulation 會把 `app-page-open`
也加上 `[_ngcontent-…]` 而永遠配不到（它屬於別的元件）。**實測產物：不會** ——
`.shell-content[_ngcontent-%COMP%]:has(app-page-open)`，只有外層被 scope。查法：build 後
`grep -ho '.\{40\}has(app-page-open.\{40\}' dist/apps/web/browser/chunk-*.js`。

## 四、殼換了之後的回歸判讀：以 main 為根重新對齊

2335 charter 第二節的 diff 用「從 body 一路下來的祖先鏈」當元素 key。**殼的 DOM 一換，main 底下每個元素的 key
都變了**，原 diff 會把全站報成「缺漏元素」，什麼也看不出來。做法：key 從 `>main` 之後截斷再比；不在 main 底下、
又不是 `app-root` 開頭的（浮層 dump）照舊。然後把屬性分兩類：

- **幾何**（width／height／left／top／min-／max-）：側欄消失、頂欄變兩列，必然大量變動，只看總數。
- **非幾何**：逐群判讀。S3 的 99 條全部歸得進四類：寬度連鎖（auto margin、grid 欄寬、`margin-left:auto`）、
  刻意的（A6 頁白底）、**滑鼠殘留 hover**、刻意拿掉的元素。

**滑鼠殘留 hover 會一直出現**：擷取腳本點過下拉／按鈕後游標留在原座標，下一頁版面一變，hover 就落在不同元素上
（輸入框邊框 zinc-200↔zinc-400、表格兩列底色互換）。判定法：同一元素實測 rest 與 hover 的值，跟 before／after 對上就是它。

## 五、手機停靠列的留底：legacy layer 裡的規則輸給元件樣式

`styles.scss` 的 `.shell-content:has(.page-actions__dock) { padding-bottom }` 從 T4（styles.scss 包進 `legacy`
layer）之後**就沒生效過**：殼的元件 SCSS 不在任何 layer 裡，未分層的規則永遠贏分層的。基底實測 390 寬 students
頁 main `padding-bottom: 8px`，停靠列蓋住分頁器。S3 搬到殼 main 上：
`max-[640.02px]:has-[.page-actions\_\_dock]:pb-[…]`（`\_` 是 Tailwind arbitrary 值裡的底線跳脫；邊界對齊
`respond-to('mobile')` 的 ≤640）。

**一般化：styles.scss 裡任何「去改某個元件元素」的全域規則，T4 之後都可能是死的** —— 只要那個元素自己的元件
SCSS 宣告了同一個屬性。要信它之前先在瀏覽器量 computed style。

## 六、頂欄的浮層用原生 popover

「更多」與帳戶都是 `<div popover id=…>`＋`<button popovertarget=…>`：點外面、Esc、top layer、焦點回觸發鈕都是瀏覽器給的，
沒有 PrimeNG `p-popover` 的全域覆寫要維護。要自己補的只有三件：

1. **定位**：popover 預設在畫面正中。`(toggle)` 開的那一刻用觸發鈕的 rect 寫 `position:fixed; left; top`；
   帳戶在手機是 CSS 的底部抽屜（`max-wide:inset-x-0 …`），這時不寫位置（`removeAttribute('style')`）。
2. **連結點了不會自己關**：每條 `<a>` 掛 `(click)="hide('shell-more')"`。⚠️ **不要掛在 popover 容器上** ——
   A27 會把有 `(click)` 的 `<div>` 當成可點元素，要求它有 44px 高度下限。
3. **resize 就關**：位置是開的那一刻算的。

jsdom 沒有 popover API：spec 只測內容（浮層內容一直在 DOM 裡，只是隱藏），`hidePopover?.()` 要加問號。

帳戶入口是**單一入口**（人 → 切換身分 → 帳號設定 → 登出），取代原本的「角色徽章 popover＋使用者 popover」。
切換身分只有多身分才出；demo 的 `teacher0001` 兼管理員，拿它看得到這一組。

## 七、小坑

- **macOS 的 `sed` 不認 `\b`**：`sed 's/\blg:/wide:/g'` 靜靜地什麼都沒換。用 `perl -pi -e 's/(?<![\w-])lg:/wide:/g'`，換完 `grep -c` 驗。
- **`git checkout -- .` 在 repo 根目錄會還原所有未提交的改動**。為了清 build 產物而 `cd` 回根目錄時順手打了它，
  S1 的四支檔整批還原（新檔沒事）。**改到一個段落就先 commit**，之後要整理用 rebase。
- **Python 腳本切 `styles.scss` 區塊**：檔裡同一個標題（`Utilities`）出現兩次，`index()` 找到前面那個，
  切出來的範圍是負的、還把一段貼成兩份。找結束標記時從起點往後找：`s.index(end, start)`，並 assert 區塊內容。
- **dev server 開著時 rebase**：中途刪檔會讓 Vite 卡一個錯誤覆蓋層（`vite-error-overlay` 擋住所有點擊），
  rebase 完要重啟 dev server。擷取前先檢查 `vite-error-overlay` 數量是 0。
- **login-link 需要 `WEB_URL`**（`.dev.vars` 沒有）：`set -a; source apps/api/.dev.vars; set +a; WEB_URL=http://localhost:4200 LOGIN_EMAIL=… npm run -s login-link`。
  輸出檔路徑寫絕對路徑 —— 寫成 `$PWD/…` 又在子 shell `cd` 進 repo，連結檔（內含一次性登入連結）就落在 repo 根目錄。
- 登入後若落在 `/link-line`，`activeRole` 還沒選：擷取腳本要再走一次 `/select-role` 點角色。
