## 一、整理 WIP 不要 `reset --soft` 到一個已經移動的 ref

**判準：整理 WIP 用 `rebase`，或從 `origin/main` 開新分支、`git checkout <舊分支> -- <自己的檔>`；
不要 `git reset --soft origin/main`。**

`reset --soft` 只搬 HEAD、index 留著**舊基底**的內容。開工後 `origin/main` 前進了的話，
index 裡每一支「上游剛改過、我沒碰」的檔都變成「把上游改動倒退」的暫存變更 ——
而 `git commit -- kb tools` 這種帶目錄的 pathspec 會把它們一起提交。
2026-10-02 #991 T4 實例：一次倒退了使用者剛親手合的 `constitution.md`（c6 修憲）、
`billing-rules.md`、`status-snapshot.md`，推上遠端才發現。
**agent 連「還原 constitution.md」都不能做**（auto mode 擋，AGENTS.md 修憲條款）——
所以這種倒退一旦碰到憲法，只能開新分支重來、壞分支由計畫席刪。

從新分支 checkout 自己的檔時，**再核一次上游在這段期間有沒有動過它們**
（`git diff --stat <舊基底> origin/main -- <那些檔>` 要空），否則整檔帶入同樣會倒退。
commit 前單獨跑 `git diff --cached --stat origin/main`，清單只能是自己的檔 —— 檢查與動作分開。

## 三、computed-style 回歸腳本的兩種假綠

- **登入失效／API 斷線**：每頁都是登入頁，前後兩邊一樣 → 0 差異。擷取時斷言落點 URL 等於目標路徑、
  頁面沒有「連線異常」。
- **元素對不上就 `continue`**：前後 DOM 不同時差異被靜靜吞掉。diff 要報「缺漏元素數」。
- 本機 stack 用 Bash 的 `run_in_background` 起；`( cmd & )` 的子行程會被收掉。
- 雜訊基準：同一份程式碼跑兩次的差異，從翻轉清單裡扣掉。
