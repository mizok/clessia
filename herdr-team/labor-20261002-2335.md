## 一、整理 WIP 不要 `reset --soft` 到一個已經移動的 ref

**判準：整理 WIP 用 `rebase`，或從 `origin/main` 開新分支、`git checkout <舊分支> -- <自己的檔>`；
不要 `git reset --soft origin/main`。**

`reset --soft` 只搬 HEAD、index 留著**舊基底**的內容。開工後 `origin/main` 前進了的話，
index 裡每一支「上游剛改過、我沒碰」的檔都變成「把上游改動倒退」的暫存變更 ——
而 `git commit -- kb tools` 這種帶目錄的 pathspec 會把它們一起提交。
2026-10-02 #991 T4 實例：一次倒退了使用者剛親手合的 `constitution.md`（c6 修憲）、
`billing-rules.md`、`status-snapshot.md`，推上遠端才發現。
**agent 連「還原 constitution.md」都不能做**（auto mode 擋，AGENTS.md 修憲條款）——
所以這種倒退一旦碰到憲法，只能開新分支重來、壞分支由計畫席刪。

從新分支 checkout 自己的檔時，**再核一次上游在這段期間有沒有動過它們**
（`git diff --stat <舊基底> origin/main -- <那些檔>` 要空），否則整檔帶入同樣會倒退。
commit 前單獨跑 `git diff --cached --stat origin/main`，清單只能是自己的檔 —— 檢查與動作分開。

## 二、樣式 cascade 翻轉怎麼判讀（#991 T4，PR #1069）

坑本身（reset 進 `base`、只改預設狀態寫 token、`--p-anchor-gutter`）寫在
`kb/wiki/architecture/tailwind-adoption.md` 2.2a。這裡放**方法**，下一次動 layer 或全域樣式時照做：

1. **動態**：拋棄式 Playwright（scratchpad 自己的 `package.json` 裝 `playwright@1.60.0`，不碰 repo lock），
   全部靜態路由＋幾個參數路由 × 1440／390，每頁擷取「載入」「前 3 個下拉打開」「前 3 個新增／編輯類按鈕開的對話框」，
   **對每個元素** dump 約 60 個 computed style 屬性。前後各一次，diff 依「元素末段＋屬性＋前後值」聚合。
2. **雜訊基準**：同一份程式碼跑兩次，兩次之間的差異從翻轉清單扣掉（實測只有 2 條：置中邊距、focus outline）。
3. **靜態補洞**：動態看不到 hover／focus／checked／invalid。把 legacy 裡每條碰 `.p-*` 的宣告，對上
   `@primeuix/styles/dist/<元件>/index.mjs`（`import()` 它取 style 字串）同屬性、同元件 class 的規則比 specificity ——
   **切換前 legacy 只在「嚴格大於」時贏**（PrimeNG 是 runtime 注入、排在全域樣式表之後，同分它贏）。
   「Aura 曾經贏」的組合就是會翻的。
4. **判讀預設是「保持畫面不變」**：從沒生效的規則刪掉，不是讓它第一次上畫面。要讓設計意圖生效是另一件事。
5. 追「這個值是哪條規則給的」用 CDP 的 `CSS.getMatchedStylesForNode`（會標出 layer 名），比讀原始碼快。

### 假綠（擷取腳本兩次差點交出 0 差異）

- **登入失效／API 斷線**：每頁都是登入頁，前後一樣 → 0。每個狀態斷言落點 URL＝目標路徑、頁面沒有「連線異常」。
- **元素對不上就 `continue`**：前後 DOM 不同時差異被吞掉。diff 要報「缺漏元素數」。
- 本機 stack 用 Bash 的 `run_in_background` 起；`( cmd & )` 的子行程會被收掉。Docker 停了的話 Supabase 一起停，
  API 回 500「Failed to get session」—— 先 `docker info`。

## 三、授權範圍函式：讀與寫的分工（#920 PR #1080、#1081 PR #1094）

| | 寫（`lib/attendance-write-scope.ts`） | 讀（`lib/attendance-read-scope.ts`） |
| --- | --- | --- |
| 函式 | `teacherAttendanceWriteAccess` → `'ok' \| 'not-yours' \| 'not-responsible'` | `teacherCanReadEvent` → boolean |
| 歸屬（任課或代課） | 有 | 有（同一支純函式 `canTeacherWriteAttendance`） |
| 點名責任歸屬 | **有**：行政負責的機構老師一律 403 | **沒有**：行政負責時老師仍要唯讀看名單 |

- **責任歸屬只管寫，不管讀** —— 兩支函式分開的理由就在這一格。把讀也套上責任歸屬，#920 的唯讀名單會整個打不開。
- 檢查順序：**先做 org 範圍的課堂查詢（別 org 的 id → 404），再做老師範圍（→ 403）**，不洩漏存在與否。
- 兩支保留類 PR 同改一支檔會強迫合併順序：讀取版刻意放新檔、查詢重複一份（ponytail 註記，都合後再收）；
  合併前用 `git merge-tree --write-tree A B` 試合，**import 相鄰也會衝突**，挪到不相鄰的位置就好。
- 修前實測：先寫路由 spec 看它紅（#920 是 200 放行、#1081 也是 200），再用本機純老師帳號實打一次。
  ⚠️ demo 的 `teacher0001` **同時有 admin 角色**，拿它測老師範圍會被 admin 豁免；純老師用 `teacher0002`
  （查法：`user_roles` 有 teacher、沒有 admin）。家長 `parent14` 是停用帳號，`parent01` 的孩子沒有成績，
  看成績頁用 `attendance-parent-01`。

## 四、規格與 rules 牴觸時，先停（#1076）

家長成績規格寫「學期篩選（預設當學期）」，但 `rules/billing-rules.md`、`enrollment-rules.md` 的「期」是**機構自訂**，
不是寫死的學期；校內考也沒有學期欄位。用日期推 8/1–1/31 是一個看起來合理、實際上違反 rules 的做法。
**動手做規格裡的篩選或分組之前，先 grep rules 有沒有定義同一個詞。** 牴觸就做不牴觸的那半、把那一半留在 issue 上。

另一個前提錯誤：工單說「API 沒回學期就只做展開」，實際上**描述也沒回**（`scope_note` 在 DB、不在回應）。
「前端只做 X」的工單，先確認 X 的資料真的在回應裡。

## 五、Tailwind 頁的工具與小坑（#991 P1，PR #1078）

- `tools/agent-harness/lib/tailwind-classes.mjs` 的 `loadTailwind`：用 design system 的 `candidatesToCss` 判斷
  class 會不會產生 CSS（拼錯回空）、取顏色值。**只對 `@source` 目錄有效**。A20／A27／A28 都靠它，新的 class 版 gate 也該用它。
- PrimeNG `p-select` 的 `pt` 有型別沒列的 `overlay`（`.p-select-overlay`，看得到的面板）；`pcOverlay.root` 在手機
  responsive 模式是全螢幕遮罩，中間的 `<p-motion>` 是 inline 寬度，要 `*:w-full` 才會全寬底部面板。
- `ng-template` 的 `let-x` 是 `any`，嚴格模板下拿它索引 `Record` 會編不過 —— 包一個帶型別的方法。
- **prettier 會重排同檔裡別人的表格**。只想插一段的 kb 檔，用腳本插入、不跑 prettier，再 `git diff | grep '^-'` 看有沒有動到別人的行。
