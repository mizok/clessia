## 二、會再撞到的坑

1. **審核席一定做突變，送審前自己先做**。這一任被退的全是「刻意改壞一個判斷、測試全綠」。最常見的原因是**那條路徑沒有 fixture**：
   - 家長只有一個孩子時，「讀出勤不限這個孩子」測不出來 → 要有兄弟姊妹（scope 兩個孩子、同一堂）
   - 時間相關的計數（補請堂數）要固定時鐘：`vi.useFakeTimers({ toFake: ['Date'] })`＋`setSystemTime`
   - 讀取失敗要 fail-closed：替身 `createMultiOrgDb` 沒有失敗開關，用 `vi.spyOn(client, 'from')` 回一個 `then` 回錯的 builder（`parent/leaves.spec.ts` 有範例）
   - 等價突變（例：scope 空時提早 return）要在 PR 寫明理由，不硬補 spec
2. **家長端路由拿不到原始 client（A19）**。要碰「不是孩子的資料」（寫老師的通知、寫 `audit_logs`）就在 `lib/child-db.ts` 做**窄能力**，先用 `ownLeave` 這類檢查確認資源屬於 scope 內的孩子。不要在 lib 裡用 `c.get('supabase')` 繞（gate 只擋 routes/parent，但那是繞過）。
3. **請假「蓋不蓋得到某堂」是讀取時推導的**（`leaveCoversSession`），不是看 `attendance_records`。所以「已經開始的那幾堂不動」做不到；要嘛整張擋、要嘛綁定堂次。設計稿寫的機制先對照這條驗證過再實作。
4. **`buildLeaveAttendanceUpserts` 會覆寫既有出勤**。管理端是刻意的（人工判斷）；家長端只改「沒有紀錄或缺席」的堂（#1734 (a)），全部已出席回 400 `ALL_ATTENDED`。
5. **疊在 squash 合併 PR 上的分支 merge main 會整批衝突**：先 `git diff <下層合併時的 head> origin/main -- <檔>` 確認是 0 行，再全部取 ours（#1713 實例）。zsh 的 `$F` 不會拆成多個參數，`git checkout --ours` 要逐檔。
6. **conformance 工具**已在 main（`tools/a6-conformance`）。工具自己的 config 從 `import.meta.dirname` 推 repo 根，搬到 scratchpad 會壞。量 base／head 用 `compare … --base origin/main --head <sha>`，API 非 8787 時帶 `A6_API_URL`；登入態 `login.mjs`，**`login-link.ts` 的 `WEB_URL` 要等於 API 的 `WEB_URL`**，不然 verify 回 403。
7. **kb 新 spec 要登記到 `tools/agent-harness/feature-map.mjs`** 的某個功能區，再 `npm run harness:write`，不然 CI 紅（#1733 撞過）。已批准的設計稿 status 用 `accepted`。
8. **本機實測完要清資料**：先看 `created_at = updated_at = 這次請求`，確認是自己新建的才刪，不要刪到 seed。
