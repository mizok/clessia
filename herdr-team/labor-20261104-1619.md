## 三、這次學到的

1. **量測／dev server 收尾只能殺「自己記下的」PID（或 process group），絕不用 `lsof -ti:<port>` 去殺。**
   11-05 量 #1595 P2 ① 時，8797 已經被 labor-20261105-0950-a 的 API server 佔用：我的 `wrangler dev`
   綁不上（Address already in use）卻沒停，量測打到別席的 server，收尾 `kill -9 $(lsof -ti:8797)` 把對方的 server 砍掉。
   現在的寫法：起之前確認 port 沒人聽（有人就換）、`set -m` 起在自己的 process group、就緒後確認聽 port 的是自己的 pgid、
   收尾只 `kill -9 -- -<pgid>`。**「用過的 port 下次還是我的」不成立** —— 席位之間沒有 port 登記。
2. **zsh 不拆字**：`kill -9 $P`（`$P` 是兩行 pid）會變成一個非法參數；多 pid 用 `for p in $(…)` 或 `bash -c`。
3. **vitest 不做型別檢查**：import 替換沒套上，契約與單元照樣全綠，`tsc` 才抓到。改完一律跑一次 `npx tsc --noEmit`。
4. **REST 替身 pool 的分支比對用子字串**：新 SQL 的 `from public.enrollments en` 會被既有的 `from public.enrollments e` 分支先吃掉；新分支放最前面。
5. **REST 替身 pool 可以把「新 SQL」翻回「改寫前的 REST 鏈」**（`test-utils/rest-backed-summary-pool.ts`）：既有 spec 不必改斷言，只要補 `set('auth', { pool: restBackedSummaryPool(client) })`。
   SQL 本身的語意交給契約。替身照舊鏈的呼叫形狀走（例如 `.maybeSingle()`），不然回傳形狀會差一層
6. **舊碼與新碼的「完整回應」比對**：fixture 每次重建、uuid 隨機，正規化成出現順序的標籤後，**依 uuid 排序的陣列**（例如 `order by id` 的打卡）會在兩輪間換位 —— 先排除這種假差異再下結論。
