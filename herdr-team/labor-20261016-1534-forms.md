## 一、機器人驗證（ALTCHA 預設、可切換 Turnstile）

- **`CAPTCHA_PROVIDER` 是白名單，沒有「不驗」**：不認得的值、turnstile 缺金鑰、siteverify 打不通 → 503；沒附／驗不過 → 400。
  原本「沒設 Turnstile secret 就不驗」被拿掉了（Q4′），別加回來。
- **altcha-lib 2.5.0 的 `algorithms/web/*` 只用 `crypto.subtle`**，Workers 與 Node 都能跑（`wrangler dev` 實測過）。
  不要 import `algorithms/pbkdf2`（那是 `node:crypto` 版）。
- widget 3.2.4 交出的 payload＝`btoa(JSON{challenge:{parameters,signature},solution})`；test 模式交 `challenge:null`，要拒收。
  前端**不掛 widget**，用 `altcha/lib` 的 `solveChallenge` 自己解（A6 只畫一列「已通過」）；payload 格式一樣。
- **Turnstile 的掛點要等畫面畫完才存在**：`load()` 一切到 `'form'` 就呼叫 `startCaptcha()`，那時 `viewChild` 還是 undefined，
  widget 從來沒畫過（spec 抓到的真 bug）。掛點不在就 `afterNextRender` 等一次。
- spec 要真的出題、真的解（`test-utils/altcha-payload.ts`，cost 1），驗證走正式路徑，不要 mock `verifySolution`。

## 二、`/api/me` 與身分管線

- **新欄位不要放進 auth middleware 的身分查詢**（計畫席裁）。那是每個請求的必經路徑：select 一個還沒套上的欄位會全站 500，
  而 identity-sql 失敗時退回的 REST 也 select 同一欄，退路一起壞。`/api/me` 自己要的東西放 `ME_EXTRAS_SQL`＋REST 退路，
  查詢出錯當 null。
- **`identity-sql.contract.ts` 比的是 SQL 與 REST 組出來的物件逐欄相等**：`MeExtras` 加欄位時，契約的 REST 側要用**同一支**函式組
  （`loadNickname` 因此住在 `lib/identity-sql.ts`）。本機跑：`set -a; . ./.dev.vars; set +a; SUPABASE_SERVICE_ROLE_KEY=$SUPABASE_SECRET_KEY CONTRACT_REQUIRED=1 npx vitest run --config vitest.contract.config.mts`。
  seed 的欄位全是 null 時兩邊相等是空轉 —— 突變（讓 REST 側回固定值）確認它會紅。

## 三、「沒暱稱不露本名」怎麼守

- `multi-org-db` 替身**一律回整列、不看 select 欄位** —— 只驗回應會漏掉「select 裡多拿了 display_name」。
  守兩層：(a) 種子放本名、驗回應序列化後不含；(b) 攔 `from().select()` 的字串、驗不含 `display_name`。
- 公開目錄 select 是 `teacher:staff!teacher_id(nickname)`，跟家長目錄同一個 FK hint；本機套完 migration 後實打過，8 位老師本名 0 外洩。

## 四、migration 與本機 DB

- **本機不要 `migration up` 還沒合的 migration**：時間戳比別席未合的早的話，對方合進 main 時本機就得 `--include-all` 補套，順序亂掉；
  PR 也可能再改。驗證用交易乾跑：`BEGIN; \i migration; 驗證; ROLLBACK;`，最後查欄位／排程／constraint／`schema_migrations` 殘留都是 0。
  統一套用由 db-reset 席照時間戳順序做。
- pg_cron 排程在交易裡 `cron.schedule` 也會被 ROLLBACK 收掉，可以乾跑。

## 五、conformance 工具（#1581，還在 a6tool 席的分支）

- **在另一個 detached worktree commit、`git push origin HEAD:<分支>`**，不要動工具席自己的工作目錄；推之前 fetch。
  node_modules 用 symlink 借，稿目錄用 `A6_DIR` 指，不要在 repo 根放 symlink（會被當成未提交修改）。
- **`diff` 沒帶 URL 會量 `A6_APP_URL` 預設的 4200 —— 那常常是別席的 app**。數字跟 base 一模一樣就是量錯了。
- dev server 有編譯錯誤時，量到的是 **Angular 的錯誤遮罩**（差異表會出現 `TS#…`、`Click outside…` 的「多」）。量之前確認編譯過了。
- compare 的「已有在跑的 web」模式：base 用 origin/main 的 detached worktree＋symlink node_modules 起在另一個 port。
- **表單控制項不繼承行高與字級**（沒有 preflight）：`font-[inherit]` 只給字族；按鈕要 `text-[length:inherit] leading-[inherit]`，
  textarea／送出鈕補 `leading-[1.5]`。

- **工具設定的 `status` 是 `===` 比對，不是 regex**（`classify()`）：一條偏離只能管一種狀態，要兩種就拆兩條。
  `a6`／`app` 的 regex 比的是**完整 key**（`>landmark:main[]>…`），不要用 `^` 錨開頭，只錨結尾。
- **ALTCHA 的難度要在降速下量**：CDP `Emulation.setCPUThrottlingRate`、360 寬。降速 4 倍不是慢 4 倍 ——
  每次嘗試一次 WebCrypto 呼叫，呼叫開銷才是大頭，cost 1000／counter 5000–10000 要 14–18 秒。
  降 counter 比降 cost 有效。量法寫在 `ALTCHA_PARAMS` 的註解，改難度時照它重量。
