## 二、坑

0. **Workers 每請求 50 個 subrequest**：supabase-js 一次查詢就一個，`waitUntil` 裡的也算。單筆請假 POST 一位就 23～24 次（`leaves-subrequest-budget.spec` 守 ≤45）。要逐筆處理多位的批次，不要在一個請求裡迴圈呼叫既有路徑 —— 要嘛前端拆成多個請求，要嘛走 pg pool 的 SQL。
1. **PostgREST 的 `.in()` 進 GET URL**：本機實測短 select 帶 500 個 uuid 就 414，長 select（巢狀 embed）帶 200 個也 414。替身不會報。大量 id 走 pg pool 的 `= ANY($1::uuid[])`。
2. **字串斷言要分得開別名**：`toContain('e.org_id = $1')` 會被 `se.org_id = $1` 滿足（#1922 一讀被抓）。SQL 語意用契約對真 DB；髒資料每一筆只讓一個條件擋住，才分得出哪個條件被拿掉。
3. **Hono 路由寫 `/:id` 在 OpenAPI 文件裡不是參數**：`list-endpoints.contract` 會把 `:id` 當字面送出回 400。新路由一律 `/{id}`，並在 PARAMS 補 fixture。
4. **兩支背景突變腳本共用同一個備份檔會互相蓋掉**（#38 時模板一度留著突變版）。突變一次只跑一支，或各用各的備份檔；跑完 `git diff` 確認還原。
5. **跑突變前先確認基準綠**；突變腳本用 `python3` 換字串 → 跑 → `finally` 還原。Prettier 會改排版，突變字串要照格式化後的檔來寫（NOAPPLY 就是排版不同）。
6. **`supabase status` 要在 repo 根目錄跑**，在 `apps/api` 下取不到環境變數，契約會 skip（看起來像綠）。`npx supabase migration new` 在背景會卡在等輸入：檔案其實已建好，直接寫內容。
7. **jsdom 的 Blob 沒有 `text()`**：測 blob 錯誤本體時在 spec 補 polyfill（`FileReader`）。下載走 blob 不走 text，後端的 UTF-8 BOM 才不會被吃掉。
8. **multi-org-db 的 `ilike`** 已改成照 Postgres 語意（`%`、`_`、`\` 跳脫、整串、不分大小寫）。
9. 本機 DB 不 up migration；SQL 一律「BEGIN → 執行／建資料 → 查 → ROLLBACK」驗。
10. 已推分支不 rebase；疊 PR 衝突用 merge main；`git add` 只加指名路徑。
