## 二、坑（本席新踩的）

0. **沒有 preview 環境**：`deploy.yml` 只部署 main。要給使用者實測的東西只能做成預設關閉的入口，合進 main。
1. **iOS 主畫面 PWA 沒有網址列**，`start_url` 固定 `/parent`：flag 不能靠網址帶，只能做成 App 裡看得到的入口。
2. **Better Auth 1.5.5 回呼時比對 state cookie**（`state_security_mismatch`）：發起和回呼必須在同一個 cookie jar。查 OAuth 落點時，用 curl 的兩個 jar 對正式站打 sign-in／callback 就能重現，不需要 LINE 帳號（#2063 留言有步驟）。
3. **`signIn.social({ disableRedirect: true })`** 回 `{ url, redirect: false }`，可以在前端改授權網址；LINE provider 不傳 additionalParams。
4. **PostgREST 聚合不吃 embed 的過濾**（42703）：反連接篩選的章節計數要改每級一支 HEAD count，或走 pg。
5. **seed 的 99 位人員 `created_at` 全相同**：只按時間排序時順序不固定，雙路契約比對要補 `id` 末鍵。
6. **雙路契約的「改前基準」**：先在改前的 main 上用 `*_BASELINE_WRITE` 錄 builder 回應；改前順序不固定的話，比之前先排序；結果超過一頁時只比摘要與 meta。
7. **測試寫錯的兩種假綠**：(a) 斷言「不是 null」，但那一列被刪掉時拿到的是 undefined，一樣通過 —— 先斷言存在；(b) 測試自己做替換再比對，等於沒測到。
8. **BSD sed 的 `\&` 不匹配**，突變會靜默沒套上：突變一律用 python 做字串替換，並 assert 只命中一次。
9. **`git checkout -- <檔>` 會毀掉未提交的改動**（auto mode 擋過一次）：突變前先提交，在暫存 worktree 裡做。
10. **契約全套平行跑會互相干擾**：挑全庫資料的契約會撿到別的檔案的暫時資料（#2059 修過 notify）。新寫的契約一律自建 org 或只挑 seed。
