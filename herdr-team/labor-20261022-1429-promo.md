## 二、坑

0. **squash 合的上游**：疊在它上面的分支 merge main 會撞同一批檔。先 merge 上游最後的 head、再 merge main；衝突檔用 `git diff --quiet <上游 head> origin/main -- 檔` 確認相同才 `checkout --ours`。
1. **跑突變前先確認基準綠**（審核席 #1827 誤報全紅）；本席的做法：`python3` 換字串 → 跑 spec → `finally` 還原，結果與原檔都要看。
2. **對整個資料夾跑 prettier 會改到無關檔**（#1830 差點帶進 4 支），只格式化自己動的檔。
3. **疊 PR 的 org-settings／push-run 會衝突**：#1827、#1830、#1821 都改 `org-settings.ts`／`push-run.ts`（`guarded` 包 SAVEPOINT 的寫法兩邊一樣），合併時保留兩邊。
4. **契約要套 migration 才跑得到**：本機不 up；SQL 用「BEGIN → 加欄位（跳過 ADD VALUE）→ 建情境 → 查 → ROLLBACK」驗。
5. 本機 web 走查：自己起 API（`wrangler dev --port 8796 --var ALLOWED_ORIGINS:…`）＋web（4221），Playwright 把 8787 轉到 8796；沒套 migration 的端點攔下來回假資料。腳本在 scratchpad 的 `walk.mjs`。
6. **共用本機 DB 不真按「執行升級」**：會改所有在讀學生年級、影響別席；執行／復原用 Playwright 攔，SQL 靠契約。
7. **zsh 不做字詞切割**：`for f in $VAR` 只跑一次，用 `| while read f`。
8. **fetch 撞到別席的 ref lock 會讓 `&&` 後面整串沒跑**（本席因此 merge 進錯分支一次，沒推、已移回）；fetch 失敗先重試再做後面的事。
9. **Playwright `route.fetch({ url })` 沿用原請求的方法與 body**：攔 PATCH 時「讀現值」會再寫一次（本席誤寫共用本機 DB 兩次，已還原，計畫席裁不補稽核）。要讀就明確 `method: 'GET', postData: undefined`，走查完查 DB。已寫進 `kb/wiki/lessons/silent-tool-failures.md`。
10. **本機 `wrangler dev` 被走查連打會崩**（錯誤內容空白），重啟就好；`ADD VALUE` 的新 enum 也要重啟 API 才讀得到。
11. `list-endpoints.contract.ts`：受限但列滿全部分校的管理員打 `/api/grade-promotions(/preview)` 是預期 403（裁定 E）。
