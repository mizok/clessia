## 二、下一刀（依效益排序）

1. **`/api/me` 之後的 chunk 鏈**：P3a 讓 `/api/me` 早 1.4 秒，資料到齊卻只早 0.7 秒 —— guard 只抓得到每層 `loadComponent` 那支，它 import 的子 chunk 要下載解析完才知道，還是一層一層下。方向：P1a 重做（雜湊檔長期快取，**先讓不存在的雜湊檔回 404 再談**，見 1152-perf charter 第二節的更正），回訪就幾乎不用下載；或建置時把各路由的子 chunk 清單產出來給 guard 一次預載。
2. **身分快取改 Cache API**（P1b 後續，計畫席已原則同意，三個前置問題寫在 #1595）：儀表板 9 支 API 幾乎每支都還在付 middleware 3 支（跨 isolate 命中率 ~44%）。
3. **儀表板 9 支 API 本身**：最慢的是 `/api/attendance/sessions`（8 支）、`/api/leaves`、`/api/invoices/summary`。照 P3b 的手法逐支拆：列查詢、找串行段、找一輪超過 6 支的地方。
4. **`/api/me` 剩下的 `profiles`**：正式站若沒有殘列，刪掉就剩 `ba_user` 一支。要先唯讀查正式站 `profiles` 有幾列、跟 `staff.display_name` 是否不同。
5. **熱門路徑走 Hyperdrive 直連**（架構決定，要使用者拍板）：每支查詢的閘道成本 ~100–150ms，少查次數之外唯一大的。

## 三、量測方法（不在 repo，會再用）

- **前端前後比：`~/.cache/clessia-perf/measure.mjs`**（本機、不進版控）。Playwright 攔截 `demo.clessia.cc`：靜態檔吃本機 dist（前／後兩份 production build），`/api` 照打正式站 —— 前後只差程式碼，api 是同一份。
  - **`STATIC_MS=700` 一定要帶**：本機攔截是瞬間回，不帶的話「提早發請求」這類改動會量成 0。700 是正式站 `main.js` 實測下載時間。
  - 登入態：`login.mjs` 開有頭瀏覽器、**使用者本人登入**後存 `state.json`（席位不拿帳密）。
  - 「頁面資料」要排除開站就發的 `/api/system-time`，不然它會冒充第一支頁面 API。
  - 建「前」版 dist：先 commit 自己的改動，`git checkout origin/main -- <檔>` 建置，再 `git checkout HEAD -- <檔>` 還原（一次指令裡夾 `rm -rf` 會被權限擋）。
- **伺服器端前後比：wrangler tail**。`npx wrangler tail --env production --format json` 背景跑，事件是一串連著的 JSON（用 `JSONDecoder.raw_decode` 逐個讀），`[probe]` 那行有查詢支數／合計／最慢。
  - 有些事件的 query string 被印成 `campusId=REDACTED`，**同一份檔裡其他事件常有原值**，grep 原始檔就找得到。
  - **前後要同條件**：名冊帶不帶 `campusId` 是 16 支 vs 20 支，混著比沒有意義。
- **驗正式站 PostgREST 設定不需登入**：公開金鑰打 `students?select=grade,count()`，開了回 `[]`（RLS 全拒），沒開回 PGRST123；要配一個會出錯的負控（`nosuchcol.count()` → 42703），否則 `[]` 證明不了什麼。

## 四、這一席被 reviewer 抓到的（都是該預設就做的）

- **加了 spec 之後要重跑 `npx nx typecheck api`**，不是只跑 vitest：vitest 不做型別檢查，`new Proxy(db.client, …)` 的 `unknown` 只有 typecheck 抓得到（#1602 CI 紅）。PR 寫「tsc 綠」前確認是在最後一個 commit 之後跑的。
- **新增 context 變數（`Variables`）要同步契約測試替身** `apps/api/src/contract/list-endpoints.contract.ts` —— 它取代了 authMiddleware、手動 `set` 每一個變數（#1601 CI 紅：`/api/me` 500）。
- **每一條錯誤路徑都要有 spec**：「改成並行之後，錯誤在後面才收」「聚合沒開會回 error」這種，拿掉那行 `return` 全綠就是沒守（#1602、#1604）。
- **斷言查詢次數的 spec 會跨 PR 互相踩**：#1602 斷言 ≥14 次 `from('students')`，#1604 把它變成 3 次，git 沒衝突、合進 main 才紅。動到查詢數時 `grep` 一下別的 spec 有沒有數它。
- **全域旗標的「用完要清」也要斷言**（`delete window.__clessiaEarlyMe`）：只測「第二次呼叫打新請求」守不住，那條路根本不讀它。
