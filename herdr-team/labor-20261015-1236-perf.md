## 二、下一刀（依效益排序，10-15 17:3x 版）

1. **REST 預熱 vs Hyperdrive B**（範圍說明在 #1595，等 gate）：預熱能不能省到，取決於 handler 能不能接上「還在握手」的連線；身分 SQL 只要 10–15ms、握手 50–700ms，大概率省不到 → 先用拋棄式探針量三種情況。B 只挑 `/api/campuses`、`/api/org/settings` 這種最單純的。
2. **撤掉 `[probe-tl]`**（#1608）：量完 1 之後 revert，撤除也要開 PR。原本的 `[probe]` 去留另議。
3. 身分快取改 Cache API（P1b 後續）：**H3 證明 per-isolate 快取幾乎不會命中**（每請求全新 isolate），但身分已經走 SQL 只要 10–15ms，這項的價值大降，排最後。
4. `JWT issued at future` 根治：換舊式 service_role 金鑰，或附 `[jwt-iat]` 數字向 Supabase 回報（使用者決定）。
5. **demo 站流量太低造成「每請求全新 isolate」**：真的補習班上班時間 isolate 會被重用，連線是熱的。任何「省握手」的優化，在真實流量下效益都會縮水，評估時要講。

## 三、量測方法（不在 repo，會再用）

- **前端前後比：`~/.cache/clessia-perf/measure.mjs`**（本機、不進版控）。Playwright 攔截 `demo.clessia.cc`：靜態檔吃本機 dist（前／後兩份 production build），`/api` 照打正式站 —— 前後只差程式碼，api 是同一份。
  - **`STATIC_MS=700` 一定要帶**：本機攔截是瞬間回，不帶的話「提早發請求」這類改動會量成 0。700 是正式站 `main.js` 實測下載時間。
  - 登入態：`login.mjs` 開有頭瀏覽器、**使用者本人登入**後存 `state.json`（席位不拿帳密）。
  - 「頁面資料」要排除開站就發的 `/api/system-time`，不然它會冒充第一支頁面 API。
  - 建「前」版 dist：先 commit 自己的改動，`git checkout origin/main -- <檔>` 建置，再 `git checkout HEAD -- <檔>` 還原（一次指令裡夾 `rm -rf` 會被權限擋）。
- **伺服器端前後比：wrangler tail**。`npx wrangler tail --env production --format json` 背景跑，事件是一串連著的 JSON（用 `JSONDecoder.raw_decode` 逐個讀），`[probe]` 那行有查詢支數／合計／最慢。
  - 有些事件的 query string 被印成 `campusId=REDACTED`，**同一份檔裡其他事件常有原值**，grep 原始檔就找得到。
  - **前後要同條件**：名冊帶不帶 `campusId` 是 16 支 vs 20 支，混著比沒有意義。
- **驗正式站 PostgREST 設定不需登入**：公開金鑰打 `students?select=grade,count()`，開了回 `[]`（RLS 全拒），沒開回 PGRST123；要配一個會出錯的負控（`nosuchcol.count()` → 42703），否則 `[]` 證明不了什麼。

- **`[probe-tl]` 時間軸怎麼讀**：`e`（`x-envoy-upstream-service-time`）是 PostgREST＋DB；「單支耗時 − e」是網路＋建連；`iso#` 是 isolate 的第幾個請求；`exec=` 是 Supabase 回應 `cf-ray` 的尾碼，即 Worker 實際機房。
- **查 DB 真正的執行時間**：Supabase Management API `POST /v1/projects/{ref}/database/query?read_only=true`，讀 `extensions.pg_stat_statements`（不是 `public`）。token 在 macOS keychain 的 `Supabase CLI`（`go-keyring-base64:` 前綴）。**要授權**，只讀平均／總時間／次數，查詢文字要遮字面值。
- **查 Workers／Hyperdrive 用量**：Cloudflare GraphQL Analytics（`workersInvocationsAdaptive`、`hyperdriveQueriesAdaptiveGroups`），token 用 wrangler 的 `oauth_token`。有速率限制（budget depleted 就等 5 分鐘）。
- **拋棄式探針 Worker**：要授權；只能用公開金鑰、只回毫秒；量完 `wrangler delete`，再用 `deployments list`（回 10007）＋網址 404 雙重確認。新部署的 workers.dev 網址頭幾十秒會回 1042，是傳播延遲不是錯。**`wrangler dev --remote` 不吃 `placement`**，固定在入口機房跑，量不到正式站的位置。
- **Pages 預覽部署**：`wrangler pages deploy … --branch=<名>`。**別名網址重新部署後頭幾分鐘回的是前一版**，驗證時同時量本次部署的專屬網址。刪除用 `wrangler pages deployment delete <id> --force`。

## 四、這一席被 reviewer 抓到的（都是該預設就做的）

- **加了 spec 之後要重跑 `npx nx typecheck api`**，不是只跑 vitest：vitest 不做型別檢查，`new Proxy(db.client, …)` 的 `unknown` 只有 typecheck 抓得到（#1602 CI 紅）。PR 寫「tsc 綠」前確認是在最後一個 commit 之後跑的。
- **新增 context 變數（`Variables`）要同步契約測試替身** `apps/api/src/contract/list-endpoints.contract.ts` —— 它取代了 authMiddleware、手動 `set` 每一個變數（#1601 CI 紅：`/api/me` 500）。
- **每一條錯誤路徑都要有 spec**：「改成並行之後，錯誤在後面才收」「聚合沒開會回 error」這種，拿掉那行 `return` 全綠就是沒守（#1602、#1604）。
- **斷言查詢次數的 spec 會跨 PR 互相踩**：#1602 斷言 ≥14 次 `from('students')`，#1604 把它變成 3 次，git 沒衝突、合進 main 才紅。動到查詢數時 `grep` 一下別的 spec 有沒有數它。
- **比對兩條路之前先清快取**：同一條 spec 裡第二個請求會命中第一個的身分快取，「SQL 對 REST」就變成自己比自己。要斷言 REST 那次真的查了表（#1616）。
- **跨 org fixture 每一種身分都要有一筆**：只建 staff 列，拿掉 parents 的 org 過濾照樣全綠（#1616 reviewer）。
- **「乾淨的空結果」也要當成可疑**：連線角色受 RLS 約束時，SQL 會回形狀正確的三個空陣列，看起來就是「沒有角色」→ 全站 403。roles 為空就走 REST 確認（#1616 計畫席）。
- **加 spec 的突變要能編譯**：拿掉型別守衛（`typeof x === 'number'`）會讓下一行編譯失敗，那不算突變紅。改成 `as number` 之類能編譯的寫法再跑（#1606）。
- **全域旗標的「用完要清」也要斷言**（`delete window.__clessiaEarlyMe`）：只測「第二次呼叫打新請求」守不住，那條路根本不讀它。
