## 二、金流：`invoices` 沒有 status 欄位（#898）

- `unpaid | partial | paid` 是 `lib/invoice-status.ts` **推導**出來的 TS union，不是 enum、不是欄位。
  看到「status enum 加一個值」的工單，前提就是錯的。
- 作廢是**事實**（`voided_at`，誰在什麼時候決定的），所以它是欄位；`void` 在推導裡蓋過其餘三態，
  `deriveInvoiceStatus` 的第三參數 `voided` **必填** —— 可選的話漏傳的呼叫端會把作廢單推成未繳。
- **「未繳清」全系統曾經寫成 `status !== 'paid'`**（API 兩處、web 兩處）。多一個狀態之後那個寫法
  會把作廢單以全額算進催繳／逾期／家長應繳。現在收斂成 `isOpenInvoice`（列舉「是」的兩態，
  不排除「不是」的）—— 下一個新狀態預設落在「不算欠」那邊。
- **淨額歸零與不可撤銷守在 DB trigger**，API 只負責好看的錯誤：寫 `invoice_items` 的不只
  `invoices.ts`（還有 `billing-runs.ts` 的 repair），而且「先算淨額再寫」有競態。
  兩個 session 互等的驗法：一個 `BEGIN; insert payment; pg_sleep(3); COMMIT`，
  另一個同時 `UPDATE … voided_at`，看後者是否等了約 2 秒後被拒。
- **CHECK 的 NULL 陷阱**：`length(btrim(void_reason)) > 0` 在 `void_reason` 為 NULL 時是 NULL，
  **CHECK 把 NULL 當通過**。要 `coalesce`。驗證腳本第一條就是故意塞 NULL。
- trigger 凍結整列時，**`ba_user` 被刪造成的 FK `SET NULL` 也是 UPDATE** —— 不放行的話人刪不掉。
  比對「其餘欄位全都沒變」用 `to_jsonb(NEW) - 'col' … = to_jsonb(OLD) - 'col' …`，將來加欄位自動涵蓋。
- 作廢要讓**收費項回到未開帳**：學費冪等查衍生列（作廢單上的不算開過）、餐費冪等靠蓋章
  （作廢時解章）、異常掃描要跳過作廢單（否則 repair 去改一張被 trigger 凍結的帳單，每次都報一筆修不掉的異常）。

## 三、稽核：`audit_logs.resource_type` 加值（#911）

- 慣例是 `DROP CONSTRAINT` + `ADD` **完整清單**，時間戳最晚的那支說了算；**同一支 PR 必須同時改
  `utils/audit.ts` 的 union**，harness A7e 會逐項比對兩份（「檔名排序最後一支含 CHECK 的 migration」）。
- 驗 gate 讀的是新檔：**故意從新 migration 刪一個既有值，harness 要紅**；只改 union 不加 migration 也要紅。
- 「已讀」不記稽核的理由（使用者裁定）：`announcement_reads` 本身就存誰、何時**第一次**讀
  （upsert 只帶主鍵，不覆寫 `read_at`），而且永久；`audit_logs` 有 cron **90 天刪**。
- **「不記」也要寫成測試**，而且要做突變驗證 —— 我第一次寫的「不記」測試是空轉的：替身的
  `upsert` 只收陣列，單則已讀傳物件，在替身裡炸成 500，於是測到的是「請求失敗所以沒稽核」。
  前置斷言 `status 204` ＋「真的 upsert 了一列」之後才有鑑別力。

## 四、效能：量的是「依序幾輪」，不是查詢速度（#944 / #948 / #949 / #951）

- 本機 `pg_stat_statements` 看得到每支查詢的真實執行時間（唯讀）；那次全部 ≤ 3.2ms。
  **慢的是往返輪數**，不是查詢本身，也不是索引（索引已覆蓋，Seq Scan 都在 <140 列的小表）。
- probe（`lib/supabase-latency-probe.ts`）只給「支數」，分不出平行與依序。量輪數的本機手法
  （**不 commit，量完 `git restore`**）：在 probed fetch 裡記起訖時間，**並注入固定 50ms 延遲**讓平行
  的呼叫明顯重疊，再用「開始時間 ≥ 目前最晚結束 ⇒ 新的一輪」算 waves。本機的絕對秒數沒有意義
  （Docker 上的 Kong 每支約 90ms），只比輪數。
- **改前改後要證明回應逐字相同**：同時起兩份 api —— 臨時 worktree 跑 `origin/main`（另一個 port）、
  工作目錄跑分支 —— 同一個 cookie 打同一批請求，`json.dumps(sort_keys=True)` 後 diff。
  ⚠️ **zsh 不會對 `$FILES` 做字詞分割**：我第一次「換回 main 再比」的 swap 迴圈靜靜沒換，
  比出全部 SAME 是假的。要用 bash 陣列，或乾脆兩個 port 各跑一份。
- **placement**：demo 流量幾乎只來自台灣，Smart Placement 可能永遠 `INSUFFICIENT_INVOCATIONS`；
  用 hint `region = "aws:ap-southeast-1"`（查法：`dig AAAA db.<ref>.supabase.co` 對 AWS
  `ip-ranges.json` → `2406:da18::/35`）。**只查一次 DB 的端點不會變快**（Hyperdrive 官方原話），
  `system-time` 會略慢 —— 量錯欄位就會錯殺。`[probe]` 行**只在登入後的請求才有**（未登入不查 DB）。
- **開站順序**：時鐘 initializer（`provideAppInitializer`，**grep `APP_INITIALIZER` 找不到它**）擋住
  啟動是對的 —— 同步前 `nowEpochMs` 退回瀏覽器時間。要省一段往返，是讓 `/me` **不等啟動**
  （提早 `inject(AuthService)`），不是讓啟動不等時鐘。測試用**真的 `appConfig.providers`** 驗接線。

## 五、請假實驗（#964，「接到電話 → 不換頁請假」）

- 這是**資訊架構**的實驗：刻意只用既有元件與 tokens，新流程不能比舊的漂亮，否則比較混了變數。
- `leaves.ts` 的請假連動是**保留類**，只能呼叫 `POST /api/leaves`，不能抽它的內部函式共用。
  預覽另算（`lib/student-day.ts`，在籍用 `isEnrolledOn`、請假覆蓋用 `leaveCoversSession`），
  **結果卡以 `GET /api/attendance` 的實際寫入為準**，不一致就寫出來 —— 不讓預覽冒充結果。
- **學生搜尋預設 `searchScope` 就會比對家長姓名**；請假對話框刻意關掉（只搜學生名）。打電話來的是家長。
- 儀表板的待處理卡片列用負 margin（`--band-seam`）壓進橘帶 —— 新區塊**不能插在帶與卡片列之間**。
- **範圍不能靠「組裝端恰好只把它當查表」**（reviewer 在 #967 標的）：每支查詢自己帶範圍。
  請假單沒有分校欄位，它的範圍定義是「學生在範圍內分校有報名」（同 `GET /api/leaves`）。
  測法：`vi.mock` 把組裝函式換成「原封不動回傳輸入」、替身照 `.in()` 真的過濾，看他校資料漏不漏。
- 元件自己 `providers: [DialogService]` 時，TestBed 的 mock 蓋不到它 —— 從
  `fixture.debugElement.injector.get(DialogService)` 拿實際那一個來 spy。

## 六、驗證「產品與規格不符」清單的查法（2026-10-02 六筆）

- **先找規格的真身**：同一件事常有兩份 kb —— `specs/admin/...` 是舊的需求規格，
  `specs/sitemap/...` 是某天的**實測現況紀錄**，`rules/...` 是使用者定案。三者衝突時，
  程式通常跟 `rules`，過期的是舊 spec（請假「不自動還原」就是這樣）。sitemap 寫的是當時看到的，**不是應然**。
- 改 sitemap 這種實測紀錄：**標「已修」並保留修前觀察**，不要刪改。
- 子代理給的行號常是約略值（`~`）且會留 OPEN QUESTIONS —— **回報前自己補成精確行號、把疑點查完**
  （例：批次匯入是否也寫 parent 角色 → `parents.ts:1671` 有）。
- 「X 關閉不刷新」這類：PrimeNG 對話框內建的 X 以 `undefined` 關閉，**不經過元件的 `onClose()`**。

## 七、跨席協作的兩個小坑

- 兩支 PR 改同一支 spec 的同一個插入點（例：都插在同一條 `it` 之前）→ 後合的必撞衝突。
  開的時候就提醒合併順序；rebase 後用 `git range-diff <舊>~1..<舊> origin/main..HEAD` 證明沒夾帶。
- `herdr agent prompt` 回 `agent_blocked` ＝對方 pane 卡在互動輸入，訊息沒送到。
  **內容先落在 issue／PR 留言**（durable），下一次送達時補一句「上一則沒送到」。
