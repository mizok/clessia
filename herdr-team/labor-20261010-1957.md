## 一、`appRtRow` 只能在 responsive-table 自己的 injector 裡建立

想把一份「列的標記」用巢狀 `ngTemplateOutlet` 共用（一個 `<ng-template let-list>` 被多張表呼叫）會炸：`appRtRow must be used inside app-responsive-table`（餐費頁 15 條 spec 全紅）。**表的 body template 必須直接寫列的標記**。要「依章分多張表」就在 `@for (table of tables())` 裡**宣告 head／body template 並餵給同一章的 `app-responsive-table`**；區間模式（單表帶分頁）就是「只有一章、沒章頭」的同一結構——標記只寫一份。章頭用 `app-chapter-head`，章的 grid 類別放 TS 常數（`[class]="isRange() ? '' : chapterGrid"`，Tailwind 才掃得到完整字串）。

## 三、做了什麼判斷（下一個做同類頁會再問）

- **一人多班在依班分章的清單裡只出現一次**（便當／帳單都是一份）：歸排序後第一個班名，其餘班名小字寫在名字下（`mealChapters`／`MealDraftRow.chapter`）。
- **跨頁連結要看權限**：報表是 `view_reports`、帳單頁是 `manage_finance`，連到帳單頁的連結用 `AuthService.hasPermission('manage_finance')` 擋；課程連結沒擋。
- **「看逾期帳單」要真的落在逾期**：給 `PaymentsPage` 一個 `due` route input（`withComponentInputBinding` 已開，query 直接進 input），只認 `dueFilter` 的合法值。帳單頁沒有分校／月份／課程的 query，所以那三種連結只到頁面、不帶篩選——要帶就是另案（含 `GET /invoices` 的參數）。
- **「合計列」用 API 的 `summary`，不在前端加各組**：報表的 🔴 陷阱（見 `reports.page.ts` 註解）。PR 附逐欄「來源／前端處理」表。
- **A6 拿掉任意日期區間→全採**：期間改成「前三個完整月＋近三個月＋本月到今天」，預設上個完整月（月初開頁時本月整頁是 0）。`reportPeriods(today)` 吃台北曆日，別用瀏覽器時區。
- 稿與現況的小差異（SelectButton vs 文字分頁、`page-open` 大標、匯出 CSV）都寫在 PR 的差異清單、不動；**`page-open` 的開場句是共用元件，不要在單頁硬改**。
