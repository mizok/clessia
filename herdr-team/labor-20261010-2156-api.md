## 一、判準只能有一份 —— 計數、列表、前端歸類都從同一支函式長出來

- **計數端點與列表共用條件產生器**（`routes/enrollments/list-query.ts` 的 `eventFilter`）：列表的期間篩選＝四種事件條件的聯集，計數＝各事件一支 `head: true` count。前端的事件歸類（`enrollment-event.util.ts`）**照抄同一份判準並在註解指回去** —— 兩邊各自想一份，Hero 的數字就跟列上的 pill 對不上。
- **「數事件」跟「數列」是兩件事，先問清楚再寫**：A6 稿的資料模型是一則事件一列（報了又退＝兩列），產品是一筆報名一列。計數數事件時加起來會 > 列數 —— 這是裁定的代價，不是 bug，要寫進 PR。
- **事件篩選不要送進計數端點**：一筆報名可以同時是新報名又是退班，帶 `event` 去計數會變交集。稿要的「選退班時新報名寫 0」在前端把沒選到的歸零就對了。
- **分校篩選＝跟受限範圍取交集再餵授權判準**（`campusFilterIds(getCampusScope(c), campusId)`）：不帶參數時等於原 scope（行為不變），不受限選 A＝A 校受限者看到的，受限者指名範圍外＝空。**不要另寫一份「篩選用」的判準**。代價要量出來寫明：帳單判準下，跨校帳單哪校都不見、跨校學生的純餐費單兩校都見 —— 各校加總≠全部，**兩個方向都有**（第二個是寫 spec 時才撞到的，範圍說明沒想到）。
- **active 的 `effective_to` 不只是「排定」**：過了那天就離開名冊（today-attendance／attendance／billing-periods 都用 `effective_to >= 日期`）。所以「退班」要含到期結束，但要截到今天（`≤ 今天`）；顯示用「已結束」用 `<`（當天還在籍）—— 差一天的邊界寫進 PR。

## 二、會騙人的東西（實測踩到）

- **`nx test web --include=<glob>` 的摘要寫 passed，但 unhandled error 讓 exit 是 1**：兩支自己建 TestBed 的舊 spec 沒給新 service 方法的替身，`undefined.pipe` 丟在 switchMap 裡。只跑子集時摘要是 `Tests N passed`，**`Errors 1` 那行在下面、而且只有全量跑時被當成失敗**。新增 service 方法時 grep 該頁 spec 的每一個 `useValue: { list: … }`（不只 `setup()` 那個）。陷阱驗證時看到 `Vitest caught 1 unhandled error` 就不能算數，修掉再塞一次。
- **陷阱塞了但編譯失敗 ≠ 紅**：拿掉一行讓某個變數變成未使用 → TS 錯 → 沒有 `Tests` 那行輸出。每道陷阱要看到 `N failed | M passed` 才算打中；沒有就換一種可編譯的塞法。
- **`multi-org-db` 的 `or()` 原本不認 `and(…)`**（已補，遞迴切頂層逗號）。替身是字串比較、不懂 enum 與 PostgREST 解析 → `and()` 包在 `.or()` 裡、巢狀 `!inner` 的真語意一律另外用 **supabase-js 探針打本機 PostgREST，跟 psql 寫的 SQL 對帳**（探針寫在 `apps/api/src/__probe.ts`，用 IIFE —— tsx 在 cjs 下不收 top-level await；跑完刪）。
- **契約測試綠 ≠ 打到你的分支**：`upcoming-unbilled` 在示範庫沒有任何 `billing_periods`，查期那步就回空，計數從沒被執行。契約 200 只證明前段沒壞，要寫明並用探針補。
- **`BRANCHES` 原本不過 `fill()`**：要帶 seed id（`campusId={campus}`）得先讓它過 fill（#1534 已改）。
- **`supabase-js` 的 select 若是動態字面值又配泛型 filter helper → `TS2589 Type instantiation is excessively deep`**。select 標成 `const select: string`，builder 先存變數再傳進 helper。
- **`getCampusScope` 對未設定的 context fail-closed（`CampusScopeMissingError` → 500）**：路由開始讀範圍後，沒經過 authMiddleware 的精簡測試 app 會整支 500。修替身（`set('campusScope', null)`），不要放寬函式。

## 三、前端的時間一律從 `SystemClockService.todayTaipei` 拿

- `format(new Date())` 是裝置時區，跟 API 的 `getCurrentTaipeiDateString` 會差一天，也躲過 `test:timetravel`。今天、近 30 天、月份選項全部從 `todayTaipei()`（computed）推，日曆加減用 `parseISO(today)`。
- spec 的時鐘替身**釘在離真實日期很遠的一天**（我用 2027-03-15），列的日期由它往前推 —— 釘今天的話，「改回 `new Date()`」的突變在今天照樣綠。
