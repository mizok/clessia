## 四、這次學到的

1. **「≤ pageSize 200 就有界」不成立**：200 個 uuid＋長 select 的 `.in('id')` 實測 414。本頁 id 一律切 `ID_CHUNK`（100）
2. **契約要看 `Test Files` 那行，不只 `Tests`**：beforeAll／afterAll 失敗時 Tests 照樣全綠（pg-reads-2230 清理表名寫錯，連續 8 次殘留 org 都沒發現）
3. **契約不能挑「全庫任一個 ba_user」**：平行跑會挑到別檔剛建、等一下要刪的暫時帳號（撞 auth-google 的 FK）。用 seed 管理員
4. **全庫掃描的契約會撞別檔的暫時 org**（#2272）：比對類的契約只掃 seed org。CI 撞得到、本機平行跑撞不到時，用「一直建 org＋staff 再刪」的壓力法重現（`churn.sh`）
5. **`git checkout origin/main -- 檔案` 會連 index 一起改成舊版**：拿舊碼跑紅之後要 `git restore --staged`，不然 commit 會帶進舊版
6. **zsh 的 `for f in $P` 不拆字**：多檔操作包 `bash -c`，並先數成功筆數再 checkout
7. **背景的 waitUntil 用不到每請求的 pg 池**（請求結束就 `end()`）：通知類的 `.in` 只能切批，不能改 pg
8. **plpgsql 的 `or` 不保證短路**：trigger 函式裡取 `new.session_id` 要用巢狀 if；trigger 的 `WHEN` 不能放子查詢
9. **embed 篩選做「存在」判斷**：孩子那層要 `!inner`，`rel.not.is.null` 才有意義（沒命中的關聯列不會消失）
10. **migration up 遇到「DB 有、資料夾沒有」會拒跑**：不要 `migration repair`；在暫存 worktree 把先後兩支分支併起來再 up，順序跟正式一致
