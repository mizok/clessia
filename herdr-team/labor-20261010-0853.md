## 一、分校範圍：「反推要開什麼」與「單筆跟列表同一條」

- **批次寫入的範圍不是「擋」而是「反推」**：受限者跑帳務作業時，用 `invoiceInScope` 的兩條反推挑母體
  （學費挑班在範圍內的報名、餐費挑 `studentInScope` 的學生），於是**開出的每張單必然在他範圍內**，
  不需要事後再濾。代價（跨校學生被兩校各 run 會拿兩張）是行為變化 —— 設計時就寫成可否決點（#1393）。
- **沒有任何報名的學生推不出分校** → 對受限者是範圍外。連帶：`DELETE /students/{id}` 只允許無報名的，
  所以受限者實質不能刪學生（#1394）。**判準照列表那條，單筆不能比列表寬** —— 寬了就是第二份判準。
- **`meal_records` 沒有 `campus_id`**：任何餐費的分校判斷都只能走學生歸屬。
- 錯誤被 `data ?? []` 吞掉的查詢（`billing-runs.ts` POST 整支都是），**契約測試抓不到形狀錯**（回應照樣 200）。
  那種查詢要用探針：從原始碼抽 select 字串（`includes` 斷言）、對本機 PostgREST 打一次看 `error`。

## 二、契約測試（`list-endpoints.contract.ts`）現在的形狀

- 三輪：家長（`/api/me` 與 `/api/me/*`，用 seed 裡有孩子的家長，`studentScope`／`childDb` 照 authMiddleware 設）、
  不受限 admin、受限 admin。**受限那輪的範圍是 org 全部分校（非 null）**：查詢形狀跟一間時一樣，
  但單筆 id 必在範圍內 —— **很多單筆路由把查詢錯誤折成 404**，範圍外的 404 跟形狀錯的 404 分不出來。
- 單筆 `{param}` 端點的 id 在 `PARAMS` 表；**文件有 `{param}` 而表裡沒有 → 紅**。新增單筆 GET 時同支補一行。
  id 要互相對得上（`scores/class/{classId}/exam/{examId}` 從 `academy_exam_classes` 取一對；學生取有報名的）。
- **前綴比對的坑**：`startsWith('/api/me')` 會吃掉 `/api/meals`（#1437 起它從沒被打過）。前綴要帶 `/` 或用精確比對。
- 上限：fixture 走不到的分支測不到（`parent/billing.ts` 付款資訊那支：seed 家長的孩子沒有在籍班的分校）。

## 三、盤點單筆 org 的機械掃描（#1429 留言有結果表）

- 掃 `.eq('id', …)` 往上到 `.from(`、往下到 `;`，整串沒有 `org_id`／`inOrg(`／`findInOrg`／`orgRef`／`childDb` 就列 MISS。
  **`inOrg(` 常寫在 `.from(` 的前一行** —— 從 `.from(` 起算會產生一批假陽性，人工排除時先看前一行。
- path 參數不叫 `id` 的單筆端點（`{studentId}`、`{eventId}`）掃不到，要另外人工看。
- `profiles`／`ba_user` 以 `userId` 查改佔 MISS 一半：看 `userId` 的來源（session 本人、或剛從 org 內查出的列）。
  `ba_user` 寫入是 A15 已登記的永久豁免，不是新洞。

## 五、兩支 PR 同時改同一份 KB 頁

- 兩支各在**同一行之後**插段落 → 第二支合時文字衝突。開第二支時對**第一支的分支**也跑一次
  `git merge-tree --write-tree origin/<第一支> HEAD`，衝突就把段落移到不相鄰的位置。frontmatter `updated:` 改成同一個值不算衝突。

## 六、第二輪（10-10 09:15 起）踩到的

- **暫存 DB 要帶真 schema —— trigger 也是 schema。** #1472 回填在「最小兩張表」的暫存 DB 驗得全綠，上正式的話會炸：
  `invoices_guard_void`（BEFORE UPDATE）擋作廢單上任何欄位變動，而暫存 DB 沒有它、seed 又沒有作廢單。
  **改既有資料的 migration 一律在本機真 DB 的交易內跑、驗完 rollback**（`begin; \i 檔; 檢查; rollback;`），
  並**先造出 seed 沒有的邊界列**（作廢單、無報名學生……）。用修正前的檔先重現失敗，證明那條驗證是活的。
- **「先 commit 再塞陷阱」這輪又踩一次**（#1473）：修正沒 commit，陷阱後 `git checkout --` 把修正一起還原，
  推上去的 PR 只有測試沒有修正。**陷阱前 `git status --short` 必須是空的。**
- **陷阱要先確認有打中**：`sed` 因 prettier 換行沒匹配到 → 「陷阱沒紅」看起來像測試沒守。
  每道陷阱印 `git diff --stat`，是 0 就是沒塞進去；替換後語法壞掉會顯示 `no tests`，不是綠也不是紅。
- **替身驗不出的東西要明講在哪裡驗**：`multi-org-db` 比字串 → enum 列舉序（`grade`）驗不出、時區字串要同格式；
  workbench 的替身不照 `in` 過濾 → 改斷言送出去的條件。驗不出的那半寫進契約測試（真 PostgREST），並在 spec 檔頭註明。
- **授權有兩層要分開守**：「授權函式有沒有守」與「這條路由有沒有呼叫它」是兩件事（reviewer 二讀 #1458）。
  新路由至少一條「拿掉路由裡那一行呼叫會紅」的 spec。
- **查不到 ≠ 沒有**：查詢失敗回空清單 200，前端會顯示「沒有帳單／沒這個人」。失敗一律 500（`LIST_FAILED`／`SEARCH_FAILED`）。
- **觀察不到的程式碼刪掉，不補假測試**：`grade` 是 NOT NULL，`nullsFirst` 永遠不生效 —— 刪，註明理由。
- **契約測試會打出既有 bug**：伺服器分頁頁數超出 → PostgREST 416 → 500（#1455）。替身的 `range` 超出只回空。
- **Python 一般字串裡的 `\`` 會留下反斜線**：用 python 改 PR 描述時，反引號不要跳脫（或用 raw string）。
- **herdr 訊息 timeout ≠ 沒送到**：`herdr agent read <席> --source recent` 看輸入框；`❯ [訊息…]` 停著就 `send-keys enter`，
  輸入框空了就是送到（對方忙時常 timeout）。
- **共用本機 DB 套了還沒進 main 的 migration 要告知**（`supabase migration up --local`）—— 契約測試要它，但其他席的 DB 會因此超前 main。
