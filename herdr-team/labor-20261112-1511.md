## 2. 新增一支 API 會撞到的 gate（這次一次撞了四個）

- **`lib/org-scope.ts` 的 `OrgTable`**：新表有 `org_id` 就要加進這個 union，否則 harness 紅（A23）。這要跟 migration 放在同一張 PR。
- **api-param-coverage**：API 收的 query 參數，前端 service 必須真的送得出去，否則 harness 紅。
  所以 API PR 要連 web service 的 client 方法一起帶（或加 EXEMPT 並寫原因）。
- **`tools/agent-harness/feature-map.mjs` 的 `AREAS`**：新的路由檔要被某個功能區認領（`routes`），規格也登在 `specs`。
- **`routes/db-error-status.spec.ts`** 用 regex 認 `c.json({ …, code: 'DB_ERROR' }, 500)`。
  把它包成 `const dbError = (m) => ({ … code: 'DB_ERROR' })` 的 helper 會被判成「認不得」而紅。**請寫在行內。**

## 3. 不碰共用本機 DB 驗 migration

本機 DB 各席共用，自己不要套 migration。在交易裡驗，最後 ROLLBACK：

```
BEGIN; \i supabase/migrations/<新檔>.sql
… 插測試列；預期會失敗的那句前後包 SAVEPOINT x / ROLLBACK TO x …
ROLLBACK;  -- 最後 SELECT to_regclass('public.<表>') 應該是空的
```

seed-demo 的新段落用同一招：把那段包進 `DO $$ DECLARE v_org uuid; … BEGIN … END $$`，變數用既有的列填。
contract 測試因此在本機跑不到（表不存在），要等 CI 的 api-contract 從頭套 migration 後才會執行。PR 內文要寫明這件事。

## 4. 疊單與 base

- 疊單的第二張起，`gh pr create --base <前一張的分支>`；PR 內文寫清楚依賴，以及「前一張合進 main 後，這張改 base 為 main，並 merge main，不 rebase」。
- 從前一張的分支開新分支時一樣帶 `--no-track`。repo 的 branch check 會印「並非基於 main 建立」的警告，疊單時這是正常的。
- 一張 PR 超過 400 行時，先依端點的用途拆（這次拆成 CRUD 與疊圖），並在 PR 內文寫明行數去向
  （例如「路由檔 424 行，多半是 OpenAPI schema」），讓計畫席判斷要不要再拆。

## 5. 走查工具（`~/.cache/clessia-ux-walk/`）

- `driver.mjs` 要先 `npm install --prefix tools/a6-conformance`，啟動時帶 `PW_FROM=<worktree>/tools/a6-conformance/node_modules`
  和 `WALK_API=http://localhost:<自己的 API port>`。
- magic link：產連結時要覆寫 `BETTER_AUTH_URL=http://localhost:<自己的 API port>`（`.dev.vars` 寫的是 8787）。
  `login.mjs` 要帶 `A6_API_URL`。**連結在 login.mjs import 失敗時不會被用掉**，可以重產。
- PrimeNG 的對話框不是 `dialog[open]`，要用 `.p-dialog:visible`；原生 `<dialog>` 才是 `dialog[open]`。
- **關服務**：kill `npx` 父行程不會帶走 `ng serve` 的 node 與 driver（它們變成 ppid 1）。
  要用 `lsof -tiTCP:<port> -sTCP:LISTEN` 找出來，再看 cwd（`lsof -a -p <pid> -d cwd`）確認是自己的才 `kill -9`。
- 本機 wrangler dev 很慢：寫入後畫面約 2～3 秒才更新，翻頁也要 1.5 秒以上。截圖要等到資料到齊，
  不然會把「舊內容」誤記成 bug（反過來說，「等待期間沒有載入中提示」是真的問題）。
- 會一次寫很多列的按鈕（例如「全部開帳」），在共用 DB 上不要真的按，改讀程式碼確認行為。
