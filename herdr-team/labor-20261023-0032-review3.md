## 二、本任新增的審法

1. **zsh 不對 `$F` 分詞**：`F=$(git diff --name-only …); git diff A B -- $F` 在 Bash 工具（zsh）裡把整串檔名當一個 pathspec，**靜默回空**＝假的「0 差異」。本席因此對 #1911／#1904／#1910 寫過沒證據的「0 差異」（事後重查前兩張真的是 0，#1910 用 patch-id 補證據並在 PR 更正）。**檔名清單一律 `bash -c` 或 `${=F}`，先印檔案數。**
2. **重驗用逐檔 patch-id，不用兩個 head 直接 diff**：作者 merge main 後，`git diff 舊head 新head` 會混進 main 的變動。用 `scratchpad/pchk.sh <審過的head> <新head>`：每檔各對自己的 merge-base 算 `git patch-id --stable`，只列真正變了的檔。合併 commit 裡作者手改的部分看 `git show --remerge-diff <merge>`。
3. **掃整棵 `app/` 的守衛 spec 在高負載全套裡會偶發紅、單獨跑綠**（10-23 兩次：skeleton 守衛、skeleton-shimmer）。看到全套只紅一支這類守衛，先單獨跑、再重跑全套，不要直接判不過。#1927（共用一次掃描）在處理根因。
4. **觸控高度看 `pointer` 不看寬度**（`styles.css:163` 的原則）。任何「桌機縮小」的尺寸改動要問：寬但用手指點的平板（iPad 橫放）拿到幾 px？#1915 第一輪就是只看寬度，平板掉到 40。
5. **`process.env.TZ` 類的測試設定要留覆寫**：硬設會讓二讀沒辦法用 `TZ=America/Los_Angeles` 驗負時區（#1912 改成 `??=`）。驗法是放一支臨時探針 spec 印 `Intl…timeZone`，跑完刪掉。
6. **背景跑多組時，worktree 一組一個**：wt1～wt5 在 scratchpad；同一棵樹不要同時跑兩組（突變會互相污染）。
7. **計畫席點名的「保留類」**（例：#1910 會刪出勤）：二讀過也要在留言與回報寫「合併等計畫席讀 diff 紀錄」。

8. **SQL 字串斷言會被子字串騙**：`toContain('e.org_id = $1')` 在 `se.org_id = $1` 也在時永遠過（#1922：拿掉校內考段的 org 條件、學生篩選都全綠，外洩等級）。看到「斷言 SQL 含某條件」的 spec，**專挑別名是另一個別名後綴的那條拿掉**（`e.`／`se.`、`s.`／`ss.`）。
9. **重建暫存樹要連兩層 node_modules**：只連根目錄的話，`apps/api` 的 spec 會整檔載入失敗（找不到 `pg`），而 `Tests N passed` 只算載入成功的那幾檔，看起來是綠的。**同時看 `Test Files` 那行**，有 failed 的檔就是環境壞了。目標資料夾已存在時 `ln -s` 會把連結建到它裡面，先確認不存在。
