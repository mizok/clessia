## 0. #1122 續課異動：設計決定與擋點位置（改這一塊之前先讀）

- **暫停不是一個欄位**：該生有一筆 `renewal_requests.status = 'pending'` 就是暫停。結案（resolved）或家長撤回（withdrawn）就自動解除。
  一生同時一筆 pending 靠部分唯一索引 `renewal_requests_pending_uniq`，API 先查一次、23505 再兜一次，兩者都回 409。
- **系統沒有自動開單**，「暫停自動開單」擋的是行政手動跑的 **期 run**：
  - 擋點在 `lib/billing-run-write.ts` 的 `billStudent`，**交易內、`for update` 與冪等重查之後**；只在 `billingPeriodId` 有值且學費非空時查。
    丟 `PausedForRenewal`，路由收成 `pausedStudents`。月 run（月繳學費、餐費）不擋（gate Q3 (a)）。
  - 放交易裡而不是規劃階段：家長送申請和 run 同時發生時以交易時點為準。放在「已開過濾」之後：已經開過的算「沒東西可開」，不報暫停。
- **手動開單不擋**（Q4 (a)）：未開單名單 `GET /api/enrollments?hasInvoice=false` 每列帶 `renewalPending`，前端標示、全部開帳不含它們，逐筆照樣能開。
  讀 `renewal_requests` 失敗回 500，不當成沒有人暫停。
- **待開單計數不扣暫停學生**（設計修正，計畫席同意）：`upcoming-unbilled` 那一期只要開過任一張明細就整列消失，暫停學生卡不住它；
  扣除還得連 `staff-digests` 的對照 SQL 一起改。
- **通知與管理入口**：送出時 `childDb.notifyRenewalRequest`（窄能力，只認 scope 內、同 org 的申請）通知該班分校、有 `manage_students` 的管理員；
  管理端併進 `/admin/applications` 當第三種申請（`parent-requests` 的 `kind=renewal`），PATCH 只收 `resolved`，以 update 的 `.eq('status','pending')` 為準。
  稽核記在學生名下（`resource_type='student'`），不動 resource_type CHECK。

## 2. 背景驗證腳本的坑（都踩過）

- **zsh 不分詞**：`for pair in "a b"; do set -- $pair` 不會拆開。多步 git 操作寫成 `bash -c '…'`。
- **等待別的腳本結束**：`pgrep -f "tmp/x.sh"` 會比對到等待迴圈自己（它的命令列也含那個字串），結果永遠等下去。
  改成同一支腳本依序跑，或比對 pid 檔。
- **web「起來了」的判準**：`curl localhost:<port>/` 在編譯完成前就會回應。要等 log 出現 `Local:` 再開始量。
- **關服務**：ng serve 的 node、wrangler 的 workerd 會變成 ppid 1 的孤兒，`pgrep -f "nx serve"` 抓不到。
  收尾時用 `lsof -tiTCP:<port> -sTCP:LISTEN` 找出行程、比對 cwd 是自己的才 `kill -9`。做兩輪，因為 wrangler 會把 workerd 重起。
- **全套紅一片的逾時**（Hook/Test timed out，散在不相干的檔案）幾乎都是負載（load 24 那次）。先看 `uptime`，降下來再重跑；
  若重跑仍有同一支逾時才當真。

## 3. 截圖：本機資料不夠時攔回應

- 截圖腳本用 Playwright 的 `ctx.route` 改寫回應，不碰共用 DB。例：續課頁攔 `renewal-preview` 補下期與處理中申請；
  申請頁把一筆假的 renewal 塞進 `parent-requests` 的回應。
- **會寫 DB 的按鈕（run／全部開帳）一定要攔成假回應**，而且獨立註冊在**後面**（Playwright 後註冊的 route 先比對），
  別讓它落到轉發 8787→8797 的那條。
- 帳單頁的未開單 banner 計數不是走 `hasInvoice=false` 那支，本機沒資料時塞假列也不會出現（這張 11-13 沒拍成）。

## 4. 家長登入態（`~/.cache/clessia-a6-conformance/state-parent03.json` 是共用的）

- 產 magic link 時 **`WEB_URL=http://localhost:4200`**（API 只信任 4200 這個 callback origin）＋`BETTER_AUTH_URL=http://localhost:<自己的 API port>`。
  用自己的 web port 當 WEB_URL 會 403。
- `login.mjs` 已改成驗過才寫（#2479 的 a017528）。舊版會在 403 時把空登入態寫進共用檔，別席的家長頁 compare 會全掛。

## 5. a6-conformance：改了可及名稱，配對就會斷

- part key 帶名稱。欄位的名稱從 placeholder 改成 label（或加 aria-label）之後，key 換名，原本靠名字配上的 part
  變成一缺一多，掛在上面的偏離也跟著失效。這就是 #2468 一開始被 revert 的原因。
- 修法：頁面層用 `mapping`（A6 key → app key）；**彈出物裡的 part 不吃頁面 mapping**，用 `popMapping: { <彈出物>: { … } }`
  （#2482 加的，key 帶 `pop[<id>]` 前綴）。配上之後名字不同會報「文案」，那才是要登 R5 的真偏離。
- 完整 key 從 `A6_OUT/<頁>/diff-d.json`、`a6-d.json`、`app-d.json` 撈，不要從報告的「›」簡寫抄。
- **`lib/config.mjs` 不是 prettier 格式**。跑 prettier 會整檔重排（+71 行）。只做文字替換、不格式化。
- R5 表新增列的標題欄不要比既有欄寬長，否則 prettier 會把整張表重排（246 行的 diff）。標題寫短。

## 6. 測試替身的幾個做法（續課異動那串審核突變逼出來的）

- `test-utils/multi-org-db.ts` 的 `hooked(client, hook)`：依表與呼叫過的方法注入結果（模擬讀取失敗、23505），
  或在 update 執行前先改資料（模擬插隊）。用來測「讀完到寫之間被搶先」→ 409。
- `fake-billing-pool` 認 SQL 時**只套 SQL 裡實際寫了的條件**（`sql.includes("status = 'pending'")` 才濾狀態）。
  替身自己硬套條件的話，拿掉條件的突變抓不到。
- 路由層測不出「擋點在交易裡的哪一行」：run 的規劃階段（交易外）已先濾掉已開的報名，已開的學生根本不進 `billStudent`。
  這種順序要直接測 `billStudent`。
- 表單「送出鈕另綁 click」在有重送守門時，API 仍只打一次（等價突變）。要抓它就 `vi.spyOn(cmp, 'save')`，數按一下被叫幾次。

  `await fixture.whenStable()` 之後先斷言 `open` 當正控。
