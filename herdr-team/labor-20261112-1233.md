# labor-20261112-1233 席 charter（生產席：#1928 第 2 輪盤點＋成績總覽 414）

> 只寫知識、不寫狀態。這一席的工作：#1928 第 2 輪全 repo 盤點（issuecomment-6814722404）、PR #2433（`GET /scores/overview` 改 embed 篩）。

## 一、「範圍清單進 `.in()`」怎麼判斷要不要改

- **門檻是實測的**：本機 PostgREST，`academy_scores` 帶 embed 的 select ＋ `exam_id=in.(260 個 uuid)` → **414**（curl 直打）。#1928 本文：~100 個可過、~200 個（長 select）就 414。supabase-js 拿到 414 的 `error.message` 是**空字串**，log 只看得到 `{"error":""}`。
- **分類看陣列從哪來**，不看陣列名字：
  - 要改：由授權範圍或時間窗展開、隨規模長大（分校全部學生、窗內全部考試）
  - 不用改：老師現任班（數十）、單一實體的關聯（一班名冊、一位學生的班）、一頁的 id（受 pageSize）、已切段／已走 pg、固定小集合（分校、科目）
- grep 只抓 `student_id|class_id|id` 會漏：成績總覽是 `.in('exam_id', …)`。盤點時把 `exam_id`／`session_id`／`event_id` 一起看。

## 二、embed `!inner` 在 DB 端篩：能做到的與限制

- **多層一對多 inner 只篩父列、不複製**：`enrollments.select('…, classes!inner(academy_exam_classes!inner(academy_exams!inner(org_id)))')` 再對 `classes.academy_exam_classes.academy_exams.exam_date` 下 `gte`／`lte`，真 PostgREST 回的是「有任一場符合的報名」，每筆一列（#2433 契約驗過）。代價是每列帶著巢狀陣列，窗大時 payload 會長。
- **同一組條件寫一次、帶路徑前綴套到每支查詢**（`scores.ts` 的 `inWindow(query, prefix)`）：考試本身 `''`、成績 `'academy_exams.'`、報名 `'classes.academy_exam_classes.academy_exams.'`。三支條件不會分岔。
- **寫這種 helper 不要用 `Q extends Filterable<Q>` 約束 supabase builder**：會 TS2589（type instantiation excessively deep）。改成 `<Q,>(query: Q)`，內部轉成只含 `eq/gte/lte/in` 的結構型別，回傳時 `as unknown as Q`。
- 受限管理員指名範圍外的 `campusId`：真 app 在中介層就回 **403**，不是 200 空結果；spec（自組 Hono app）會走到 handler 回空。契約要斷言 403。

## 三、`multi-org-db` 替身的窗口限制

- `eq`／`in`／`neq`／`gte`／`lte` 遇到巢狀路徑中途是陣列時，都是「任一筆符合」。**但每個條件各自 `.some`**：`gte` 跟 `lte` 可以由不同子列滿足（「一筆太早、一筆太晚」的父列在替身會過，真 PostgREST 要同一筆子列同時符合）。窗口類邏輯要驗，就寫契約。
- 替身不解析 select，embed 形狀要放在 fixture 裡。從考試表推出成績、報名的 embed（見 `scores-overview.spec.ts` 的 `withEmbeds`），比手寫每列好維護，也跟真 join 同源。

## 四、契約 fixture 要灌幾百列時

- **整批 `unnest`，不要逐列往返**：260 班 × 4 支 insert 逐筆跑要 98 秒，改成每種表一支 `insert … select unnest($1::uuid[]), unnest($2::uuid[])` 後 12 秒。考試要編號就用 `unnest($n::date[]) with ordinality t(d, i)`。`returning id` 的順序跟輸入順序一致，可以用索引配對。
- `courses` 有 `(campus_id, name)` 唯一鍵：同一校建第二門課要換名字。
- 證明「舊碼紅」的最快做法：`git show origin/main:<檔> > <檔>` 跑契約，跑完立刻蓋回新檔，再 `git diff --stat` 確認沒留下舊碼。
