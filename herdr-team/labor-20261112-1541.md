## 一、「只算已載入那幾頁」的修法：API 撈全量、記憶體排序後切頁

- **先看那支 API 是不是本來就撈了全部。** `GET /api/me/billing` 為了算 `totalDue` 早就有一支「不分頁撈全部」的查詢，旁邊那支分頁查詢其實是重複的。拿掉分頁查詢，改成 `sort → slice`，張數、期限、排序就全都是全量，不必新增查詢。
- 前端分章靠 API 的順序。家長帳單的順序是「待繳依期限升冪（沒期限墊底）→ 已繳清依開立日新到舊 → 作廢」，所以第 1 頁就是最該先繳的。「N 張」改讀 `meta.counts`，不要數已載入的列。
- 管理端 `GET /invoices` 帶推導條件（overdue、dueState…）時本來就走「撈到底再篩再切」的路徑，排序加在 `sliceDerivedPage` 前一行就好。**JS 的 sort 是穩定的**：同到期日會沿用 DB 給的開立日新到舊，不必再寫第二鍵。
- **spec 的測資要讓「不排序」跟「排序」結果不同。** 我第一次寫的測資是「開立越晚、到期越早」，DB 順序（開立日新到舊）剛好就等於到期日升冪，排序那行拿掉照樣綠。改成「開立越晚、到期越晚」才測得出來。寫完一定要把排序那行拿掉，確認會紅。
- 前端改成照 API 順序畫之後，spec 要斷言**畫面上列的順序**，不要只看 signal。這頁每一列帶 `view-transition-name: inv-main-<id>`，可以從 style 讀出 id。

## 二、`reload-veil` 的「載入中」膠囊：sticky 零高軌道

- 原本膠囊是 `absolute top-0`。人捲到清單底部按分頁器時，膠囊在畫面外，看起來像沒反應（走查記成「翻頁無載入提示」）。
- 改法：外面包一層 `sticky top-3 z-10 flex h-0 justify-center pointer-events-none`，膠囊放在裡面、改回 `pointer-events-auto`。軌道高度是 0，膠囊溢出、疊在內容上，所以**不推版面**；sticky 讓它貼著可視範圍頂端。這是共用元件，全站的重抓都一起受惠。
- jsdom 沒有版面，spec 只能釘 class（父層帶 `sticky`、`h-0`）。真的看不看得到要靠 compare 或實機。

## 三、`app-dialog-frame` 接 Esc：根因與 `defaultPrevented`

- **根因**：DynamicDialog 開啟時沒帶 `closable`，`DynamicDialogComponent` 會把 `undefined` 綁給內層 `p-dialog` 的 `[closable]`。而 `p-dialog` 只在 `closeOnEscape && closable` 時才掛 Esc 監聽（`primeng-dialog.mjs` 約 836 行）。全站 `showHeader:false` 的開啟點都中。#714 的註解早就寫過，當時只補了 ✕。
- **修在殼上，不要改 45 個開啟點**：host 加 `'(keydown.escape)': 'onEscape($event)'`，發 `closed`。跟按 ✕ 同一條路，離開保護、回報結果都由各對話框自己的 `closed` 處理決定。
- **`event.defaultPrevented` 時略過**：PrimeNG select 在清單開著時按 Esc，會先關清單，並且 `preventDefault`＋`stopPropagation`。殼吃掉 Esc 之後也要 `preventDefault`＋`stopPropagation`，不然外層原生 `<dialog>` 的 cancel、PrimeNG 的 document 監聽會再各關一次。
- 「有離開保護的表單對話框，Esc 與 ✕ 行為相同」：全站目前**沒有**對話框有離開保護（`form-page-leave.guard` 只管整頁）。spec 用 class-form 斷言兩者呼叫 `ref.close` 的次數與參數相同；將來誰加了離開保護，Esc 會自動走同一條路。
- A6 稿的對話框是原生 `showModal`，本來就按 Esc 關，所以這是照稿，不登 R5。

## 四、從原生 `<dialog>` 裡開 ConfirmDialog：`appendTo` 指向那個 dialog

- 家長端詳情用原生 `<dialog>.showModal()`，它在 top layer。DynamicDialog 預設掛在 body，會被蓋在下面，而且被 inert 擋住點不到。開窗時給 `appendTo: this.detailDialog()?.nativeElement`，確認框就跟著進 top layer。
- 確認框的 DOM 在 `<dialog>` 底下，但不在詳情的殼裡面，所以 Esc 只關確認框（殼吃掉了），不會連詳情一起關。
- 元件層 `providers: [DialogService]` 會遮蔽 TestBed 的 provider，spec 要用 `overrideComponent(..., { set: { providers: [...] } })`。替身的 `open` **每次呼叫都回一個新的 Subject**，不然前一次開窗的訂閱還活著，下一次 `next(true)` 會連打兩次。

## 五、「確認前後送出的東西逐欄相同」：golden payload spec

- 在加確認步驟**之前**，先把舊實作會送出的 payload 原樣抄成 literal（`[[{ studentId, items: [...] }], ...]`）。改完後斷言 `create.mock.calls` `toEqual` 這份 golden。不要用改過的程式算預期值，那樣跟自己比永遠綠。
- 預覽裡的期別只能寫**開出去的帳單真的會顯示的字**。開帳 payload 不帶 `periodMonth`，所以期別是「學費」「堂數包」；另編月份就跟開出去的帳單對不上。
- 期限照後端的算法（台北今天＋`invoiceDueDays`）。沒有 `manage_finance` 時 API **不給這個 key**（不是 0），這時寫「依機構設定」，不要猜。

## 六、matchMedia 污染怎麼找

- 症狀：`dialog-steps` 的「沒有 matchMedia 當桌機」在全套測試裡紅，單跑綠。紅不紅取決於 worker 怎麼分配，所以加了不相干的 spec 也可能撞到。
- 找法：列出所有碰 `matchMedia` 的 spec，比較「設定次數」（`stubGlobal('matchMedia'`、`defineProperty`、直接賦值）跟「還原次數」（`unstubAllGlobals`、`deleteProperty`、還原原值）。只有設定、沒有還原的就是嫌犯。這次是 `classrooms-dialog.component.spec.ts`，跟 #2412 的 campus-form 同族。
- 修法：檔頭加 `afterEach(() => vi.unstubAllGlobals())`。另開一張小 PR 先合，不要混進功能 PR。

## 七、流程上的坑

- **驗證腳本吃的是 `HEAD`**：腳本在等鎖，我就切分支，結果驗到的是錯的那支。腳本要吃明確的 sha（`tmp/verify.sh <用途> <sha>`）。
- **`git checkout -- <檔>` 會連沒 commit 的改動一起還原**：做突變時要先 commit 再改，或另存原檔，不要用 checkout 收回突變。
- **一次合併驗證**（機器負載高時計畫席的做法）：開一個暫存 worktree，從最新 main 依序 merge 各支、跑一次全套，合併後 grep 關鍵宣告的次數（「定義＋呼叫」是 2，不是重複）。compare 共用合併版的 API。各張 PR 內文寫「五支疊在 main xxx 一起跑」。
- **compare 前先確認登入態**：`state-admin.json` 過期時會報「被導到 /login」。重產時把 `BETTER_AUTH_URL` 設成自己的 API port，`login.mjs` 帶 `A6_API_URL`。conformance 工具要先 `npm ci --prefix tools/a6-conformance` 才有 playwright。
- 新頁面文案改了，conformance `config.mjs` 該頁的 `deviations` 要跟著換。舊條目的出處不再成立就拿掉（例如「超過一頁不寫張數」）；R5 表則是只加列、不刪。
- Web 單檔 spec：`npx nx test web --skip-nx-cache --include='**/路徑/*.spec.ts'`（在 `apps/web` 底下直接跑 vitest 會找不到 `@core` 別名）。
