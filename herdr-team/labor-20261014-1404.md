## 一、背景跑突變腳本會跟 Stop hook、換分支互相踩（這輪最貴的一課）

- **突變腳本跑 5–10 分鐘（每項約 30 秒 × N），期間檔案是壞的。** Stop hook 剛好在那時跑測試就會報「這輪弄壞了 N 支測試」（假警報，但你得等腳本跑完才能證明）；**同一時間 `git checkout` 別的分支會把別支的檔案換進來**。所以：**突變腳本在背景跑時不碰那幾個檔案、不換分支**；要插隊（reviewer 要你先修別的 PR）就**先停腳本、確認檔案乾淨、WIP commit、再換**。
- **背景程序（`&`／`nohup`）在非互動 shell 會忽略 SIGINT**，`pkill -INT` 殺不掉；**SIGTERM 會殺但不跑 `finally`**，停在哪一項檔案就停在突變狀態。腳本開頭一定加 `signal.signal(SIGTERM/SIGINT, lambda *a: sys.exit(1))`，`finally` 才會跑。這輪就是沒加、手動還原的（逐項檢查「原字串還在不在」找出被改的那項）。
- **`python3 -u`＋`flush=True`**，否則輸出卡在緩衝、你以為還沒開始。等它用 `run_in_background` 的 `until grep -q ALLDONE out; do sleep 5; done`（前景 `sleep N; cat` 會被擋）。
- **突變要「能編譯」才算數**：`@if (false)` 讓模板型別收窄壞掉＝`TS2531`，那不是 spec 抓到的。換成語意等價但能編譯的寫法（`@if (!x)`、`?? {…零物件…}`）。報表那條「billed 0 仍畫條」第一版就是這樣被我誤算成紅。
- **fixture 全部同值，突變就看不見**：餐費章頭「訂 N／M」第一輪 15 紅 2 綠，那 2 項是因為 fixture 裡整班都訂了（N＝M）。**補「0／部分／全部」三種**。reviewer 也抓同一類：**測的是畫面哪個東西，就要有一條斷言那個東西**（餐費「未處理」點的色調整個沒人斷言，改回 `new Date()` 全綠）。

## 二、時鐘與日期（前端一律 `SystemClockService.todayTaipei`）

- **spec 的 fake today 要刻意跟「真實今天」不同**（例如 2027-03-05；本機現在 2026-10-14）。否則元件改回 `new Date()` 也綠。替身：`{ provide: SystemClockService, useValue: { todayTaipei: today } }`，`today` 是 `signal`，**測「過了午夜」就 `today.set(隔天)`**（computed 會跟著變）。要測日界線本身就用**真正的** `taipeiDateString(Date.parse('2026-10-14T15:59:00Z'))`（15:59Z＝當天、16:00Z＝隔天），替身寫成 `todayTaipei: () => taipeiDateString(Date.parse(now))`，**不要在 spec 裡自己再寫一份換算**（測到自己）。
- **原生 `<input type="date">`**：`[value]="dateStr()"`＋`(change)="onDateInput(input)"`；**空值（清空、只打一半）要把欄位還原成目前日期**（`input.value = this.dateStr()`），不然畫面空著、底下還是上一天的名單。`dateStr` 是台北日期**字串**，不經 `new Date()`；要餵 `p-datepicker` 才轉本地午夜 `new Date(y, m-1, d)`（**不要** `new Date('YYYY-MM-DD')`，那是 UTC）。
- **A6 日期格式不一致，別憑印象**：稿裡顯示完整日期的只有 4 頁（通知中心、費用方案、學生檔案、設定）且**全是斜線** `YYYY/MM/DD`；短版一律 `M/D` 不補零。本機另有 6 個模板仍連字號 → #1314 有「全站日期政策」後續項，**單頁改格式只改該頁、spec 註明來源與裁決日期**（通知中心 spec 就寫了「晚於 #425 M4」）。

## 三、Tailwind／harness 的坑

- **`hidden` 與 `grid` 同層時誰贏看 CSS 輸出順序**：我第一版「基礎 `hidden`＋`[class.grid]` 展開」手機展開後仍 `display:none`。**做法：基礎層就是 `grid`，用 `[class.hidden]="!open()"` 切換，桌機 `wide:grid` 蓋掉**（同 #1552）。reviewer 要的是**實測 computed display**（收合 `none`／展開 `grid`／桌機 `grid`），寫進 PR。
- **純 `<button>` harness 要求基底 ≥44px**（`h-11`／`size-11`／`min-h-11`），桌機要小就 `h-11 wide:h-[30px]`；只在桌機顯示的鈕也一樣（基底 `hidden`＋`h-11`）。`p-button outlined` 投影進 `page-actions` 不吃 #1550 的樣式，要改純按鈕（見 1242 charter）。
- 純按鈕共用 class：`border border-solid border-zinc-300 bg-white text-zinc-900 cursor-pointer hover:border-zinc-400 hover:bg-zinc-50`（注意 `enabled:hover:` 與 `hover:` 兩種寫法 repo 內都有）。
- **色面兩行句**：`headline()` computed 回 `{ first, second }`，模板 `{{ first }}<br />{{ second }}`；載入中／失敗／空資料回 `null` 退回頁名（**舊數字配新篩選是最糟的騙法**）。spec 斷言 `app-page-open br` 個數（有資料 1、空 0）。

## 四、稿與頁面對照的判斷

- **稿標「新」＝應然規格、不是漏做**（收件匣、提醒老師補寫、匯出 CSV、今天請假提示、「還沒登入過」chip）。範圍說明裡逐條寫「不做＋原因」，不要默默略過。
- **路由名稱不一定等於使用者講的**：「公告」＝`/admin/notifications`（通知中心），`/admin/notices` 不存在；先 `grep routes-catalog` 再開工，範圍說明開頭寫明對應。
- **稿的 tab 用 hash 切**（`notifications.html#publish`），`acc1404.mjs` 的第二參數直接帶 `"檔名#hash"` 就能拍到；稿的互動分頁（餐費區間）要用 Playwright 點 `[data-tab="range"]` 另拍。
- **稿的共用 CSS 預設 vs 頁面覆寫**：同樣的 `.chap__side` 手機直排／橫排在不同頁不一樣（人員、費用方案頁覆寫成橫排，通知中心沒覆寫＝直排）。**量到差異先查是頁面覆寫還是共用規則**，再決定是不是值得動共用元件（多半不值得，列殘差）。
- **「分校」下拉不加**：本機頁若已 `campusCtx.use()` 跟頂欄（報表、人員、費用方案…），稿多畫的「分校」欄一律不加（10-10 ST 已裁，一半卡片跟頂欄一半自己選比不接更糟）。
