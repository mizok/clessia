## 一、替身會讓測試空轉綠（這一席踩的兩種）

- **`multi-org-db` 的 `rows()` 回的是複本。** 在測試裡 `db.rows('classes')[0]!['x'] = …` **不會進替身**。
  #1212 有一條「清空成 null」的測試因此空轉綠：初值本來就是 null，PUT 有沒有寫都綠。
  **初值一律從 seed 給**（`seed(currentFee)`、`seed({ [CLS]: { … } })`），斷言前先 `expect` 一次初值不是目標值。
  塞陷阱（把寫入改成 `if (body.x)`）才看得出來 —— 改完後陷阱才紅。
- **Angular 的 unit-test builder 會把本地模組打包進 spec，`vi.mock('./本地檔')` 換不到。**
  #1229 實測：元件拿到的是真的解碼器（jsdom 裡退到 jsqr、永遠回 null），測試紅在「沒被呼叫」，看起來像邏輯錯。
  **外部套件（`vi.mock('jsqr')`）換得到。** 本地依賴要換替身就走 DI（`InjectionToken`＋`providedIn: 'root'` 的預設 factory，
  測試 `{ provide: TOKEN, useValue: … }`），範例 `checkin-station/qr-camera.ts` 的 `QR_DECODER_FACTORY`。
- 紅要紅在斷言上：#1220 的新測試一開始紅在 `signInMagicLink is not a function`／`WEB_URL` 的 `trim` —— 那是替身缺東西，
  不是「實作前紅」。先補替身（auth mock 加 `signInMagicLink`、env 帶 `WEB_URL`），讓它紅在 `AssertionError` 再寫實作。

## 二、本機實打：空 embed 長得像成功

## 三、疊 PR 鏈收尾的實際手順（kiosk 鏈、#1212→#1216 都這樣做過）

1. 下層合了 → `gh pr edit <上層> --base main`
2. `git rebase --onto origin/main <下層舊 head>`（舊 head 從 `gh pr view <上層>` 讀到 rebase 前的 base 分支 head；先 `merge-base --is-ancestor` 確認）
3. 跑 gate → `git push --force-with-lease=<分支>:<遠端舊 sha>`（**帶明確的舊 sha**，不是裸 `--force-with-lease`）
4. PR 描述加「追加」段寫新 head 與驗證；保留類轉 ready 但不催合
5. 刪已合併的分支：先 `gh pr list --state open --base <分支>` 確認沒有人疊在上面；遠端常常已被合併時自動刪掉，`ls-remote` 看一下；
   本機分支若掛在別的 worktree（`git branch` 前面是 `+`）不要動

**衝突的解法**：#1206 撞 #1188（兩邊都在 daily-checkins 撈假單）時，不是把兩段都留著，而是**合成一份查詢＋一支 `coveredByLeave`**，
寫入與確認畫面都呼叫它。計畫席明確要求「別讓兩套 leaveCoversSession 各算一次」。

## 四、刻意的判斷（理由的索引）

- **日到班被假蓋到的堂寫 `on_leave`，不是跳過**（#1206）：點名名單送出時也是補寫 `on_leave`（system）；取消打卡只刪 `present`，
  所以這筆跟著假單走。
- **班級目錄參考價的寫入要 `manage_finance`**（#1212）：它改的是家長看到的價錢；沒權限的前端**不畫也不送 key**，
  編輯時**沒改就不送**（原本掛的範本可能已停用，照送會 400）。FK `ON DELETE SET NULL`（不像報名的 RESTRICT）。
- **推薦掛在班不掛課程**（#1216）：目錄一列一班，掛課程會連已額滿的班一起推。
- **打卡站相機**（#1229）：`BarcodeDetector` 要「類別存在**且**格式含 `qr_code`」才用（有 Chromium 有類別沒格式）；
  否則動態 import `jsqr`。選 `jsqr` 不選 `barcode-detector` polyfill：後者的 zxing-wasm 預設從 CDN 抓（離線、c12 自架都卡）。
  機台 `camera="auto"`、管理端 `manual`（桌機一進頁跳權限詢問很擾人）。

## 五、前端雜項

- **不加 SCSS 也能有說明文字**：沒在 Tailwind `@source` 裡的舊元件（例如 `class-form-dialog`）沿用該元件既有的 class（`.class-date-hint`），
  不為一行字開 `@source` 或新 SCSS。
- 加到共用介面的新欄位（`Class.defaultFeeTemplateId`）**先宣告 optional**：required 會讓一堆既有 spec 的 fixture `as Class` 編不過（TS2352）。
- `nx test web` 只跑一支：`--include='**/<檔名>.spec.ts'`（不是 positional，也不是相對 `src/` 的路徑）。
- `prettier --write` 一支別人沒格式化過的 md／json 會改到別人的內容：先 `git show origin/main:<檔> | prettier --check --stdin-filepath <檔>`，
  main 本來就沒過就只做最小改動。
- `qrcode` 沒有型別：測試裡用 `// @ts-expect-error` 寫理由，不為一條測試加 `@types/qrcode`。

## 六、疊 PR 的 migration 時間戳會被後合的追過（v2）

**時間戳是開檔那一刻決定的，合併順序是之後才決定的。** #1216 開檔時 `20261003123801` 是最新的，
等它的時候別人合了 `20261003124241` —— `migrate.yml` 用 Supabase CLI 套差集、不帶 `--include-all`，
CLI 會以 *inserted before the last migration on remote database* 拒絕，**合了才紅**。

- **轉 ready 之前、以及要被合之前**，對一次：`git ls-tree --name-only origin/main supabase/migrations/ | tail -1`，
  自己的檔必須比它新。
- 舊了就 `git mv` 成 `date -u +%Y%m%d%H%M%S`（**UTC**，同 `supabase migration new`），內容不動、grep 舊檔名有無引用，
  `force-with-lease` 推、PR 留言寫理由。**沒合過的才能改**（c3 管的是已提交＝已合進 main）。
- **改名會連帶別的 PR**：新時間戳是「現在」，於是比同時期其他還沒合的 migration（#1247 的 `172458`）新 ——
  **規則是「後合的那支時間戳要最新」**，不是「改過的那支就安全」。合併當下由後合者對一次。

## 七、公開端點鏈（#1241 → #1247 → #1251 → #1259 → #1126）的做法（v2）

- **org 從部署設定來**（`PUBLIC_ORG_SLUG`，`lib/public-org.ts`），沒設＝404 `PUBLIC_DISABLED`。中介層掛在 `authMiddleware` **之前**，
  自建 service client；已經有人設好 `supabase`（測試替身）就沿用 —— 這讓路由 spec 能用 `multi-org-db` 測。
- **harness A7 對 `/api/public/*` 的例外**：免宣告角色，但必須在 `app.use('/api/*', authMiddleware)` 之前。
  比對那一行要**錨在行首**（`index.ts` 的註解裡也寫得出同一串字，`indexOf` 會找到註解）。改 gate 一定塞兩個陷阱（搬到後面、改成非公開路徑）。
- **未驗證的陌生人資料另存一張表**（`public_applications`）：家長端的 `enrollment_requests`／`trial_requests` 要 `student_id`＋`requested_by`
  （ba_user）NOT NULL；送出時建帳號＝讓匿名請求建帳號。報名與試聽共用一張表（`kind`），申請人欄位與寫入抽 `application-common.ts`。
- **班／課程一律以部署 org 重查**，任一不開放整筆 400，**不透露是哪一種**（別 org、不存在、停用、已結束都同一個 code）。
- **名額與額滿用同一支**（`lib/catalog-class.ts` 的 `takenSeats`）：目錄顯示的名額與送出時判的額滿不同源，就會出現「目錄說有位子、送出變候補」。
- 家長目錄與公開目錄共用 `catalog-class.ts` 的映射；**抽共用時對方的 spec 原樣通過**才算沒改行為。
- 測試 helper 的參數預設值會吃掉 `undefined`：`post(db, body, slug = 'demo')` 傳 `undefined` 進去拿到的是 `'demo'`，
  「沒設 slug」那條要傳 `''`。

## 八、管理端看陌生人資料：分校範圍的判準（#1245，v2）

- 公開申請**沒有學生、沒有分校欄位** —— 分校從**目標**推：受限管理員看得到「**任一**目標班／課程的分校在範圍內」的申請；
  試聽的目標是課程，看 `courses.campus_id`。
- **目標全被刪（`SET NULL`）的申請只有不受限的看得到** —— 推不出分校就不給受限的人，不是給所有人。
- PATCH 用同一個 `visible()`，範圍外跟不存在一樣 404（同 `findInOrg` 慣例，不透露存在）。
- **讀也要權限**（`all: 'manage_students'`），不是只擋寫：這張表就是個資。
- `inOrg(...)` 包住長 select 的 builder 會撞 TS2589：直接 `.eq('org_id', orgId)`，註解指向 `org-scope.ts:96` 的同款既有做法；
  另外長 select 字串宣告成 `const SELECT: string` 才不會被 supabase-js 的型別解析器展開。
