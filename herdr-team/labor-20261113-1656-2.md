## 2. `audit_campus_ids()` 的維護規則（#2521）

- **新增 `resource_type` 時，同一張 PR 要把它加進 `audit_campus_ids()`**（新的 migration，用 `CREATE OR REPLACE`；
  不能改已提交的檔，c3）。沒加的話會落到 ELSE、變成 NULL，受限者看不到那些紀錄。這是 fail-closed，不會誤放，
  但會「看不到」。
- 同一種 type 的 `resource_id` 不統一：`attendance` 有 event／daily_checkin／leave 三種，`enrollment` 有兩處放
  classId。函式是逐表試的，新加的呼叫點如果又放了別種 id，要在函式裡補一條試法。
- **刪除**：寫稽核時那一列已經不在，trigger 反查不到。呼叫端帶 `campusIds`：能從刪前讀的列拿就拿，
  否則在刪前呼叫 `auditCampusIdsBeforeDelete()`（rpc 同一支函式）。
- 不在 `logAudit` 反查是刻意的：那樣每筆稽核多一個 subrequest，請假（≤45）、學生、開帳單都有預算測試在守。

## 3. 驗證腳本與鎖（這次踩過的）

- **拿鎖只寫 `until mkdir $L; do sleep 30; done`**，pid 檔只寫 `$$`，席名另寫 `$L/who`。
  派單範本裡那段「pid 不在就清」的過期分支，在 pid 檔不是純數字時會判成過期、刪掉別人正在用的鎖。
  11-13 我因此刪了審核席的鎖兩次。
- 暫存 worktree 腳本的收尾會 kill 自己 port 的 workerd，但 **wrangler 可能在收尾之後才重生一支 workerd**。
  它的 cwd 留在已移除的暫存目錄，會把目錄重新建出來，下一次 `git worktree add` 就失敗（already exists）。
  遇到就用 `lsof -a -p <pid> -d cwd` 確認是自己的再 kill；目錄刪不掉（`rm -rf` 被擋）就換一個暫存路徑。
- **PR 改到 API 時，compare 要用那份程式碼起 API**（暫存 worktree 裡起 wrangler），不然前端拿不到新欄位。
  起完先 `curl /api/me` 暖兩三次再跑 compare：冷啟動的 wrangler 會讓頁面被導到 `login?reason=connection-error`。
- **compare 的工具版本取自「執行時座位 checkout 的分支」**：背景排著 compare 時切了分支，量的就是別支的工具設定。
  報表頭的「工具 @ <sha>」要跟你以為的一致。
- 暫存 worktree 併 main 撞衝突時，腳本照規則停下、不跑。分支還沒派合的話，由作者在分支上 merge main 解掉再重跑。
  A30 的 `campus-scope-contract-baseline.json` 常撞：兩邊各刪不同的鍵，**兩邊的刪除都要保留**。

## 4. A6 compare 讀法

- 待修總數相同、但同時出現「新增 1、修掉 1」，可能只是同一處換了文案。例：量測帳號今天沒課，
  色面句本來就跟稿不同；換了新句子，就被算成新增一條、修掉一條。不是回歸，PR 內文寫明即可。
- 依資料決定出不出現的元件（例如「兩週內沒課就不放主按鈕」），量測帳號剛好落在不出現那一側時會被算成「缺」，
  要在 `tools/a6-conformance/lib/config.mjs` 登記偏離，出處寫 R5 那一列。
- `p-renewal-none` 原本量的是沒有任何課的張品妍，月繳孩子的文案量不到；已加 `prep: PARENT_PREP` 切到張宇軒（#2507）。
