# 考務與成績板塊 — 重構設計（方案 B+）

> **狀態**：設計完成，待審閱
> **日期**：2026-04-10
> **背景**：原三頁設計（補習班考試 / 段考登錄 / 成績查閱）經 Claude Code 與 Codex 獨立審查，發現多個致命流程問題與過度設計。本文件為重構後的設計方案。

---

## 一、問題回顧

### 致命問題
1. **首次成績登錄走不通** — API 只讀既有成績，新考試打開是空表，無法輸入
2. **段考登錄完全不可用** — 沒有「選學生」機制，也沒有定義學生來源

### 嚴重問題
3. **成績登錄塞在 720px dialog** — 30+ 筆輸入在彈窗裡捲動，核心操作被當附帶功能
4. **三態狀態機過度設計** — draft/published/closed 無對應營運價值（無通知、無權限鎖定）
5. **前後端驗證不一致** — classIds 後端必填但前端沒驗；closed 狀態 API 沒擋寫入
6. **成績查閱頁價值模糊** — flat 列表無匯總，跟學生詳情頁功能重複
7. **scores API 搜尋不準** — UI 說搜「學生或考試名稱」，API 只搜學生名
8. **scores API 記憶體分頁** — 全抓再 slice，大量資料會慢

---

## 二、設計決策

### 已拍板決策

| 決策 | 結論 | 理由 |
|------|------|------|
| 頁面架構 | 從 3 頁改為 2 頁（考試管理 + 成績總覽） | 符合管理員心智模型：「建考試登成績」和「查成績」 |
| 補習班考試 target model | 關聯班級，登錄時從班級成員選人填分數 | 不預定名單、不快照；「誰考了」= 誰有成績紀錄 |
| 段考 target model | 不關聯班級，科目從系統科目管理拉，學生從全部 active 學生選 | 段考是學校考試，跟補習班課程班級無直接關係 |
| 段考 exam_date | 新增 `exam_date` 欄位 | 混排排序需要統一時間軸 |
| 狀態機 | 移除 `draft`，只保留 `active` / `closed` | draft 無營運價值，建立即可用 |
| 進度顯示 | 顯示「已登 N 筆」，不顯示「已登/應登」 | 名單不預定義，無法算精確的「應登」 |
| 成績登錄 | 從 dialog 改為子頁面 | 核心操作需要完整空間 |
| 列表合併 | 不用 tab 硬切 academy/term，用 chip/select 篩選 | 避免資訊斷裂 |

### 待辦提醒

- 條件：`status = active` 且 `已登錄筆數 = 0` 的考試
- UI：頂部 InlineNotice 或輕量卡片
- 點「查看」展開或篩選出這些考試

### 篩選列

| 篩選 | 元件 | 說明 |
|------|------|------|
| 類型 | Chip/SegmentedControl | 全部 / 補習班考試 / 段考 |
| 校區 | Select | 多分校篩選（補習班考試用 campus_id，段考暫不篩校區） |
| 科目 | Select | 補習班考試的 subject_id |
| 狀態 | Select | 全部 / 進行中 / 已結束 |

### 列表欄位

| 欄位 | 來源 | 說明 |
|------|------|------|
| 考試名稱 | `name`（academy）或 `label`（term） | 可點擊，進入成績登錄 |
| 類型 | Tag | 「補習班」或「段考」 |
| 日期 | `exam_date` | 統一排序欄位 |
| 範圍 | 關聯班級數 | 補習班顯示「N 班」，段考顯示「—」 |
| 已登錄 | score count | 「N 筆」 |
| 狀態 | Tag | 「進行中」/「已結束」 |
| 操作 | PopupMenu | 見下方 |

### 操作選單

| 操作 | 條件 | 說明 |
|------|------|------|
| 進入登錄 | status = active | 主要 CTA，跳轉到成績登錄子頁面 |
| 編輯基本資料 | status = active | 開 dialog 編輯考試資訊 |
| 結束考試 | status = active | 確認後改為 closed |
| 重新開啟 | status = closed | 確認後改回 active |
| 刪除 | 已登錄 = 0 筆 | 僅限無成績紀錄時 |

### 建立考試流程

1. 點「建立考試」按鈕
2. 先選類型（補習班 / 段考）— 可用 SegmentedControl 或兩個按鈕
3. 進入對應表單 dialog：
   - **補習班考試**：名稱、類型（小考/模擬考/分班考）、科目、考試日期、滿分、範圍說明、關聯班級（必填 multi-select）
   - **段考**：學年度、學期、考次、考試日期
4. 建立成功後**自動跳轉到成績登錄子頁面**

### 補習班考試編輯器（type = academy）

**維度**：1 場考試 × N 學生 × 1 科（或無科目）

**學生來源**：從關聯班級的 active enrollments **聯集已有成績紀錄的學生**（確保轉班/退班學生的歷史成績不消失）。

**UI 結構**：
- 頂部：班級篩選（如果關聯多個班級，可切換顯示哪個班的學生）
- 表格（名冊式，學生為列）：

| 學生 | 年級 | 分數 | 狀態 | 備註 |
|------|------|------|------|------|
| 王小明 | 國一 | `[72]` | `[已作答▾]` | `[______]` |
| 李小華 | 國一 | `[  ]` | `[已作答▾]` | `[______]` |
| 張大偉 | 國一 | `[  ]` | `[缺考  ▾]` | `[______]` |

**交互**：
- 分數欄位支援 Tab 鍵連續跳到下一個學生
- 選「缺考」時自動清空分數、disable 分數輸入
- 已有成績的學生自動帶入現有值
- 未登錄的學生分數欄位為空
- 離頁防呆：有未儲存變更時提示

**儲存行為**：
- 只送出有值的行（分數不為空 或 狀態為缺考/補考）
- 空白行不送出（不會產生無意義的 score record）
- Upsert：`INSERT ... ON CONFLICT (exam_id, student_id) DO UPDATE`

### 段考編輯器（type = term）

**維度**：N 學生 × N 科目（從系統科目管理拉）

**學生來源**：系統全部 active 學生，需要良好的搜尋/篩選 UX。

**UI 結構**：

```
┌─────────────────────────────────────────────────┐
│ 選擇學生                                          │
│ ┌──────────────────────────┐                      │
│ │ 🔍 搜尋學生姓名...        │  [國一][國二][國三] │  ← 搜尋 + 年級 chip 篩選
│ └──────────────────────────┘                      │
│                                                   │
│ 最近登錄：王小明、李小華、張大偉          [展開全部] │  ← 快捷入口
├─────────────────────────────────────────────────┤
│ ▼ 王小明（國一）                         [收合]   │  ← 選中學生，展開成績表
│ ┌─────────────────────────────────────────────┐  │
│ │ 科目   │ 分數       │ 狀態     │ 備註       │  │
│ │ 國文   │ [85]       │ [已作答▾]│ [______]   │  │
│ │ 英文   │ [72]       │ [已作答▾]│ [______]   │  │
│ │ 數學   │ [  ]       │ [已作答▾]│ [______]   │  │
│ │ 自然   │ [  ]       │ [缺考  ▾]│ [______]   │  │
│ └─────────────────────────────────────────────┘  │
│                                       [儲存]     │
│                                                   │
│ ▶ 李小華（國一）                         [展開]   │  ← 下一個學生
│ ▶ 張大偉（國一）                         [展開]   │
└─────────────────────────────────────────────────┘
```

**搜尋學生 UX**：
1. **搜尋框**：支援姓名模糊搜尋，打 2 個字開始過濾
2. **年級 chip 篩選**：段考按年級考，這是最自然的篩選維度（P1-P6, J1-J3, S1-S3）
3. **校區篩選**：多分校時先選校區縮小範圍
4. **最近登錄**：這場段考已有成績紀錄的學生列在上方，方便確認進度和繼續輸入
5. **搜尋結果**：顯示學生姓名 + 年級 + 校區，點擊後展開該學生的科目成績表

**交互**：
- 點擊學生 → 展開該生的科目成績表（accordion 風格）
- 科目列表從系統科目管理拉取
- 已有成績自動帶入
- 儲存後收合，繼續選下一個學生
- 支援同時展開多個學生

**儲存行為**：
- 頁面底部統一「儲存成績」按鈕，一次送出所有已展開學生的變更
- 支援連續操作：展開學生 A 填完 → 展開學生 B 填完 → 一起儲存
- Upsert：`INSERT ... ON CONFLICT (term_exam_id, student_id, subject_id) DO UPDATE`

## 七、DB Schema 變更

### 變更清單

| 表 | 變更 | 說明 |
|----|------|------|
| `academy_exam_status` | 移除 `draft`，只保留 `active`, `closed` | 簡化狀態機 |
| `academy_exams.status` | 預設值改為 `'active'` | 建立即可用 |
| `term_exams` | 新增 `exam_date date`、`status term_exam_status` | 排序用 + 狀態控制 |
| `term_exam_status` | 新建 enum `('active', 'closed')` | 段考也需要狀態 |

### 不做的事

| 項目 | 理由 |
|------|------|
| `academy_exam_targets` 快照表 | 不預定名單，「誰考了」= 誰有成績紀錄 |
| `term_exam_classes` 段考關聯班級 | 段考不關聯班級 |
| `term_exam_subjects` 段考關聯科目 | 直接從系統科目管理拉取 |

## 八、API 變更

### 補習班考試 API 修正

| 端點 | 變更 |
|------|------|
| `POST /api/academy-exams` | status 預設 `active`（移除 draft） |
| `POST /api/academy-exams/:id/scores` | **新增 closed 狀態檢查**，拒絕 closed 考試的寫入 |
| `GET /api/academy-exams/:id/scores` | **改為從班級 enrollment ∪ 已有成績學生產生候選名單**，LEFT JOIN 現有成績 |
| `PATCH /api/academy-exams/:id/publish` | **移除**（不再需要） |
| `PATCH /api/academy-exams/:id/reopen` | **新增**，closed → active |

### 段考 API 修正

| 端點 | 變更 |
|------|------|
| `POST /api/term-exams` | 新增 `exam_date` 欄位 |
| `GET /api/term-exams/:id/scores` | 維持現有行為（回傳已登錄成績） |
| `POST /api/term-exams/:id/scores` | **新增 closed 狀態檢查** |
| `PATCH /api/term-exams/:id/close` | **新增** |
| `PATCH /api/term-exams/:id/reopen` | **新增** |

### 段考編輯器所需 API（新增）

| 端點 | 說明 |
|------|------|
| `GET /api/students?search=&grade=&campusId=&page=1&pageSize=20` | 候選學生搜尋（複用現有 students API）。支援分頁（page + pageSize）、按姓名排序、年級篩選（grade）、校區篩選（campusId）。 |
| `GET /api/term-exams/:id/recent-students` | **新增**：該場段考已有成績紀錄的學生列表（按 `updated_at` 倒排），用於段考編輯器的「最近登錄」快捷入口。 |
| `GET /api/term-exams/:id/scores?studentId=xxx` | **擴充**：支援 `studentId` 參數，回傳該學生在此段考的各科成績。避免全量抓取再前端過濾。 |
| `GET /api/subjects` | 複用現有 API，取得系統科目列表。 |

### 成績查閱 API 修正

| 端點 | 變更 |
|------|------|
| `GET /api/scores` | **搜尋修正**：同時搜學生名和考試名稱 |
| `GET /api/scores` | **分頁修正**：改為 DB 層 UNION ALL + LIMIT/OFFSET |
| `GET /api/scores` | **段考日期修正**：使用 `exam_date` 而非 `created_at` |
| `GET /api/scores/student/:studentId/summary` | **新增**：學生成績摘要（各科平均） |
| `GET /api/scores/class/:classId/exam/:examId` | **新增**：班級某場考試統計 |

## 十、Metadata 變更規則

考試建立後，某些欄位在特定條件下不可修改：

### 補習班考試

| 欄位 | 無成績時 | 已有成績時 | 已結束 |
|------|----------|-----------|--------|
| 名稱 | ✅ 可改 | ✅ 可改 | ❌ 不可改 |
| 類型 | ✅ 可改 | ❌ 不可改 | ❌ 不可改 |
| 科目 | ✅ 可改 | ❌ 不可改 | ❌ 不可改 |
| 考試日期 | ✅ 可改 | ✅ 可改 | ❌ 不可改 |
| 滿分 | ✅ 可改 | ❌ 不可改 | ❌ 不可改 |
| 範圍說明 | ✅ 可改 | ✅ 可改 | ❌ 不可改 |
| 關聯班級 | ✅ 可改 | ❌ 不可改 | ❌ 不可改 |

### 段考

| 欄位 | 無成績時 | 已有成績時 | 已結束 |
|------|----------|-----------|--------|
| 學年/學期/考次 | ✅ 可改 | ❌ 不可改 | ❌ 不可改 |
| 考試日期 | ✅ 可改 | ✅ 可改 | ❌ 不可改 |

**原則**：會影響成績語意的欄位（科目、滿分、關聯班級、學年學期考次），一旦有成績就鎖定。

## 十一、校區篩選語意

| 場景 | 校區篩選行為 |
|------|-------------|
| 考試管理列表 | 按 `academy_exams.campus_id` 篩選；段考不受校區篩選影響（段考不關聯校區） |
| 補習班考試成績登錄 | 不需要校區篩選（學生來自關聯班級） |
| 段考成績登錄（選學生） | 校區篩選作用於學生搜尋（按學生的 campus 篩選），用於縮小搜尋範圍 |
| 成績總覽 | 學生視角不篩校區；班級視角按班級所屬課程的校區篩選 |
