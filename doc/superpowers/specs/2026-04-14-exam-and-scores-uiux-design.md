# 考務與成績板塊 UI/UX 改版設計

> 狀態：設計完成，待實作
> 日期：2026-04-14
> 範圍：管理端考試管理、成績總覽、成績登錄；家長端成績頁

## 一、背景與問題

目前「考務與成績」板塊已具備基本流程，但整體 UI/UX 仍存在以下明顯缺陷：

1. 多數頁面仍以桌機表格思維為主，手機操作時需要大量橫向捲動。
2. 視覺層次偏平，重點資訊、狀態與主操作沒有被明確設計出來。
3. 高頻任務如找考試、找學生、輸入分數、辨識異常分數，缺少低阻力互動。
4. 家長端成績頁尚未落地，整個板塊缺少 mobile-first 的閱讀型介面。

本次改版目標不是只做樣式微調，而是重新整理資訊結構、操作節奏與跨裝置呈現策略。

## 二、改版目標

### 核心目標

1. 讓管理端在手機上也能完成成績輸入與查閱。
2. 建立更符合人類視覺閱讀的層次，而不是單純白卡 + 表格。
3. 提升高頻任務效率，降低搜尋、篩選與輸入成本。
4. 補齊家長端成績頁，完成整個板塊的主要使用情境。

### 成功標準

1. 成績登錄在手機上不需要依賴水平卷軸完成核心操作。
2. 成績總覽能在 3 秒內辨識重點表現與異常狀態。
3. 考試管理頁能在手機上快速篩選、定位並進入目標考試。
4. 家長端可直接在手機上閱讀孩子近期成績與科目表現。

## 三、設計原則

1. Mobile-first，但保留桌機高密度優勢。
2. 高頻操作優先於資訊完整平鋪。
3. 重要資訊不能被埋進水平卷軸。
4. 先做摘要，再做明細。
5. 狀態、分數、異常必須一眼可辨。

## 四、視覺方向

### 設計主題

`Calm Academic Operations`

介面應呈現有秩序、可信賴、帶有學務管理感的視覺語言，而不是通用後台模板。

### 視覺規範

1. 主色維持 `zinc + sky`。
2. 警示使用 `amber`，風險與不及格使用 `red`。
3. 摘要卡、提醒卡、狀態卡需建立明確主次層次。
4. 行動裝置減少並列欄位，改用卡片與區塊式呈現。

## 五、頁面改版方案

## 5.1 考試管理

### 路由

`/admin/grades/exams`

### 桌機版結構

1. Header：
   - 左側：頁面標題與說明
   - 右側：主 CTA `新增考試`
2. 待辦提醒條：
   - 顯示未登錄考試數量
   - 直接提示待處理情境
3. 篩選區：
   - 第一列：搜尋、時間範圍
   - 第二列：考試類型
   - 第三列：校區、科目、狀態
4. 列表區：
   - 主資訊：考試名稱、日期、狀態、已登錄
   - 次資訊：類型、校區、科目、範圍

### 手機版結構

1. Header 改直向堆疊。
2. `新增考試` 改為滿寬主按鈕。
3. 搜尋獨立一列。
4. `考試類型` 用 segmented control 單獨一列。
5. `校區 / 科目 / 狀態 / 時間` 收進篩選 bottom sheet。
6. 列表改成卡片清單，不以 table 為主視圖。

### 手機版考試卡片

1. 第一行：考試名稱 + 狀態 tag
2. 第二行：日期 + 類型
3. 第三行：校區 / 科目 / 範圍
4. 第四行：已登錄筆數
5. 底部：`進入登錄` 主按鈕 + 更多操作按鈕

## 5.2 成績總覽

### 路由

`/admin/grades/overview`

### 改版重點

目前只有視角切換器，沒有前導摘要，也沒有讓兩種視角形成不同任務感。

### 新結構

1. Header：
   - 標題與說明
2. 視角切換卡：
   - 學生視角：查看單一學生歷次成績
   - 班級視角：查看單場考試的班級統計與排名
3. 內容區依視角呈現完全不同節奏

### 手機版

1. 視角切換器滿寬。
2. 下方補一行說明文，明確交代目前模式用途。
3. 首屏直接進入任務內容，不保留過多空白。

## 5.3 班級視角

### 路由內子區塊

`/admin/grades/overview` -> `class-view`

### 桌機版結構

1. 先選班級
2. 再選考試
3. 顯示 2x2 摘要卡：
   - 平均分
   - 最高分
   - 最低分
   - 已登錄 / 缺考
4. 狀態篩選列
5. 名次列表

### 桌機列表要求

1. 可維持 table
2. 分數欄要成為視覺重點
3. 缺考與不及格需有一致 badge / 警示樣式
4. 備註不能只剩 ellipsis，需支援完整閱讀

### 手機版結構

1. 選擇器改直向堆疊
2. 摘要卡維持 2 欄 grid
3. 名次列表改成學生卡片

### 手機版學生卡

1. 名次 + 姓名
2. 分數
3. 狀態 tag
4. 備註
5. 低分以警示色條凸顯

## 5.4 學生視角

### 路由內子區塊

`/admin/grades/overview` -> `student-view`

### 桌機版結構

1. 搜尋學生
2. 學生資訊卡
3. 科目摘要卡群
4. 篩選列
5. 成績紀錄列表

### 科目摘要卡

每張卡包含：

1. 科目名稱
2. 補習班平均
3. 段考平均
4. 總紀錄數

### 成績紀錄列表

桌機可保留 table，但需改成更強調：

1. 考試名稱
2. 分數
3. 日期與類型作為次資訊

### 手機版結構

1. 學生資訊卡滿寬
2. 科目摘要改成 2 欄 grid 或可橫滑卡片列
3. 篩選列直向堆疊
4. 成績紀錄改成 timeline / card list

### 手機版成績卡

1. 第一行：考試名稱 + 分數
2. 第二行：日期、類型、科目
3. 若不及格，分數使用警示色
4. 若有總分，顯示 `得分 / 滿分`

## 5.5 補習班考試成績登錄

### 路由

`/admin/grades/exams/:type/:id/scores`，`type = academy`

### 桌機版

1. 保留 table 輸入模式
2. 表頭 sticky
3. 學生姓名欄 sticky
4. 分數欄寬增加
5. 狀態與備註欄避免過窄

### 手機版

改成學生輸入卡，不使用 table 主呈現。

### 每張學生輸入卡內容

1. 姓名
2. 年級
3. 分數輸入
4. 狀態選擇
5. 備註輸入
6. 若有修改，顯示 `未儲存` 標記

### 互動規則

1. 狀態為缺考時，分數欄 disabled 或收起
2. 可加入 `只看未登錄` 篩選
3. 儲存成功後提供局部回饋，不只 toast

## 5.6 段考成績登錄

### 路由

`/admin/grades/exams/:type/:id/scores`，`type = term`

### 桌機版

1. 搜尋學生
2. 年級篩選
3. 最近登錄學生
4. 展開學生後顯示科目輸入區

### 手機版

1. 搜尋框滿寬
2. 年級篩選獨立一列
3. 最近登錄 chip 放大為明確可點擊入口
4. 學生展開後改成科目卡片列表

### 每個科目卡內容

1. 科目名稱
2. 分數輸入
3. 狀態選擇
4. 備註
5. 若已有資料，顯示已登錄提示

## 5.7 成績登錄共用頁首

### 共用範圍

`score-entry`

### 桌機版

1. breadcrumb / 返回
2. 考試名稱與狀態
3. meta 資訊
4. 摘要區
5. sticky action bar

### 手機版

1. 標題與狀態允許換行
2. meta 改成多行資訊列或 chip 組
3. 底部 action bar 改為上下堆疊
4. 明確顯示未儲存狀態

## 5.8 家長端成績頁

### 路由

`/parent/grades`

### 設計定位

此頁應以 mobile-first 為原則，是閱讀型頁面，不應使用桌機表格思維。

### 結構

1. 孩子切換器
2. 本期重點摘要
3. 最近考試成績卡
4. 科目平均卡
5. 歷次成績列表

### 手機版成績卡

1. 考試名稱
2. 日期
3. 科目
4. 分數
5. 缺考 / 低分狀態

### 桌機版

1. 保持卡片閱讀形式
2. 只做寬版排版，不轉成資料表格

## 六、元件層建議

### 建議新增或調整的共用模式

1. `stats-card-group`
   - 用於平均分、最高分、最低分、缺考等摘要
2. `mobile-input-card`
   - 用於手機版成績輸入
3. `record-list-card`
   - 用於手機版成績紀錄清單
4. `filter-sheet`
   - 用於行動裝置進階篩選
