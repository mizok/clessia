# 試聽申請流程

本文件整理 PRD 6.2，定義試聽申請從提交、安排、試聽到跟進的完整流程。此流程與報名申請流程獨立，但可在資料層建立來源關聯。

## 1. 流程範圍與角色

- 主要角色：家長（通常為無帳號新家長）、系統、管理員。
- 關聯功能：`/trial`（公開表單）、`/admin/trials`（試聽管理）、任務中心（安排/跟進）。

## 2. 狀態流轉

`pending` → `scheduled` → `completed`

可中止分支：

- `canceled`：家長取消時由管理員代為標記。

## 3. 完整流程（誰做什麼）

### 步驟 1：家長提交試聽申請

- 觸發條件：家長在 `/trial` 送出表單。
- 家長填寫：家長資訊、學生資訊、想試聽課程（可多選）、方便時段、備註。
- 系統建立 Trial Request，狀態 `pending`。

### 步驟 2：系統建立試聽安排任務

- 系統自動產生任務：`trial_arrangement`。
- 任務派送給對應分校管理員團隊。

### 步驟 3：管理員安排試聽

- 管理員認領任務後聯繫家長。
- 管理員在系統填寫安排課堂與聯繫備註。
- 狀態轉為 `scheduled`。

### 步驟 4：學生到班試聽

- 觸發條件：試聽日到達並完成試聽。
- 管理員將申請標記為試聽完成。

### 步驟 5：系統建立試聽跟進任務

- 系統自動產生任務：`trial_followup`。
- 管理員收到待跟進工作。

### 步驟 6：管理員電話跟進意願

- 管理員記錄結果：
  - 要報名：引導家長另填報名申請（`/apply`）或由管理員建立報名。
  - 不報名：記錄原因並結案。
  - 考慮中：記錄備註，後續再跟進。
- 試聽流程最終狀態為 `completed`（或在中途轉 `canceled`）。

## 4. 與報名流程的關係

- 試聽與報名是兩條獨立流程，不互為前置條件。
- 家長可不經試聽直接報名，也可試聽後再報名。
- 當系統偵測到同家長/學生已建立報名申請時，可自動關閉仍進行中的試聽申請與相關跟進任務，避免重工。
